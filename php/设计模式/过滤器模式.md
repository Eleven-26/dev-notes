# 过滤器模式（Criteria）：把"谓词"当一等公民，对集合做可组合的筛选

> 素材来源：博客系列 [PHP 设计模式(九)：过滤器模式](https://blog.csdn.net/weixin_43837229/article/details/102683061)。
> 原文用 `Criteria` 接口层层套娃演示 and/or/not；本篇改成 PHP 习用的**闭包 + `array_filter` 写法，实测各组合命中条数**，
> 并补上原文回避的工程问题：**为什么真实项目里它常被 SQL 条件拼装或 Laravel Scope 取代，剩下哪些场景仍值得在内存里筛**。

## 一、它和策略、责任链到底差在哪

过滤器（Filter/Criteria）：对**同一个集合**用多个布尔谓词做筛选，且谓词可 **and / or / not 组合**。三条本质区别：

| | 过滤器（Criteria） | 策略 | 责任链 |
| --- | --- | --- | --- |
| 返回值 | bool（只回答"要不要"） | 业务结果（加工数据不算错） | 处理结果或"传给下一个" |
| 对数据做什么 | 只选不改，纯函数 | 可任意加工 | 可加工、拦截、短路 |
| 顺序敏感吗 | 不敏感（与或非可交换） | 单选一个 | 顺序即语义 |
| 组合代数 | andX/orX/notX 封闭：组合后还是谓词 | 一般不提供组合子 | `next()` 链式传递 |

判别口诀：**能画出"谓词进、bool 出、组合后仍是谓词"闭环的才是过滤器**；会改数据、会中断流程的已经滑向责任链。

## 二、最小实现：闭包谓词 + 三个手写组合器

```php
<?php
declare(strict_types=1);

$rows = [
    ['name' => 'Ann',  'age' => 35, 'city' => '杭州', 'active' => true],
    ['name' => 'Bob',  'age' => 28, 'city' => '杭州', 'active' => false],
    ['name' => 'Cid',  'age' => 41, 'city' => '上海', 'active' => true],
    ['name' => 'Dan',  'age' => 22, 'city' => '上海', 'active' => true],
    ['name' => 'Eve',  'age' => 30, 'city' => '北京', 'active' => false],
    ['name' => 'Finn', 'age' => 33, 'city' => '杭州', 'active' => true],
];
// 谓词 = "一行进、bool 出"的闭包
$age30 = static fn(array $r): bool => $r['age'] >= 30;
$hz    = static fn(array $r): bool => $r['city'] === '杭州';
$on    = static fn(array $r): bool => $r['active'] === true;

// 组合器：PHP 到 8.1 都没有内置 and/or，只能自己写这三行
$andX = static fn(callable $a, callable $b): callable => static fn(array $r): bool => $a($r) && $b($r);
$orX  = static fn(callable $a, callable $b): callable => static fn(array $r): bool => $a($r) || $b($r);
$notX = static fn(callable $a): callable => static fn(array $r): bool => !$a($r);

$show = static function (string $label, callable $p) use ($rows): void {
    $hits = array_filter($rows, $p);
    printf("%-26s hits=%d  names=%s\n", $label, count($hits), implode(',', array_column($hits, 'name')) ?: '-');
};

$show('age>=30', $age30); $show('city==杭州', $hz);
$show('age AND city', $andX($age30, $hz)); $show('age OR city', $orX($age30, $hz));
$show('(age AND city) OR active', $orX($andX($age30, $hz), $on)); $show('NOT active', $notX($on));
$kept = array_filter($rows, $hz); echo 'array_filter 保留原键: ', implode(',', array_keys($kept)), PHP_EOL;
```

实测输出（`D:\phpstudy_pro\Extensions\php\php8.0.2nts\php.exe`）：

```text
age>=30                    hits=4  names=Ann,Cid,Eve,Finn
city==杭州               hits=3  names=Ann,Bob,Finn
age AND city               hits=2  names=Ann,Finn
age OR city                hits=5  names=Ann,Bob,Cid,Eve,Finn
(age AND city) OR active   hits=4  names=Ann,Cid,Dan,Finn
NOT active                 hits=2  names=Bob,Eve
array_filter 保留原键: 0,1,5
```

四条与语言绑定相关的事实，别记错：

1. **组合子是自己写的三行，不是标准库**。andX/orX/notX 把两个谓词变成一个**新谓词**，所以可无限嵌套——第五行 `(age AND city) OR active` 就是嵌套现场，命中 = {Ann,Finn} ∪ {Ann,Cid,Dan,Finn} = 4 条。
2. **`array_filter` 保留原键**（末行实测 `0,1,5`：Bob/Dan/Eve 的下标被抠掉但位置不补）。要连续下标、或 `json_encode` 给前端（否则变成对象）之前记得补 `array_values()`。
3. **回调按原数组顺序逐行求值**，行为稳定可依赖；短路只发生在 `&&`/`||` 内部，`array_filter` 没有"前面筛掉就跳过后面"的能力。
4. PHP 8.1 也没有内置组合器——网上若见到 `array_filter_and()` 这类"标准函数"，都是杜撰。

## 三、和 Collection 类的关系：过滤器是集合类的常见接口形状

函数式写法够用，但当同一套筛选要被多个消费方复用时，把谓词挂到集合对象上更符合 PHP 生态习惯——Laravel Collections 的 `filter()/reject()` 就是这个模式的材料化：

```php
<?php
declare(strict_types=1);

// Collection 风格：filter/reject/anyOf 都返回"新集合"，原集合不变
final class RowCollection implements Countable, IteratorAggregate
{
    private array $items;
    /** @var callable[] 累积的谓词，filter 链就是 andX */
    private array $predicates = [];

    public function __construct(array $items) { $this->items = array_values($items); }

    public function filter(callable $p): self { $c = clone $this; $c->predicates[] = $p; return $c; }
    public function reject(callable $p): self { return $this->filter(static fn(array $r): bool => !$p($r)); }
    /** anyOf 是"一层 orX"：满足任意一个即保留（与其它 filter 之间仍是 AND） */
    public function anyOf(callable ...$ps): self
    {
        return $this->filter(static fn(array $r): bool => (bool) array_filter($ps, static fn(callable $p): bool => $p($r)));
    }
    public function all(): array
    {
        $rows = $this->items;
        foreach ($this->predicates as $p) { $rows = array_values(array_filter($rows, $p)); }
        return $rows;
    }
    public function count(): int { return count($this->all()); }
    public function getIterator(): ArrayIterator { return new ArrayIterator($this->all()); }
    public function names(): string { return implode(',', array_column($this->all(), 'name')) ?: '-'; }
}

$rows = [
    ['name' => 'Ann',  'age' => 35, 'city' => '杭州', 'active' => true],
    ['name' => 'Bob',  'age' => 28, 'city' => '杭州', 'active' => false],
    ['name' => 'Cid',  'age' => 41, 'city' => '上海', 'active' => true],
    ['name' => 'Dan',  'age' => 22, 'city' => '上海', 'active' => true],
    ['name' => 'Eve',  'age' => 30, 'city' => '北京', 'active' => false],
    ['name' => 'Finn', 'age' => 33, 'city' => '杭州', 'active' => true],
];
$age30 = static fn(array $r): bool => $r['age'] >= 30;
$hz    = static fn(array $r): bool => $r['city'] === '杭州';
$on    = static fn(array $r): bool => $r['active'] === true;

$base = new RowCollection($rows);
$adultsHk = $base->filter($age30)->filter($hz);    // 链式 filter = andX
$rest = $base->reject($age30);                      // reject = notX
$mixed = $base->filter($age30)->anyOf($hz, $on);    // age>=30 AND (杭州 OR active)

echo 'base 未被修改: count=', count($base), PHP_EOL;
echo 'filter(age)->filter(city): ', $adultsHk->names(), PHP_EOL;
echo 'reject(age): ', $rest->names(), PHP_EOL;
echo 'filter(age)->anyOf(city,active): ', $mixed->names(), PHP_EOL;
echo '可迭代(用于视图循环): '; foreach ($adultsHk as $r) { echo $r['name'], ' '; } echo PHP_EOL;
```

```text
base 未被修改: count=6
filter(age)->filter(city): Ann,Finn
reject(age): Bob,Dan
filter(age)->anyOf(city,active): Ann,Cid,Finn
可迭代(用于视图循环): Ann Finn
```

两处设计决定：**谓词延迟求值**（存进 `$predicates`，`all()` 时才跑），所以能链式追加，链式 = `andX` 的另一种书写；`reject(age30)` 只剩 Bob、Dan——Eve（30 岁）被 `>=30` 筛走，提醒边界写进谓词而不是写在调用方脑子里。实现 `Countable + IteratorAggregate` 后 `count($col)`、`foreach` 都免费，与 [组合模式.md](组合模式.md) "实现 `RecursiveIterator` 换遍历"是同一思路：**行为挂接口，遍历交给标准库**。

## 四、为什么真实项目里它被 SQL 条件拼装 / Laravel Scope 取代

不是过滤器不好，而是**筛选发生在数据还在数据库里时，闭包版根本碰不到数据**。要下推给数据库，条件就不能是闭包——闭包不透明、无法序列化成 SQL。解法：谓词载体从 `callable` 换成 `['sql' => ..., 'params' => ...]` 数组，**组合代数一行不改**：

```php
<?php
declare(strict_types=1);

// 同一个"谓词代数"，闭包换成数组（SQL 片段 + 占位参数），就能下推给数据库执行
$cond = static fn(string $sql, array $params): array => ['sql' => $sql, 'params' => $params];
// andX/orX/notX 与第二节同形，只是操作数类型从 callable 换成 array
$andX = static fn(array $a, array $b): array => ['sql' => '(' . $a['sql'] . ') AND (' . $b['sql'] . ')', 'params' => [...$a['params'], ...$b['params']]];
$orX  = static fn(array $a, array $b): array => ['sql' => '(' . $a['sql'] . ') OR (' . $b['sql'] . ')', 'params' => [...$a['params'], ...$b['params']]];
$notX = static fn(array $a): array => ['sql' => 'NOT (' . $a['sql'] . ')', 'params' => $a['params']];

$age    = $cond('age >= ?', [30]);
$city   = $cond('city = ?', ['杭州']);
$active = $cond('is_active = ?', [1]);
$tree = $orX($andX($age, $city), $active);
echo 'SELECT * FROM users WHERE ', $tree['sql'], PHP_EOL;
echo 'bindings: ', json_encode($tree['params'], JSON_UNESCAPED_UNICODE), PHP_EOL;
echo 'not  : ', $notX($age)['sql'], '  params=', json_encode($notX($age)['params']), PHP_EOL;
```

```text
SELECT * FROM users WHERE ((age >= ?) AND (city = ?)) OR (is_active = ?)
bindings: [30,"杭州",1]
not  : NOT (age >= ?)  params=[30]
```

对比第二节：结构完全同构，只是 `$r['age'] >= 30` 变成 `'age >= ?'`。Laravel 的 **Local Scope 就是这套代数的"方法命名版"**——常用谓词固化成模型方法，`Query Builder` 当组合器：

```php
<?php

// 接上文（Laravel 项目内片段，依赖 Eloquent 运行环境，不参与脚本自动对账）
// User 模型上：
// public function scopeAdult(Builder $q): void { $q->where('age', '>=', 30); }
// public function scopeInCity(Builder $q, string $c): void { $q->where('city', $c); }
// 调用：User::query()->adult()->inCity('杭州')->get()
// 每个 scope 就是一个可命名复用的 Criteria；where() 链是 andX，
// orWhere 闭包是 orX，whereNot 是 notX。
```

取代的根本原因只有一个：**数据库筛是 O(命中行数) 的网络传输，内存筛是 O(全表行数) 的 PHP 进程内存**。百万行的表 `->get()` 出来再 `array_filter`，先 OOM 的是 PHP。

## 五、什么时候仍值得在内存里做

| 场景 | 为什么 SQL/Scope 到不了 | 做法 |
| --- | --- | --- |
| 已加载集合的二次筛选 | 数据已在手里（页内搜索、按会话权限再筛一层） | 第三节集合写法，别再查库 |
| 外部接口返回 | 对方 API 不接受自定义谓词，只给整包 JSON | 转换 + 过滤只能在本侧内存做 |
| 单元测试 fixture | 测试不想起数据库 | 谓词纯函数，直接喂行断言 bool，比 mock QueryBuilder 便宜 |
| 运行时计算属性 | 判定依赖会话、Feature flag 等进程内状态 | 硬翻成 SQL 会漏业务口径 |

判据一句话：**数据源能接条件就下推（第四节），接不了或已经加载完才用内存谓词（第二、三节）**。

## 六、Java 对照（本机 jdk1.8.0_321，`javac -encoding UTF-8` + `java` 通过）

同一份数据集在 Java 8 Stream 上跑同样的组合——`filter().filter()` 链就是内置 andX，无需手写组合器：

```java
import java.util.ArrayList;
import java.util.List;

public class FilterDemo {
    public static void main(String[] args) {
        long age = rows().stream().filter(u -> u.age >= 30).count();
        // filter().filter() 链式调用就是内置 andX
        long and = rows().stream().filter(u -> u.age >= 30).filter(u -> u.city.equals("HZ")).count();
        long or = rows().stream().filter(u -> u.age >= 30 || u.city.equals("HZ")).count();
        long not = rows().stream().filter(u -> !u.active).count();
        System.out.println("age>=30: " + age + " | andX: " + and + " | orX: " + or + " | notX: " + not);
    }

    static class User {
        final String name; final int age; final String city; final boolean active;
        User(String n, int a, String c, boolean v) { name = n; age = a; city = c; active = v; }
    }

    static List<User> rows() {
        List<User> l = new ArrayList<User>();
        l.add(new User("Ann", 35, "HZ", true));
        l.add(new User("Bob", 28, "HZ", false));
        l.add(new User("Cid", 41, "SH", true));
        l.add(new User("Dan", 22, "SH", true));
        l.add(new User("Eve", 30, "BJ", false));
        l.add(new User("Finn", 33, "HZ", true));
        return l;
    }
}
```

```text
age>=30: 4 | andX: 2 | orX: 5 | notX: 2
```

命中数与第二节 PHP 版逐项一致（`HZ` 即杭州）。语言边界差异一目了然：Java 8 Stream 把 and 组合做进了类型系统（链式 `filter`），or/not 在 lambda 体内写；PHP 三种组合器全要手写，但 `array_filter` 足够轻。

## 面试官会追问什么

- **过滤器和策略代码长得一样，怎么区分？** → 看返回值契约：策略返回处理结果；过滤器返回 bool，且必须提供 and/or/not 组合子才成其为过滤器。没有组合代数的 "Criteria 类" 只是带 if 的策略。
- **为什么生产代码里很少见到 Criteria 类？** → 条件以闭包形态无法下推数据库；换成 SQL 片段数组（第四节实测）或 Laravel Scope 后，组合代数原封不动活下来。
- **`array_filter` 有什么坑？** → 保留原键（实测 `0,1,5`），序列化与连续下标前要 `array_values`；回调逐行求值、顺序稳定，但没有跨行短路。
- **多条件组合怎么测？** → 谓词是纯函数、组合器是纯代数：单测对 `$andX($a, $b)` 喂几行 fixture 断言 bool，不需要数据库不需要 mock——这正是第五节"测试 fixture 值得内存筛"的理由。
- **andX/orX/notX 构成什么代数结构？** → 布尔代数（与/或/非 + 吸收律成立），所以过滤器链能像表达式一样做去重、常量折叠、下推——查询优化器干的就是这件事。

# PHP 设计模式笔记索引

> 本目录是对个人博客「PHP 设计模式」系列（共 15 篇，见下表原文列）的**重写版**，不是转载。
> 重写时做了三件事：
> 1. **每篇只讲一个模式**，标题从"什么是 XX 模式"改成"这个模式在 PHP 里到底怎么用得对不对"；
> 2. **每条结论后面配一段能跑的证据**——所有代码块都在本机 PHP 8.0.2 / go1.26.5 / jdk1.8 上真跑过，
>    文中 `text` 块就是原始 stdout，由脚本逐块抽出对账（见文末「校验口径」）；
> 3. 补上原系列基本没写、但 PHP 面试和落地都绕不开的主线：**请求生命周期**。
>    php-fpm 每个请求结束就回收用户态内存，这一条同时决定了单例、注册表、观察者表、缓存代理"能不能跨请求"，
>    也是 PHP 与 Java/Go 在同一模式下写法差异的根因。各篇相关小节都回链到这条主线。

## 三、模式之间的边界（一张表收尾）

面试最爱问"这几个不都是包一层/都是 new 对象吗"，答法按**它回答的问题**区分，而不是按类图：

| 问题 | 归属 |
| --- | --- |
| 该 new 哪个类？ | 工厂 / 抽象工厂 |
| 怎么在不改老类的前提下加行为？ | 装饰器（接口不变）/ 策略（换算法） |
| 谁控制这次访问（延迟、缓存、权限、远程）？ | 代理 |
| 调用方要的接口形状不对，谁来翻译？ | 适配器 |
| 一串子系统调用能不能收敛成一个入口？ | 外观 |
| 一对多通知，谁要被告知？ | 观察者 |
| 这一步用哪种算法，能不能替换？ | 策略 |
| 怎么遍历一个聚合而不暴露内部结构？ | 迭代器 |
| 整体-部分要不要统一对待？ | 组合 |
| 集合按条件筛选，条件能不能组合？ | 过滤器 |
| 全局怎么拿到同一个实例 / 一张对象表？ | 单例 / 注册 |
| 横切关注点要不要单独成层？ | 面向切面（+ 装饰器、代理是它的手工件） |

## 四、校验口径

- **PHP**：`D:\phpstudy_pro\Extensions\php\php8.0.2nts\php.exe`（PHP 8.0.2 / Zend 4.0.2，CLI）。每个代码块先 `php -l` 再执行，正文 `text` 块为原始 stdout。语法定位 **PHP 8.0**：属性类型声明需 7.4+、构造器属性提升需 8.0+，全目录未使用 `readonly` / `enum` 等 8.1+ 特性（本机最高只有 8.0.2，用了就无法验证）。
- **Go**：`go1.26.5`，`gofmt` 无差异 + `go vet` 通过 + `go run` 实跑。
- **Java**：`D:\java\jdk1.8`（`javac -encoding UTF-8` + `java`）实跑，语法限制在 JDK 8。
- **对账方式**：脚本逐块抽取每篇的 `php` / `go` / `java` 块，真跑一遍与文中 `text` 块逐项比对（空白与 CRLF 归一化），不一致即报错退出。片段块（依赖前文定义的类）在块首标 `// 接上文`，脚本跳过并在汇报里计数。
- **未验证项**：全目录没有任何真实中间件实例（MySQL / Redis / MQ 均未连），涉及框架内部实现（Laravel / Symfony / Swoole）的描述属于"公开用法或定性推断"级，各篇「校验口径」里都单独点名了；文中不含任何性能基准数字。

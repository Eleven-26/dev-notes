# 类加载

双亲委派机制，向上检查，向下委派：

在 Java 中，类加载器是用来加载 Java 类到 Java 虚拟机（JVM）中的组件。Java 提供了不同层次的类加载器，主要包括以下几种：

+ **启动类加载器（Bootstrap Class Loader）**：它是最顶层的类加载器，由 C++ 实现，负责加载 Java 的核心类库，如 `java.lang`
  包下的类等，这些类位于 JRE 的 `lib` 目录下。
+ **扩展类加载器（Extension Class Loader）**：它是启动类加载器的子加载器，负责加载 Java 的扩展类库，这些类位于 JRE 的
  `lib/ext` 目录下。
+ **应用程序类加载器（Application Class Loader）**：也称为系统类加载器，负责加载用户类路径（`classpath`）下的类，一般是我们自己编写的类和第三方库。
+ **自定义类加载器（Custom Class Loader）**：用户可以根据自己的需求自定义类加载器，继承自 `ClassLoader` 类。

### 工作原理

双亲委派机制的工作过程可以概括为 “先委托，后自己加载”，具体步骤如下：

1. 当一个类加载器收到类加载请求时，它首先不会自己去尝试加载这个类，而是把这个请求委派给父类加载器去完成。
2. 每一层的类加载器都是如此，依次向上委托，直到到达启动类加载器。
3. 启动类加载器会尝试加载这个类，如果能加载则加载成功；如果不能加载，就会将加载任务返回给子类加载器，让子类加载器去尝试加载。
4. 依次向下，直到有类加载器成功加载该类或者所有类加载器都尝试过仍无法加载，此时会抛出 `ClassNotFoundException` 异常。

### 优点

+ **安全性**：双亲委派机制可以防止恶意代码替换 Java 的核心类库。例如，由于核心类库由启动类加载器加载，即使用户编写了一个名为
  `java.lang.String` 的类，也不会被加载，从而保证了 Java 核心类库的安全性。
+ **避免类的重复加载**：当父类加载器已经加载了某个类时，子类加载器就不需要再重复加载，保证了类在 JVM 中的唯一性。
+ **层次结构清晰**：通过这种层次化的加载方式，不同层次的类加载器负责不同范围的类加载，使得类加载的管理更加清晰和有序。

# Dubbo

> 本目录是 Dubbo 的**纵向深入**：**3 篇**从「一次调用穿过哪些对象」讲到「路由与容错怎么配」。
> 横向选型（该不该用 Dubbo、和 gRPC / Thrift 怎么比）在上一层的 [RPC框架选型对比.md](../RPC框架选型对比.md)；
> 本目录**假定调用层已经选了 Dubbo**，只回答「它内部怎么运转、会踩什么」。
>
> 内容整理自个人学习笔记。**本文件只给阅读顺序、依赖关系、边界与口径** —— 每篇的知识点描述见
> [目录.md](../../../../目录.md)，本文件不重复描述。素材见 [素材清单.md](../../../../素材清单.md)。
> 约定见 [AGENTS.md](../../../../AGENTS.md)。
>
> ⚠️ **本册 3 篇全部零实测**：跑通 Dubbo 需要 JDK + Maven 依赖 + 一个可用注册中心，
> 本机三样不齐，所有结论来自官方文档与源码结构核对。**这是本册与 gRPC 册最大的差别** ——
> 那边每个数字都有实验台，这边一个都没有。口径逐篇写在各自的 `## 校验口径`。

## 七、口径坐标（本册的「实测」是怎么回事）

本册 **0 篇有运行读数**。这不是遗漏，是环境不具备：Dubbo 的最小可运行组合是
「JDK + `dubbo-spring-boot-starter`（Maven 拉包）+ 注册中心（Nacos / Zookeeper）+ 至少一个 provider 实例」，
本机没有任何一项。

| 项 | 本册的实际做法 |
|---|---|
| 类名与链路顺序 | 按 Dubbo 3.x 官方文档的架构章节与源码包结构核对 |
| 默认值（`timeout` / `retries` / `threads` / `forks`） | 按文档核对，**并标注哪些会随版本变**（队列类型、MeshRule 优先级、应用级发现开关） |
| Triple 的兼容行为 | 按官方文档陈述，**content-type 未写死**，要求接之前抓包确认 |
| 报文 16 字节头 | 按协议规范整理，**没有构造过字节验证** |

⭐ **一句判据**：本册内容都属于「把产品换掉就不再成立」的机制描述，
因此**照抄配置能跑起来，但任何数字都不能当读数引用** —— 需要读数时去 [gRPC 册](../gRPC/README.md)，或自己做实验。

## 八、版本与口径矩阵

| 项 | 本册口径 | 备注 |
|---|---|---|
| Dubbo | 3.x（文档与 API 形态） | 未指定补丁版本；`接入Dubbo.md` 的 `3.2.15` 是**占位坐标** |
| 注解 API | `@DubboService` / `@DubboReference` | 2.7 及以前是 `@Service` / `@Reference`，包名与语义都不同 |
| `RpcContext` | 3.x 拆成 `getClientAttachment` / `getServerAttachment` | 2.7 的 `getContext().setAttachment()` 客户端服务端共用，迁移要改 |
| 默认协议 | 2.x `dubbo://`（私有 TCP）；3.x 推荐 `tri://`（Triple） | 两者可同时暴露 |
| JDK | 3.x 最低 8，Triple 建议 11+ | 未验证具体下限 |

⚠️ **口径纪律**：本册对「不同版本会变」的地方一律写「接版本核对」，**没有给出「某版本一定是某值」的断言**。
要在生产里引用某条结论，先在目标版本上打一次 `URL` 或抓一次包确认。

## 九、已知缺口

| 缺口 | 现状 | 补了吗 |
|---|---|---|
| **运行读数** | 全册零实测 | ❌ 缺环境（JDK + Maven + 注册中心） |
| **Triple 与 gRPC 互通** | 只给兼容边界 | ❌ 没起过「Java provider + Go 客户端」 |
| **线程池过载的两种表现** | 只给机理（排队 vs 拒绝） | ❌ 没复现 |
| **重试放大** | 只给算术（3 跳 × 3 次 = 27） | ❌ 没测实际流量倍数 |
| **tag 灰度的退化行为** | 只给 `force` 的两种后果 | ❌ 没验证「灰度实例全挂」 |
| **报文抓包** | 只给 16 字节头的读法 | ❌ 没抓过包，也没构造过字节 |
| **Go 侧 `dubbo-go`** | 只在选型篇提了定位 | ❌ 本册不覆盖 |
| **Dubbo Mesh / Proxyless** | 只在 [通信协议.md](通信协议.md) 第四节点到边界 | ❌ 未涉及 |

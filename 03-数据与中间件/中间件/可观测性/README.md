# 可观测性笔记索引（本目录导读）

> 本目录回答的是**排障链条上的三段**：指标发现异常 → 链路定位到环节 → 日志印证根因。
> 一篇做**选型与分工**（横向对比），两篇是**可替换的实现**（SkyWalking / Jaeger 两条主线），
> 一篇是**指标侧的实现细节**（分位数怎么算才可聚合）。
>
> 内容整理自个人学习笔记。**本文件只给阅读顺序、依赖关系与实测坐标**——每篇的知识点描述见
> [全仓知识点目录](../../../目录.md)，本目录**不重复描述**；跨目录的延伸见「五、与其它目录的分工」。

---

## 一、先读哪一篇（总纲）

| 顺序 | 篇 | 视角 | 一句话 |
|---|---|---|---|
| ① | [可观测性选型对比.md](可观测性选型对比.md) | ⭐ **总纲 / 横向** | 三支柱各自的定位与成本重心，链路 / 指标 / 日志 / 存储 / 可视化五个层面的选型对比 + 三套可直接照搬的组合 |

选型篇是**唯一的决策入口**：本目录其余三篇都是它某一行的「展开」。⚠️ 具体判据（谁干什么、采样率怎么定、成本怎么降）**只在选型篇写一份**，零件篇指回去，不重复讲。

```text
        ↓

   （探针原理 / UI / 部署）    （OTel 埋点 / 采样 / 部署）
```

| 篇 | 版本坐标 | 本机是否实跑 |

## 六、本目录的边界与缺口

**边界**：本目录只管**应用埋点出来的三类数据**（Metrics / Traces / Logs）怎么采、怎么存、怎么看、怎么告警。

| 本目录收 | 不收（在哪） |
|---|---|
| 三支柱分工与串联（traceId 为纽带） | **主机与内核侧观测**（perf / eBPF / `ss` / 火焰图）→ [性能排查.md](../../../02-计算机基础/linux/性能排查.md) |
| 探针实现原理与选型代价 | **各语言接入代码**→ [go/](../../../01-编程语言/go/)、[java/](../../../01-编程语言/java/)、[php/](../../../01-编程语言/php/) |
| 存储后端按查询模式选型 | **存储引擎本身的原理**→ [数据存储/](../../数据存储/) |
| 指标侧的分位数计算 | **告警之后的处置流程 / SRE 值班机制**→ 无（属流程而非知识） |
**已知缺口**（按主题全仓 grep 实测，不是凭印象列）：

| 缺口 | 现状 | 结论 |
|---|---|---|
| **日志采集管道**（Fluent Bit / Vector / Loki 落地） | 选型篇第四节只有对比表，无零件篇 | 待补：要么单独立篇，要么并入选型篇第四节展开 |
| **Service Mesh 侧的无埋点观测** | 只在选型篇 7.3 出现过一次 eBPF | 属 [服务网格](../服务网格/README.md) 主题，本目录不展开 |
| **告警规则实操**（MQE 表达式、燃烧率算法） | Skywalking.md 4.6 只贴了出厂 `alarm-settings.yml` | 待补：Prometheus 侧 recording rule + Alertmanager 路由未成篇 |

> ⭐ 与 [网络目录导读](../../../02-计算机基础/网络/README.md) 同一写法：**导读只给顺序、依赖与边界**，
> 知识点描述一律留给 [目录.md](../../../目录.md)，避免两处同时过期。

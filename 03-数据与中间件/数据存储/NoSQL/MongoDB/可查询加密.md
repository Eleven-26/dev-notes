# MongoDB 可查询加密

> CSFLE（4.2）与 Queryable Encryption（6.0 预览 → 7.0 GA）的分工、
> 加密索引的内部结构与调参项（contention / sparsity / precision / trimFactor）、
> 等值 / 范围 / 前缀后缀子串查询的版本演进，以及 KMS、驱动与生产环境的关键注意。
>
> 内容整理自个人学习笔记，机制与版本事实取自 MongoDB 官方文档与 Release Notes。
> ⚠️ 本篇的加密集合创建与查询**本机未实测**（需要 KMS 与 Automatic Encryption Shared Library），按官方文档整理。

## 一、CSFLE 与 QE 差在哪？

**本节要点**：两者都是「客户端加密、服务端存密文」，区别在**能不能查**以及**谁来做可查询索引**。

| 维度 | CSFLE（客户端字段级加密） | QE（可查询加密） |
| --- | --- | --- |
| 起始版本 | 4.2（Enterprise / Atlas） | 6.0 公开预览、**7.0 GA**（需 7.0+ 的副本集或分片集群） |
| 加密位置 | 客户端驱动加解密，服务端只见密文 | 同左 |
| 可查询性 | 「确定性加密」只能做**等值**，且相同明文产生相同密文（会泄露频率分布）；随机加密不可查 | 服务端维护**加密索引**，支持等值 / 范围 / 子串等查询 |
| 配置载体 | 加密模式（encryption schema）+ KMS | 同左（另有集合级加密模式） |
| standalone | 不支持 | 不支持 |

选型口径：只要「离线存储敏感字段、不需要查它」→ CSFLE 更简单；「既要加密又要按字段查」→ QE。
⚠️ 确定性加密看起来「够用」，但它把**值的频率分布**暴露给了服务端，两者安全模型不同。

## 二、加密索引是怎么工作的？

**本节要点**：QE 为每个加密集合建**两个元数据集合**、为每个加密字段建**一个索引**；

字段的查询类型「等值」与「范围」**只能二选一**；写入会同时改索引，因此写更慢、空间更大。

### 2.1 结构（官方口径）

- 每个加密集合会创建**两个元数据集合**，用于存放加密索引数据 → 直接增加存储占用。
- 每个加密字段对应**一个索引**；写操作更新被索引的加密字段时，**同步更新索引** → 写耗时增加。
- 于是「可查询」是有代价的：加密字段越多、开启的查询类型越多，写入越慢、空间越大。

### 2.2 三个关键调参项

| 参数 | 默认 | 作用与取舍 |
| --- | --- | --- |
| `contention` | 8 | 把「同值计数器」分区，缓解**同值并发写**的争用；调大 → 写更快、读更慢 |
| `sparsity`（范围） | 2 | 范围值的索引密度：越低（越密）查询越快、每次写要存更多元数据 → 空间开销更大；**8.2 起上限从 4 提到 8** |
| `trimFactor`（范围） | 6 | 并发写吞吐的旋钮：调高 → 并发插入更新更快、部分范围读更慢 |

范围字段还可配 `precision`：限定 `double` / `decimal` 参与查询的小数位，位数越多空间与索引生成开销越大（多余位是**截断**不是四舍五入）。

### 2.3 等值与范围不能同时开

官方明确：一个加密字段只能配成 `equality` 或 `range` 之一，不能两者都要。所以「加密模式要按**实际查询类型**提前设计」——
建集合后再改「哪些字段加密、哪些可查」＝重建集合与加密模式。

### 2.4 支持的操作符是受限的

只有一部分查询操作符与聚合表达式能作用在加密字段上；清单以官方「Supported Query Types & Operators」为准，
拿不准时不要假设普通查询能直接套用。

## 三、查询类型的版本演进

**本节要点**：等值（7.0 GA）→ 范围（8.0）→ 前缀 / 后缀 / 子串（9.0 GA），每一步都扩大了「能查什么」。

| 查询类型 | 起始 / GA | 说明 |
| --- | --- | --- |
| 等值 | 7.0 GA | QE 的基础能力 |
| 范围 | 8.0 | 官方原文：8.0 起支持用 `$lt` / `$lte` / `$gt` / `$gte` 在加密字段上做范围查询 |
| 前缀 / 后缀 / 子串 | ⭐ 9.0 GA | 在加密字符串字段上开启子串查询；用 `mongosh` 时还需单独下载 **Automatic Encryption Shared Library 9.0+** 并指定路径 |

子串查询不是「免费打开」的开关：它要求配置**字段最大长度**与**可查询的最小 / 最大长度**（超范围的插入或查询会直接报错），
还要声明**大小写敏感**与**变音符号敏感**（同一字段上同时开多种子串类型时，这两项必须一致）。
⚠️ 官方特别提示：可查询长度越长，性能影响越大，能限短就要限短。

## 使用：配置加密字段并查询

⚠️ **本机未实测**：需要 KMS（本地 key 或云 KMS）与 Automatic Encryption Shared Library，下列片段按官方文档整理。

```javascript
// 集合级加密模式（示意）：指定哪些字段加密、开哪种查询
const encryptedFields = {
  fields: [
    {
      path: "patientName",
      bsonType: "string",
      keyId: "<dataKeyId>",
      queries: { queryType: "substring",           // 9.0 GA
                 minQueryLength: 2, maxQueryLength: 6,
                 caseSensitive: false, diacriticSensitive: false }
    },
    { path: "ssn",  bsonType: "string", keyId: "<dataKeyId>",
      queries: { queryType: "equality", contention: 8 } },
    { path: "age",  bsonType: "int",    keyId: "<dataKeyId>",
      queries: { queryType: "range", min: 0, max: 150 } }
  ]
}
```

要点三条：

- **一个字段只能选一种查询类型**（等值 **或** 范围，字符串可走子串类），要按真实查询需求提前定。
- **`keyId` 指向数据密钥**：密钥由 KMS 管理；加密模式与密钥都要纳入版本化与备份。
- ⚠️ **`mongocryptd` 已被弃用（9.0 起）**：改用 **Automatic Encryption Shared Library**，它不需要额外起一个进程。

## 四、驱动、KMS 与生产环境注意

**本节要点**：加密方案的安全边界在**密钥**——密钥丢了数据就找不回来；同时要正视存储与写的代价。

### 4.1 驱动与组件

- 主流官方驱动都支持自动加密；但**新查询类型（如 9.0 的子串）要对应版本的驱动与共享库**，
  具体可用性以「驱动 Release Notes + 客户端兼容性表」为准，不要按服务端版本想当然。
- `mongocryptd` → **Automatic Encryption Shared Library**（9.0 起弃用前者）。

### 4.2 ⚠️ 密钥与备份

- **密钥（KMS 主密钥 + 数据密钥）丢失 = 数据不可恢复**。备份策略必须同时覆盖「密文数据 + 加密模式 + 密钥」。
- 备份 / 恢复还要把**元数据集合**一起带走，否则加密索引与密文对不上。
- 轮换密钥是运维动作：要有回滚路径，并先在非生产环境演练。

### 4.3 性能与容量

- 加密字段越多 → 写越慢（每次写要更新对应索引）、空间越大（两个元数据集合 + 每个字段的索引）。
- 开启范围 / 子串这类「可查询」会进一步放大空间（可查询越小、密度越高，空间越大）。
- 基准测试要在**开启加密**的前提下做：普通集合的吞吐数字不可平移。

## 延伸追问

- **CSFLE 与 QE 怎么选？**
  → 看「要不要按这个字段查」：只要加密、不需要按它检索，CSFLE 更省；既要加密又要按字段等值 / 范围 / 子串查，用 QE。注意 CSFLE 的确定性加密会让相同明文产生相同密文，泄露值的频率分布。
- **为什么加密字段只能选一种查询类型？**
  → 因为查询类型的索引结构不同（等值索引 vs 范围索引 vs 子串索引），一个字段配一套索引；官方明确 equality 与 range 不能同时开。所以加密模式必须按真实查询需求提前设计，事后改动等于重建集合。
- **密钥丢了会怎样？**
  → 数据不可恢复。密文在库里没有意义，解密需要 KMS 主密钥与数据密钥；因此备份必须把「密文 + 加密模式 + 密钥」一起管，恢复时元数据集合也要一并还原。
- **开启 QE 后性能掉多少？**
  → 没有通用数字：取决于加密字段数、开启的查询类型、`contention` / `sparsity` / `trimFactor` 的取值。应在本机开启加密后实测写入吞吐与空间占用，别拿未加密的基准做容量规划。

# VictoriaMetrics 目录导读

> 覆盖 VictoriaMetrics 单机与集群的定位与适用场景、架构与存储引擎（mergeset / 倒排索引 / 分区与 part）、
> 数据模型与写入路径、索引与查询优化、MetricsQL、与 Prometheus 生态的关系、高可用与集群部署、
> 运维与监控、性能调优，以及选型与落地案例。
>
> 内容整理自个人学习笔记。**基础框架**参考《Mastering Prometheus》（William Hegedus, Packt 2024）
> 与 VictoriaMetrics 官方文档、Release Notes；版本相关结论均标注官方出处。
>
> ⚠️ **本目录本轮未做容器实测，正文均整理自官方文档与 Release Notes**——凡涉及版本、默认值、
> 容量数字，均标注官方出处，不贴运行读数。素材见 [素材清单](../../../../素材清单.md)。

### 1.2 核心术语速查

**本节要点**：下面这些词会在十篇里反复出现；先把它们记准，后文就不用反复解释。

| 术语 | 含义 |
|---|---|
| 序列（series） | 指标名 + 一组标签，唯一确定一条时间序列 |
| 样本（sample） | (时间戳, 值) 二元组；时间戳为毫秒精度 |
| TSID | VM 内部给每条序列分配的数字 ID，样本只带 TSID 与值 |
| 基数（cardinality） | 不同序列的条数，接近各标签取值数的组合规模 |
| 活跃序列 | 最近一小时内有数据点的序列，主要决定内存开销 |
| churn（序列替换率） | 每天新增的、此前未出现过的序列数，决定索引增长 |
| mergeset | 按 TSID + 时间排序存放**样本值**的存储结构 |
| IndexDB（倒排索引） | 维护"标签=值 → 一组 TSID"的映射，负责**定位序列** |
| part | 一次刷盘形成的不可变数据块，命名形如 `rows_blocks_minTS_maxTS` |
| block | part 内的数据块，最多约 8K 样本且同属一条序列 |
| 分区（partition） | 按月划分的目录 `YYYY_MM`，超出保留期才删除 |
| compaction（合并） | 后台把多个小 part 合并成更大 part 的过程 |
| vmagent | 轻量采集 agent，抓取后 remote write，带持久化磁盘队列 |
| vmalert | 执行告警规则与 recording rule 的组件 |
| vmauth | 认证与路由代理，常放在集群组件之前 |
| vmctl | 从其他监控系统迁移数据的工具 |
| MetricsQL | VM 的查询语言，PromQL 兼容并做了扩展 |

### 1.3 VM 组件全景

**本节要点**：VM 不是"一个数据库进程"，而是一套组件；先知道每个组件干什么，再看各篇才不会张冠李戴。

| 组件 | 角色 |
|---|---|
| `victoria-metrics`（单机二进制） | 单机版全部功能：接收 + 存储 + 查询集于一个进程 |
| `vminsert` / `vmselect` / `vmstorage` | 集群版的三类服务，分别管写入 / 查询 / 存储 |
| `vmagent` | 采集 agent：抓取或接收指标、relabel 后 remote write，带持久化磁盘队列 |
| `vmalert` | 告警规则与 recording rule 的执行引擎，通知发往 Alertmanager |
| `vmauth` | 认证与路由代理，常置于 vminsert / vmselect 之前 |
| `vmctl` | 从 Prometheus / InfluxDB 等系统迁移数据的工具 |
| `vmbackup` / `vmrestore` | 基于快照的备份与恢复工具 |
| `vmbackupmanager` | 企业版：在 `vmbackup` 之上的备份自动化管理 |
| `vmui` | 内置 Web UI，用于探索、排障与基数分析 |
| `VictoriaLogs` / `VictoriaTraces` | 同厂商的日志 / 链路数据库，**不属于本目录主题** |

⚠️ 本目录聚焦"指标存储与查询"这条主线（单机二进制、集群三件套、vmagent / vmalert / vmauth）；
备份编排、告警通知渠道等只在 [运维与监控.md](运维与监控.md) 作必要交代。

## 二、版本坐标速查

⭐ 一条线看清"哪一版能做什么"。下表每条均可在官方文档 / Release Notes 中核到（版本号与日期以官方为准）：

| 能力 / 变更 | 版本 | 说明 |
|---|---|---|
| 单机 / 集群双形态、mergeset + 倒排索引存储 | 核心（自早期版本） | 单机垂直扩展，集群拆 vminsert / vmselect / vmstorage |
| vmui 内置 Web UI | 2021 年引入 | 官方 2021 年度回顾；后续陆续加入基数探索等能力 |
| 企业版多级降采样 `-downsampling.period` | v1.71.0（2021-12-20） | 支持 `offset:interval` 语法，可多次指定分级 |
| MetricsQL `@` 修饰符任意位置、`keep_metric_names` | v1.72.0（2022-01-18） | 官方 2022 年第一季度发布说明 |
| 高写入下 vminsert / vmstorage 内存最多降 50% | v1.76.0（2022 年第一季度） | 同期新增多个查询与缓存限制类参数 |
| 标签超限语义由"截断"改为"丢弃" | v1.108.0（2024-12-16） | 影响 `-maxLabelsPerTimeseries` / `-maxLabelNameLen` / `-maxLabelValueLen` |
| LTS 线 | v1.110.x（2025 起） | 官方承诺自 v1.110.0 起至少 12 个月支持，含企业版修复 |
| 基数限制器哨兵值 `-1` | v1.140.0 | `-storage.maxHourlySeries` / `-storage.maxDailySeries` 可只统计不限流 |

⚠️ 两条使用纪律：

- 本目录**不做实测**，因此凡是"某版本起……"的说法都以官方文档 / Release Notes 为准；
  版本间默认值可能变化，落地前请以所装版本的 `-help` 输出核对。
- 上表刻意只留**核得实**的条目；核不到确切版本的特性（如保留过滤器、基数限制器的引入版本）
  一律不写进表格，需要时以官方文档为准。

### 2.1 两条最容易误判的变更

**本节要点**：这两条一旦按老教程的预期理解，会直接导致"数据为什么变少 / 行为不一样"的误判。

1. **标签超限：截断 → 丢弃（v1.108.0）**。此前超限标签会被**截断**，可能造成**静默的数据冲突**
   （不同序列截断后标签相同而被合并）；此后直接**丢弃整条序列**并计入 `vm_rows_ignored_total`
   （`reason` 为 `too_many_labels` / `too_long_label_name` / `too_long_label_value`）。
   详见 [数据模型与写入路径.md](数据模型与写入路径.md) 第七节。
2. **去重不是"写入即丢弃"**。设置了 `-dedup.minScrapeInterval` 后，样本**仍会先全部落盘**，
   去重发生在**后台合并期与查询期**；要在写入前就去重，得用 vmagent 的 `-streamAggr.dedupInterval`。
   详见 [架构与存储引擎.md](架构与存储引擎.md) 第四节。

### 3.2 读完之后你应该能回答（自测清单）

**本节要点**：下面每问都能在对应篇里找到答案；答不上来就回去补那篇。

1. 单机版能扛多大的写入与活跃序列？什么时候**必须**上集群？（①）
2. 一条序列、一条样本分别由什么构成？为什么高基数标签最贵？（②③）
3. 数据从采集到落盘经过哪几站？**在哪一站可能丢数据**？（③）

5. 保留期、去重、降采样分别作用在哪一层？为什么会"数据看起来变少"？（②③）
6. MetricsQL 与 PromQL 有哪些**刻意的**行为差异？（⑤）
7. 集群版三类组件怎么分工？扩缩容为什么不能随便加减节点？（⑦）
8. 该盯哪些自监控指标来判断 VM 是否健康？（⑧）

### 4.1 本目录不覆盖什么

**本节要点**：明确边界，避免在这个目录里找它本来就不讲的东西。

- **不做通用 SQL、不做日志 / 链路存储**：VM 的查询语言是 MetricsQL（PromQL 系），日志与链路是另一套产品线；需要 SQL 与跨信号关联看 [README.md](../GreptimeDB/README.md)。
- **不展开 Prometheus 本体**：本仓没有 Prometheus 本体篇，凡涉及 Prometheus 数据模型、scrape、remote write 的地方，只作两三句背景交代（集中在 [与Prometheus生态的关系.md](与Prometheus生态的关系.md)）。
- **不做三方横向对比**：Prometheus / VictoriaMetrics / InfluxDB 的对比在 [可观测性选型.md](../../../../06-工程实践/可观测性/可观测性选型.md)，本目录只在 [选型与落地案例.md](选型与落地案例.md) 收口。

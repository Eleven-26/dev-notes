## 一、最小生成树是什么？它和最短路到底差在哪？

**本节要点**：先把「生成树」这个词拆开，再回答那个最容易混的问题 —— **MST 不是最短路**。两者的目标函数根本不同，把它们当成一回事是这一块最常见的错误。

### 1.1 定义：连一圈、不绕路、花最少

给定一张**带权连通无向图** `G = (V, E)`，它的**生成树**是满足两条的一组边：

| 条件 | 含义 |
|---|---|
| **连通全部 `\|V\|` 个点** | 从任一点都能沿选中的边走遍全图 |
| **恰好 `\|V\| − 1` 条边、且无环** | 边数再多一条就必然成环，成了环就不是树 |

在这两条前提下，**让选中的边权之和最小**的那棵，就是**最小生成树（MST, Minimum Spanning Tree）**。

⭐ 一句话：**MST 要的是「把整张图接通，总造价最低」**。它不关心任意两点之间走起来贵不贵。

### 1.2 与最短路的区别（最容易混的一处）

`MST` 和「最短路」长得像（都在带权图上选边、都用贪心），但**目标是两个完全不同的函数**：

| | 最小生成树（Kruskal / Prim） | 最短路径（Dijkstra / Bellman-Ford） |
|---|---|---|
| **优化的量** | **所有边权之和**（一次全局账单） | **源点到每个点的路径长度**（一组点对距离） |
| **约束** | 选中 `\|V\|−1` 条边、连通、无环 | 一条从源点到目标的路径 |
| **产出** | 一棵**树**（边集） | 一棵**最短路树** + 到各点的距离 |
| **有没有源点** | **没有**，谁当根都行 | **有**，一切距离都以它为参照 |
| **能不能有环** | 结果必须是树，**不能有环** | 路径本身无环，但整体选边可以构成环 |

⚠️ **最容易踩的一个反例**：MST 里**任意两点之间在树上的路径，不一定是最短路**。

用本篇实验二那张图（7 点 11 边）说：原图里 `5` 到 `6` 有一条直连边 `5-6(11)`，最短路就是 11；但 Kruskal 的 MST **为了压低总造价，恰恰没要这条 11 的边**，于是在 MST 上从 `5` 走到 `6` 必须绕 `5-3(6)→3-0(5)→0-1(7)→1-4(7)→4-6(9) = 34`。**MST 上的 34 是最短路 11 的三倍多** —— MST 宁可让个别点对绕远，也要把**全局总数**压到 39（而最短路树的总权是 54）。这就是「全局总造价最小」与「点对距离最小」的分裂。

![Prim 与 Dijkstra 的对照](images/Prim与Dijkstra的对照.svg)

⭐ **判据**：看到「总代价最小 / 把所有点连起来最便宜」→ MST；看到「从 A 到 B 最快 / 最少代价」→ 最短路。**问错目标，两套算法会各给一个「对但没用」的答案。**

### 1.3 两个前提

- **图要连通**，否则只有「最小生成**森林**」（见 5.1）；
- **边权可以是负数**（与 Dijkstra 不同）—— 因为 MST 从不做「累加路径」，负权不影响正确性（见 5.3）。

## 二、Kruskal 是怎么一步步建起这棵树的？

**本节要点**：全部机制一句话——**按边权从小到大扫，能加就加、会成环就跳过**。看懂「哪条边被跳过、为什么跳过」，就看懂了 Kruskal。

### 2.1 两条规则

| 步骤 | 动作 |
|---|---|
| ① | 把所有边**按权升序**排好（同权按端点编号排，保证结果可复现） |
| ② | 从小到大逐条看：若这条边的两个端点**还不连通**，就选它；**已连通**（会成环）就跳过 |
| ③ | 当选够 `\|V\| − 1` 条边时停止 —— 这 `\|V\|−1` 条就是 MST |

⭐ 第二步的「还不连通」就是**判环**：一条边 `(u, v)` 会成环，当且仅当 `u`、`v` 已经被选中的边连通了。这一步正好是**并查集**的主场（第四节）。

### 2.2 逐步推演（本机实跑）

7 点 11 边的经典例图，排序后的边序列与 Kruskal 的决策：

```text
================ 实验二：同一张图上 Kruskal 与 Prim 的总权对照 ================
  图：7 点 11 边（无向，权见下）
    0-3(5) 2-4(5) 3-5(6) 0-1(7) 1-4(7) 1-2(8) 4-5(8) 1-3(9) 4-6(9) 5-6(11) 3-4(15)
  Kruskal 选中 6 条边：0-3(5) 2-4(5) 3-5(6) 0-1(7) 1-4(7) 4-6(9)
  Kruskal 总权 = 39
  Prim    选中 6 条边：0-3(5) 3-5(6) 0-1(7) 1-4(7) 4-2(5) 4-6(9)
  Prim    总权 = 39
  ⭐ 两份最小生成树总权相等 = true
  ⚠️ 这张图上两版选出的边集【恰好相同】—— 同权边没有改变谁被选中，见实验四的真不同例
  （连通分量数 = 1，等于 1 表示这棵树连通全部 7 个点）
```

逐条看 Kruskal 的动作（升序扫描）：

```text
 0-3(5)   → 0、3 不连通   ✅ 选，{0,3}
 2-4(5)   → 2、4 不连通   ✅ 选，{2,4}
 3-5(6)   → 3、5 不连通   ✅ 选，{0,3,5}
 0-1(7)   → 0、1 不连通   ✅ 选，{0,1,3,5}
 1-4(7)   → 1、4 不连通   ✅ 选，{0,1,2,3,4,5}
 1-2(8)   → 1、2 已连通   ✗ 跳过（会成环）
 4-5(8)   → 4、5 已连通   ✗ 跳过（会成环）
 1-3(9)   → 1、3 已连通   ✗ 跳过（会成环）
 4-6(9)   → 4、6 不连通   ✅ 选，{0,1,2,3,4,5,6}  ⇒ 已 6 条 = n−1，停止
```

三处必须看清的细节：

1. **⚠️ 跳过的边全部是「两端已连通」** —— 不是「权大所以不要」。`4-5(8)` 比 `1-4(7)` 只大 1，但它两端早就在同一棵树里了；
2. **停止条件是边数够 `n−1`**，不必扫完全部 11 条。本例在 `4-6(9)` 处就停了，后面 `5-6(11)`、`3-4(15)` 连看都不用看；
3. **⭐ 排序是全局的，Kruskal 有「上帝视角」**：它一次拿到全部边、从最小开始挑。这正是它与 Prim 最大的区别（Prim 只盯着当前树的边界，见 [Prim.md](Prim.md) 第一节）。

### 2.3 结果：与最短路树完全是两棵不同的树

同一张图上，Prim 从点 0 出发选出的边集是 `0-3(5) 3-5(6) 0-1(7) 1-4(7) 4-2(5) 4-6(9)`。**它和 Kruskal 的边集恰好相同**（只是输出的加入顺序不同），两者总权都是 39 —— 这张图的同权边恰好没造成分歧，真正的「同权不同形」例子见 5.2 的实验四。

再看「最短路树」（Dijkstra 从点 0 出发）：它的边是 `0-3(5) 0-1(7) 3-5(6) 1-4(7) 1-2(8) 5-6(11)`，**总权 54** —— 比 MST 的 39 大出一截。**同一张图、同一个源点，两棵树的总权能差这么多，因为它们在优化两件不同的事**（1.2）。

## 三、为什么「按边权从小到大取、不成环」一定得到最优解？

**本节要点**：贪心最容易「看起来对」。这一节给出**能讲出口的证明** —— 两条互补的性质：**切分定理**（说明「加对了一条边」）和**环性质**（说明「跳过一条边不亏」）。

### 3.1 切分定理：横切一刀，最轻的那条边一定在某棵 MST 里

把点集任意切成两半 `(S, V−S)`，称跨过这条分界线的边为**横切边**。

**结论（切分定理）**：`(S, V−S)` 的横切边中，**权最小的那条，一定存在于某棵最小生成树里**。

**证明（交换论证）**：设最小横切边为 `e = (u, v)`（`u ∈ S`，`v ∉ S`）。任取一棵 MST `T`：

1. 若 `e ∈ T`，证毕；否则 `T` 上必然存在一条从 `u` 到 `v` 的路径，这条路径从 `S` 走到 `V−S`，**至少有一条横切边 `f`**；
2. 把 `e` 加进 `T`、再把 `f` 拿掉，得到的 `T'` 仍是一棵生成树（连通性不变、边数不变）；
3. 代价变化 `w(T') − w(T) = w(e) − w(f)`；由 `e` 是最小横切边，`w(e) ≤ w(f)`，故 `w(T') ≤ w(T)`；
4. `T` 已是最优，所以只能取等号 —— `T'` **也是**一棵 MST，且它包含 `e`。∎

⭐ **一句话直觉版**：想接通 `S` 和 `V−S` 这两个「国家」，走最便宜的那条路总不会错。

### 3.2 环性质：环上最重的那条边，一定可以被扔掉

**结论（环性质）**：图上任意一个环，**环上权最大的那条边一定不在任何最小生成树里**。

**证明**：设环 `C` 上最重的边为 `f`。任取一棵 MST `T`：若 `f ∉ T`，证毕；否则 `T` 去掉 `f` 会裂成两半 —— 而环 `C` 去掉 `f` 后剩下的边里，必有一条 `e` 横跨这两半（否则 `C` 不构成环）。把 `e` 加回去得到 `T'`，边数不变、仍连通，且 `w(T') − w(T) = w(e) − w(f) ≤ 0`，故 `T'` 也是 MST 且不含 `f`。∎

### 3.3 两条性质怎么合起来保证 Kruskal 正确

Kruskal 的每一步只需要回答两个问题，而这两个问题刚好被上面两条性质各管一个：

| Kruskal 的动作 | 由哪条性质保证「不亏」 |
|---|---|
| **选**当前最小的边（两端不连通） | **切分定理** —— 此刻「已连通的那堆点」与其余点构成一个切分，这条边正是它跨越切分时最轻的选择 |
| **跳**过会成环的边 | **环性质** —— 它的两端已被树上一段路径连通，那条路径与它共成一个环，而它必是环上最重的（因为更轻的边早就被考虑过了），可以放心扔 |

⭐ 合起来：**每一步都不亏 ⟹ 归纳起来全局最优**。这也是为什么 Kruskal 敢「一次排序、一条条挑」而从不回头。

### 3.4 复杂度 O(E log E)

| 步骤 | 代价 |
|---|---|
| 排序全部边 | `O(E log E)` —— **主导项** |
| 每条边做两次 `find` + 至多一次 `union` | `O(E α(V))`，`α` 是反阿克曼函数，实践中视作常数 |
| 总计 | **`O(E log E)`** |

⚠️ **注意复杂度里没有 `V`**：Kruskal 的瓶颈是「把所有边排一遍」，与点数无关。这也解释了 5.1 的推论 —— **图越稀疏（`E` 越接近 `V`），Kruskal 越划算；图越稠密（`E ≈ V²`），排序就越贵**。所以稠密图应该换 Prim，判据与实测见 [Prim.md](Prim.md) 第三节。

⭐ 另外注意：Kruskal 对 `E` 的依赖是**天然的**，它不挑图的结构 —— 稀疏、稠密、多连通分量都能直接跑，这是它比 Prim 省心的地方。

## 四、并查集：怎么在 O(α(n)) 内判断「加这条边会不会成环」？

**本节要点**：Kruskal 的正确性已经证完，剩下的是**工程问题** —— 怎么高效回答「两端连通吗」。答案就是并查集，而它的两个优化是这一节的重点。

### 4.1 判环为什么正好是并查集

Kruskal 整个过程中只被问两种问题：

1. `u` 和 `v` **是否属于同一个连通块**？（决定选还是跳）
2. 把 `u`、`v` 所在的**两个连通块合并**起来。

这正是并查集（Disjoint Set / Union-Find）的两个接口 `find` 与 `union` 的定义。数据结构本体的讲解见 [数据结构.md](../../基础算法/数据结构.md) 第七节，本篇只讲**它在 Kruskal 里的代价**。

### 4.2 两个优化的实测代价

并查集朴素实现会长成一条链，`find` 退化成 `O(n)`。两个优化各自对应一个直觉：

- **按秩合并** = 合并时让「矮树」挂到「高树」下，别让树因合并而变高；
- **路径压缩** = 查询时顺手把路上所有点直接挂到根上，「这次问得贵、下次就便宜」。

![并查集路径压缩前后](images/并查集路径压缩前后.svg)

本机实测（`n = 20000`，按 `union(i-1, i)` 依次合并，再 `find(0)…find(n-1)` 各一次）：

```text
================ 实验一：并查集「路径压缩 / 按秩合并」的查找代价对照 ================
  操作序列：n = 20000，依次 union(i-1, i)（i = 1..n-1）
  查询序列：find(0), find(1), …, find(n-1) 各一次，统计「走过的父指针条数」

  变体                                   查找步数       压缩改写
  朴素（无压缩、无按秩）                     199990000          0
  只加路径压缩                              39997      19998
  只加按秩合并                              19999          0
  路径压缩 + 按秩合并                         19999          0
  ⭐ ① 与 ② 用同一种建树方式（无按秩，会形成深度 n-1 的链），唯一区别是 find 做不做压缩：
     查找步数从 199990000 降到 39997（约 5000 倍）—— 压缩把「一次查询顺手压平整条链」的收益兑现了
  ⭐ ③ 是另一条独立的路：建树时按秩合并，树一开始就是扁的，压根不会形成深链
     ⇒ 两条优化各自都会把「最坏情况」掐掉，实践中两者一起用
```

⭐ **读懂这张表的两件事**：

1. **① 与 ② 唯一的变化就是「压缩开不开」**（都无按秩、都会长链）。首次 `find(0)` 走了 19999 步、顺手把 19998 条父指针改写成「直接指根」（那一列 `压缩改写`），之后每个点到根都只剩 1 步 —— **一次查询付了两次账，把后面全买单了**；
2. **③ 走的是另一条路**：建树时就按秩合并，树压根不长链，所以 19999 步就够了。**按秩合并在「合并时」防患，路径压缩在「查询时」补救**，两者不是替代关系。

⚠️ **关键提醒**：并查集**不支持删除、也不能回滚**（路径压缩破坏了历史结构）。这也是 Kruskal 只能「只加不减」地建树的原因 —— 它从不需要撤销。

### 4.3 实现

```go
// 并查集：路径压缩 + 按秩合并
func (d *DSU) Find(x int) int {
	root := x
	for d.p[root] != root { // 先走到根
		root = d.p[root]
	}
	for d.p[x] != root { // 再顺手把整条路径压平
		nxt := d.p[x]
		d.p[x] = root
		x = nxt
	}
	return root
}

func (d *DSU) Union(a, b int) bool {
	ra, rb := d.Find(a), d.Find(b)
	if ra == rb {
		return false // ⚠️ 已经连通：这条边会成环，Kruskal 据此跳过
	}
	if d.rank[ra] < d.rank[rb] {
		d.p[ra] = rb // 矮树挂到高树下
	} else if d.rank[ra] > d.rank[rb] {
		d.p[rb] = ra
	} else {
		d.p[rb] = ra
		d.rank[ra]++
	}
	return true
}
```

⚠️ `Union` 的返回值就是 Kruskal 的「选 / 跳」开关：返回 `true` 说明合并了两个不同的集合、这条边该选；返回 `false` 说明两端早已连通、会成环。

## 五、三个边界情况（本机实测）

**本节要点**：这三个都不是「理论上可能」，而是本机真跑出来的。它们分别对应「图不连通」「同权多解」「负权」三类输入。

### 5.1 图不连通 → 生成森林

```text
================ 实验三：图不连通时 → 生成森林 ================
  去掉两条边 4-6(9)、5-6(11) 后，点 6 变成孤立点
  选中 5 条边：0-3(5) 2-4(5) 3-5(6) 0-1(7) 1-4(7)
  生成森林总权 = 30，连通分量数 = 2
  ⭐ 这就是「最小生成森林」：Kruskal 不关心连通性，它只是「能合并就合并」
  ⚠️ 于是「图不连通」不会让它报错，而是悄悄少选几条边 —— 判据是 len(选中) == n-1
     本次 n-1 = 6，只选到 5 条 ⇒ 图不连通
```

⭐ **Kruskal 天然给出「最小生成森林」**：它扫完所有边、停在哪算哪，每个连通分量各自得到一棵最小生成树。**判据**：`选中边数 == n − 1` 当且仅当图连通；少一条都不行。

⚠️ 工程含义：**很多实现不检查这一点，于是在不连通的输入上静默返回一个「残缺的树」** —— 调用方以为拿到了生成树，实际只覆盖了部分点。要连通性就把 `len(选中) == n-1` 判一次。

### 5.2 边权相同 → 多解

⚠️ **先说一个容易想当然的点**：本篇实验二那张 7 点图**同权边有两条 5、两条 7，但 Kruskal 与 Prim 选出的边集其实完全相同** —— 同权没有真的造成分歧。所以要演示「多解」，得专门造图。本机实验四就是这样一个例子（4 点 4 边，权 1 有两条、权 2 有两条）：

```text
================ 实验四：同权多解 —— Kruskal 与 Prim 真选出不同的边集 ================
  图：4 点 4 边，两组同权边（权 1 有两条、权 2 有两条）
    0-1(1) 2-3(1) 0-3(2) 1-2(2)
  Kruskal 选中：0-1(1) 2-3(1) 0-3(2)   总权 = 4
  Prim    选中：0-1(1) 1-2(2) 2-3(1)   总权 = 4
  两棵树的边集相同 = false，总权相同 = true
  ⭐ 总权唯一、树形不唯一：同权边谁先被选中，会改变树的形状
  ⚠️ 所以「你的 MST 边集和我的不一样」不代表谁写错了 —— 判据只看总权
```

⭐ **两棵都是合法 MST，总权都是 4，边集却不同**：Kruskal 按 `(权, u, v)` 排序、先拿了 `2-3(1)`；Prim 从 `0` 出发先拿 `0-1(1)`，再从 `1` 把 `2` 拉进来，于是拿的是 `1-2(2)`。切分定理只保证「存在一棵包含某条最小横切边的 MST」，**没保证唯一**。

⚠️ **工程后果**：若你依赖 MST 的**边集**（而不是总权）做后续处理（比如输出一份布线方案），**必须固定 tiebreak 规则**。本机 Go / Java 两版都按 `(权, u, v)` 排序，才能逐行对齐；否则同权边谁先被选中取决于实现，结果不可复现。**这就是为什么「总权」可以拿来断言，「边集」不行。**

### 5.3 负权边不影响正确性

⭐ **这是 Kruskal（与 Prim）和 Dijkstra 最本质的一处差别**：MST 算法**不在乎边权是正是负**。

原因看第三节能明白：切分定理与环性质的证明里**只有「比较大小」、没有「累加」**。负权边只是「最小横切边」的候选之一，比正权边更容易被选中而已 —— **没有任何一步依赖「权 ≥ 0」**。

⚠️ 反过来，Dijkstra 的证明里「绕远路不会更便宜」**依赖非负**（见 [../最短路/Dijkstra.md](../最短路/Dijkstra.md) 第二节），所以负权会让它出错。**「MST 能处理负权、最短路不能」正是两者目标函数不同的又一个证据** —— MST 只需要在**单条边之间比大小**，从不需要把边权沿路径累加起来。

## 使用：Kruskal 在你的系统里以什么形式出现

Kruskal 几乎不会由业务代码直接实现，它以「被用作选型与工具」的形式出现在项目的三层里。结合本仓库已有篇目看：

**第一层：集群与网络的「最小成本组网」**。把机房/交换机当点、把链路当带权边（权 = 布线成本或延迟），「用最低总成本把所有节点接通」就是一次 MST。⚠️ 与 [../最短路/Dijkstra.md](../最短路/Dijkstra.md) 里的 OSPF 正好互补：**OSPF 求「任意两点最短」用 Dijkstra，而「全局布线最省」用 MST** —— 同一个网络问题、两个不同目标，别用错。相关：[../../../网络/网络通信链路详解.md](../../../网络/网络通信链路详解.md)。

**第二层：聚类与「断边」**。Kruskal 的第 `n−1` 条边之前是一棵连通树；如果**提前停在第 `k` 条**，就得到 `k+1` 个连通块 —— 这正是**单链聚类（single-linkage clustering）**：把最相似的连起来，连到想要的分组数就停。⚠️ 所以 MST 是「层次聚类」的一个天然底座，而不是只能用于图问题。

**第三层：任何「把一堆东西用最小总代价连成一体」的模型**。判据只有两条，缺一不可：

| 判据 | 为什么 |
|---|---|
| **代价可加、且只关心总和** | MST 优化的是边的总和，不是某条路径 |
| **要求「全部连通」而非「某两点之间」** | 否则那是最短路问题（见 1.2） |

⭐ **归纳成一条判断**：**你几乎不会「写」Kruskal，但你会「决定该不该把问题建模成 MST」**。而 1.2 那张对照表就是要问自己的问题 —— 我要的是**一张总账单最小**，还是**某个点对之间的距离最小**？

## 延伸追问

- **MST 上的路径是不是最短路？** → **不是**。MST 优化的是**边权总和**，最短路优化的是**点对距离**，两者目标函数不同（本机 1.2 实测：同一张图 MST 总权 39、最短路树总权 54）。**这是这一块最容易混的一处。**
- **Kruskal 和 Prim 结果一样吗？** → **总权一定一样**（都求出了最小生成树），**但边集可能不同**（同权边谁先选决定形态，本机 2.2 实测）。所以「你的树和我的不一样」不代表谁错了。
- **怎么判图不连通？** → 看最后**选中了几条边**：等于 `n−1` 才连通，否则是生成森林（本机 5.1 实测选了 5 条、`n−1=6`）。⚠️ Kruskal 自己不报错，得调用方判。
- **边权有负数会错吗？** → **不会**。切分定理与环性质的证明里**只有比较、没有累加**，完全不依赖非负（5.3）。这与 Dijkstra 必须非负形成鲜明对照。
- **为什么判环不用 DFS？** → 用 DFS 每条边判一次是 `O(V+E)`、整体退化成 `O(E(V+E))`。并查集把「连通块」维护成动态结构，单次 `find` 摊还 `O(α(n))`，整体只需 `O(E α(V))`（4.2）。
- **路径压缩和按秩合并，哪个更关键？** → **都要**（本机 4.2 实测）：按秩合并让树**不长深**，路径压缩让**已有的深树被压平**；单用任一都够用，但两者一起用才稳（最坏情况 `O(α(n))` 的结论依赖两者同时开启）。
- **能提前退出吗？** → 能：选够 `n−1` 条边立刻停（本机 2.2 实测在 `4-6(9)` 处就停了）。⚠️ 但排序的 `O(E log E)` 已经在前面付掉了，提前退出只省下「扫描剩余边」这一小截。
- **并查集能删除吗？** → **不能**（也不支持回滚）。路径压缩把历史结构压平了，无法还原。好在 Kruskal 只「只加不减」，从不需要撤销（4.2）。
- **稠密图上 Kruskal 会怎样？** → 会**明显变慢**，因为要排全部 `E ≈ V²` 条边（本机实测比 Prim 慢一个数量级）。判据与实测见 [Prim.md](Prim.md) 第三节。

## 一、BFS 的原理：一圈一圈往外扩

**本节要点**：BFS 的全部机制一句话——**先来的点先展开**。这个"先来先服务"由**队列**保证，于是访问顺序天然按"到起点的步数"分层。看懂队列的逐步快照，就看懂了后面所有性质。

### 1.1 规则与两个不变量

BFS 的规则：**先发现的点，先展开它的邻居**。

实现上只有一个容器要求：**队列（FIFO）**。但光有队列不够，还要同时守住两个不变量：

| 不变量 | 谁保证 | 破坏的后果 |
|---|---|---|
| **每个点只入队一次** | 入队时就标记 `visited`（⚠️ 不是出队时） | 一个点被反复入队，队列膨胀甚至死循环 |
| **队列里的点按距离单调不减** | FIFO + 入队时定距离 | 层的概念失效，`size` 快照也失去意义 |

⭐ 第二点值得多说一句：**队列里任意时刻只有两批点——"第 d 层"和"第 d+1 层"**，绝不会出现第 d+2 层混在中间。因为第 d+2 层的点只可能在第 d+1 层的点出队时才入队，而那时它必然排在第 d+1 层所有点的后面。**这就是"队列 = 一条正在平移的层边界"**，也是"层数即距离"的根源。

### 1.2 队列逐步快照

用一篇通用的示例图（无向、6 点 7 边，邻接表按编号升序）：

```text
        0
      / | \
     1  2  3
      \ | /
        4
        |
        5

adj = [[1 2 3] [0 4] [0 4] [0 4] [1 2 3 5] [4]]
```

从 `0` 出发，一步步看队列的变化（本机实跑）：

```text
第 1 步  弹出 0  → 队列 [1 2 3]   新入队 [1 2 3]   dist[0]=0
第 2 步  弹出 1  → 队列 [2 3 4]   新入队 [4]       dist[1]=1
第 3 步  弹出 2  → 队列 [3 4]     新入队 []        dist[2]=1
第 4 步  弹出 3  → 队列 [4]       新入队 []        dist[3]=1
第 5 步  弹出 4  → 队列 [5]       新入队 [5]       dist[4]=2
第 6 步  弹出 5  → 队列 []        新入队 []        dist[5]=3
```

把队列的形状画出来，1.1 节的两个不变量一眼可见：

```text
弹出 0  之前:  [0]              ← 只有源点
弹出 0  之后:  [1 2 3]          ← 第 1 层整批（0 的三个邻居）
弹出 1  之后:  [2 3 4]          ← 第 1 层还剩 2 3，第 2 层的 4 排在它们后面 ✅
弹出 2  之后:  [3 4]
弹出 3  之后:  [4]              ← 第 1 层清空，只剩第 2 层
弹出 4  之后:  [5]              ← 第 3 层
弹出 5  之后:  []

⭐ 队列里永远只有「当前层」和「下一层」两批 —— 这就是分层的来源
```

> 注意第 3、5 步的 `新入队 []`：`2` 的邻居是 `0`、`4`，都被访问过了；`5` 的邻居是 `4`，也是。**"看得见但不用入队"**正是 `visited`（这里是 `dist` 充当）在起作用——没有它，`2` 会把 `0`、`4` 重新入队，队列永不清空。

### 1.3 结果与对照

```text
BFS 访问序: [0 1 2 3 4 5]
距离      : [0 1 1 1 2 3]         ← 顶点 4 的最短距离是 2，顶点 5 是 3
层分组    : 第 0 层 [0]｜第 1 层 [1 2 3]｜第 2 层 [4]｜第 3 层 [5]
```

换成一篇 5 元环图（`0-1 1-2 2-3 0-4 4-3`，即 [DFS深度优先遍历.md](DFS深度优先遍历.md) 第一节那张），BFS 与 DFS 的差别最刺眼：

```text
BFS（队列）   0 → [1 4] → [2 3]     层号即距离：dist = [0 1 2 2 1]
DFS（递归）   0 → 1 → 2 → 3 → 4     一条路钻到底，结果里没有「层」这个概念
DFS（显式栈） 0 → 4 → 3 → 2 → 1     同一份邻接表，LIFO 把访问序整个反过来
```

⭐ 读法：**顶点 4 的最短距离是 1**（直接 `0→4`），BFS 第二轮就给出；而递归 DFS 沿 `0→1→2→3→4` 走满 4 跳才碰到它——**谁把"DFS 里的第几个"当成距离，谁就得到 4 这个错答案**。顺序由**容器**决定，不由"DFS / BFS"这个名字决定。

⚠️ 「BFS 一定比 DFS 快」是错的：两者访问同一张连通图的每条边都是 O(V+E)，**渐近复杂度相同**（推导见 [DFS深度优先遍历.md](DFS深度优先遍历.md) 第九节），差别在内存画像、能否提前退出、以及是否需要最短性。

## 二、为什么 BFS 给得出无权图最短路

**本节要点**：上一节的"队列里只有两层"是直觉，这一节把它变成**能讲出口的证明**——这是 BFS 最值钱的性质，也是"为什么不用 DFS 求最短路"这个问题的答案。

### 2.1 结论与前提

**结论**：在**每条边代价相同**（无权或等权）的图上，BFS 第一次到达某点时的层号 = 该点到源点的最短边数。

**前提**（少了它结论就不成立）：**边权相同**。有权重时 BFS 的层数不等于距离，要走 [图论算法/最短路/Dijkstra.md](../最短路/Dijkstra.md)。

### 2.2 反证法证明

设 BFS 赋给点 `v` 的距离为 `k`，假设存在一条更短的路径 `s → w → … → v`，长度为 `k' < k`。

沿这条路径取 `v` 的前驱 `w`，`w` 到 `s` 的距离是 `k' - 1`。因为 `k' - 1 < k - 1 < k`，由**归纳假设** `w` 在 BFS 里被赋的距离也正是 `k' - 1`（它比 `v` 更早一层被正确处理）。

`w` 出队时会扫描它的邻居，其中就有 `v`：此时若 `v` 还未被访问，就必然被赋为 `(k' - 1) + 1 = k'`——与 `dist[v] = k` 矛盾。若 `v` 已被访问，则它的距离只会更早被确定（≤ `k'`），同样矛盾。

所以不存在长度为 `k' < k` 的路径，`dist[v] = k` 就是最短路长度。∎

⭐ 换成一句话的直觉版：**更短的路径必然经过"更早的层"，那一层早就处理完了——如果 `v` 能通过它到达，它早就被赋成更小的距离了。**

### 2.3 三个直接推论

| 推论 | 说明 |
|---|---|
| **BFS 首次到达即最短** | 所以可以"找到目标立刻返回"，不必跑完整图 |
| **DFS 没有这个性质** | 它可能先钻一条十跳的路径抵达终点，然后再也不更新距离 |
| **"最少步数"类问题必须 BFS** | 迷宫最少步数、单词接龙、社交网络几度人脉；DFS 只能回答"可不可达" |

⚠️ 边界：**边权不等时层数 ≠ 距离**。BFS 的层号是"边数"，不是"总代价"。带权图要用 Dijkstra（优先队列 + 松弛）；边权只有 0/1 时可以用双端队列的 0-1 BFS（见第五节）。

## 三、层序：每轮先取 `size` 快照 ⭐

**本节要点**：BFS 本身只知道"距离"，要拿到"每一层都有谁"，必须在循环里**先快照本轮长度**。这是层序遍历唯一容易写错的地方。

入队会让队列长度不断变化，所以**处理本轮之前必须先把长度记下来**——用这个快照决定"本轮处理几个"，多处理的就落到下一层去了。

```go
func levelOrder(root *TreeNode) [][]int {
	res := [][]int{}
	if root == nil {
		return res
	}
	q := []*TreeNode{root}
	for len(q) > 0 {
		size := len(q) // ⭐ 快照：本轮只处理这一层
		level := make([]int, 0, size)
		for i := 0; i < size; i++ {
			n := q[0]
			q = q[1:]
			level = append(level, n.Val)
			if n.Left != nil {
				q = append(q, n.Left)
			}
			if n.Right != nil {
				q = append(q, n.Right)
			}
		}
		res = append(res, level)
	}
	return res
}
```

用那棵例子树（`3` 只有左孩子），逐轮看「快照 → 处理 → 下一层入队」：

```text
              1
            /   \
           2     3
          / \   /
         4   5 6

轮 1  size=1  本轮队列 [1]        记 [1]      处理中 2、3 入队 → 队列变 [2 3]
轮 2  size=2  本轮队列 [2 3]      记 [2 3]    处理中 4、5、6 入队 → 队列最长到 3
轮 3  size=3  本轮队列 [4 5 6]    记 [4 5 6]  无孩子，队列清空

结果: [[1] [2 3] [4 5 6]]
```

⚠️ **不写 `size` 快照、直接 `for !q.isEmpty() { 弹一个 }` 的写法，会把「层」这个概念丢掉**——结果变成普通 BFS，只知道距离、不知道每层谁。**Java 侧同理**：`int size = q.size()`，且 `ArrayDeque` 上要用 `addLast` / `pollFirst`（或 `add` / `poll`），别用 `pop` 配 `add` 混着当队列。

## 四、Kahn 拓扑排序：BFS 的入度版

**本节要点**：拓扑排序有两种写法，**Kahn 是 BFS 那一路**——它不问"谁是祖先"，只问"**谁还不欠人**"。天然带层次、天然能判环，是工程里最常用的那种。

### 4.1 原理：反复取走"入度为 0"的点

规则三句话：

1. 统计每个点的**入度**（有多少条边指向它）；
2. 所有入度为 0 的点入队——它们**不依赖任何前置**，可以立刻执行；
3. 反复：取出一个点加入结果，**删掉它的所有出边**（让邻居的入度减 1），谁的入度因此变成 0 就入队。

⭐ **为什么要"删出边"**：入度为 0 意味着"依赖都满足了"。删掉 `u→v` 就是告诉 `v`："你少了一个等的人"。

### 4.2 逐轮实测：每一轮就是一个并行边界

拿一张 6 点 DAG（弧表 `5→{2 0}`、`4→{0 1}`、`2→{3}`、`3→{1}`）跑一遍：

```text
初始入度: 0:2  1:2  2:1  3:1  4:0  5:0

第 1 轮 [4 5] → 删 4→0 使 0:2→1；4→1 使 1:2→1；5→2 使 2:1→0；5→0 使 0:1→0
              ⇒ 下一轮候选 [2 0]
第 2 轮 [2 0] → 删 2→3 使 3:1→0
              ⇒ 下一轮候选 [3]
第 3 轮 [3]   → 删 3→1 使 1:1→0
              ⇒ 下一轮候选 [1]
第 4 轮 [1]   → 删 无出边
              ⇒ 下一轮候选 []

拓扑序: [4 5 2 0 3 1]   收到点数 6 = n ✅（判定无环）

摊平成层级图（同一层内没有依赖，可并发执行）:
 5   4   →   2   0   →   3   →   1
```

⚠️ 每轮取出的是「当前入度为 0 的**全部**点」，这一批就是**并行边界**：CI 里同一层的任务可以并发跑，跨层必须等。少取一个（只取队首）拓扑序仍然合法，但白白串行化了一层。

### 4.3 判环是"免费"的 ⭐

```text
真环 0→1→2→0: 收到 0 点 < n=3 ⇒ 有环 ✅（环上点入度永不为 0）
```

⭐ **`order` 里的点数 < n ⇔ 有环**：环上的点互相依赖，入度永远不会降到 0，所以它们永远进不了队列。这个判据是**顺带得到的**——不需要额外写一个判环算法（DFS 那一侧则必须用三色，见 [DFS深度优先遍历.md](DFS深度优先遍历.md) 第六节）。

### 4.4 两种写法的分工

| 写法 | 原理 | 判环 | 适用 |
| --- | --- | --- | --- |
| Kahn（BFS 入度） | 反复取出入度为 0 的点，删它的出边 | ⭐ 天然：`order.size() < n` 即有环 | 构建依赖、任务编排、DDL 外键顺序、包初始化顺序 |
| DFS + 后序反转 | 每个点在后序（所有后继完成时）入列，整体反转即拓扑序 | 靠三色，遇到灰边 | 已经写了 DFS、要顺带拿 SCC / 关键路径 |

⭐ **拓扑序不唯一**：同一张图，Kahn 给出 `[4 5 2 0 3 1]`，DFS 后序反转给出 `[5 4 2 3 1 0]`。两个序**都成立**（每条弧都满足 `pos[u] < pos[v]`）——所以「你的拓扑序和我的不一样」不代表谁写错了。

> ⭐ 记忆点：**拓扑排序只对 DAG 存在**；Maven 模块依赖、Go 包 `init` 顺序、K8s 资源的 apply 顺序都是它。

## 五、三个进阶变体

**本节要点**：这些变体的差别**全在"容器怎么用"**上——多源是"起点多灌几个"，双向是"两头一起扩"，0-1 BFS 是"队列变双端"。看清容器，就不用背四个算法。

| 变体 | 做法 | 解决什么 |
| --- | --- | --- |
| **多源 BFS** | 把所有起点**一次性**灌进队列，再做分层扩散 | 多个火种同时扩散（腐烂的橘子）、多个仓库最近距离、地图上多个 POI 的最近归属 |
| **双向 BFS** | 从起点和终点各起一个 BFS，每轮扩展**较小**的那侧，交集即接通 | 状态空间大、分支因子 b、深度 d：复杂度从 `b^d` 降到约 `2·b^(d/2)`（单词接龙、迷宫两端已知） |
| **0-1 BFS** | 用**双端队列**：边权 0 的 `push_front`、边权 1 的 `push_back` | 边权只有 0/1 时不用堆，仍是 O(V+E) 拿到最短路 |
| 迭代加深（IDDFS） | 限制 DFS 的最大深度，逐层放宽 | 要 DFS 的空间（O(d)）又要 BFS 的最短性；代价是同一层被重复展开（常数约 `b/(b-1)`） |

变体的差别也全在「队列的形状」上：

```text
   ① 双向 BFS（起点 s、终点 t 都已知，分支因子 b、解深 d）

        s ── a ── b ── c ── d ── t
        └─ 正向扩 ─┘   ↑相遇   └─ 反向扩 ─┘
        单侧要展开 b^d 个状态；两侧各展开 b^(d/2) 个就会在中间撞上

   ② 0-1 BFS（边权只有 0 / 1，用双端队列代替优先队列）

        push_front ← 权 0 的邻居（距离不变，属于「同一层」）
        push_back  → 权 1 的邻居（距离 +1，排到后面）
        双端队列因此天然按距离单调，弹出顺序就是层序 —— 不需要堆，省下 O(log n)

   ③ 多源 BFS（所有起点一次性入队，之后照常按层推进）

        第 0 层队列: [s1 s2 s3]     ← 而不是分别从 s1、s2、s3 各跑一遍 BFS
        每轮仍取 size 快照，扩散一圈 = 一个时间单位（腐烂的橘子、最近仓库归属）
```

**多源 BFS 实测**（5×5 网格，两个初始腐烂点，腐烂以"每轮感染四邻"扩散）：

```text
全部腐烂所需分钟: 8  剩余新鲜: 0
含孤立新鲜橘子: 分钟 -1（-1 = 不可能）  剩余新鲜: 2
```

⚠️ 第二条是这类题最容易漏的边界：**有新鲜橘子被 0（空位）隔开时，永远烂不到**，必须返回 -1 —— 用 `fresh > 0` 在循环结束后判一次即可。

⚠️ **带一般正权重的图，普通 BFS 会算错**：BFS 的层数只在「每条边代价相同」时等于距离。有权重要走 [图论算法/最短路/Dijkstra.md](../最短路/Dijkstra.md)（优先队列 + 松弛），有负权边走 [图论算法/最短路/Bellman-Ford.md](../最短路/Bellman-Ford.md) / SPFA。这是「为什么 BFS 是最短路」最常见的边界误用。

## 六、手推演练：拿一张 6 点图跑一遍

**本节要点**：把第一节的图**手动跑一遍**，与上面的程序输出逐行对。会手推就说明前面的机制都通了。

图与邻接表（同 1.2 节）：

```text
        0
      / | \
     1  2  3
      \ | /
        4
        |
        5

adj = [[1 2 3] [0 4] [0 4] [0 4] [1 2 3 5] [4]]
```

**逐步推演（源点 0，入队时标记距离）**：

| 步 | 弹出 | 队列（弹出后） | 这一步新入队的 | 距离表 |
|---|---|---|---|---|
| 0 | — | `[0]` | 源点 0 入队，`dist[0]=0` | 0:0 |
| 1 | 0 | `[1 2 3]` | 1、2、3 都未访问 → 全部入队，`dist=1` | 0:0 1:1 2:1 3:1 |
| 2 | 1 | `[2 3 4]` | 邻居 0（已访问）、4（未访问）→ 只入队 4，`dist=2` | +4:2 |
| 3 | 2 | `[3 4]` | 邻居 0、4 **都已访问** → 不入队 | 不变 |
| 4 | 3 | `[4]` | 邻居 0、4 都已访问 → 不入队 | 不变 |
| 5 | 4 | `[5]` | 邻居 1、2、3 已访问；5 未访问 → 入队，`dist=3` | +5:3 |
| 6 | 5 | `[]` | 邻居 4 已访问 → 队列空，结束 | 不变 |

**结论**（与 1.3 节实测一致）：

```text
访问序 : [0 1 2 3 4 5]
距离   : [0 1 1 1 2 3]
层分组 : 第 0 层 [0]｜第 1 层 [1 2 3]｜第 2 层 [4]｜第 3 层 [5]
```

⚠️ **手推时最容易错的两处**：

1. **标记发生在"入队时"**，不是"出队时"。第 1 步把 1、2、3 一起入队后，它们三个都已经"占用"，所以第 3 步处理 2 时**不能再把 4 抢先入队**——4 是第 2 步由 1 入队的。若改成"出队时才标记"，4 会被 1、2、3 各入队一次，队列虚长（结果仍对，但队列里出现重复点）。
2. **每一步只处理"当前队列里的全部"**，处理完才算一轮。第 2~4 步都在第 1 层内部，这就是"层"的边界；漏掉这个边界感，就会把 `dist` 算成"第几个被弹出来"。

## 七、Go 实现：BFS

> ⭐ 图表示 `type Graph` 是**单一来源**，统一写在总纲 [DFS与BFS遍历.md](DFS与BFS遍历.md) 末节；本节与 [DFS深度优先遍历.md](DFS深度优先遍历.md) 的代码都直接使用它。

```go
// BFS：dist 同时充当 visited（inf = 未访问）
func (g *Graph) bfsDist(src int) []int {
	const inf = 1 << 30
	dist := make([]int, g.n)
	for i := range dist {
		dist[i] = inf
	}
	dist[src] = 0
	q := []int{src}
	for len(q) > 0 {
		u := q[0]
		q = q[1:]
		for _, v := range g.adj[u] {
			if dist[v] == inf { // ⭐ 入队时标记，避免重复入队
				dist[v] = dist[u] + 1
				q = append(q, v)
			}
		}
	}
	return dist
}
```

**实测**（5 元环 `0-1 1-2 2-3 0-4 4-3`，源点 0）：`dist = [0 1 2 2 1]`——顶点 3 的最短距离是 2（走 `0→4→3`），而不是沿长路 `0→1→2→3` 的 3。

多源 BFS（腐烂橘子式扩散）的骨架——把全部起点一次入队，再按层推进：

```go
type cell struct{ r, c int }

q := []cell{}                 // ⭐ 多源：所有起点一次入队
fresh := 0
for r := 0; r < R; r++ {
	for c := 0; c < C; c++ {
		if grid[r][c] == 2 {
			q = append(q, cell{r, c})
		} else if grid[r][c] == 1 {
			fresh++
		}
	}
}
min := 0
dirs := [4][2]int{{-1, 0}, {1, 0}, {0, -1}, {0, 1}}
for len(q) > 0 && fresh > 0 {
	size := len(q) // 层快照
	min++
	for i := 0; i < size; i++ {
		cur := q[0]
		q = q[1:]
		for _, d := range dirs {
			nr, nc := cur.r+d[0], cur.c+d[1]
			if nr >= 0 && nr < R && nc >= 0 && nc < C && grid[nr][nc] == 1 {
				grid[nr][nc] = 2 // ⭐ 原地标记，省掉一份 visited
				fresh--
				q = append(q, cell{nr, nc})
			}
		}
	}
}
if fresh > 0 {
	min = -1 // 有橘子永远烂不到
}
```

> 实测：5×5 网格、两个初始腐烂点 → `全部腐烂所需分钟: 8 剩余新鲜: 0`；含孤立新鲜橘子的网格 → `-1`（剩余 2 个烂不到）。⚠️ 这段是**函数体内片段**，编译时需要外部声明 `grid / R / C`。

## 八、Java 实现：同一套逻辑的容器选型

```java
static List<List<Integer>> levelOrder(TreeNode root) {
    List<List<Integer>> res = new ArrayList<>();
    if (root == null) return res;
    Deque<TreeNode> q = new ArrayDeque<>(); // ⭐ ArrayDeque 当队列：add / poll
    q.add(root);
    while (!q.isEmpty()) {
        int size = q.size();                // ⭐ 快照本轮层宽
        List<Integer> level = new ArrayList<>(size);
        for (int i = 0; i < size; i++) {
            TreeNode n = q.poll();
            level.add(n.val);
            if (n.left != null) q.add(n.left);
            if (n.right != null) q.add(n.right);
        }
        res.add(level);
    }
    return res;
}

// Kahn 拓扑排序：order.size() < n 即有环
List<Integer> topoKahn() {
    int n = adj.size();
    int[] in = new int[n];
    for (int u = 0; u < n; u++) for (int v : adj.get(u)) in[v]++;
    Deque<Integer> q = new ArrayDeque<>();
    for (int i = 0; i < n; i++) if (in[i] == 0) q.add(i);
    List<Integer> order = new ArrayList<>(n);
    while (!q.isEmpty()) {
        int u = q.poll();
        order.add(u);
        for (int v : adj.get(u)) if (--in[v] == 0) q.add(v);
    }
    return order;
}
```

⚠️ **容器选型口径**（Java 侧很容易踩）：

| 需求 | 用 | 别用 |
| --- | --- | --- |
| 队列（BFS） | `ArrayDeque`（`add` / `poll`） | `LinkedList`（节点分配多、慢）、`Queue` 配 `pop`（`pop` 是栈语义） |
| 栈（DFS） | `ArrayDeque`（`push` / `pop`） | `Stack`（遗留同步类，性能差） |
| 存 `null` 或哨兵 | `ArrayList` / Go slice | `ArrayDeque` / `HashMap` 的 key（会抛异常或 NPE） |

## 延伸追问

- **为什么 BFS 能求最短路而 DFS 不能？** → 队列按层推进：节点首次入队时的层数就是最短距离（第二节给了反证法）；DFS 先探到的路径可能长得多，且它不会回头更新。⚠️ 前提是**边权相同**。
- **BFS 队列会不会爆内存？** → 会。满二叉树的最后一层就占一半节点（实测高度 20 的树队列峰值 524288）。「宽」的图 BFS 内存压力大于 DFS；反之深而窄的图 DFS 栈压力大（完整实测见总纲第三节）。
- **层序为什么一定要 `size` 快照？** → 入队会改变队列长度。不快照就分不清"这一轮该处理几个"，结果退化成普通 BFS，只拿到距离、拿不到分层。
- **`dist` 和 `visited` 能合并吗？** → 能，而且推荐：用 `dist = inf` 表示"未访问"，`dist[v] == inf` 就是判据。少一个数组，也不会出现两者不一致。
- **多源 BFS 为什么不用"每个源点各跑一次取最小"？** → 复杂度从 O(k(V+E)) 降到 O(V+E)。多源只是"起点从 1 个变 k 个"，其余机制完全不变。
- **双向 BFS 为什么快？** → 复杂度从 `b^d` 降到约 `2·b^(d/2)`（分支因子 b、深度 d）。要点是**每轮扩展较小的那一侧**，否则退化成单侧。
- **0-1 BFS 为什么不直接用 Dijkstra？** → 边权只有 0/1 时双端队列天然按距离单调，弹出顺序就是层序，省掉堆的 O(log n)；有权重则不行，必须用堆（Dijkstra）。
- **Kahn 的判环为什么"免费"？** → 环上的点入度永远降不到 0，永远进不了队列，所以最后 `order` 里点数 `< n` 就是有环。DFS 那一侧必须显式写三色，见 [DFS深度优先遍历.md](DFS深度优先遍历.md) 第六节。
- **每轮取出一整批（当前所有入度为 0 的点）和只取队首有区别吗？** → 拓扑序都合法，但**整批取出才对应"并行边界"**：同一层的任务可并发、跨层必须等。CI / K8s 的资源编排要的就是这个边界。
- **IDDFS 什么时候值得用？** → 需要 DFS 的 O(d) 空间、同时又要 BFS 的最短性时（状态空间巨大、深度未知）。代价是同一层被重复展开，常数约 `b/(b-1)`。

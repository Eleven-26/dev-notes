## 一、核心思想

**本节要点**：一个动作 —— **松弛**；一个前提 —— **按什么顺序取点**。所有最短路算法的差别**只在这一句**上。

### 松弛（Relaxation）：唯一的原子操作

```text
if (dist[u] + w(u,v) < dist[v]) {
    dist[v] = dist[u] + w(u,v);     // 发现了一条更短的路
}
```

⭐ 所有最短路算法（Dijkstra / Bellman-Ford / SPFA / Floyd）**共用这一个动作**，区别只在**「按什么顺序取点、松弛多少轮」**：

| 算法 | 取点顺序 | 松弛几轮 | 适用前提 |
|---|---|---|---|
| **BFS** | 队列（按跳数） | 一层扫一遍 | ⚠️ 仅**等权图** |
| **[Dijkstra.md](Dijkstra.md)** | **小顶堆**（按当前 `dist`） | 每点出堆一次 | 非负权 |
| **[Bellman-Ford.md](Bellman-Ford.md)** | 无所谓（**每轮扫全部边**） | **`V − 1` 轮** | 可负权 |
| **SPFA** | **队列**（只放刚被改小的点） | 直到队列空 | 可负权 |
| **[Floyd.md](Floyd.md)** | 按**中转点** `k` 逐层放开 | `k` 从 0 到 `V−1` | 全源 |

⭐ 这张表就是「最短路」这一族知识的**全部骨架**。看到一个新算法，先问它两件事：**按什么顺序取点**、**能处理什么权**。

### ⚠️ 从 BFS 到 Dijkstra 的那一步

BFS 求最短路有个硬前提：**每条边代价相同**。一旦边权不等，「层号」就不再等于「距离」：

```text
0 ──4── 1        从 0 到 1：BFS 说「1 跳」，但这 1 跳要花 4
                 绕道 0 → 2 → 1 是 2 跳，却只要 1 + 2 = 3
```

**跳数少 ≠ 代价小** —— 这就是 Dijkstra 要解决的问题（[Dijkstra.md](Dijkstra.md) 第一节）。

## 二、适用条件

**本节要点**：选型的**第一判据永远是「有没有负权」**，第二判据是「单源还是全源」，第三才是效率。

| 算法 | 边权 | 源 | 能判负环 | 复杂度 |
|---|---|---|---|---|
| **[Dijkstra.md](Dijkstra.md)** | ⚠️ **必须非负** | 单源 | ❌ | `O((V+E) log V)`（堆） |
| **[Bellman-Ford.md](Bellman-Ford.md)** | 可负 | 单源 | ✅ 能 | `O(V × E)` |
| **SPFA** | 可负 | 单源 | ✅ 能 | 平均 `O(kE)`，**最坏 `O(VE)`** |
| **[Floyd.md](Floyd.md)** | 可负 | **全源** | ✅ 能（看对角线） | `O(V³)` |
| **A\*** | 非负 | 单源（带启发函数） | ❌ | 取决于启发函数的质量 |

### ⚠️ 负权不是「慢一点」，而是「算错」

| 前提被破坏 | 后果 |
|---|---|
| **Dijkstra 遇到负权** | ⚠️ **静默给出错答案** —— 本项目实测：错的不是「被污染的那个点」，而是**一次局部修正没能传播出去**（`dist[3]` 停在 3，正确答案是 2） |
| **存在负环** | 「最短路」**没有定义**（每绕一圈更短）→ 必须**检测并报错**，而不是返回一个数 |

⭐ 这两条是本节最重要的内容：**Dijkstra 的失效不是异常、不报错**，所以「建图后先扫一遍边权」这个动作**不能省**。

### 典型场景

| 场景 | 归到哪个算法 |
|---|---|
| **地图导航** | Dijkstra（+ A* 启发式加速） |
| **网络路由** | 域内 **OSPF 用 Dijkstra**（链路状态）；域间 RIP 用距离向量（**Bellman-Ford 思想**） |
| **游戏寻路** | 网格地图（等权用 BFS；带权用 Dijkstra/A*） |
| **社交网络关系链** | 无权 → BFS；带权（亲密度）→ Dijkstra |
| **差分约束系统** | 转成最短路判定可行性 → Bellman-Ford / SPFA 判负环 |

## 三、解题模板

**本节要点**：四步 —— 关键在于第 3 步「选算法」，而选算法的第一问是**有没有负权**。

| 步骤 | 做什么 | 关键点 |
|---|---|---|
| **1. 图的表示** | 邻接表（稀疏）/ 邻接矩阵（稠密）/ 边列表（Bellman-Ford 要扫全部边） | Floyd **必须**用矩阵 |
| **2. 初始化** | `dist[source] = 0`，其余 `∞`；⚠️ **哨兵值要选对** | `INF` 取多大有讲究（见第六节最后一条） |
| **3. 选算法** | 按第二节的表 | ⚠️ **先判负权**，再判单源/全源 |
| **4. 返回** | `dist[]` 或**路径** | 要路径就得额外维护 `prev`（Dijkstra/BF）或 `next` 矩阵（Floyd） |

### ⭐ 第 3 步：选型决策树

```text
要算哪些点之间的距离？
├─ 全部点对（全源）
│    └─ V 不大（几百）→ Floyd（三行代码，O(V³)）             [Floyd.md]
│         ⚠️ V 很大 → 跑 V 次 Dijkstra（稀疏图）或 Johnson 算法
└─ 只从 1 个源点（单源）
     ├─ 边权全 ≥ 0 → Dijkstra（堆优化）                      [Dijkstra.md]
     └─ 有负权
          ├─ 图小 / 要判负环 → Bellman-Ford（最坏 O(VE)，但稳定）  [Bellman-Ford.md]
          └─ 想要平均更快   → SPFA ⚠️ 最坏仍 O(VE)，可能被卡
```

### ⭐ 第 4 步：路径还原

`dist[]` 只给「多远」，要「怎么走」得额外记：

| 算法 | 记什么 |
|---|---|
| Dijkstra / Bellman-Ford / SPFA | `prev[v] = u`（最后一次把 `v` 改小的那个 `u`），从终点往回走 |
| **Floyd** | 额外维护 `next[i][j]` 矩阵（因为 Floyd 一次算全源，`prev` 不够用）—— 见 [Floyd.md](Floyd.md) 第四节 |

## 五、正确性证明

**本节要点**：两套工具 —— **贪心 + 不变量**（Dijkstra）与 **DP 的阶段不变式**（Bellman-Ford / Floyd）。

| 算法 | 工具 | 核心不变量 |
|---|---|---|
| **[Dijkstra.md](Dijkstra.md)** | 贪心 + 归纳 | ⭐「**出堆即最终**」：非负权下，堆顶的点不可能再被更短的路径改善 |
| **[Bellman-Ford.md](Bellman-Ford.md)** | DP / 逐轮松弛 | ⭐「**第 `k` 轮后 ≤ 用 `k` 条边的最短距离**」→ `V−1` 轮必收敛 |
| **SPFA** | 同 Bellman-Ford | 只是换了松弛顺序，**不改变正确性**（但改变最坏复杂度） |
| **[Floyd.md](Floyd.md)** | 纯 DP | ⭐「**第 `k` 轮后 = 只允许用 `{0..k}` 中转时的最优**」→ `k` 必须在最外层 |

### Dijkstra 的证明要点（为什么非负权是必需的）

```text
反证：假设取出点 u 时 dist[u] 不是最终值。
则存在一条更短路径 source → … → u，它必然经过某个「还没取出」的点 x。
由于边权非负 ⇒ source → x 的距离 ≤ source → u 的这条路径长度 < dist[u]
但 x 还在堆里，它的 dist[x] < dist[u] —— 这与「u 是堆顶（最小）」矛盾。∎
```

⭐ **注意第 2 步用到「边权非负」**：如果边权为负，「`source→x` 的距离 ≤ `source→u`」这一步就不成立了 ——
**证明在哪里断，算法就在哪里失效**。[Dijkstra.md](Dijkstra.md) 第三节给出了实测对照（懒惰版会自我修正，定稿版不会）。

### Bellman-Ford 的证明要点

```text
归纳：第 k 轮结束后，对所有 v：dist[v] ≤ (从 source 到 v、最多用 k 条边的最短距离)
① k = 0：只有 source 是 0，其余 ∞，成立
② 第 k 轮：对每条边做松弛，等价于「在 k−1 条边的基础上再走一条边」
③ 故 k = V−1 时，覆盖了「最多 V−1 条边」的全部路径 = 所有简单路径 ⇒ 收敛
```

⚠️ 推论：**第 `V` 轮还能松弛 ⇒ 存在负环** —— 因为「不超过 `V−1` 条边」已经是最优，还能变小只能是绕了负环（[Bellman-Ford.md](Bellman-Ford.md) 第三节）。

### Floyd 的证明要点

```text
dp[k][i][j] = 「只允许用 {0,1,…,k} 这些点当中转」时 i → j 的最短距离
转移：dp[k][i][j] = min(dp[k−1][i][j], dp[k−1][i][k] + dp[k−1][k][j])
                    └ 不用 k      └ 用 k 中转
```

⭐ **`k` 就是 DP 的「阶段」** —— 所以它必须在最外层。放进内层就变成「同一阶段里边读边写」，用到的不是上一阶段的值（[Floyd.md](Floyd.md) 第二节有实测：`d[0][1]` 从 3 变成 `∞`）。

## 六、常见陷阱

**本节要点**：最短路是本项目**踩坑最多**的一族 —— 前提类（负权、连通、编号）、实现类（哨兵、遍历顺序）、性能类（SPFA 退化）。

| 陷阱 | 症状 | 怎么避免 |
|---|---|---|
| **负权边让 Dijkstra 失效** | ⚠️ **静默错答案**（不是报错） | 建图后**先扫一遍边权**；有负权换 BF / Floyd |
| **有向图与无向图混淆** | 单向边被当成双向（或反之） | 无向图每条边加两次 —— 这是最常见的低级错误 |
| **重边、自环未处理** | 权重取错 / 死循环 | 重边取最小；自环直接忽略 |
| **图不连通** | 不可达点的 `dist` 应保持 `∞` | 明确「不可达」的语义，别把它当成 0 |
| **节点编号 0 起 / 1 起** | 越界或漏点 | 建图时统一 |
| **稀疏图用邻接矩阵** | 内存超限 | 邻接表；Floyd 才必须用矩阵（它本来就是 `O(V²)` 空间） |
| **SPFA 最坏 `O(VE)`** | 对抗数据上被卡死 | ⭐ **非负权就老老实实用 Dijkstra**，别赌数据友好 |
| **负环检测方式不对** | 漏检 / 误判 | Bellman-Ford：第 `V` 轮还能松弛；SPFA：某点入队次数 ≥ `V` |
| **只算距离、还原不出路径** | 有数值没路线 | 维护 `prev` / `next`（第三节第 4 步） |
| **Floyd 的 `INF + 负权` 污染** | 出现 `536870908` 这类**假值**（其实是不可达） | 内层加 `d[i][k] < INF && d[k][j] < INF` 判断（[Floyd.md](Floyd.md) 第三节） |
| **`INF` 取值跨语言不一致** | ⚠️ Go 得 `2147483648`，**Java 的 32 位 `int` 回绕成负数** | 要么加可达性判断，要么挑一个「`INF + INF` 两边都不溢出」的值（[Floyd.md](Floyd.md) 第三节） |

### 补两条「实验设计」层面的坑

| 坑 | 说明 |
|---|---|
| **性能测试的图选得「太友好」** | 本项目实测过：随机图的边序**恰好顺着主干链**时，Bellman-Ford 只跑 1~7 轮、甚至**比 Dijkstra 还快** —— 拿它当性能判据会得出完全相反的结论。真正的对照要**打乱边序**或构造**最坏情况**（反向长链：BF 比 Dijkstra 慢 40~140 倍） |
| **只测「能跑通」，没测「该失效的失效了吗」** | 演示「负权让 Dijkstra 出错」时，反例必须让**被错过的点有下游邻居** —— 否则错误传播不出去，错误实现看起来是「对」的 |

## 七、与其他思想对比

**本节要点**：`最短路 vs 最小生成树` 是最需要分清的一对；`Dijkstra vs Bellman-Ford / Floyd` 则是「贪心 vs DP」在图上的投影。

### 最短路 vs 最小生成树（⭐ 高频误区）

| 维度 | 最短路 | 最小生成树 |
|---|---|---|
| 目标 | **两点之间**路径代价最小 | **连通所有点**、边权**总和**最小 |
| 结果 | 距离表 / 最短路树 | 一棵 `V−1` 条边的树 |
| 边权非负是前提吗 | ✅ Dijkstra 需要 | ❌ 不需要 |
| 典型 | Dijkstra、Bellman-Ford、Floyd | Kruskal、Prim |

⚠️ **最短路树上的路径不一定是最短路**：三角形 `A—B(2), B—C(2), A—C(3)` 的 MST 是 `A—B—C`（总权 4），
但 `A→C` 在 MST 上要走 4，直接走 `A—C` 只要 3。

⭐ 判据一句话：**问「总代价最小」→ MST；问「从 X 到 Y 最省」→ 最短路**。详见 [../最小生成树/README.md](../最小生成树/README.md)。

### 最短路 vs 贪心

| 算法 | 是不是贪心 |
|---|---|
| **Dijkstra** | ✅ 贪心 —— 每轮取「当前距离最小」的点（前提是非负权） |
| Bellman-Ford / Floyd | ❌ DP |
| Prim / Kruskal | ✅ 贪心（但目标不同，见上） |

⭐ **Dijkstra 是「贪心失效」最好的教学案例**：它平时完全正确，只在负权下出错 —— 而且**出错的方式很隐蔽**（[Dijkstra.md](Dijkstra.md) 第三节）。这正好印证了贪心的通病：**不给证明就用，会静默给出次优解**（[../../贪心/README.md](../../贪心/README.md) 第一节）。

### 最短路 vs 动态规划

| 关系 | 说明 |
|---|---|
| **Floyd 是纯 DP** | `k` 是阶段，压在二维矩阵上（第五节） |
| **Bellman-Ford 是 DP 的逐轮松弛** | 轮数 = 阶段数 |
| **DAG 上的最短路 = 按拓扑序做一次 DP** | 有向无环图**不需要 Dijkstra** —— 拓扑序天然给出推进顺序，一趟 `O(V+E)` 就够了 |
| **图上的 DP 类问题** | 「恰好经过 `k` 条边的最短路」要把边数加进状态（[../../动态规划/README.md](../../动态规划/README.md)） |

### 最短路 vs 回溯

| | 最短路算法 | 回溯 |
|---|---|---|
| 目标 | **一个最优路径** | **枚举所有路径**（或所有解） |
| 复杂度 | 多项式 | 指数级 |
| 关系 | DFS 当然也能「找所有路径」，但要**最短的那条**就没必要枚举 —— 专门算法的复杂度低得多 | — |

⚠️ 边界情况：如果题目要「**第 k 短路**」或「**满足约束的所有路径**」，就不是本目录的算法能直接解决的了 —— 那属于**搜索 + 剪枝**（[../../回溯/README.md](../../回溯/README.md)）或 K 短路专门算法（Yen / A*）。

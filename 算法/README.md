# 算法地图（本目录索引）

> 本目录收「**语言无关、有独立原理层**」的通用算法；**具体语言的实现与工程用法留在对应语言目录**
> （[go/](../go/)、[java/](../java/)、[php/](../php/)、[linux/](../linux/)），两边互相引用。
>
> 目录内部按主题分成 **7 个二级目录**：`基础算法/`（复杂度 / 数据结构 / 查找与排序）、`动态规划/`、`贪心/`、
> `回溯/`、`字符串匹配/`、`图论算法/`（下含 `图的遍历/`、`最短路/`、`最小生成树/`）、`高级数据结构/`
> （位图与布隆过滤器 / 基数与频率估计）；[压缩算法.md](压缩算法.md) 不属以上任何一类，**留在本目录根下**。
>
> 这篇是本目录的索引，也是**全仓算法原理的入口**：—— 按「算法」复习时从这里进，按「技术栈」复习时从 [全仓知识点目录](../目录.md) 进。

## 四、收录门槛：一个知识点该不该进本目录

按这四条依次判：

1. **语言无关吗？** 只对某个语言 / 框架成立 → 归对应语言目录，那是**机制**不是算法（如 `context`、`Stream`、`channel`）；
2. **有独立原理层吗？** 能写出 ≥1 屏的原理（模型 / 参数 / 复杂度 / 优缺点 / 选型）→ 才值得独立成篇；
3. **≥2 个场景或语言会用到吗？** 只有一个组件用到的，跟着那个组件走；
4. 是某个**已成体系领域**的底座吗（GC / 密码学 / 数据库内核）？→ 留在该领域，不要搬散。

### 反过来：什么时候"实现"要拆出去

| 情况 | 处理 | 例 |
|---|---|---|
| 某语言的实现 / 工程用法 **≥1 屏**，且与该语言生态有关联 | **拆**：原理留本目录，实现进语言目录，**双向引用** | [限流算法.md](../分布式/限流算法.md) ↔ [../go/并发/限流器.md](../go/并发/限流器.md) |
| 实现只是原理的**短示例**（直译、不足 1 屏） | **不拆**，同篇放一起 | [位图与布隆过滤器.md](高级数据结构/位图与布隆过滤器.md) 里的 Go / Java 位图 |
| 是"**用某语言解决的具体问题**"（面试题、业务场景） | 写在语言目录 / **面试目录**，不进本目录 | [../面试/Go算法题.md](../面试/Go算法题.md)、[../go/并发/并发控制实战.md](../go/并发/并发控制实战.md) |

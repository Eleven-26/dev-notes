## 一、两者差的是「下一步先走哪条边」

DFS / BFS 不是两种数据结构，而是**同一张图上的两种访问顺序**；它们的差别只由**容器**决定：

| 维度 | DFS 深度优先 | BFS 广度优先 |
| --- | --- | --- |
| 口诀 | 一条路走到黑，走不通再退 | 一圈一圈往外扩 |
| 容器 | **栈**（递归调用栈或显式栈） | **队列**（FIFO） |
| 空间 | O(树高 / 路径长度) | O(**最宽一层的节点数**) |
| 能否保证最短（无权图） | ❌ 只保证「可达」，不保证「最近」 | ⭐ 保证：第一次到达即最短 |
| 典型用途 | 判环、拓扑排序、连通分量、回溯（全排列 / 子集 / 剪枝） | 最短路（无权）、层级遍历、邻域扩散、多源扩散 |
| 失败模式 | 递归过深 → 爆栈（见第五节实测） | 宽图 / 深解 → 队列吃内存 |
| 是否「回头」 | 会回溯，能携带路径状态 | 不回溯，只记最短信息 |

⭐ **遍历的本质是「顺序」，顺序必须画出来才看得清**。同一张图（一条 5 元环，边集 `0-1 1-2 2-3 0-4 4-3`，邻接表就按这个顺序插入）：

```text
        0
      /   \
     1     4
     |     |
     2 ─── 3

BFS（队列）   0 → [1 4] → [2 3]     层号即距离：dist = [0 1 2 2 1]
DFS（递归）   0 → 1 → 2 → 3 → 4     一条路钻到底，结果里没有「层」这个概念
DFS（显式栈） 0 → 4 → 3 → 2 → 1     ⚠️ 同一份邻接表，LIFO 把访问序整个反过来
```

> 三条顺序都来自本机实跑（`go vet` 通过后 `go run`）。读法：**点 4 的最短距离是 1**（`0→4`），BFS 第二轮就给出；递归 DFS 沿 `0→1→2→3→4` 走满 4 跳才碰到它——谁把「DFS 里的第几个」当成距离，谁就得到 4 这个错答案；而换成显式栈，4 反而第二个就被访问到。顺序由**容器**决定，不由「DFS」这个名字决定。

⭐ **BFS 为什么天然给出无权图最短路**：队列按层推进，结点第一次入队时的层数就是它到源点的边数；而更短的路径必然经过更早的层，那层已经在它之前处理完了。**DFS 没有这个性质**——它可能先钻一条十跳的路径抵达终点，然后再也不更新。

⚠️ 「BFS 一定比 DFS 快」是错的：两者访问同一张连通图的每条边都是 O(V+E)，**渐近复杂度相同**，差别在于内存画像、能否提前退出、以及是否需要最短性。DFS 常在「解很深很窄」或「找到的第一个解就够用」时更快退出。

## 二、树是图的特例：四种顺序只有「根什么时候被记」的差别

二叉树的前 / 中 / 后序是 DFS 的三种记录时机，**孩子访问顺序完全一样**，差别只在根的位置；层序才是 BFS。

| 顺序 | 记录时机 | 用途 |
| --- | --- | --- |
| 前序 Pre-order | 根 → 左 → 右 | 复制树、序列化、XML/HTML 深度优先遍历、自顶向下传参（如「父到子」的 depth） |
| 中序 In-order | 左 → 根 → 右 | ⭐ **BST 上得到升序**：范围查询、验证 BST、把树拉平成有序数组（对应 B+ 树叶子链表的作用） |
| 后序 Post-order | 左 → 右 → 根 | ⭐ 必须先算完孩子：删目录、释放依赖、求子树聚合值（size / sum / 高度）、编译器的表达式树求值 |
| 层序 Level-order | BFS | 打印分层、最短路径分层、地图「一公里内」扩散 |

本节所有输出都以这棵例子树为准（`3` 只有左孩子）：

```text
              1
            /   \
           2     3
          / \   /
         4   5 6
```

⭐ 把 DFS 想成「沿树的外圈走一圈」：每个节点被碰到三次（从左回来、从右回来、真正离开），三种顺序的差别**只是在哪一次碰它时把值写进结果**——所以代码上只是挪动一行：

```text
外圈走一圈的括号写法:  (1 (2 (4) (5)) (3 (6)))

前序 = 进入（左括号）时记  →  1 2 4 5 3 6
中序 = 左子树回来时记      →  4 2 5 1 3 6
后序 = 离开（右括号）时记  →  4 5 2 6 3 1
层序 = BFS 按层收集        →  [1] [2 3] [4 5 6]
```

⚠️ 树**不需要 `visited`**：树无环且父子方向唯一，标记反而是冗余开销。一旦把这段代码搬到「无向图」上，**没有 `visited` 就会在 u-v 之间来回死循环**——这是图遍历与树遍历唯一但最致命的区别（见第三节）。

### 2.1 递归版（三种顺序只差一行位置）

```go
func preorderRec(root *TreeNode, out *[]int) {
	if root == nil {
		return
	}
	*out = append(*out, root.Val) // ① 改这三行的先后顺序，就是前/中/后序
	preorderRec(root.Left, out)   // ②
	preorderRec(root.Right, out)  // ③
}
```

```java
static void preorderRec(TreeNode n, List<Integer> out) {
    if (n == null) return;
    out.add(n.val);              // ① 改成「递归之后再 add」是中序；「两次递归之后」是后序
    preorderRec(n.left, out);    // ②
    preorderRec(n.right, out);   // ③
}
```

### 2.2 迭代版：显式栈替代调用栈

三序里 **前序最容易**（弹出即记录），**中序要「一路向左」**，**后序用「变体前序反转」**（单栈最省事的写法）：

- 前序：弹出记录，**先压右、再压左**（栈是 LIFO，左先出才符合「左右」）。
- 中序：`cur` 不停往左压栈，压到空再弹、记录、转向右子树。
- 后序：按「根 → 左 → 右」的变体收集，最后整体反转 = 「左 → 右 → 根」。

⚠️ 后序另一种常见写法是「压 `nil` 哨兵」——**Go 里可以，Java 里不行**：`ArrayDeque` / `Stack` 都禁止 `null` 元素，照抄会直接 `NullPointerException`（实测踩过，见第七节代码注释）。

把例子树喂给前序迭代，栈的逐步变化（栈顶写在右边）：

```text
操作                栈(底 → 顶)    输出
压 1                1              -
弹 1，压 3、2        3 2            1
弹 2，压 5、4        3 5 4          1 2
弹 4（叶子）         3 5            1 2 4
弹 5（叶子）         3              1 2 4 5
弹 3，压 6          6              1 2 4 5 3
弹 6               -              1 2 4 5 3 6

⭐ 「右先压、左后压」就是为了让左孩子总在栈顶 —— 前序因此最好写。

中序：一路向左压到底，弹出时才记录，然后转向被弹节点的右子树
  压到底 1 2 4  →  弹 4 记 4
  弹 2 记 2，转 2 的右子树：压 5 → 弹 5 记 5
  弹 1 记 1，转 1 的右子树：压到底 3 6 → 弹 6 记 6，再弹 3 记 3
  输出 4 2 5 1 3 6
```

```go
func preorderIter(root *TreeNode) []int {
	out := []int{}
	if root == nil {
		return out
	}
	st := []*TreeNode{root}
	for len(st) > 0 {
		n := st[len(st)-1]
		st = st[:len(st)-1]
		out = append(out, n.Val)
		if n.Right != nil {
			st = append(st, n.Right) // ⭐ 右先压
		}
		if n.Left != nil {
			st = append(st, n.Left)
		}
	}
	return out
}

func inorderIter(root *TreeNode) []int {
	out := []int{}
	st := []*TreeNode{}
	cur := root
	for cur != nil || len(st) > 0 {
		for cur != nil { // 一路向左
			st = append(st, cur)
			cur = cur.Left
		}
		cur = st[len(st)-1]
		st = st[:len(st)-1]
		out = append(out, cur.Val)
		cur = cur.Right
	}
	return out
}
```

### 2.3 层序：每轮先取 `size` 快照 ⭐

层序最容易写错的地方是**本轮处理多少个**：入队会让队列长度不断变化，所以必须先快照。

```go
func levelOrder(root *TreeNode) [][]int {
	res := [][]int{}
	if root == nil {
		return res
	}
	q := []*TreeNode{root}
	for len(q) > 0 {
		size := len(q) // ⭐ 快照：本轮只处理这一层
		level := make([]int, 0, size)
		for i := 0; i < size; i++ {
			n := q[0]
			q = q[1:]
			level = append(level, n.Val)
			if n.Left != nil {
				q = append(q, n.Left)
			}
			if n.Right != nil {
				q = append(q, n.Right)
			}
		}
		res = append(res, level)
	}
	return res
}
```

逐轮看「快照 → 处理 → 下一层入队」，就明白 `size` 为什么必须在循环外取：

```text
轮 1  size=1  本轮队列 [1]        记 [1]      处理中 2、3 入队 → 队列变 [2 3]
轮 2  size=2  本轮队列 [2 3]      记 [2 3]    处理中 4、5、6 入队 → 队列最长到 3
轮 3  size=3  本轮队列 [4 5 6]    记 [4 5 6]  无孩子，队列清空
```

⚠️ 不写 `size` 快照、直接 `for q.Len() > 0 { 弹一个 }` 的写法，会把「层」这个概念丢掉——结果变成普通 BFS，只知道距离、不知道每层谁。**Java 侧同理**：`int size = q.size()`，且 `ArrayDeque` 上要用 `addLast/pollFirst`（或 `offer/poll`），别用 `pop` 配 `add` 混着当队列。

## 三、图上的 DFS：`visited`、连通分量、判环与拓扑

### 3.1 无向图：标记时机决定正确性

| 做法 | 后果 |
| --- | --- |
| **入队/入栈时**就标记 `seen` | ✅ 正确，每个点只进一次，边最多被看两次 |
| **弹出时**才标记 `seen` | ⚠️ 结果仍对，但同一节点可能多次入队，最坏队列膨胀 |
| 完全不标记 | ❌ 无向图上一条 `u-v` 边会让遍历在 u、v 之间无限来回 |

「无限来回」画出来是这样——无向边 `u-v` 在邻接表里就是两条有向记录 `adj[u]=[v]`、`adj[v]=[u]`：

```text
   u ⟷ v        邻接表: adj[u]=[v]  adj[v]=[u]

   不标记      : u → v → u → v → …              ❌ 在这条边上来回振荡，永远走不完
   弹出时才标记 : u → v → u(已见, 跳过)          ✅ 结果对，但 u 被重复入队过
   入队时就标记 : u✓ → v✓                        ✅ 每个点最多进队一次
```

⭐ `visited` 的三种实现取舍：`bool[]`（点有整数下标时最快，O(V) 空间）、`map/set`（点是无序 key 或稀疏时）、**原地改色/打标记**（如「岛屿问题」直接把 `1` 改成 `2`，省一份 `visited`，代价是破坏输入）。

### 3.2 有向图判环：必须三色，二色会误判 ⭐

```go
type Digraph struct {
	n   int
	adj [][]int // 有向图只加一条弧：addArc(u, v) 只写 adj[u]，不写 adj[v]
}

const (
	white = 0 // 未访问
	gray  = 1 // 在当前这条递归路径上（栈里）
	black = 2 // 已完成，它下面的子图都查过了
)

func (d *Digraph) hasCycle() bool {
	color := make([]int, d.n)
	var rec func(u int) bool
	rec = func(u int) bool {
		color[u] = gray
		for _, v := range d.adj[u] {
			switch color[v] {
			case gray:
				return true // ⭐ 灰遇灰 = 回到自己这条路径上的祖先 = 有环
			case white:
				if rec(v) {
					return true
				}
			}
		}
		color[u] = black
		return false
	}
	for i := 0; i < d.n; i++ {
		if color[i] == white && rec(i) {
			return true
		}
	}
	return false
}
```

颜色变化的过程只有画出来才看得清 —— 左边是要误判的菱形依赖，右边是真环：

```text
   菱形依赖（无环，D 被两条路径各到一次）        真环

            A                                       0
          /   \                                     ↓
         B     C                                    1
          \   /                                     ↓
            D                                       2 ──→ 回到 0，闭合

   弧表: A→{B C}  B→{D}  C→{D}               弧表: 0→{1}  1→{2}  2→{0}
```

三色在菱形上的时间线（灰 = 「在我当前这条路径上」）：

```text
   A灰 → B灰 → D灰 → D黑 → B黑 → C灰 → 看到 D 是「黑」= 后代早算完 ⇒ 不是环
                                                      → C黑 → A黑    ⇒ hasCycle = false ✅
   二色的同一时刻（只有 visited）：
   A✓ → B✓ → D✓ → B 回 → C✓ → 又看到 D✓ ⇒ 误报「有环」❌
```

⭐ **为什么二色（只有 `visited`）不够**：菱形依赖 `A→B→D`、`A→C→D` 里，`D` 会被两条路径各访问一次。二色实现看到第二次 `visited[D] == true` 就报「有环」，**这是假阳性**；三色里 `D` 第二次是 `black`（已完成后代），不算环。**只有指向「灰」的边才是环。**

错误实现与它只差几行，实测结果却差得很远（同一个 `Digraph`，弧表按 `A→{B C}`、`B→{D}`、`C→{D}` 插入）：

```go
// 二色版：把颜色数组换成 bool visited —— 菱形会被判成有环
func (d *Digraph) hasCycle2Color() bool {
	seen := make([]bool, d.n)
	var rec func(u int) bool
	rec = func(u int) bool {
		seen[u] = true
		for _, v := range d.adj[u] {
			if seen[v] || rec(v) { // ⭐ 「访问过」不等于「在当前路径上」
				return true
			}
		}
		return false
	}
	for i := 0; i < d.n; i++ {
		if !seen[i] && rec(i) {
			return true
		}
	}
	return false
}
```

> 实测：菱形 `hasCycle2Color = true`（❌ 假阳性）、`hasCycle3Color = false`（✅）；真环 `0→1→2→0` 两者都返回 `true`——**二色只在「无环图」上判错，所以测试用例很容易盖不住它**。

⚠️ 概念别混：JVM / Go GC 的「三色标记法」（白灰黑）与这里的三色判环**同名不同义**——前者用颜色表达「是否确认存活」，后者用颜色表达「是否在当前搜索路径上」。面试被连着问要分清（GC 侧见 [../垃圾回收/并发标记与写屏障.md](../垃圾回收/并发标记与写屏障.md)）。

### 3.3 拓扑排序：DFS 后序反转 vs Kahn（BFS 入度）

| 写法 | 原理 | 判环 | 适用 |
| --- | --- | --- | --- |
| DFS + 后序反转 | 每个点在后序（所有后继完成时）入列，整体反转即拓扑序 | 靠三色，遇到灰边 | 已经写了 DFS、要顺带拿 SCC / 关键路径 |
| **Kahn（BFS）** | 反复取出入度为 0 的点，删它的出边 | ⭐ 天然：最后 `order.size() < n` 即有环（环上点入度永不为 0） | 构建依赖、任务编排、DDL 外键顺序、包初始化顺序 |

拿一张 6 点的 DAG 把 Kahn 的「逐轮」画出来（本机实跑的输入与输出）：

```text
   弧表:      5→{2 0}   4→{0 1}   2→{3}   3→{1}
   初始入度:   0:2  1:2  2:1  3:1  4:0  5:0

   第 1 轮 [4 5]  → 删 5→2、5→0、4→0、4→1  ⇒ 入度 2:1→0、0:2→0、1:2→1
   第 2 轮 [2 0]  → 删 2→3                 ⇒ 入度 3:1→0（0 没有出边）
   第 3 轮 [3]    → 删 3→1                 ⇒ 入度 1:1→0
   第 4 轮 [1]    → 队空；收到 6 个点 = n  ⇒ 判定无环

   摊平成层级图（同一层内没有依赖，可并发执行）:

     5   4   →   2   0   →   3   →   1
```

> ⚠️ 每轮取出的是「当前入度为 0 的**全部**点」，这一批就是并行边界：CI 里同一层的任务可以并发跑，跨层必须等。少取一个（只取队首）拓扑序仍然合法，但白白串行化了一层。

⭐ **拓扑序不唯一**：同一张图，DFS 后序反转写法给出 `[5 4 2 3 1 0]`，Kahn 给出 `[4 5 2 0 3 1]`。实测逐条边校验 `pos[u] < pos[v]`，两个序都成立（`true true`）——所以「你的拓扑序和我的不一样」**不代表谁写错了**，只要求每条弧都满足前后续关系。

> ⭐ 记忆点：**拓扑排序只对 DAG 存在**；「一个工程要按什么顺序编译/启动」本质上就是一次 Kahn——Maven 模块依赖、Go 包 `init` 顺序、K8s 资源的 apply 顺序都是它。

## 四、BFS 的三个进阶变体

| 变体 | 做法 | 解决什么 |
| --- | --- | --- |
| **多源 BFS** | 把所有起点**一次性**灌进队列，再做分层扩散 | 多个火种同时扩散（腐烂的橘子）、多个仓库最近距离、地图上多个 POI 的最近归属 |
| **双向 BFS** | 从起点和终点各起一个 BFS，每轮扩展**较小**的那侧，交集即接通 | 状态空间大、分支因子 b、深度 d：复杂度从 `b^d` 降到约 `2·b^(d/2)`（单词接龙、迷宫两端已知） |
| **0-1 BFS** | 用**双端队列**：边权 0 的 `push_front`、边权 1 的 `push_back` | 边权只有 0/1 时不用堆，仍是 O(V+E) 拿到最短路 |
| 迭代加深（IDDFS） | 限制 DFS 的最大深度，逐层放宽 | 要 DFS 的空间（O(d)）又要 BFS 的最短性；代价是同一层被重复展开（常数约 `b/(b-1)`） |

变体的差别也全在「队列的形状」上：

```text
   ① 双向 BFS（起点 s、终点 t 都已知，分支因子 b、解深 d）

        s ── a ── b ── c ── d ── t
        └─ 正向扩 ─┘   ↑相遇   └─ 反向扩 ─┘
        单侧要展开 b^d 个状态；两侧各展开 b^(d/2) 个就会在中间撞上

   ② 0-1 BFS（边权只有 0 / 1，用双端队列代替优先队列）

        push_front ← 权 0 的邻居（距离不变，属于「同一层」）
        push_back  → 权 1 的邻居（距离 +1，排到后面）
        双端队列因此天然按距离单调，弹出顺序就是层序 —— 不需要堆，省下 O(log n)

   ③ 多源 BFS（所有起点一次性入队，之后照常按层推进）

        第 0 层队列: [s1 s2 s3]     ← 而不是分别从 s1、s2、s3 各跑一遍 BFS
        每轮仍取 size 快照，扩散一圈 = 一个时间单位（腐烂的橘子、最近仓库归属）
```

⚠️ **带一般正权重的图，普通 BFS 会算错**：BFS 的层数只在「每条边代价相同」时等于距离。有权重要走 Dijkstra（优先队列 + 松弛），有负权边走 Bellman-Ford / SPFA。这是「为什么 BFS 是最短路」最常见的边界误用。

## 五、复杂度与内存画像（本机实测）

两者时间复杂度都是 **O(V + E)**（邻接表；邻接矩阵是 O(V²)），差别全在**峰值内存**与**栈深**。

### 5.1 实测一：BFS 队列峰值 = 最宽一层，DFS 栈深 = 树高

对完全二叉树（节点数 `2^d - 1`）跑层序，记录队列长度峰值（Go 1.26.5，windows/amd64）：

```text
高度 10（节点    1023）：BFS 队列峰值     512，DFS 最大栈深 10，峰值/节点 = 50.05%
高度 16（节点   65535）：BFS 队列峰值   32768，DFS 最大栈深 16，峰值/节点 = 50.00%
高度 20（节点 1048575）：BFS 队列峰值  524288，DFS 最大栈深 20，峰值/节点 = 50.00%
```

⭐ 结论：**满二叉树的最后一层占掉一半节点**，所以 BFS 的队列峰值约为总节点数的 50%，而 DFS 栈深只有 20。「宽而浅」的树 / 图用 DFS 更省内存；反过来「深而窄」的（链状）用 BFS 更省，且不容易爆栈。

```text
   ① 宽而浅 —— 完全二叉树（峰值在最后一层）

            1                     DFS 栈深 = 树高 = 3
          /   \                   BFS 队列峰值 = 最后一层 = 4 个
        2       3
       / \     / \                ⭐ 2^h-1 个节点里最后一层占 2^(h-1) 个 ≈ 一半
      4   5   6   7

   ② 深而窄 —— 链状图（结论整个反过来）

        0 → 1 → 2 → … → 199999    DFS 栈深 = n（Java 默认栈实测 ~2 万层爆栈）
                                  BFS 队列峰值 = 1（每个点只有一个后继）
```

⚠️ 所以「DFS 省内存」只对**宽图**成立；深而窄的图里 DFS 既费栈又危险——这正是 5.3 语言差异要命的地方。选 DFS 还是 BFS，本质是在选「栈深 = 一条路径的长度」还是「队列 = 最宽一层」，**跟哪个更快无关**（渐近都是 O(V+E)）。

### 5.2 实测二：最短路只有 BFS 给得出

图 `0-1-2-3`（长路）加 `0-4-3`（短路），就是第一节画过的那条 5 元环：

```text
BFS 距离  : [0 1 2 2 1]     # dist[3] = 2，走 0→4→3
DFS 可达  : [true true true true true]（只判可达，不含距离）
连通分量数: 1
```

### 5.3 实测三：递归深度上限的语言差异 ⭐

同一段「链状图递归 DFS」，Go 与 Java 表现完全不同（JBR 17，Windows x64）：

```text
# Go：100 万节点长链，三色判环
递归深度 1000000 的三色判环：hasCycle=false，耗时 359.8629ms（Go 协程栈自动增长，未爆栈）

# Java：默认栈
递归在深度 22503 抛 StackOverflowError
20 万长链三色判环（递归）：StackOverflowError，耗时 3ms
20 万长链连通分量（显式栈）：分量 1 个，耗时 34ms

# Java：-Xss64m
递归在深度 4160284 抛 StackOverflowError
20 万长链三色判环（递归）：hasCycle=false，耗时 215ms
20 万长链连通分量（显式栈）：分量 1 个，耗时 43ms
```

> ⭐ 三条推论：
> **① Java 侧「递归 DFS」在生产图上有实际爆栈风险**（默认栈只扛得住 ~2 万层，且同机两次实测分别给出 10410 / 22503，说明**阈值不稳定、不能作为设计依据**）；深图要么 `-Xss` 加大（治标），要么改显式栈（治本，实测显式栈版本在默认栈下 34ms 跑完 20 万长链）。
> **② Go 递归可以走百万层**：协程栈初始小、按需增长，因此「递归写法更安全」——但栈内存会涨（默认上限 1GB），深递归仍是 OOM 候选，不是免费的。
> **③ 同一算法换语言，工程结论会变**：Go 里「直接递归」是合理的默认写法，Java 里「深图必须显式栈」是硬约束（对照 [../go/并发/goroutine.md](../go/并发/goroutine.md) 的栈增长与 [../java/JVM与垃圾回收.md](../java/JVM与垃圾回收.md) 的栈/堆内存）。

## 六、Go 实现：图的表示与四种遍历

```go
type Graph struct {
	n   int
	adj [][]int // ⭐ 邻接表：稀疏图的首选；邻接矩阵只在稠密 + 需要 O(1) 判边时用
}

func newGraph(n int) *Graph { return &Graph{n: n, adj: make([][]int, n)} }

func (g *Graph) addEdge(u, v int) {
	g.adj[u] = append(g.adj[u], v)
	g.adj[v] = append(g.adj[v], u) // 无向图加两条
}

// BFS：dist 同时充当 visited（-1 = 未访问）
func (g *Graph) bfsDist(src int) []int {
	const inf = 1 << 30
	dist := make([]int, g.n)
	for i := range dist {
		dist[i] = inf
	}
	dist[src] = 0
	q := []int{src}
	for len(q) > 0 {
		u := q[0]
		q = q[1:]
		for _, v := range g.adj[u] {
			if dist[v] == inf { // ⭐ 入队时标记，避免重复入队
				dist[v] = dist[u] + 1
				q = append(q, v)
			}
		}
	}
	return dist
}

// DFS 迭代版求连通分量：显式栈，深图不怕爆栈
func (g *Graph) components() int {
	seen := make([]bool, g.n)
	cnt := 0
	for i := 0; i < g.n; i++ {
		if !seen[i] {
			cnt++
			st := []int{i}
			seen[i] = true
			for len(st) > 0 {
				u := st[len(st)-1]
				st = st[:len(st)-1]
				for _, v := range g.adj[u] {
					if !seen[v] {
						seen[v] = true
						st = append(st, v)
					}
				}
			}
		}
	}
	return cnt
}
```

多源 BFS（腐烂橘子式扩散）的骨架——把全部起点一次入队，再按层推进：

```go
type cell struct{ r, c int }

q := []cell{}                 // ⭐ 多源：所有起点一次入队
fresh := 0
for r := 0; r < R; r++ {
	for c := 0; c < C; c++ {
		if grid[r][c] == 2 {
			q = append(q, cell{r, c})
		} else if grid[r][c] == 1 {
			fresh++
		}
	}
}
min := 0
dirs := [4][2]int{{-1, 0}, {1, 0}, {0, -1}, {0, 1}}
for len(q) > 0 && fresh > 0 {
	size := len(q) // 层快照
	min++
	for i := 0; i < size; i++ {
		cur := q[0]
		q = q[1:]
		for _, d := range dirs {
			nr, nc := cur.r+d[0], cur.c+d[1]
			if nr >= 0 && nr < R && nc >= 0 && nc < C && grid[nr][nc] == 1 {
				grid[nr][nc] = 2 // ⭐ 原地标记，省掉一份 visited
				fresh--
				q = append(q, cell{nr, nc})
			}
		}
	}
}
if fresh > 0 {
	min = -1 // 有橘子永远烂不到
}
```

> 实测输入 5×5 网格、两个初始腐烂点，输出 `全部腐烂所需分钟: 5 剩余新鲜: 0`；2000 节点 / 4 万条边的随机图，连通分量 `1` 个。

## 七、Java 实现：同一套逻辑的容器选型

```java
static List<List<Integer>> levelOrder(TreeNode root) {
    List<List<Integer>> res = new ArrayList<>();
    if (root == null) return res;
    Deque<TreeNode> q = new ArrayDeque<>(); // ⭐ ArrayDeque 当队列：add / poll
    q.add(root);
    while (!q.isEmpty()) {
        int size = q.size();                // ⭐ 快照本轮层宽
        List<Integer> level = new ArrayList<>(size);
        for (int i = 0; i < size; i++) {
            TreeNode n = q.poll();
            level.add(n.val);
            if (n.left != null) q.add(n.left);
            if (n.right != null) q.add(n.right);
        }
        res.add(level);
    }
    return res;
}

static List<Integer> postorderIter(TreeNode root) {
    List<Integer> out = new ArrayList<>();
    if (root == null) return out;
    Deque<TreeNode> st = new ArrayDeque<>();
    st.push(root);
    while (!st.isEmpty()) {
        TreeNode n = st.pop();
        out.add(n.val);
        if (n.left != null) st.push(n.left);  // ⭐ ArrayDeque 禁止 null，不能压哨兵（会 NPE）
        if (n.right != null) st.push(n.right);
    }
    java.util.Collections.reverse(out);       // 「根左右」变体反转 = 后序
    return out;
}

// Kahn 拓扑排序：order.size() < n 即有环
List<Integer> topoKahn() {
    int n = adj.size();
    int[] in = new int[n];
    for (int u = 0; u < n; u++) for (int v : adj.get(u)) in[v]++;
    Deque<Integer> q = new ArrayDeque<>();
    for (int i = 0; i < n; i++) if (in[i] == 0) q.add(i);
    List<Integer> order = new ArrayList<>(n);
    while (!q.isEmpty()) {
        int u = q.poll();
        order.add(u);
        for (int v : adj.get(u)) if (--in[v] == 0) q.add(v);
    }
    return order;
}
```

⚠️ **容器选型口径**（Java 侧很容易踩）：

| 需求 | 用 | 别用 |
| --- | --- | --- |
| 队列（BFS） | `ArrayDeque`（`add` / `poll`） | `LinkedList`（节点分配多、慢）、`Queue` 配 `pop`（`pop` 是栈语义） |
| 栈（DFS） | `ArrayDeque`（`push` / `pop`） | `Stack`（遗留同步类，性能差） |
| 存 `null` 或哨兵 | `ArrayList` / Go slice | `ArrayDeque` / `HashMap` 的 key（会抛异常或 NPE） |

## 八、怎么选：场景对照表 ⭐

| 我要解决 | 选 | 为什么 |
| --- | --- | --- |
| 两个结点是否连通 / 有几个连通块 | DFS（迭代显式栈） | 不需要最短性，栈/标记数组最省 |
| 无权图最短步数、最少转换次数 | **BFS** | 层数即距离，唯一正确选择 |
| 依赖先后顺序（编译、启动、建表） | Kahn（BFS 入度） | 天然输出层次 + 顺带判环 |
| 有向图是否有环 | DFS 三色 | 灰遇灰即环，二色会假阳性 |
| 全排列 / 子集 / 组合 / 数独 | **DFS + 回溯** | 需要「携带路径状态 + 撤销」，BFS 记不住整条路径 |
| 求子树聚合、删除整棵目录 | 后序 DFS | 孩子必须先算完 |
| 判断 / 修复 BST、输出有序序列 | 中序 DFS | BST 中序必升序 |
| 层级展示、按距离分波次 | 层序 BFS | 天然带「层」概念 |
| 状态空间巨大且解可能很深 | IDDFS 或双向 BFS | 平衡空间与最短性 |
| 带权图最短路 | Dijkstra（堆）/ 0-1 BFS | 普通 BFS 对带权图不成立 |
| GC 存活对象标记 | 原理上 DFS / BFS 都可 | ⭐ 标记阶段常用 **DFS**（内存峰值更低）；复制式 GC 里 **Cheney 是 BFS**、Fenichel-Yochelson 是 DFS，取舍见 [../垃圾回收/复制与分代回收.md](../垃圾回收/复制与分代回收.md) 与 [../垃圾回收/标记类GC算法.md](../垃圾回收/标记类GC算法.md) |

## 九、易错点速查

| 症状 | 原因 | 修法 |
| --- | --- | --- |
| 无向图遍历卡死 / 无限递归 | 忘了 `visited`，u-v 来回走 | 图上必带标记，且**入队时就标记** |
| 以为「DFS 先访问到谁，谁就离起点近」 | 访问序 ≠ 距离（第一节图里递归 DFS 走满 4 跳才碰到距离为 1 的点 4） | 要距离只用 BFS，别拿 DFS 的序去推断 |
| 换了实现（递归 ↔ 显式栈）后单测/快照挂掉 | 同一份邻接表，两种实现的访问序**互为逆序**（实测 `[0 1 2 3 4]` vs `[0 4 3 2 1]`） | 断言只校「集合相等 / 层号正确」，别把 DFS 的序写死进用例 |
| 判环把菱形依赖误报成环 | 只用二色 `visited` | 换三色：只有指向 **灰** 的边才是环 |
| 层序输出「层」不对 | 没先快照 `size` | 循环内先 `int size = q.size()` / `size := len(q)` |
| 后序迭代写不出来 | 想一条栈走到底 | 「根左右」变体 + 整体反转；或用 `prev` 记录上次弹出口 |
| 拓扑排序结果点数少于 n | 有环，入度永不归零 | 这是**判环信号**，不是 bug；先判环再产出 |
| Java 深图 `StackOverflowError` | 默认线程栈只扛 ~2 万层，且阈值随环境波动 | 改显式栈；线程池里还要给 worker 线程设 `-Xss` |
| Go 深递归 RSS 暴涨 | 协程栈按需增长不等于免费 | 限制深度 / 换显式栈 / 分批 |
| `ArrayDeque` 抛 NPE | 压了 `null` 哨兵 | 换可存 `null` 的结构，或改成「变体前序反转」 |
| BFS 算带权最短路出错 | 边权不等时层数 ≠ 距离 | 换 Dijkstra / 0-1 BFS |
| 网格 DFS 在大地图上崩 | 面积即深度（最坏 O(n) 层） | 改 BFS 或显式栈；LeetCode 岛屿类题的标准解法 |

## 十、延伸追问

- **DFS 和 BFS 的时间复杂度不是一样的吗，还选什么？** ⭐ → 渐近一样（O(V+E)），差的是**峰值内存画像**（BFS 装最宽一层、DFS 装一条路径）、**能否给出最短性**、**能否提前退出**、以及**是否需要路径状态**（回溯必须 DFS）。
- **为什么 BFS 能求最短路而 DFS 不能？** → 队列按层推进：节点首次入队时的层数就是最短距离；DFS 先探到的路径可能长得多，且它不会回头更新。⚠️ 前提是**边权相同**。
- **图上遍历和树上遍历最大的区别？** → 图有环，必须 `visited`；树无环不需要。忘标记会导致在一条无向边上无限来回。
- **三色标记为什么能判环，二色不行？** → 灰表示「在当前递归路径上」，指向灰的边就是回边 = 环；黑表示「已完成后代」，指向黑是菱形依赖不是环。二色把两者混为一谈就会假阳性。
- **为什么后序遍历适合做依赖处理？** → 它保证「孩子全部处理完才处理根」，天然对应拓扑序；编译构建、删目录、销毁依赖、表达式求值都是这个语义。
- **BFS 队列会不会爆内存？** → 会。满二叉树的最后一层就占一半节点（实测高度 20 的树队列峰值 524288）。「宽」的图 BFS 内存压力大于 DFS；反之深而窄的图 DFS 栈压力大。
- **递归改显式栈有什么代价？** → 每帧要自己保存「走到哪个孩子了」的状态，代码复杂度上升；非线性回溯（多分支、要撤销选择）尤其明显（对照 [../面试/Go算法题.md](../面试/Go算法题.md) 第二题「用栈消除递归」）。
- **有向图的拓扑排序有两种实现，选哪个？** → 只想拿顺序 + 判环 → Kahn（好写、层次直观、`order.size()<n` 即环）；已经在做 DFS / 需要更强信息（SCC、关键路径） → DFS 后序反转。
- **Java 里递归 DFS 生产可用吗？** ⭐ → 深图不可用：实测默认栈 ~2 万层就 `StackOverflowError`，而且阈值随环境/JIT 波动，不能当容量依据；`-Xss` 只是把问题推远。**线上代码优先显式栈**，Go 侧才允许直接递归（实测百万层不爆，359ms 跑完 100 万长链，但要盯 RSS）。
- **GC 的三色标记和这里的三色判环是一回事吗？** → 不是。同名不同义：GC 的颜色表达存活状态（用于并发标记 + 漏标分析），这里表达「是否在当前搜索路径上」。两处都被问到要能立刻区分。

> - **文中的 ASCII 图**逐条对过实测：第一节的三条顺序是同一张 5 元环（邻接表 `[[1 4] [0 2] [1 3] [2 4] [0 3]]`）跑出来的——递归 DFS `[0 1 2 3 4]`、显式栈 DFS `[0 4 3 2 1]`、BFS 距离 `[0 1 2 2 1]`；3.3 的逐轮入度变化与 `[4 5]→[2 0]→[3]→[1]` 的分层是 Kahn 程序的原始输出，两种拓扑序另用 `pos[u] < pos[v]` 逐条边校验（`true true`）。第二节/2.2/2.3 的图是例子树的推演，结果与 ① 的实测输出一致。

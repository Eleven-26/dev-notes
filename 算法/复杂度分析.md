## Q1. 时间复杂度是什么？为什么要关心它？

认识算法之前，先理解一个**概念**：什么是时间复杂度，以及它的表示方法。

时间复杂度是同一问题可用不同算法解决，而一个算法的质量优劣将影响到算法乃至程序的效率。算法分析的**目的在于选择合适算法和改进算法**。

在计算机科学中，算法的时间复杂度是一个函数，它**定性**描述了算法的运行时间。时间复杂度常用**大 O 符号**表述，且**不包括这个函数的低阶项和首项系数**。它不仅用于表示时间复杂度，也用于表示空间复杂度。

## Q2. 大 O 表示法怎么用？

O 后面的括号中有一个函数，指明某个算法的耗时/耗空间与**数据增长量**之间的关系，`n` 代表输入数据的量。

**三条规则**：

1. **只保留最高阶项** —— `n² + n + 1` → `O(n²)`
2. **去掉系数** —— `2n` → `O(n)`
3. **关注最坏情况**，同时也要知道平均情况与最好情况

> ⭐ 注意区分：`O` 描述的是**上界**（最坏保证），`Ω` 是下界，`Θ` 是紧确界。工程上说的"时间复杂度"通常默认指 O。

## Q3. 常见复杂度有哪些典型例子？

| 复杂度 | 含义 | 典型算法 |
|---|---|---|
| **O(1)** | 最低的时空复杂度，耗时/耗空间与输入数据大小无关，输入增大多少倍都不变 | 哈希查找（不考虑冲突）、数组按下标访问 |
| **O(log n)** | 数据增大 n 倍时，耗时只增大 log n 倍（以 2 为底：数据增大 256 倍，耗时只增大 8 倍），比线性还低 | 二分查找、平衡树查找 |
| **O(n)** | 数据量增大几倍，耗时也增大几倍 | 顺序遍历查找 |
| **O(n log n)** | 耗时增加为 n 乘以 log n；数据增大 256 倍时，耗时增大 256×8 = 2048 倍。**高于线性、低于平方** | 归并排序、快速排序（平均） |
| **O(n²)** | 数据量增大 n 倍时，耗时增大 n 的平方倍 | 冒泡排序（需扫描 n×n 次） |

**量级排序**：`O(1)` < `O(log n)` < `O(n)` < `O(n log n)` < `O(n²)` < `O(n³)` < `O(2ⁿ)` < `O(n!)`

> ⚠️ 数据量稍大时，`O(n²)` 与 `O(n log n)` 的差距会急剧放大：n = 10 万时，前者约 10¹⁰ 次操作、后者约 1.7×10⁶ 次，差 4 个数量级。

## Q4. 什么是摊还分析？它和平均复杂度有什么区别？

**要解决的问题**：某些操作偶尔很贵，大多数时候很便宜。只用"最坏单次代价"会过度悲观，于是引入**摊还（amortized）**：把一批操作的总代价摊到每个操作上。

**动态数组：为什么单次 O(n)、摊还 O(1)**

容量满时申请两倍空间、把全部元素拷过去——那一次确实是 O(n)。但按**倍数**增长时，扩容发生的间隔也按倍数拉开：

```text
第 k 次扩容：元素数 2^k，拷 2^k 个
总拷贝量   = 1 + 2 + 4 + … + n  <  2n        （等比级数，和由最后一项主导）
n 次插入总代价 = 拷贝 < 2n + 写入 n 次 ≈ O(n)   →  摊到每次插入 = O(1)
```

> 示意伪代码，只用于说明"为什么总量还是线性"，不是某个语言的具体实现。

**为什么"每次只多分配 1 个"不行**：那就变成满一次拷一次，总拷贝量 = 1 + 2 + 3 + … + n = **n(n+1)/2** → 总 O(n²)，摊还退化成 **O(n) 每次**。
⭐ 一句话：**倍数增长的全部意义，是把"总代价从 n² 拉回 n"**，它买的是总量的平摊，不是"那一次不卡"。

**摊到了哪些代价（必须一起说）**：**空间浪费**（扩容后平均约一半容量空着，倍数越大浪费越多 → 增长率调小或精确预留）、**尾延迟毛刺**（那一次 O(n) 拷贝不会消失，只是不常发生 → 实时链路预分配、大对象改用分块 deque/chunk）、**一次性大停顿**（rehash / 全量搬迁同理 → 见下面的渐进式）。

**渐进式 rehash 就是"主动摊还"**：字典从 m 个桶扩到 2m 个桶，一次性搬迁是 O(n)；改成"每次读写操作顺手搬几个桶"，代价被摊进后续 n 次操作，每次约 O(1)。**取舍是"一次性大停顿"换"持续小额成本"**：一次性搬迁适合有后台线程、能容忍停顿的进程；渐进式适合**单线程事件循环**（一次停顿 = 全服务卡住）和有严格 p99 要求的服务，代价是搬迁期间要查两张表。

> 典型实现：Redis dict 的渐进式 rehash、Go map 的增量扩容。**具体"每次搬几个桶""由谁触发"各版本不同，以官方文档/源码为准。** 结构层面的说明见 [数据结构.md](数据结构.md) 的散列表一节。
>
> ⚠️ 摊还分析的失效点：它保证的是**一批操作的总量**，不保证"任意起点的一段操作序列"都很便宜。压测时如果采样窗口正好盖住两次扩容，你会看到毛刺，而摊还结论看起来"被违反"了——那是采样问题，不是分析错了。

## Q5. 递归的复杂度怎么估？主定理的直觉是什么？

不看公式，只看递归树的三个问题：**每层分出几个子问题 / 规模缩小几倍 / 同一层加起来花多少钱**。层数由**最深那条路径**决定。

| 算法 | 每层代价 | 层数 | 递归树形状 | 结果 | 最坏原因 |
|---|---|---|---|---|---|
| 二分查找 | O(1)（只往一个方向递归） | log n（每次砍一半） | 一根斜线：每层一个点 | O(log n) | 没有最坏退化，只要数组有序 |
| 归并排序 | **O(n)**（同层所有段加起来就是 n 个元素） | log n（对半分，树平衡） | 满二叉树，宽度抵消深度 | O(n log n) | 结构上不会退化，代价恒定 |
| 快速排序 | **O(n)**（划分扫描整层） | **取决于划分**：均匀 → log n；极值 → n | 平衡树 or 一条退化的链 | 平均 O(n log n)，最坏 O(n²) | **层数失控**：每层切掉 1 个元素，树高变成 n |

```
归并（形状永远平衡）          快排·均匀划分            快排·每次取到极值
        n                 n                     n
      /     \             /    \                  \
    n/2     n/2         n/2    n/2                  n-1     ← 每层只少 1
    … 共 log n 层 …      … log n 层 …                 … 共 n 层 …
   → n × log n          → n × log n                  → n × n
```

⭐ **关键洞察**：快排和归并**每层代价都是 O(n)**，差距完全来自"层数"。所以快排的所有优化（随机 pivot、三数取中、深度上限转堆排）本质上都在**控层数**，而不是在降每层代价。

**主定理的定性版本**（不推公式）：比较"子问题数量带来的增长"和"根层合并代价"。

- 子问题总量涨得比根层快 → 结果由**叶子层**主导（形如 O(n^log_b a)，比如 a=2、b=2 时是 O(n)）。
- 根层涨得快 → 由**根**主导（比如每次只留一个子问题但根做 O(n) 工作）。
- 两边持平 → 多出一个 log 因子（形如 O(n log n)，归并就是这种）。
- ⚠️ 使用边界：这套直觉假设**各子问题规模相同**。划分极不均匀（如 1/9 与 8/9）时，层数按最深路径算，量级常不变但常数明显变大。

## Q6. 空间复杂度、原地排序与稳定性到底意味着什么？

**先分清三种"空间"**：输入本身、**输出**（排序结果不算额外空间）、**额外空间**（辅助数组、递归栈、计数桶、visited 标记）。"原地（in-place）"通常指额外空间 O(1)，放宽一点也接受 O(log n) 栈。

| 算法 | 额外空间 | 空间从哪来 | 什么时候成为问题 |
|---|---|---|---|
| 冒泡 / 选择 / 插入 | O(1) | 只有几个临时变量 | 时间太贵，不是空间 |
| 快排 | 平均 O(log n) | **递归栈** | 退化时栈深可达 O(n) → 栈溢出；嵌入式/小栈线程敏感 |
| 堆排 | O(1) | 原地建堆、原地下沉 | 缓存不友好、不稳定 |
| 归并 | O(n) | 临时数组 | 大对象、内存紧张、多路并发排序时最贵 |
| 计数 / 基数 / 桶 | O(k) / O(n+k) | 计数桶、分发桶 | k（值域）远大于 n 时反而更耗内存 |
| 图搜索 DFS/BFS | O(V) | 栈或队列 + visited | 超深图/宽图的 visited 数组 |

**稳定性的实际意义**（不是"学术性质"，是下游契约）：

| 场景 | 为什么必须稳定 |
|---|---|
| **多关键字排序** | 先按次要关键字排、再按主要关键字排；不稳定会把第一次的结果搅乱。（等价做法：一次排序 + 比较器里逐级 tie-break） |
| **外部排序的归并阶段** | 内存放不下，只能"分块内排序 + 多路归并"；归并必须稳定，否则各块合并后的次序不可预测，也没法靠"原始顺序"做增量 |
| **链表排序 / 需要保序的合并** | 归并排序在链表上既是稳定又只需 O(1) 额外空间，这是链表不用快排的常见原因 |
| **分页、日志、UI 列表** | 时间戳相同的记录要按写入顺序呈现；不稳定排序会让"翻页看到重复/漏项"这种诡异现象出现 |
| 反过来：不需要稳定 | 只为取极值/分组、元素等价次序无意义（如只按分数分档），此时可选常数更好的不稳定排序 |

> ⭐ 记忆点：**"稳定"是一种对下游的承诺**——凡是你之后还想依赖"上一次排好的顺序"的地方，就不能用不稳定算法。堆排序/快排不稳定是它们换来 O(1)/小常数的代价。

## Q7. 大 O 之外还有哪些陷阱？

**① 常数因子与 cache 局部性——同为 O(f(n)) 不等于同速**

| 对照 | Big-O 相同 | 实际差在哪 |
|---|---|---|
| 数组 vs 链表线性扫描 | 都 O(n) | 预取 vs 指针追逐（见 [数据结构.md](数据结构.md) 数组一节） |
| 快排 vs 归并 | 都 O(n log n) | 快排原地交换、归并要多份数组和拷贝；但归并最坏有保证 |
| B+ 树 vs 红黑树 | 都 O(log n) | 磁盘上"层数 = I/O 次数"，高扇出直接把次数压成常数级 |
| 装箱元素 vs 原始类型数组 | 都 O(n) | 每个元素一次间接寻址 + 缓存行里塞不进几个 |

> ⭐ 说法要精确：**Big-O 只描述增长趋势，n 不够大时常数项就是全部**。所以"这个实现更快"这种结论必须有实测支撑，不能靠 Big-O 推。

**② 平均情况 vs 最坏情况——线上事故几乎都出在最坏**

| 结构/算法 | 平均 | 最坏 | 触发条件 | 工程上的"逃生通道" |
|---|---|---|---|---|
| 散列表 | O(1) | O(n) | 冲突堆积、恶意构造碰撞键 | 控负载因子 + 扩容、桶内升级成树、哈希加扰动 |
| 快排 | O(n log n) | O(n²) | 划分持续取到极值 | 随机/三数 pivot + **深度上限转堆排** |
| 递归树深度 | O(log n) | O(n) | 同上 | 改写成显式栈 + 循环，或限制深度 |
| 跳表 | O(log n) | O(n) | 随机层数运气极差（概率极低） | 无保证，靠 p 与规模换稳定 |

答题落点：**"我看的是 p99 而不是平均值"**，并且能说清"我给最坏情况准备了什么兜底路径"——这正是 introsort / 渐进式 rehash 存在的原因。

**③ 数据规模未知时怎么判断"够不够快"**：先估 **n 的上界**（未来一年，不是今天），再对照粗略量级（按"每秒约 10⁸ 次简单操作"的心算口径，**只是数量级判断，不是性能承诺**）：

| n 量级 | 通常能过 | 通常吃力 |
|---|---|---|
| 10³～10⁴ | O(n²) 也没问题，别优化 | — |
| 10⁵～10⁶ | O(n log n) | O(n²)（≈10¹⁰~10¹²） |
| 10⁸～10⁹ | O(n) 且要注意常数/内存 | O(n log n) 也可能顶不住 |
| 更大 / 数据流 | 只能 O(n) 单遍 + 分片/预聚合/近似算法 | — |

**默认策略**：规模不明时先写"能过的最简实现"（一般就是 O(n log n) 或一次哈希遍历），跑起来拿到真实分布再针对热点优化——过早优化的收益常在常数项，而常数项要靠数据说话，且简单实现的正确性风险低得多。**反例**：在没有规模数据时比较两个同为 O(n log n) 的实现孰优孰劣，那属于"没有测量就下结论"；要结论就先测。

> ⭐ 一句话收口：**Big-O 用来排除"方向错了"的方案（n² 用在 10⁶ 上），常数与局部性用来在"方向都对"的方案之间挑（快排 vs 归并），最坏情况分析用来决定"线上会不会炸"。**

## 面试官会追问什么

- **时间和空间复杂度怎么权衡？** → 常见做法是**空间换时间**：哈希表、缓存、预计算都是这个思路；反之内存受限时用时间换空间，如用计算代替存储。
- **摊还复杂度和平均复杂度是一回事吗？** → 不是。摊还对**任意操作序列**都成立（是"这一批操作的最坏总量 ÷ 次数"），平均复杂度要对**输入/访问分布做假设**（见 Q4）。
- **动态数组不是每次插入都可能 O(n) 吗，为什么敢说 O(1)？** → 因为按倍数扩容时总拷贝量是等比级数，被最后一次扩容主导，n 次插入总量仍是 O(n)（见 Q4）。
- **不用公式怎么讲主定理？** → 递归树 = 每层代价 × 层数；比较"子问题数量增长快"还是"根层合并代价增长快"，就能定性判断结果由叶子主导还是由根主导（见 Q5）。
- **递归写的快排算原地排序吗？** → 严格说它的递归栈是 O(log n) 额外空间，"原地"只在平均意义上成立；一旦退化，栈深可到 O(n)，这是真实的栈溢出故障来源（见 Q6）。
- **为什么要区分稳定性？** → 多关键字排序时需要：先按次要关键字排、再按主要关键字排，稳定排序才能保住前一次的次序（见 Q6）。

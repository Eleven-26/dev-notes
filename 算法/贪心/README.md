## 一、核心思想

**本节要点**：贪心的三句话 —— 每步选「当前看起来最好」的、**选完不再反悔**、并指望这样能拼出全局最优。它的全部难度都压在第三句上。

| 要素 | 含义 | 关键点 |
|---|---|---|
| **局部最优选择** | 每步只在**当前候选**里挑最好的一个 | 「最好」按什么排 —— 这就是**贪心键** |
| **不回退** | 做过决策就不再撤销，也不重新考虑 | 所以复杂度通常只是「排序 + 一趟遍历」 |
| **期望全局最优** | 指望局部最优能拼出全局最优 | ⚠️ **这不是自动成立的，必须证明** |

⭐ **贪心最危险的地方**：它**失败时不报错**。DP 写错通常是答案偏大/偏小但不至于错得离谱，而贪心一旦选错键，会**安安静静地给出一个次优解**（见 [活动选择.md](活动选择.md) 第二节的三种排序键对照）。所以「**能不能贪**」这个问题，靠直觉判断是不可靠的。

## 二、适用条件

**本节要点**：贪心要成立必须同时满足两条性质 —— **贪心选择性质**（第一步的贪心选择属于某个最优解）与**最优子结构**（选了之后，剩下的问题仍是最优子问题）。两条缺一，贪心就可能给次优解。

### 贪心选择性质

「**每一小步的局部最优选择，都能成为某个全局最优解的一部分**」。

注意措辞：不是「局部最优一定是全局最优」（那太强，通常不成立），而是「**存在**一个全局最优解，包含这个局部选择」—— 也就是这个选择是**安全的**（safe move）。

这正是 [活动选择.md](活动选择.md) 里交换论证要证的东西：先按结束时间选出第一个活动，再证明**任何最优解都能改造成包含它的解**。

### 最优子结构

做出选择之后，**剩下的部分仍然是一个同类型的最优子问题**。

霍夫曼编码是这条的样板：合并了频率最小的两个节点之后，剩下的节点集仍是一个「构造最优前缀码」的问题（[霍夫曼编码.md](霍夫曼编码.md) 第二节）。

### 什么时候不能用

| 情况 | 为什么不行 | 出路 |
|---|---|---|
| **不满足贪心选择性质** | 局部最优拼不出全局最优 → **次优解** | 换 DP（[区间调度.md](区间调度.md) 第四节的带权版本就是典型） |
| **有后效性** | 当前选择会改变后续候选的状态 | 换 DP / 搜索 |
| **贪心键选错** | 问题本身能贪，但键不对 | 换键 —— 但**必须先用反例验证新键**（[活动选择.md](活动选择.md) 给了三种键的反例） |

⭐ **实用判据**：「**证不出来就别贪**」。贪心正确的证明通常只有一页纸（交换论证 / 割性质），如果你写不出这个证明，大概率它本来就不成立。

## 三、解题模板

**本节要点**：五步里第 2 步（选键）和第 3 步（证明）是全部难点 —— 第 2 步选错会得到错误的答案，第 3 步跳过则不知道自己错没错。

| 步骤 | 做什么 | 容易错在哪 |
|---|---|---|
| **1. 理解问题** | 明确目标（最大化什么）与约束（什么是「冲突」） | 把「冲突」的条件理解错 → 后面的键必然错 |
| **2. 选择贪心策略** | 决定**按什么排序**（贪心键）或用**什么优先队列** | 键选错 —— 而且错了**不报错**，只是答案次优 |
| **3. 证明正确性** | 交换论证 / 割性质 / 归纳法 | **跳过这一步**是最常见的错误（见第六节陷阱表第一条） |
| **4. 实现** | 排序 + 遍历，或优先队列 + 不断取极值 | 同权元素的 tiebreak 没定死，导致结果不可复现 |
| **5. 验证** | 小规模手算 + **拿反例去试着推翻它** | 只测「能过」的例子，没测「看起来该贪但其实不能」的输入 |

### ⭐ 第 2 步的关键：贪心键怎么找

贪心键**不是拍脑袋定的**，它通常来自「**看最后一步**」：

- 活动选择看「**最后一个活动什么时候结束**」→ 所以键是**结束时间**（早结束 = 给后面留出更多空间）；
- 霍夫曼看「**哪些节点最不常用**」→ 所以是**频率**（把最不常用的压到最深）；
- 区间合并看「**谁先开始**」→ 所以是**开始时间**（先开始的区间必须被覆盖掉）。

⭐ 找到键之后，**先自己构造反例试一遍**（能否用别的排序得到更好解）—— 这个动作能拦下大部分错误。

### ⭐ 第 4 步的关键：tiebreak 要定死

当键相同的元素有多个时，**选哪一个会影响输出**（虽然最优值相同）。做实测对照时要**显式定义 tiebreak**（比如「同权按原始下标」），否则每次运行结果都不同、无法与其它语言逐行比对。

## 四、经典问题

**本节要点**：贪心的题型不多，但**同一个问题在不同的约束下结论可能完全相反** —— 下表按「贪心键」归类。

| 问题 | 贪心键 | 为什么安全 | 在哪 |
|---|---|---|---|
| **活动选择** | 按**结束时间**升序 | 早结束 ⇒ 后面能放更多 | [活动选择.md](活动选择.md) |
| **区间合并** | 按**开始时间**升序 | 先开始的一定要被覆盖 | [区间调度.md](区间调度.md) |
| **最少点覆盖** | 按**结束时间**升序取点 | 同一个「留出最多空间」的道理 | [区间调度.md](区间调度.md) |
| **霍夫曼编码** | 每轮取**频率最小**的两个 | 最不常用的应该被压到最深 | [霍夫曼编码.md](霍夫曼编码.md) |
| **最小生成树** | Kruskal 按**边权**、Prim 按**离树最近** | 割性质 | [../图论算法/最小生成树/](../图论算法/最小生成树/) |
| **单源最短路** | Dijkstra 每轮取**当前距离最小**的点 | 非负权下「定稿即最终」（贪心 + 松弛） | [../图论算法/最短路/Dijkstra.md](../图论算法/最短路/Dijkstra.md) |
| **分数背包** | 按**单位价值**降序 | 物品可切分 ⇒ 先装性价比最高的 | ⚠️ 待补（本目录未落盘；与 `0-1` 背包的对照见 [../动态规划/背包问题.md](../动态规划/背包问题.md)） |

⚠️ **分数背包与 0-1 背包只差「能不能切分」，结论却完全相反**（前者贪心正确、后者必须 DP）—— 这是理解「贪心为什么需要证明」最好的入口。

## 五、正确性证明

**本节要点**：贪心的证明有固定套路，**交换论证**能覆盖九成场景。学它的目的不是应付，而是**发现自己贪错了**。

### 交换论证（本目录的主力工具）

思路固定为四步：

```text
① 任取一个最优解 OPT（假设它和贪心的第一步不一样）
② 把 OPT 里的某一步，换成贪心选择的那一步
③ 证明「换完之后不会变差」（代价不变或更优）
④ 结论：存在一个包含贪心选择的最优解 → 贪心的第一步是安全的 → 归纳到每一步
```

- [霍夫曼编码.md](霍夫曼编码.md) 第二节用它证明了「频率最小的两个必须是最深层的一对兄弟」；
- [活动选择.md](活动选择.md) 第二节用它证明了「按结束时间排序，第一个活动一定属于某个最优解」。

### 割性质（图论专用）

在图上，交换论证常以**割性质**的形式出现：**对任意一个把顶点分成两部分的「割」，横跨它的最小权边一定属于某棵最小生成树**。Kruskal 与 Prim 的安全性都由它保证（[../图论算法/最小生成树/Kruskal.md](../图论算法/最小生成树/Kruskal.md) 第三节）。

### 归纳法

适合「每轮都做同一个动作」的算法：证明**每一步加入的选择都是安全的**，由归纳传递到最终解。Prim 就是典型（每轮拉进来的边都是当前割上最小的）。

### 反证法

配合前两者使用：假设贪心得到的不是最优，推出与已知性质矛盾。

⭐ **实战建议**：如果三种方法**都写不出来**，这本身就是最强的信号 —— 说明这个贪心大概率是错的，该换 DP 了。

## 六、常见陷阱

**本节要点**：贪心的坑有个共同点 —— **代码跑得通、结果看着也像对的**，所以只能靠「证明」和「反例」发现。

| 陷阱 | 症状 | 怎么避免 |
|---|---|---|
| **未证明贪心正确** | 小数据过了，大数据次优 | ⭐ 动笔前先做交换论证；**证不出来就换 DP** |
| **排序关键字选错** | 答案稳定地偏小（拿不到最优） | 用第六节的「看最后一步」找键；**拿反例验证**（[活动选择.md](活动选择.md) 给了三种键的对照） |
| **局部最优 ≠ 全局最优** | 带权区间调度这类问题必错 | 先判断问题有没有「选择之间互相影响」的结构；有 → 换 DP |
| **优先队列用错**（最小堆 vs 最大堆） | 取出的极值方向反了 | 霍夫曼取**最小**（小顶堆）；Dijkstra 取**最小**（小顶堆）；别凭印象写 |
| **忽略问题约束** | 边界输入（空集、单个元素、全同权重）出错 | 专门测这几类边界（[霍夫曼编码.md](霍夫曼编码.md) 第五节列了四个边界，其中一个是真 bug） |

### 补一个隐形陷阱：同权元素的处理

贪心算法的输出常常**不唯一**（多个最优解）。如果要做跨语言/跨版本的逐行比对，**必须把 tiebreak 写死**，否则「两边都对但结果不同」，会误判成 bug。

## 七、与其他思想对比

**本节要点**：贪心与 DP 的差别只有一个字 —— **回不回头**；与回溯的差别是**要不要枚举全部解**。

### 贪心 vs 动态规划

| 维度 | 贪心 | DP |
|---|---|---|
| 决策方式 | 每步取当前最优，**不回头** | 枚举所有决策，**比较后**取最优 |
| 正确性 | 需要**证明**（交换论证 / 割性质） | 只要三性质成立就天然正确 |
| 复杂度 | 通常 `O(n log n)`（瓶颈在排序） | 通常 `O(n²)`、`O(nW)` 等 |
| 失败的样子 | ⚠️ **静默给出次优解** | 不会错，最多慢 |
| 典型 | 活动选择、霍夫曼编码 | 0-1 背包、LCS |

⭐ **判据：能证明贪心就用贪心**（省时间省空间），**证不出来就用 DP**。反过来做（先写 DP 再考虑能不能简化）是安全的；先贪再补证明是危险的。

### 贪心 vs 回溯

| 维度 | 贪心 | 回溯 |
|---|---|---|
| 搜索范围 | **只走一条路** | **穷举所有分支**（靠剪枝收窄） |
| 何时用 | 有安全性证明时 | 要枚举所有解，或找不到贪心性质时 |
| 复杂度 | 多项式 | 指数级（剪枝后可能可用） |
| 典型 | 区间调度 | 全排列、八皇后、数独（[../回溯/](../回溯/)） |

⭐ 三者其实是一条**取舍链**：能贪就贪 → 贪不了但要求最优值就 DP → 要求枚举所有解就回溯。

## 一、核心思想

**本节要点**：DP 凭什么成立 —— 下面三个性质**缺一不可**，而且它们各管一件事：无后效性管「状态怎么定义」、最优子结构管「转移方程能不能写」、重叠子问题管「值不值得用 DP」。

| 性质 | 说的是什么 | 它决定 |
|---|---|---|
| **最优子结构** | 大问题的最优解，能由**子问题的最优解**拼出来 | 转移方程**写不写得出来** |
| **无后效性** | 状态一旦确定，往后怎么走与「**怎么到达**这个状态」无关 | 状态**该怎么定义** |
| **重叠子问题** | 递归展开时，**同一个子问题会被反复求解** | **值不值得**用 DP |

### 最优子结构：拼得出来才算数

如果「子问题最优」拼不出「父问题最优」，就**不能**用 DP。之所以能拼，是因为子问题之间**互相独立**。

反例是路径类问题里的「最长简单路径」：从 `A` 到 `C` 经过 `B` 时，`A→B` 与 `B→C` 各自的最长路径可能**共用同一个顶点**，拼起来就不是合法路径了。而最短路径没有这个问题（正权下绕路只会更长），所以 Dijkstra 能用。

### 无后效性：状态里必须装够信息

它约束的是**状态定义**。如果「往后怎么走」还依赖「怎么来的」，说明状态漏了维度。

最典型的例子：**股票买卖**。只写 `dp[i] = 前 i 天的最大收益` 是**不够**的 —— 第 `i+1` 天能不能买，取决于「手上有没有股票」，而后者取决于之前**卖没卖过**。所以状态得写成 `dp[i][持股/不持股]`（甚至更细的「已买几次」）——**把「后效」塞进状态里，它就变成无后效了**。

### 重叠子问题：不重叠就别用 DP

如果子问题**互不重叠**，那连缓存都不需要 —— 直接分治（如归并排序、快排），DP 反而是负担。

⭐ 所以 DP 与分治的分界线不是「能不能拆子问题」，而是「**拆出来的子问题是不是被重复算的**」。

> 三者串起来的一句话：**无后效性 → 敢定义状态；最优子结构 → 敢写转移；重叠子问题 → 这笔账值得算。**

## 二、适用条件

**本节要点**：把「能不能用 DP」变成一条**有先后顺序的决策链** —— 先排除贪心，再检查后效性，最后看子问题重不重叠。

### 什么时候能用

三个条件**同时**满足：

1. 能把问题拆成**有限个**状态（状态数是可枚举的多项式量级，不是指数）；
2. 状态之间有**明确的转移关系**（`dp[i]` 由更小的 `dp[...]` 推出）；
3. 有**确定的边界**（能停下来的最小子问题）。

### 什么时候不能用

| 情况 | 症状 | 出路 |
|---|---|---|
| **有后效性** | 转移时发现「还需要知道路径细节」 | **扩状态**（把缺的信息加进维度，如股票买卖加「持股与否」）；实在加不下 → 换搜索 / 状态压缩 |
| **子问题不重叠** | 每个子问题只被算一次 | 用**分治**（归并排序、快排） |
| **贪心可证明正确** | 局部最优能推出全局最优 | 用**贪心**，别上 DP（如活动选择、霍夫曼编码） |
| **状态数爆炸** | 状态是指数级（如子集枚举） | 看能不能**状压**（`n ≤ 20` 量级），否则只能搜索 + 剪枝 |

### ⭐ 判断顺序：先贪心，后 DP

拿到题**不要**直接想 DP，按这个顺序过一遍：

```text
① 能贪心吗？   —— 能证明「局部最优 ⇒ 全局最优」就直接贪心（省一个维度）
        ↓ 不能
② 有后效性吗？ —— 有就把缺的信息塞进状态（扩维度）
        ↓ 没有
③ 子问题重叠吗？—— 重叠就用 DP；不重叠用分治
```

**`0-1` 背包就是①被卡住的经典例子**：分数背包（物品可切分）按单位价值贪心就是对的，但 `0-1` 背包不能切分，贪心会选出「性价比最高但装不下」的组合 —— 这一步的对照实验在 [背包问题.md](背包问题.md) 第一节。

## 三、解题模板

**本节要点**：五步的顺序**不能乱**，尤其第 1 步和第 4 步 —— 状态定义错了后面全错，遍历顺序错了代码能跑但答案是错的。

| 步骤 | 做什么 | 容易错在哪 |
|---|---|---|
| **1. 定义状态** | 用一句**中文**说清 `dp[i]` / `dp[i][j]` 的含义（含「前 `i` 个」「以 `i` 结尾」这类限定） | 维度不够（漏了「持股」「还剩几次」）→ 转移写不出来 |
| **2. 写转移方程** | 枚举**最后一个决策**，写出 `dp[i] = max/min(…)` | 漏掉「不选」这一支；`i-1` 越界 |
| **3. 初始化边界** | 定清 `dp[0]`、`dp[0][*]`、`dp[*][0]` 的含义 | 边界写成 0 还是 `∞` 取决于求 max 还是 min |
| **4. 确定遍历顺序** | ⚠️ **不是随意的** —— 既要保证「用到的状态已算好」，又要保证「每个元素只用一次」 | 0-1 背包压一维时**必须逆序**、完全背包**必须正序**（见 [背包问题.md](背包问题.md) 第三节） |
| **5. 返回答案** | 不一定是 `dp[n]` | 可能是 `max(dp[0..n])`（如 LIS 要看「以谁结尾」的最大值） |

### ⭐ 第 1 步的自检：把状态读一遍

定义完状态后，**用中文把这个句子读出来**：

```text
dp[i][j] = 前 i 个物品、背包容量为 j 时能装下的最大价值
```

读得通 → 状态定义合格；读起来别扭（如「`dp[i]` 表示前 i 个的最优解」——「最优解」是什么？）→ 回去重定义。

### ⭐ 第 4 步的自检：数组是「读旧写新」还是「读新写新」

一维滚动数组下，遍历方向决定了「本轮的更新会不会被本轮后续用到」：

- **每个元素只能用一次**（`0-1` 背包）→ 让本轮不再碰已更新的位置 → **逆序**；
- **每个元素可用多次**（完全背包）→ 就是要让它接着被用 → **正序**。

这条判据比死记「逆序 / 正序」更可靠，实测对照见 [背包问题.md](背包问题.md) 第三、四节。

## 四、经典问题

**本节要点**：DP 的题型很多，但**状态定义**的套路只有几类 —— 按「状态是什么」分类，比按题目名背要省力得多。

| 类型 | 状态长相 | 代表问题 | 在哪 |
|---|---|---|---|
| **线性 DP** | `dp[i]` = 前 / 以 `i` 结尾 | LIS、最大子段和 | [LIS.md](LIS.md) |
| **区间 DP** | `dp[i][j]` = 区间 `[i, j]` 上的最优 | 最长回文子序列、矩阵连乘 | — |
| **双序列 DP** | `dp[i][j]` = 两个前缀之间 | LCS、编辑距离 | [LCS.md](LCS.md) |
| **背包 DP** | `dp[i][j]` = 前 `i` 个物品、容量 `j` | 0-1 / 完全 / 多重背包 | [背包问题.md](背包问题.md) |
| **状态机 DP** | `dp[i][状态]` | 股票买卖、打家劫舍 | ⚠️ 待补 |
| **状压 DP** | `dp[集合的位掩码]` | TSP、`n ≤ 20` 的覆盖问题 | ⚠️ 待补 |

本目录已交付的三篇：

- [背包问题.md](背包问题.md) —— **DP 第一站**。为什么 `0-1` 不能贪心、一维数组为什么 `0-1` 逆序而完全背包正序（两种写错的结果都实测打出来了）、多重背包的二进制拆分；
- [LCS.md](LCS.md) —— **二维 DP 的样板**。两个串各占一维、逐格推演与回溯出子序列、空间优化「方向不能反」、与编辑距离的关系、⚠️ 子序列 ≠ 子串；
- [LIS.md](LIS.md) —— **同一问题的两种解法**。`O(n²)` 直译 DP 与 `O(n log n)` 的「`tails` + 二分」；⚠️ `tails` 里存的**不是**答案序列（给了反例）。

**还没写的（已在上面表格标记）**：编辑距离（双序列 DP 的第二个样板）、股票买卖（状态机 DP 的入口）。⚠️ 这两篇尚未落盘，**本篇不留链接**（避免断链），写完会回补。

## 五、空间优化

**本节要点**：优化只有两个动作 —— 砍掉「用不到的旧行」（滚动数组），或把「集合」编成整数（状态压缩）。**但必须先有正确的二维版**。

### 滚动数组：只留用得着的那几行

观察转移方程**只依赖哪些行**：

- 只依赖上一行（`dp[i-1][*]`）→ 二维**压成一维**；
- 只依赖左上 / 上 / 左三个格子 → 可以连一维都省，只留常数个变量（如编辑距离只留三个滚动变量）。

压维之后**遍历方向立刻变成关键**（见第三节第 4 步）：`0-1` 背包要逆序、完全背包要正序 —— 这不是记忆题，而是「本轮更新能不能被本轮再读」的直接推论。

### 状态压缩：把集合编成二进制

当状态的「维度」本身是个**集合**（哪些点走过了、哪些数选过了），用位掩码表示：

```text
dp[mask][i] = 已访问点集为 mask、当前停在点 i 的最小代价     // TSP
```

代价是状态数 `2^n × n` —— 所以只适合 `n` 在 20 上下的小规模。**这不是省空间，而是让「不可枚举的状态」变得可枚举。**

### ⭐ 铁律：先写二维版，再压

压维后的代码**更短但更难查错** —— 遍历方向写反、或者不小心复用了本行的值，都会**静默给出错误答案**（不报错、不崩溃）。

所以流程固定为：

```text
① 写二维版 → ② 小数据上跑通、确认真对 → ③ 压成一维 → ④ 与二维版逐值比对
```

本项目就是这么做的：先让两版在**同一组随机数据上互校**，一致之后才把一维版写进正文（见 [背包问题.md](背包问题.md) 第六节、[LCS.md](LCS.md) 第三节）。

## 六、常见陷阱

**本节要点**：下面三个是 DP 里**最高频**的错误 —— 共同点是**代码能跑、结果错了**，所以只能靠「对照验证」发现，不能靠编译器。

| 陷阱 | 症状 | 根因 | 怎么避免 |
|---|---|---|---|
| **遍历顺序错** | 压维后答案偏大 / 偏小，但二维版是对的 | 本轮更新被本轮后续读到了（或该读到却读不到） | 用第三节的判据判断「读旧写新 / 读新写新」；**与二维版逐值比对** |
| **边界没处理** | 结果里出现「不可能的极值」，或下标越界 | `dp[0]` 的语义没定清；求 min 时边界写成 0（应为 `∞`） | 明确写出 `dp[0]` 的中文含义；min 问题用足够大的哨兵 |
| **状态定义不清** | 转移方程写不出来，或写出来是错的 | 维度不够（漏了「还剩几次」「持没持股」） | 第 1 步的中文自检；写不出转移就回去加维度 |

### 还有一类「隐形陷阱」：只算数据、不算代价

DP 求出的往往只是**数值**（最大价值、最长长度）。真要用到工程里，还得把**解的本身**还原出来：

- 回溯 DP 表（记下每个状态是从哪来的）—— 见 [LCS.md](LCS.md) 第二节的回溯；
- 或者额外维护一张 `choice` / `next` 表（最短路里的 `prev`、Floyd 的 `next` 矩阵是同一个手法）。

⚠️ **只打印最优值就以为做完了**，是 DP 代码最常见的「看起来对、用起来不对」。

## 七、与其他思想对比

**本节要点**：DP 与贪心、回溯**经常能解同一道题**，区别不在「能不能用」，而在**要不要回头**和**要不要算全部**。

### DP vs 贪心

| 维度 | 贪心 | DP |
|---|---|---|
| 决策方式 | 每步取**当前最优**，**不回头** | 枚举**所有**决策，**比较后**取最优 |
| 正确性依据 | 需要**证明**（交换论证 / 切分定理） | 天然正确（只要三性质成立） |
| 复杂度 | 通常 `O(n log n)`（排序主导） | 通常 `O(n²)`、`O(nW)` 等 |
| 失败的样子 | **静默给出错误答案** | 不会错，最多**慢** |
| 典型 | 活动选择、霍夫曼编码（[../贪心/](../贪心/)） | `0-1` 背包、LCS、LIS |

⭐ **实用判据：能证明贪心就用贪心，证不出来就用 DP。** 「证不出来」是最强的信号 —— 贪心失败时不会报错，只会安静地给你一个错的答案。

### DP vs 回溯

| 维度 | 回溯 | DP |
|---|---|---|
| 目标 | **枚举所有解**（或找第一个可行解） | 求**一个最优值** |
| 重复计算 | 会重复（除非加记忆化） | 天然不重复（每个状态算一次） |
| 状态空间 | 指数级，靠**剪枝**活下来 | 多项式级，靠**状态合并**活下来 |
| 典型 | 全排列、八皇后、数独（[../回溯/](../回溯/)） | 背包装满、最长公共子序列 |

⭐ 两者其实**是同一个东西的两面**：给回溯加一张 **`memo` 表**（记下「这个状态已经算过了」），它就变成了**记忆化搜索** —— 也就是 DP 的**递归写法**。区别只在于：

- 递推版（DP）：先算小状态，**自底向上**填表；
- 记忆化搜索：从大问题出发递归，**自顶向下**按需计算。

同一份状态与转移，两种写法**答案必然一致**（[LIS.md](LIS.md) 第六节就实测了两种解法在同一输入上的互校）。

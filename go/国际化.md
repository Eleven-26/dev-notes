## Q1. Go 官方怎么做国际化本地化？gotext 方案的整体结构是什么？

**来源**：`BV12qjA6aErF p=24` B站 Go 面试真题 · 时长 12分30秒
**考察意图**：考"知不知道官方方案长什么样"。官方方案不是自己写 `map[lang]map[key]string`，而是 **`message.Printer` 负责运行时输出、`language.Tag` 负责语种识别、`gotext` 负责编译期抽取与生成**；要能讲清三者分工和 `locales/` 目录结构。

### 一、要解决的问题：同一句话，不同语种

```go

package main

import (
	"golang.org/x/text/language"
	"golang.org/x/text/message"
)

// 消息只写一次（源语言），输出什么语种交给 Printer 决定
func check(p *message.Printer) {
	p.Printf("位置错误\n")
}

func main() {
	check(message.NewPrinter(language.SimplifiedChinese)) // 位置错误
	check(message.NewPrinter(language.English))           // invalid position（翻译来自 catalog）
}
```

关键点：**业务代码里只写一次消息，语种由 `message.Printer` 持有的 `language.Tag`(locale) 决定**——而不是到处写 `if lang == "zh"`。翻译内容来自编译期生成的 catalog（Q2 的三步工作流）；**没有 catalog 时两边都会输出源文**，这也是联调时"翻译没生效"最常见的原因。

### 二、三块拼图

| 组件 | 包 / 工具 | 职责 |
|---|---|---|
| 运行时输出 | `golang.org/x/text/message` | `message.NewPrinter(tag)` 造打印器，翻译表由 `message.DefaultCatalog` 提供 |
| 语种标签 | `golang.org/x/text/language` | `language.SimplifiedChinese`(zh-Hans)、`language.English`、`language.Make("zh-CN")` |
| 编译期工具 | `golang.org/x/text/cmd/gotext` | 抽取源码里的消息 → 生成待翻译文件 → 生成 catalog Go 代码 |

> 用 x/text 而不是自己糊一个 map 的价值在于：语言匹配（`zh-CN` 命中 `zh-Hans`）、复数规则、数字/日期本地化格式，官方都实现好了。

### 三、工程目录结构（gotext 的默认约定）

```

translation/                       # 专放翻译相关东西的包
├── translation.go                 # 只有一个 //go:generate 标记
├── catalog.go                     # generate 产物（不要手改）
└── locales/                       # -dir 默认值就是 ./locales
    ├── zh/
    │   ├── out.gotext.json        # extract 产物：待翻译清单，每次覆盖
    │   └── messages.gotext.json   # 翻译成果，会被 import 回去参与生成
    └── en/
        └── ...
```

两条命名规则直接决定了工作流：

- **`out.gotext.json`**：`out` = 发出去（发给翻译人员）。`OutPattern` 默认 `{{.Dir}}/{{.Language}}/out.{{.Ext}}`，**重新 extract 会整份覆盖**；
- **`messages.xxx.json`**：gotext 只 import 匹配 `messages\.(.*)\.json$` 的文件，所以翻译成果必须**另存为 `messages.gotext.json`** 才能被吃回去。

### 四、运行时怎么挑语种

拿 `Accept-Language`、Cookie 之类做语言协商，再用 `message.Printer` 输出（这段是官方 `cmd/gotext/examples/extract_http` 示例里的写法）：

```go

var matcher = language.NewMatcher(message.DefaultCatalog.Languages())

func Generize(w http.ResponseWriter, r *http.Request) {
	lang, _ := r.Cookie("lang")
	accept := r.Header.Get("Accept-Language")

	tag := message.MatchLanguage(lang.String(), accept) // 多个候选里挑最匹配的
	p := message.NewPrinter(tag)

	p.Fprintf(w, "Hello %s!\n", r.Header.Get("From"))
}
```

### 面试官会追问什么

- **为什么不用 `map[string]map[string]string`？** → 只解决了字符串替换，复数（`1 apple / 2 apples`）、语言回退、数字格式全都要自己写，x/text 已经内置。
- **源语种（中文）需要翻译吗？** → 不需要。merge 时会自动把 `translation` 填成原文，并标记 `Fuzzy` + `Copied from source`。
- **运行时怎么知道用户要哪种语言？** → HTTP 场景解析 `Accept-Language`，配合 `message.MatchLanguage` / `language.NewMatcher` 做匹配，不要求精确命中。

## Q2. gotext 的完整工作流怎么走？（extract → 翻译 → generate）

**来源**：`BV12qjA6aErF p=24` B站 Go 面试真题 · 时长 12分30秒
**考察意图**：考能不能真的跑通这条链路——**抽取、翻译、生成、blank import** 四步缺一不可；只会 `p.Printf` 写代码但没跑过 `go generate` 的人，答不到 `init()` 挂 catalog 这一层。

### 一、装工具、加依赖

```bash

go install golang.org/x/text/cmd/gotext@latest   # 装到 $(go env GOPATH)/bin
go get golang.org/x/text                          # 项目依赖 message / language
gotext help                                       # 就四条命令，文档很薄
```

| 命令 | 作用 |
|---|---|
| `gotext extract <pkg>*` | 从源码抽取消息 |
| `gotext update <pkg>* [-out <file>]` | **一整套流程**：extract + import + merge + export（+ 生成） |
| `gotext generate <pkg> [-out <file>]` | 只根据现有翻译生成 catalog 代码 |
| `gotext rewrite <pkg>` | 一次性把 `fmt.*` 调用改写成 `message.Printer` 调用 |

| 全局参数 | 作用 | 默认值 |
|---|---|---|
| `-srclang` | 源语种 | `en-US` |
| `-lang` | 语种列表（决定生成哪些 locale 目录） | `en-US` |
| `-dir` | 翻译文件根目录 | `locales` |
| `-out` | 生成的 Go 文件路径，为空则输出到 stdout | 空 |
| `-tags` | 构建 tag | — |

三步工作流的命令形态（`update` = extract + import + merge + export + generate，平时一条 `update` 就够，CI 里常拆成两步执行）：先抽取得到 `locales/<lang>/out.gotext.json`，人工翻译后另存 `messages.gotext.json`，最后生成 `catalog.go`。

```bash

gotext -srclang=en -lang=en,zh extract ./...                   # ① 抽取
gotext -srclang=en -lang=en,zh -out=catalog.go generate ./...  # ③ 生成（② 是人工翻译）
```

### 二、第一步：标记并抽取（extract）

标记方式就是**把 `fmt` 换成 `message.Printer`**，但有硬限制：抽取器在 `seedEndpoints()` 里**只硬编码了三个方法**——`Printf`、`Sprintf`、`Fprintf`，全都带格式串；`Print`、`Println` 之类不会被采集。而且抽取器要求包里 import 了 `golang.org/x/text/message`，否则直接报 `pipeline: golang.org/x/text/message is not imported`。

```go

package translation

// 标记：gotext 靠它驱动；不带包参数时默认处理当前目录（官方 sample 就是这么写的）
//go:generate gotext -srclang=en -lang=en,zh -out=catalog.go update

import "golang.org/x/text/message"

func Check(p *message.Printer, pos int) {
	p.Printf("位置错误")                        // ✅ 会被采集
	p.Sprintf("字段 %s 不合法", "id")            // ✅ 会被采集
	// p.Println("位置错误")                    // ❌ 不会被采集（无格式串的方法不支持）
	// fmt.Printf("位置错误")                   // ❌ 不认 fmt
}
```

```bash

go generate ./...    # 触发上面那行 go:generate；等价于在消息所在包目录下手工执行：
gotext -srclang=en -lang=en,zh -out=catalog.go update
```

执行后 `locales/en/out.gotext.json`、`locales/zh/out.gotext.json` 被生成（源语种 + `-lang` 列表里的每个语种各一份），内容是这种结构：

```json

{
    "language": "zh",
    "messages": [
        {
            "id": "Hello {From}!",
            "message": "Hello {From}!",
            "translation": "",
            "placeholders": [
                {
                    "id": "From",
                    "string": "%[1]s",
                    "type": "string",
                    "argNum": 1,
                    "expr": "r.Header.Get(\"From\")"
                }
            ]
        }
    ]
}
```

注意 `id` 是把 `%s` 规范化成 `{From}` 之后的结果，**它是翻译表的主键**，所以**源码里的格式串不能随便改**，改了等于换了一条新消息，旧翻译会失效。

### 三、第二步：翻译，另存为 `messages.gotext.json`

翻译人员只需要填 `translation` 字段：

```json

{
    "id": "位置错误",
    "message": "位置错误",
    "translation": "invalid position"
}
```

填完**另存为 `locales/zh/messages.gotext.json`**（源语种那份留空即可）。原因在 Q1 讲过：gotext 只 import `messages.*.json`，`out.gotext.json` 下次 extract 还会被覆盖，**不能拿 out 文件当唯一成果**。

> **关于 `.po` / `.xliff`**：gotext CLI **没有 `-format` 参数**，`pipeline.Config` 里虽然预留了 `Format`（XMB 默认，另有 GetText/XLIFF/L20n/GoText），但源码里 `- handle different file formats (PO, XLIFF)` 至今仍是 TODO，import 也只解析 JSON。所以给专业翻译团队时，要么直接给 JSON，要么自己写脚本在 JSON ↔ `.po`/`.xliff` 之间转（转回来文件名必须带 `messages.` 前缀）。

### 四、第三步：生成 catalog，然后 blank import

```bash

gotext -srclang=en -lang=en,zh -out=catalog.go generate
```

产出的 `catalog.go`（取自官方生成模板）核心就一个 `init()`：

```go

import (
	"golang.org/x/text/language"
	"golang.org/x/text/message"
	"golang.org/x/text/message/catalog"
)

func init() {
	dict := map[string]catalog.Dictionary{
		"en": &dictionary{index: enIndex, data: enData},
		"zh": &dictionary{index: zhIndex, data: zhData},
	}
	fallback := language.MustParse("en-US")
	cat, err := catalog.NewFromMap(dict, catalog.Fallback(fallback))
	if err != nil {
		panic(err)
	}
	message.DefaultCatalog = cat   // ← 翻译表挂到默认 catalog
}
```

**所以主程序里只要 blank import 这个包，翻译就生效了**——不需要（也无法）显式调用任何函数，靠的是 `init()` 的副作用：

```go

import (
	_ "your/app/translation" // 只为触发 init()：message.DefaultCatalog = cat
)
```

没翻译到的条目不会报错，会按 `catalog.Fallback(fallback)` 落到源语种。

### 面试官会追问什么

- **为什么 `import _` 就够了？** → 生成文件把 catalog 赋给 `message.DefaultCatalog` 写在 `init()` 里，import 触发包初始化即完成注册。
- **`generate` 和 `update` 什么区别？** → `update` = extract + import + merge + export（+ 生成），开发期用；`generate` 只读现有翻译生成代码，适合 CI（翻译由另一个流水线管）。
- **改了源码里的格式串会怎样？** → `id` 变了，被当成新消息，generate 时会打 `Missing entry` 警告并回退源语种。

## Q3. 用 gotext 最容易踩哪些坑？

**来源**：`BV12qjA6aErF p=24` B站 Go 面试真题 · 时长 12分30秒
**考察意图**：这题考"有没有真用过"。gotext 文档极薄、行为版本敏感，讲得出坑的人一定是落地过的；答不出坑的往往只是看过 `p.Printf` 的示例。

### 一、方法名不对，抽取就是空的

抽取器只认 `*message.Printer` 的 **`Printf` / `Sprintf` / `Fprintf`** 三个方法（源码 `seedEndpoints()` 里硬编码）。写 `p.Println("...")`、`p.Print("...")` 或者图省事继续用 `fmt.Printf`，**一个字都抽不到，而且没有任何报错**——这是最容易闷声踩的坑。

### 二、必须配合 `go generate` 使用

`gotext` 是给 `go:generate` 调用的工具，不是拿来单独跑着玩的：

```go

//go:generate gotext -srclang=en -lang=en,zh -out=catalog.go update
```

单独执行 `gotext` 只会打出一份很简略的帮助；`gotext help extract` 也只有两行用法。**真正可参考的是源码里的示例**：`$GOMODCACHE/golang.org/x/text@<ver>/cmd/gotext/examples/`（`extract`、`extract_http`、`rewrite` 三个可直接跑的样例）。

### 三、`out` 文件会被覆盖，成果必须另存

- `locales/<lang>/out.gotext.json` 每次 extract **整份重写**（翻译进度会被冲掉）；
- 翻译成果必须落在 `locales/<lang>/messages.gotext.json`，因为 CLI 的 import 正则是 `messages\.(.*)\.json$`；
- `catalog.go` / `catalog_gen.go` 是生成物，**手改下次生成就没了**，应该加进 `.gitignore` 或标记为 generated。

### 四、版本与执行目录很敏感

- 抽取链路依赖 `golang.org/x/tools/go/loader`（GOPATH 时代的包加载器），对**当前工作目录和包路径**敏感：`go generate` 请在消息所在包目录下执行，报 `could not load package` / `golang.org/x/text/message is not imported` 时先查这两点；
- 行为随版本变化（例如 0.22 一代的实现），**升级 x/text 后要重新跑一遍 `extract` 验证抽取结果没变**，不要只看编译是否通过。

### 五、迁移存量代码用 `rewrite`，但只用一次

```bash

gotext rewrite ./...      # 把 printf 系列调用改写为 message.Printer 调用（默认输出到 stdout）
gotext rewrite -w ./...   # -w 才写回源文件
```

它是"一次性"工具（官方注释写得很明白：`rewrite is typically done once for a project`），而且只在 `message.Printer` 已在作用域内时才改写，别指望它一把梭把全项目改完。

### 面试官会追问什么

- **翻译没跟上怎么办？** → `catalog.Fallback` 决定兜底语种（通常设成源语种），未翻译条目自动回退；生成时会打 `Missing entry for "xxx"` 警告，可以拿它做 CI 卡点。
- **怎么在 CI 里保证翻译不遗漏？** → CI 跑 `gotext generate`，把 `Missing entry` 警告当失败；或对 `messages.*.json` 与 `out.gotext.json` 的 id 集合做 diff。
- **还有别的 i18n 方案吗？** → 社区常见的是 `nicksnyder/go-i18n`（TOML/YAML 文案 + `Localizer`），风格更接近传统 gettext；官方这套的优势是零第三方依赖、与 `x/text` 的格式化/复数能力天然打通。

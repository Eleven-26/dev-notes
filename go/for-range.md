## Q1. for range 中赋值的变量，是临时变量还是真实地址？

**来源**：`p=41` 深信服 Go 面试 · 时长 7分58秒

### 一、结论：指向的是「临时变量」

**证据 1（语法层面）**：

```go
for i, v := range s { ... }
//   ↑ 这里用的是 := —— 海象运算符是「定义新变量」的语法
//     如果 v 已经是原始元素，就没必要"定义"它
//     → 所以必然存在一次复制
```

**证据 2（运行时）**：打印 `i`、`v` 和 `&v` 的**地址**会发现
**每次迭代地址都不一样**——说明**每次都定义了一个新的变量**。

> ⚠️ **Go 1.22 的重要变更**：循环变量改为**每次迭代新建**，
> 因此 `for` 里启动 goroutine / 闭包捕获变量**不再有"都捕获到最后一个值"的问题**。
> 但"**range 的值变量是临时变量**"这个结论**没有变**。

### 二、⚠️ 想通过指针修改原始数据：只有切片可以

| 类型 | 能否改原始数据 | 原因 |
|---|---|---|
| **切片** | ✅ **可以** | 切片元素**可以取地址**——用索引 `&s[i]` 拿到原始元素地址 |
| **map** | ❌ **不行** | **map 的元素不可寻址**——语法上就取不到地址 |
| **channel** | ❌ **不行** | channel 是**跨协程的数据传递**，**根本不存在"原始数据"**——<br>原始数据可能在**另一个协程**的某个变量里 |

**正确写法（改切片原始数据）**：

```go
// ✗ 错：改的是临时变量的地址，切片内容不变
for _, v := range s {
    modify(&v)
}

// ✓ 对：用索引取元素的原始地址
for i := range s {
    modify(&s[i])
}
```

### 三、为什么 map 不可寻址（顺带解释）

> **map 的底层是哈希表（buckets + 溢出桶）**，
> 元素在桶里的位置**会随扩容、搬迁而改变**——
> 如果允许取地址，**扩容后这个地址就失效了**，
> 会变成一个**悬空指针**。所以 Go **从语言层面禁止**取 map 元素的地址。

### 面试官会追问什么

- **`for range` 遍历 map 的顺序是固定的吗？** → **不固定**，
  Go 刻意**随机化起始位置**，防止开发者依赖遍历顺序。
- **`for range` 遍历字符串呢？** → 按 **rune（Unicode 码点）** 迭代，
  索引是**字节偏移**（所以中文等变长字符的索引会跳着走）。
- **怎么避免大元素复制开销？** → 遍历 `[]struct{}` 这类大元素时，
  用 `for i := range s` 配合 `&s[i]`，**避免每轮复制一份**。

## 一、为什么要分层？

网络是用物理链路把孤立的工作站或主机连起来，组成数据链路，从而资源共享与通信。通信是信息交流与传递；网络通信则是通过网络连接孤立设备，通过信息交换实现人与人、人与计算机、计算机与计算机之间的通信。

网络通信中最重要的就是**协议**。互联网的实现分成好几层，每一层都有自己的功能，就像建筑物一样，**每一层都靠下一层支持**。用户接触到的只是最上面一层，根本没有感觉到下面的层——要理解互联网，必须从最下层开始自下而上理解。

| 层次 | 名称 | 解决什么 |
| --- | --- | --- |
| 1（最底） | **实体层**（Physical Layer） | 把电脑连起来的物理手段，负责传送 0 和 1 的电信号 |
| 2 | **链接层**（Link Layer） | 确定 0 和 1 的**分组方式**（以太网帧、MAC 地址） |
| 3 | **网络层**（Network Layer） | 引入一套**新地址**（IP），区分设备是否在同一子网 |
| 4 | **传输层**（Transport Layer） | 建立**端口到端口**的通信（UDP / TCP） |
| 5（最上） | **应用层**（Application Layer） | 规定**应用程序的数据格式**（HTTP / FTP / SMTP…） |

⭐ 越下面的层越靠近硬件，越上面的层越靠近用户。**分层最大的好处是「上层的变动完全不涉及下层结构」**——这句话在第七节会看到一个具体的例子。

> 分法有七层、五层、四层多种，把互联网分成**五层**最容易解释。

每一层都会定义很多协议，**这些协议的总称就叫「互联网协议」**（Internet Protocol Suite）。本篇讲的是它们拼在一起的整体结构，单个协议的细节见各专篇。

> **局域网协议的历史**：早期局域网里最常用的三套协议是微软的 **NETBEUI**、Novell 的 **IPX/SPX** 与 **TCP/IP**，最后只有 TCP/IP 活了下来——因为它是**可路由、可扩展**的那一套。所以今天说「学网络」，基本等于「学 TCP/IP 协议栈」。

## 二、实体层：只负责传 0 和 1

电脑组网的第一件事是先把电脑连起来：光缆、电缆、双绞线、无线电波等。

**实体层就是把电脑连接起来的物理手段**，它规定了网络的一些电气特性，作用是**负责传送 0 和 1 的电信号**。

单纯的 0 和 1 没有任何意义——必须规定解读方式：多少个电信号算一组？每个信号位有何意义？这就是下一层要解决的问题。

---

## 三、链接层：0 和 1 怎么分组

链接层在实体层之上，**确定 0 和 1 的分组方式**。

### 3.1 以太网协议

早期每家公司都有自己的分组方式，逐渐地**以太网（Ethernet）**协议占据主导。以太网规定一组电信号构成一个数据包，叫做**帧（Frame）**，每帧分成两部分：

| 部分 | 内容 | 长度 |
| --- | --- | --- |
| **标头**（Head） | 数据包的说明项：发送者、接收者、数据类型等 | **固定 18 字节** |
| **数据**（Data） | 数据包的具体内容 | **最短 46 字节，最长 1500 字节** |

因此整个帧最短 **64 字节**、最长 **1518 字节**。数据很长时必须**分割成多个帧**发送——这是后面「分片」的源头。

### 3.2 MAC 地址

标头里的发送者与接收者如何标识？以太网规定连入网络的所有设备都必须有**网卡**接口，数据包必须从一块网卡传到另一块网卡——**网卡的地址就叫 MAC 地址**。

- 每块网卡出厂时有**全世界独一无二**的 MAC 地址，长度 **48 个二进制位**，通常写成 **12 个十六进制数**；
- 前 6 个十六进制数是**厂商编号**，后 6 个是该厂商的**网卡流水号**。

有了 MAC 地址，就可以定位网卡和数据包的路径。

### 3.3 广播

有了地址还不够，还得解决两个问题：

1. **怎么知道对方的 MAC 地址？** → 由 **ARP 协议**解决（见 4.4）；
2. **怎么把数据包准确送到接收方？** → 以太网采用一种很「原始」的方式：**不是精确投递，而是向本网络内所有计算机发送**，让每台机器自己判断是否为接收方。

⚠️ 接收方的 MAC 与自身相同就收下做进一步处理，否则丢弃——这种方式就叫**广播（broadcasting）**。

有了数据包定义、MAC 地址与广播发送，「链接层」就能在多台计算机之间传送数据了。

## 四、网络层：为什么还要一套 IP 地址

### 4.1 网络层的由来

理论上只靠 MAC 地址，上海的网卡也能找到洛杉矶的网卡。但以太网用**广播**发送，所有成员人手一「包」，不仅效率低，而且**广播局限在发送者所在的子网络**——两台计算机不在同一个子网络时广播传不过去（这个设计是合理的，否则互联网上每台机器都会收到所有包，那是灾难）。

互联网是无数子网络组成的巨型网络，必须找到一种方法**区分哪些 MAC 地址属于同一个子网络**：

- 同一个子网络 → 用广播发送；
- 否则 → 用**路由**方式发送。

遗憾的是 **MAC 地址做不到这一点**——它只与厂商有关，与所处网络无关。

**这就导致了网络层的诞生**：它引进一套新的地址，用来区分不同计算机是否属于同一个子网络。这套地址叫**网络地址**，简称**网址**。

于是每台计算机有了两种地址，且**两者之间没有任何联系**：MAC 地址绑定在网卡上，网络地址由管理员分配。

| 地址 | 谁分配 | 作用 |
| --- | --- | --- |
| MAC | 网卡出厂 | 把数据包送到**子网内**的目标网卡 |
| IP | 管理员 / DHCP | 确定设备**在哪个子网络** |

⭐ 因此逻辑上是**先处理网络地址，再处理 MAC 地址**。

### 4.2 IP 协议与子网掩码

规定网络地址的协议叫 IP 协议，它定义的地址就是 **IP 地址**。目前广泛使用的是**第四版（IPv4）**：网络地址由 **32 个二进制位**组成，习惯写成四段十进制数（`0.0.0.0` ~ `255.255.255.255`）。

IP 地址分成两部分：**前一部分代表网络，后一部分代表主机**。例如 `172.16.254.1`，若网络部分是前 24 位（`172.16.254`），主机部分就是最后 8 位（`1`）——同一子网的电脑，网络部分必定相同。

⚠️ **问题在于：单看 IP 地址无法判断网络部分是几位**（24 位？16 位？28 位？看不出来）。这就要用到**子网掩码（subnet mask）**：

- 形式上等同于 IP 地址，也是 32 位，**网络部分全为 1、主机部分全为 0**；
- 若网络部分是前 24 位，掩码就是 `11111111.11111111.11111111.00000000`，即 `255.255.255.0`；
- **判断方法**：把两个 IP 地址分别与子网掩码做 **AND 运算**，结果相同则在同一个子网络。

**举例**：`172.16.254.1` 与 `172.16.254.233` 掩码都是 `255.255.255.0`，分别 AND 后都得 `172.16.254.0`，因此二者在同一子网。

**IP 协议的两个作用**：①为每台计算机分配 IP 地址；②确定哪些地址在同一个子网络。

### 4.3 IP 数据包

IP 数据包同样分「标头」和「数据」两部分：标头主要包括版本、长度、IP 地址等，数据则是具体内容。

它怎么放进以太网帧？答案是**直接把 IP 数据包放进以太网数据包的「数据」部分**，完全不用修改以太网的规格——⭐ **这就是分层结构的好处：上层的变动完全不涉及下层的结构**。

| 数据包 | 标头长度 | 总长上限 |
| --- | --- | --- |
| 以太网帧 | 18 字节（固定） | 1518 字节（数据部分最长 1500） |
| IP 数据包 | 20 ~ 60 字节 | 65,535 字节（数据部分最长 65,515） |
| UDP 数据包 | **8 字节** | 65,535 字节 |
| TCP 数据包 | 20 字节起 | 理论无上限，实践上不超过 IP 包长度以避免再分割 |

⚠️ 因为**以太网数据部分最长只有 1500 字节**（这就是 MTU），而 IP 包可以有 65,515 字节的数据，所以**超过 1500 字节的 IP 包必须分割成几个以太网帧分开发送**。

### 4.4 ARP 协议

IP 数据包放在以太网帧里发送，所以必须同时知道两个地址：对方的 **MAC 地址**和 **IP 地址**。通常 IP 已知，MAC 未知——需要一种机制**从 IP 得到 MAC**，分两种情况：

| 情况 | 做法 |
| --- | --- |
| **不在同一子网络** | 事实上拿不到对方的 MAC，只能把数据包送到两个子网连接处的**网关（gateway）**，由网关处理 |
| **在同一子网络** | 用 **ARP 协议**：发出一个 ARP 请求包（内含要查询的 IP），在「对方 MAC」一栏填 `FF:FF:FF:FF:FF:FF` 即**广播地址**；子网内每台主机都收到，取出 IP 与自身比较，相同则回复自己的 MAC |

有了 ARP，就能拿到**同一子网内**主机的 MAC 地址。

⚠️ ARP 是**无认证**的（谁来应答都行），因此存在 **ARP 欺骗**：攻击者伪造 ARP 应答冒充网关，把流量引到自己这里（中间人）。这是内网安全的经典问题，防御靠静态 ARP 绑定、DHCP Snooping、动态 ARP 检测（DAI）。

## 五、传输层：从「主机到主机」到「端口到端口」

有了 MAC 和 IP，已经能在任意两台主机间通信。但同一台主机上有许多程序都要用网络（一边浏览网页一边聊天），**数据包来了怎么知道该给哪个程序？** 这就需要**端口（port）**——每个使用网卡的程序的编号。

- 端口是 0~65535 的整数，正好 16 个二进制位；
- 0~1023 被系统占用，用户程序只能选大于 1023 的端口。

**传输层的功能就是建立「端口到端口」的通信**，相比之下网络层建立的是「主机到主机」的通信。确定主机 + 端口就能实现程序之间的交流，所以 Unix 把「主机 + 端口」叫做**套接字（socket）**。

| 协议 | 特点 |
| --- | --- |
| **UDP** | 最简单，格式几乎就是在数据前加端口号；标头只有 8 字节，总长不超过 65,535 字节，正好放进一个 IP 包。⚠️ 不可靠：数据包发出后无法知道对方是否收到 |
| **TCP** | 近似「有确认机制的 UDP」：每发出一个数据包都要求确认，收不到确认就重发，因此**能确保数据不遗失**。代价是过程复杂、实现困难、消耗更多资源 |

两者的数据包都**内嵌在 IP 数据包的「数据」部分**。TCP 数据包本身没有长度限制，但为效率通常不超过 IP 包长度，以保证单个 TCP 包不必再分割。

> TCP 的握手、滑动窗口、拥塞控制等细节见 [tcp/](tcp/) 四篇；TCP 与 UDP 的选择见 [通信选型.md](通信选型.md)。

## 六、应用层：规定数据格式

应用程序收到传输层的数据后要进行解读。互联网是开放架构，数据来源五花八门，**必须事先规定好格式**——这就是应用层的作用。

例如 TCP 可以为 Email、WWW、FTP 等各种程序传递数据，那就必须有不同协议规定各自的格式，这些应用协议构成了「应用层」。它是最高一层，**直接面对用户**，数据放在 TCP 数据包的「数据」部分。

> HTTP / gRPC / WebSocket / SSE 的对比见 [HTTP与gRPC.md](HTTP与gRPC.md) 与 [通信选型.md](通信选型.md)。

## 七、一次访问网页的完整旅程 ⭐

这一节是原文最值得保留的部分：把五层串成一个可追踪的过程。假定参数已设置好：

```text
本机 IP     : 192.168.1.100
子网掩码    : 255.255.255.0
网关 IP     : 192.168.1.1
DNS 服务器  : 8.8.8.8
```

用户在浏览器输入 `www.google.com`：

| 步骤 | 层 | 做了什么 |
| --- | --- | --- |
| **1. DNS** | 应用层 | 只知道网址不知道 IP，于是向 DNS 服务器（8.8.8.8:53）发 DNS 查询，得到 Google 的 IP `172.194.72.105` |
| **2. 子网掩码判断** | 网络层 | 本机 IP 与掩码 AND 得 `192.168.1.0`；目标 IP 与掩码 AND 得 `172.194.72.0`。**结果不相等 → 不在同一子网** → 必须经网关转发，**目标 MAC 将是网关的 MAC** |
| **3. 应用层封装** | 应用层 | 构造 HTTP 请求（`GET / HTTP/1.1`、`Host:`、`User-Agent:`、`Cookie:` 等），假定 4960 字节 |
| **4. 传输层封装** | 传输层 | 加 TCP 标头（20 字节），设置双方端口（目标 80，本机随机 51775）→ 总长 4980 字节 |
| **5. 网络层封装** | 网络层 | 加 IP 标头（20 字节），填双方 IP → 总长 5000 字节 |
| **6. 链接层封装** | 链接层 | 加以太网标头，填双方 MAC（发送方本机网卡，**接收方是网关**——通过 ARP 得到） |
| **7. ⭐ 分片** | 链接层 | 以太网数据部分最大 1500 字节，而 IP 包有 5000 字节 → **必须分成 4 个包**：因为每个包都有自己的 IP 标头（20 字节），所以四段的 IP 包长度分别是 **1500 / 1500 / 1500 / 560** |
| **8. 网关转发** | 网络层 | 数据包经多个网关转发（每个网关按路由表决定下一跳，改写链路层标头），最终到达 Google 服务器 |
| **9. 服务端响应** | — | Google 按 IP 标头的序号把 4 个包拼起来，取出完整 TCP 数据包，读出 HTTP 请求，做出 HTTP 响应，再按同样过程发回来；本机收到后渲染网页 |

⭐ **这条旅程把三个问题一次讲清**：

1. **为什么需要两套地址**：IP 决定「往哪个子网 / 哪台主机发」，MAC 决定「链路层下一跳交给谁」——**注意第 6 步里目标 MAC 填的是网关而不是最终主机**，因为跨子网通信时链路层只负责「交给下一跳」；
2. **分片为什么发生**：因为下层（以太网）有 MTU 限制，而上层数据可以更大——**每层只关心自己那一段**；
3. **分层怎么生效**：HTTP 只管文本格式，TCP 只管可靠传输，IP 只管寻址与路由，以太网只管把帧送到下一跳，**谁都不知道对方内部细节**。

> 细节补充：TCP 的「拆包重组」在传输层，IP 的「分片重组」在网络层，两者不是一回事——TCP 依据的是**字节序号**，IP 分片依据的是**分片偏移量**。现代实践中应尽量用 **PMTUD（路径 MTU 发现）** 避免 IP 层分片（分片会显著降低转发效率，且丢一片就要重传整个包）。

## 八、小结：两种地址的分工

发送数据包需要知道两个地址：**对方的 MAC 地址**与**对方的 IP 地址**。有了这两个地址，数据包才能准确送到接收者手中。

但 MAC 地址有局限：**如果两台电脑不在同一个子网，就无法知道对方的 MAC，必须通过网关转发**。所以**目标地址实际分两种情况**：

| 场景 | 数据包的目标地址 |
| --- | --- |
| 同一子网络 | 对方的 MAC 地址 + 对方的 IP 地址 |
| 非同一子网络 | **网关的 MAC 地址** + 对方的 IP 地址 |

⭐ 这也是最好记的一句话：**IP 地址永远是最终目标，MAC 地址只描述「下一跳」。** 每经过一个网关，链路层标头（MAC）都被改写一次，而 IP 标头基本不变（除非做 NAT）。

另外，「静态 IP」与「动态 IP」的区别在于**四个参数怎么来**：

```text
* 本机的 IP 地址
* 子网掩码
* 网关的 IP 地址
* DNS 的 IP 地址
```

手动填这四项叫静态 IP；由 **DHCP 协议**自动分配叫动态 IP——新加入的机器不知道 DHCP 服务器地址，于是发一个**广播**包（目标 MAC 填 `FF:FF:FF:FF:FF:FF`、发送方 IP 填 `0.0.0.0`、接收方 IP 填 `255.255.255.255`、UDP 端口 68→67），DHCP 服务器识别后回响应包，把 IP、掩码、网关、DNS 一并下发。完整流程见 [DHCP.md](DHCP.md)。

**跨子网时到底经过什么**——原文的例子值得保留：1 号电脑要把包发给 4 号电脑，判断后**发现不在同一个子网络**，于是把包发给**网关 A**（所以链路层的目标 MAC 填的是网关 A 的）；网关 A 查路由表发现 4 号位于子网络 B，转发给**网关 B**；网关 B 再送到 4 号。

⭐ **每一跳都只改写链路层标头（MAC），IP 标头端到端不变** —— 这就是上面「MAC 只描述下一跳、IP 才是最终目标」那句话的完整过程。

## 使用：把这条旅程在本机量出来

上面 9 步在真实环境里都有对应的观测手段。⚠️ **以下命令为 Linux / macOS 侧**（本机为 Windows，未实测；Windows 下对应 `nslookup` / `tracert` / `Get-NetRoute`）：

```bash
# 1) 本机四参数：IP / 掩码 / 网关
ip -4 addr show && ip route show          # 等价老命令：ifconfig / route -n

# 2) DNS 解析（对应旅程第 1 步）
dig www.google.com +short                 # 只输出解析结果
dig www.google.com +trace                 # 从根开始逐级查询，看 DNS 分层

# 3) 判断目标是否同子网（对应第 2 步）
ip route get 172.194.72.105               # 输出里带 「via <网关>」，说明走网关而非直连

# 4) 看 ARP 表：即「目标 MAC 是对方还是网关」（对应第 6 步）
ip neigh show                             # 同子网目标会直接出现；跨子网出现的是网关的 MAC

# 5) 观察实际发出的包与分片（对应第 7 步）
sudo tcpdump -i any -nn 'host 172.194.72.105 and tcp port 80' -w /tmp/trace.pcap
# 抓完后看分片：分片的 IP 包会带 MF（More Fragments）标志与偏移量

# 6) 逐跳看路径（对应第 8 步）
traceroute -n 172.194.72.105              # 每一跳就是一个网关

# 7) 查路径 MTU，确认是否会发生 IP 分片
ping -M do -s 1472 172.194.72.105         # 1472 + 20(IP) + 8(ICMP) = 1500，成功即 MTU 1500 可用
```

⭐ 这套命令的价值在于：**每一条都对应旅程里的一步**，把「分层」从一个抽象概念变成可以验证的对象。例如第 4 步 `ip neigh show` 能看到跨子网时表里是网关的 MAC ——这正是第八节那张分工表的实证。

## 面试官会追问什么

- **为什么既需要 IP 又需要 MAC？只用一个不行吗？** → 两者解决的问题不同：**IP 负责「在哪个子网、哪台主机」并可跨网络路由**（能聚合、能分层），**MAC 负责「链路层下一跳交给哪块网卡」**（扁平、不可路由）。只靠 MAC 就得靠广播找遍全球；只靠 IP 则链路层无法封装帧。⚠️ 关键细节：**跨子网时目标 MAC 是网关的 MAC，不是最终主机的**——IP 才是端到端的标识。
- **子网掩码有什么用？** → 用来从 IP 地址里区分「网络部分」和「主机部分」，从而判断两台主机是否在同一子网（分别与掩码做 AND 运算比较结果）。它决定了「用广播直达」还是「交给网关路由」。
- **一个 IP 包为什么要分成多个以太网帧？** → 因为以太网的 MTU 是 **1500 字节**（帧的数据部分上限），而 IP 包最大可达 65,535 字节。超出部分必须在 IP 层分片（带 MF 标志与偏移量）。⚠️ 分片会显著降低效率（丢一片要重传整包），所以现代网络用 **PMTUD** 尽量避免。
- **TCP 的分段和 IP 的分片是一回事吗？** → 不是。TCP 分段按**字节序号**在传输层完成，是端到端行为；IP 分片按**分片偏移量**在网络层完成，是逐跳行为。TCP 会尽量按 MSS 分段以避免 IP 分片。
- **ARP 是怎么工作的？有什么安全问题？** → 发广播请求（目标 MAC 填 `FF:FF:FF:FF:FF:FF`，内含要查询的 IP），同子网主机比对 IP 后单播回复自己的 MAC。⚠️ ARP **无任何认证**，攻击者可伪造应答冒充网关做中间人（ARP 欺骗），防御靠静态绑定、DHCP Snooping 与动态 ARP 检测（DAI）。
- **分层的好处是什么？举一个例子。** → 每层只依赖下一层提供的接口，**上层的变化不影响下层**。原文的例子很典型：IP 数据包要加 IP 地址，但**完全不用修改以太网规格**，只需把 IP 包放进以太网帧的「数据」里——这就是分层。
- **为什么说「下层不知道上层在干什么」？** → 以太网帧只认 MAC（它不解析 IP 头），IP 只认地址与路由（不解析 TCP 端口），TCP 只管可靠传输（不理解 HTTP 语法）。**每层只处理自己那一段标头和载荷**，这正是协议可以自由演进的基础。
- **DHCP 为什么要用广播？** → 新机器加入网络时既不知道自己的 IP、也不知道 DHCP 服务器地址，只能广播求助（MAC 填全 F、源 IP `0.0.0.0`、目的 IP `255.255.255.255`、UDP 68→67）。DHCP 服务器识别后单播/广播回响应包，下发 IP、掩码、网关、DNS 四项参数。

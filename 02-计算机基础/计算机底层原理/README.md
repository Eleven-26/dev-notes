# 计算机底层原理

> 本目录收「**后端开发用得上的那部分执行与存储**」，按职责分成三册：一条机器码指令在 CPU 里走哪五段、为什么 IPC 能大于 1、分支猜错赔多少、乱序与写缓冲如何引出内存屏障（[微架构/](微架构/)）；一次访存落在哪一层、缓存行为什么是 64 字节、MESI 四态如何解释「写一个字节要抢整行」、一次访存 110 ns 为什么还能跑到 10.6 GB/s（[缓存与内存/](缓存与内存/)）；多个核要改同一份数据时硅与内核各管哪一段、无竞争时互斥为什么不进内核（[底层同步/](底层同步/)）。
>
> 当前 **3 册 / 9 篇**：[微架构/](微架构/) 4 篇、[缓存与内存/](缓存与内存/) 3 篇、[底层同步/](底层同步/) 2 篇。每册有自己的 `README.md`（分工表、读序、篇间依赖、实测坐标、册边界），本页只管**跨册的判断**。
>
> 内容整理自个人学习笔记。

## 一、这个目录收什么？与相邻目录的边界在哪？

**本节要点**：判据是「**这条结论落在硅里，还是落在内核里，还是落在翻译过程里**」。三者都成立「换语言也成立」，但回答的是不同问题。

| 归本目录 | 不归本目录，归 | 原因 |
|---|---|---|
| 取指 / 译码 / 执行 / 访存 / 退休、流水线、超标量、IPC | [编译原理/](../编译原理/)（源码 → 产物那一段） | 一边是「机器码怎么被造出来」，一边是「机器码怎么被执行」 |
| 分支预测、乱序执行、写缓冲、重排缓冲 | [操作系统/](../操作系统/)（进程与调度） | OS 管「**谁**用 CPU」，本目录管「CPU 怎么执行**一条**指令」 |
| 缓存层次（L1/L2/L3）、缓存行、伪共享 | [操作系统/](../操作系统/)（页表与缺页） | 一个是**物理缓存**，一个是**地址翻译**；两者常被混为一谈 |
| 内存屏障的**物理原因** | [Go内存模型.md](../../01-编程语言/go/并发编程/Go内存模型.md)、[JMM与内存屏障.md](../../01-编程语言/java/并发编程/JMM与内存屏障.md)（语言层的内存序） | 语言规定「**什么能重排**」，本目录解释「**为什么会重排**」 |
| 指令集架构（x86 变长 / arm64 定长）对编码的影响 | [机器码、字节码与opcode.md](../编译原理/机器码、字节码与opcode.md)（编码格式本身） | 一边是「字节怎么拼」，一边是「拼出来的字节怎么被译码器切」 |

⭐ 最容易搞混的是第二行：[操作系统/调度与时间片.md](../操作系统/调度与时间片.md) 讲的是**调度**视角（分给谁、分多久，本机时间片 2.1 ms、切一次 9.4 µs）；[微架构/](微架构/) 的「五段流水线」是**执行**视角（拿到之后怎么算，本机 IPC 2.92）。两者正交，不重复——而把两者接起来的正是 [操作系统/中断机制.md](../操作系统/中断机制.md)：时钟中断打断流水线，但**返回用户态之前的那次判断**才决定换不换人。

## 二、三册怎么分工？

**本节要点**：按「**一条指令 / 一次访存 / 多个核**」三个问题分册。三册之间有明确的数据流方向，不是一个维度的三个切面。

| 册 | 回答的问题 | 一句话判据 | 篇数 |
|---|---|---|---|
| [微架构/](微架构/) | 一条指令怎么被执行、一次装几个元素 | 换语言、换 OS 都成立，且**不涉及数据放在哪** | 4 |
| [缓存与内存/](缓存与内存/) | 一次访存落在哪、几个核怎么共享、顺序靠什么保证、这条内存能搬多快 | 换语言成立，但**讲的是存储层次不是执行逻辑** | 3 |
| [底层同步/](底层同步/) | 多个核改同一份数据时谁保证正确 | 讲的是**硅与内核的协作**，语言壳只是组合者 | 2 |

三者的依赖方向是单向的：

```text
微架构/ ──写缓冲、LOCK 为什么必要──► 底层同步/
    │                                     ▲
    └──访存延迟──────────────► 缓存与内存/ ──行是隔离单位──┘
```

⭐ 反过来的引用只出现在「上游读数」上：`底层同步/` 引用 `缓存与内存/` 的行宽结论，但不重讲 MESI。

## 三、跨册读序

**本节要点**：按「**执行 → 存储 → 同步**」走。三条线各自的读序在各册的 `README.md` 里，这里只给跨册顺序与理由。

1. **[微架构/CPU怎么执行一条指令.md](微架构/CPU怎么执行一条指令.md)** —— 全目录的入口。它给的 8.81 / 2.55 / 1.81 是后面所有篇的共同起点。
2. **[微架构/CPU流水线与乱序执行.md](微架构/CPU流水线与乱序执行.md)** —— 把单条指令放大成「多条同时在飞」，末尾收口到 `LOCK` 前缀，这是通往同步册的接口。
3. **[缓存与内存/CPU缓存与缓存行.md](缓存与内存/CPU缓存与缓存行.md)** —— 第 2 篇说「store 要等缓存行独占权」，这里解释那行是什么、多宽、几个核怎么抢。
4. **[微架构/分支预测.md](微架构/分支预测.md)** —— 回到执行侧看一个特例：流水线怕的不是指令多，是方向错。
5. **[微架构/向量化与SIMD.md](微架构/向量化与SIMD.md)** —— 回到执行侧的另一条路：不猜方向，改成一次多算几个。它把第 1、2 篇的「编译器骗法」与「每批周期」用在同一段加法上。
6. **[缓存与内存/内存屏障与内存序的代价.md](缓存与内存/内存屏障与内存序的代价.md)** —— 第 3 篇说「写要抢整行」，这里量化抢完之后还要等多久、等的那条指令多少钱。
7. **[缓存与内存/内存带宽与访存并行度.md](缓存与内存/内存带宽与访存并行度.md)** —— 第 3 篇量的是「一次等多久」，这里问「一秒能搬多少」：110 ns 的延迟与 10.6 GB/s 的带宽靠「在飞请求数」接上，读 / 写 / 拷贝的 GB/s 也因此不能直接比。
8. **[底层同步/原子操作.md](底层同步/原子操作.md)** —— 落到指令层：`LOCK` 锁的是行、CAS 靠 `ZF` 回报、x86 上四种内存序只差一条指令。
9. **[底层同步/互斥的实现.md](底层同步/互斥的实现.md)** —— 全目录的收口：22 ns 与 1.7 µs 差 70 倍，因为 200 万次加锁只有几百次真的进了内核。

⚠️ 第 4 篇放中间不是因为它难，而是它复用第 1、2 篇的 IPC 概念；先读它会把「0.55 与 1.77」的出处搞丢。

| NT store 与非临时写 | 普通写与 NT 写的路径差在哪；`sfence` 为什么在 NT 语境下不再免费 | [缓存与内存/内存屏障与内存序的代价.md](缓存与内存/内存屏障与内存序的代价.md) | ✅ **已落地**（3.4 节）。NT 20.34 vs 普通写 8.54 GB/s；每条 `sfence` 掉到 0.57，摊销约 56 ns/次 |

## 五、这些内容现在在哪？

**本节要点**：先建立边界，**不搬动已有结论**；写新篇时再从这些位置回收共性判断。

- **`LOCK` 前缀的汇编证据** → [Go内存模型.md](../../01-编程语言/go/并发编程/Go内存模型.md) 4.1 节（`LOCK XADDQ` 与普通 `INCQ` 的对照）。本目录只补「为什么要清写缓冲」，不重放那份汇编。
- **第一条指令是怎么来的** → [从可执行文件到第一条指令.md](../编译原理/从可执行文件到第一条指令.md) 第四节（C 的 `_start` 12 条 / Go 的 `_rt0_amd64` 3 条）。本目录从「PC 拿到地址之后」接起。
- **字节怎么编码** → [机器码、字节码与opcode.md](../编译原理/机器码、字节码与opcode.md) 第三节（REX / ModRM / SIB / rel32）。[微架构/CPU怎么执行一条指令.md](微架构/CPU怎么执行一条指令.md) 2.2 的「切边界」是它的译码侧。
- **缺页与页表** → [用户态内核态与一次IO的内存路径.md](../操作系统/用户态内核态与一次IO的内存路径.md)。那是地址翻译，比 [缓存与内存/](缓存与内存/) 的 L1d 命中晚一个量级。
- **指令集不可移植的现场表现** → [从可执行文件到第一条指令.md](../编译原理/从可执行文件到第一条指令.md) 7.3（`exec format error` 与退出码 126）。

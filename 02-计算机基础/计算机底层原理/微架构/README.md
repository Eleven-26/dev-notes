# 微架构

> 本册只收**一条指令在硅上怎么被执行**：五段分工、流水线重叠、分支预测的赔偿、乱序与写缓冲。判据是「**换一门语言、换一个操作系统，这些结论仍然成立**」——它们由微架构决定，不由语言或内核决定。
>
> 当前 **4 篇**：[CPU怎么执行一条指令.md](CPU怎么执行一条指令.md)（五段 + 编译器骗法）、[CPU流水线与乱序执行.md](CPU流水线与乱序执行.md)（IPC + 写缓冲 → `LOCK`）、[分支预测.md](分支预测.md)（猜错赔多少 + 预测器怎么记）、[向量化与SIMD.md](向量化与SIMD.md)（一条指令算几个元素 + 三语言各落在哪一档）。
>
> 内容整理自个人学习笔记。

---

## 一、本册收什么

**本节要点**：一句话——「**PC 拿到地址之后，那串字节在 CPU 里发生什么**」。上游是编译原理（字节怎么造出来），下游是缓存（数据从哪来）与同步（怎么让多个核看到同一个值）。

## 二、分工表

**本节要点**：四篇各有一组别处没有的读数——8.81/2.55/1.81 的依赖结构、0.55/1.77/3.17 的 IPC、4.32 与 1.05 的 µop 比、0.105 与 0.810 的 ns/元素、12.2 与 16.5 的 GB/s。分工的判据是「问的是哪一层」。

| 篇 | 回答什么 | 独有读数 |
|---|---|---|
| [CPU怎么执行一条指令.md](CPU怎么执行一条指令.md) | 取指 / 译码 / 执行 / 访存 / 退休各干什么；编译器会怎么把你要测的东西删掉 | 依赖结构 8.81 / 2.55 / 1.81 周期每加法；五段价码 0.282 / 1.012 / 3.042 / 0.541 / 1.052；前端两个上限 3.78 条/周期、18~19 字节/周期；`-O1` 把 2 亿次加法算成 `movabs $0x470de4d98c1f00` |
| [CPU流水线与乱序执行.md](CPU流水线与乱序执行.md) | IPC 为什么能大于 1；乱序凭什么安全；写缓冲为什么让 store 看起来提前；`LOCK` 在还什么债 | 三档 IPC 0.55 / 1.77 / 3.17；链数饱和 1.013 → 0.279（4 个 ALU 端口）；写缓冲转发 1.12 / 4.62 / 15.22 周期每轮 |
| [分支预测.md](分支预测.md) | 猜错到底赔多少；什么情况下根本不存在「猜」；预测器靠什么记 | µop / 指令 1.05 → 4.32（指令数只差 1.7%）；`branch-misses` 占比 0.49 ≈ 随机天花板；每次翻转赔 0.0175 → 1.82（台阶在 64 与 128）；无分支写法随机 12.86 → 2.69、有序 2.06 → 2.69 |
| [向量化与SIMD.md](向量化与SIMD.md) | 一条指令一次算几个元素；编译器什么时候肯做；Go 与 Java 各落在哪一档；服务端真正吃到 SIMD 的是哪些库函数 | L1 档 0.810 → 0.231 → 0.105 ns/元素（**7.7 倍**）；`-O2` 报告 0 条、`cheap` 10 条；Java 开关 SuperWord 差 5.2 倍；CRC32C 16.5 GB/s 关 SSE4.2 掉 12 倍、AES-GCM 关 AES-NI 掉 43~51 倍、IndexByte 26 GB/s 但比逐字节快 12~16 倍 |

## 三、读序

**本节要点**：按「一条指令 → 多条指令 → 猜错的分支」走，不按难度走。三篇的读数互相引用，倒着读会看不懂数字的出处。

1. **先读 [CPU怎么执行一条指令.md](CPU怎么执行一条指令.md)**。它给五段分工与那组 8.81 / 2.55 / 1.81——后面两篇都在解释「为什么同一条链的 8.81 能被摊薄成 1.81」。
2. **再读 [CPU流水线与乱序执行.md](CPU流水线与乱序执行.md)**。把「单条指令」放大到「多条同时在飞」，给 IPC 与乱序窗口，末尾收口到 `LOCK` 前缀——这是通往缓存与同步的接口。
3. **再读 [分支预测.md](分支预测.md)**。它是流水线的一个特例：流水线怕的不是指令多，是「取指方向错了」。放在这里是因为它复用前两篇的 IPC 概念。
4. **最后读 [向量化与SIMD.md](向量化与SIMD.md)**。前三条讲「一条指令怎么走」，这一条讲「一条指令一次装几个元素」。它复用第 1 篇的「编译器会怎么骗你」与第 2 篇的 IPC，放最后不会丢数字的出处。

## 四、篇间依赖

**本节要点**：依赖是单向的——编译原理给 PC 初值，本册给执行机制，缓存与同步册接在后面。**读数只从上游往下游引用，不反向重述**。

```text
编译原理/从可执行文件到第一条指令.md
        │  PC = e_entry
        ▼
CPU怎么执行一条指令.md ──五段──► CPU流水线与乱序执行.md ──LOCK──► 底层同步/
        │                              │
        │  ！编译器骗法                  │  IPC 概念
        ▼                              ▼
分支预测.md ◄──────────────────────────┘
        │
        ▼
向量化与SIMD.md ── 端口瓶颈 ──► 缓存与内存/CPU缓存与缓存行.md
```

- 三篇都依赖 [CPU缓存与缓存行.md](../缓存与内存/CPU缓存与缓存行.md) 的 L1/L2/L3 延迟表，但**不重复讲**缓存，只引用。
- 第三篇的 `-O1` 反转实验与第一篇的 `cmov` 判据是**同一处证据的两种用法**：第一篇用它证明「编译器会骗你」，第三篇用它证明「测分支前先确认还有分支」。

## 五、实测坐标

**本节要点**：三篇共用一台实验台，绝对值不可跨机器引用，倍数关系比绝对值稳。

| 项 | 值 |
|---|---|
| 宿主 CPU | Intel Core i7-6700HQ @ 2.60 GHz（4 核 8 线程） |
| 容器 | `perf-lab` = debian:bookworm-slim + `linux-perf 6.1.190` + `gcc 12.2.0`，`--privileged`，无 CPU 配额 |
| SIMD 篇环境 | `elflab` = `golang:1.26-bookworm`（`go1.26.8`、`gcc 12.2.0`）；6.1~7.2 的 C 对照与 7.3 的 Go 标准库 A/B 都在这里，`nproc=4` |
| 内核 | 6.18.54.1-microsoft-standard-WSL2 |
| `perf_event_paranoid` | `2`（可测自己启动的进程，不可 `-a` 全局） |
| 编译选项 | 第一节的对照实验用 `-O0`，`-O1` 只用于「编译器骗法」；**第 3 节起的所有微基准用 `-O2`**（被量的指令全写在 `asm volatile` 里，`-O2` 只把外层循环编紧），向量化篇另有 `-O3` 与 `-march=native` 两档 |

⚠️ **第一节那组对照（8.81 / 2.55 / 1.81、IPC、µop 比）各只跑 1 次**，没取多轮区间；第 3 节起的微基准**一律每档 3 轮取最快一轮**（WSL2 的干扰只会往慢的方向抖，所以取最快最接近「无干扰」）。同一档三轮之间的抖动普遍 ±5%，个别档（链数饱和的 `chain4`）到 ±20%，各篇的「校验口径」里逐条标了。

## 六、本册边界

**本节要点**：边界线只有一条——**「谁在用 CPU」归操作系统，「CPU 怎么执行一条指令」归本册**。其余（编码、装载、缓存、同步）各有宿主。

| 不归本册 | 归 |
|---|---|
| 字节怎么编码（REX / ModRM / SIB / rel32） | [机器码、字节码与opcode.md](../../编译原理/机器码、字节码与opcode.md) |
| 程序怎么被装载、PC 初值从哪来 | [从可执行文件到第一条指令.md](../../编译原理/从可执行文件到第一条指令.md) |
| L1/L2/L3 的容量与延迟、MESI、伪共享 | [CPU缓存与缓存行.md](../缓存与内存/CPU缓存与缓存行.md) |
| `LOCK` 锁的是缓存行、跨行贵 175 倍 | [原子操作.md](../底层同步/原子操作.md) |
| 无竞争加锁为什么不进内核、futex 三态 | [互斥的实现.md](../底层同步/互斥的实现.md) |
| 语言层规定的「什么能重排」 | [Go内存模型.md](../../../01-编程语言/go/并发编程/Go内存模型.md)、[JMM与内存屏障.md](../../../01-编程语言/java/并发编程/JMM与内存屏障.md) |

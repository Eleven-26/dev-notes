# 微架构

> 本册只收**一条指令在硅上怎么被执行**：五段分工、一条算术指令在 ALU 内部怎么算出结果、流水线重叠、分支预测的赔偿、乱序与写缓冲，以及这些「多少周期」的读数建立在哪个频率上。判据是「**换一门语言、换一个操作系统，这些结论仍然成立**」——它们由微架构决定，不由语言或内核决定。同一台 ALU 上不同操作之间的**价差**（哪条 1 拍、哪条 23 拍、为什么）也算在本册内。
>
> 当前 **7 篇**：[CPU怎么执行一条指令.md](CPU怎么执行一条指令.md)（五段 + 编译器骗法）、[CPU流水线与乱序执行.md](CPU流水线与乱序执行.md)（IPC + 写缓冲 → `LOCK`）、[分支预测.md](分支预测.md)（猜错赔多少 + 预测器怎么记）、[向量化与SIMD.md](向量化与SIMD.md)（一条指令算几个元素 + 三语言各落在哪一档）、[时钟周期与频率.md](时钟周期与频率.md)（标称 vs 实际 + 三种计时口径 + ns↔周期换算）、[补码与整数运算.md](补码与整数运算.md)（补码的物理意义 + 加减乘除怎么落地）、[位运算.md](位运算.md)（ALU 里不进位的那一半 + 位级代价）。
>
> 内容整理自个人学习笔记。

## 一、本册收什么

**本节要点**：一句话——「**PC 拿到地址之后，那串字节在 CPU 里发生什么**」。上游是编译原理（字节怎么造出来），下游是缓存（数据从哪来）与同步（怎么让多个核看到同一个值）。

## 三、读序

**本节要点**：按「一条指令 → 指令内部怎么算 → 多条指令 → 猜错的分支 → 单位与量具」走，不按难度走。七篇的读数互相引用，倒着读会看不懂数字的出处。

1. **先读 [CPU怎么执行一条指令.md](CPU怎么执行一条指令.md)**。它给五段分工与那组 8.81 / 2.55 / 1.81——后面几篇都在解释「为什么同一条链的 8.81 能被摊薄成 1.81」。
2. **再读 [补码与整数运算.md](补码与整数运算.md)**。第 1 篇把 `add` 量成 0.282 周期，这一篇拆开那一个周期里发生了什么：进位怎么传、减法为什么复用加法器、`idiv` 为什么占住单元 30 拍。
3. **再读 [位运算.md](位运算.md)**。上一篇把 ALU 里「会进位」的那一半拆完了，这一篇补另一半：为什么 `and` 与 `add` 同价（都是 1.1 周期）、贵的是乘除；`% 2ⁿ` 换 `&` 的 11 倍在什么条件下才成立；以及位掩码、对齐、无分支这三类工程用法各自的判据。它复用第 2 篇的进位链与补码，不重讲。
4. **再读 [CPU流水线与乱序执行.md](CPU流水线与乱序执行.md)**。把「单条指令」放大到「多条同时在飞」，给 IPC 与乱序窗口，末尾收口到 `LOCK` 前缀——这是通往缓存与同步的接口。
5. **再读 [分支预测.md](分支预测.md)**。它是流水线的一个特例：流水线怕的不是指令多，是「取指方向错了」。放在这里是因为它复用前两篇的 IPC 概念。
6. **再读 [向量化与SIMD.md](向量化与SIMD.md)**。前三条讲「一条指令怎么走」，这一条讲「一条指令一次装几个元素」。它复用第 1 篇的「编译器会怎么骗你」与第 2 篇的 IPC。
7. **最后读 [时钟周期与频率.md](时钟周期与频率.md)**。它不引入新的执行机制，而是给出**前面六篇共用的单位与量具**：那些 0.282 与 1.012 是周期还是 ns、8.81 与 1.81 的频率分母是多少、`rdtsc` 为什么不能当周期数。放在最后，前面每个数字都已经在头脑里，换算时不会丢出处。

## 四、篇间依赖

**本节要点**：依赖是单向的——编译原理给 PC 初值，本册给执行机制，缓存与同步册接在后面。**读数只从上游往下游引用，不反向重述**。

```text
编译原理/从可执行文件到第一条指令.md
        │  PC = e_entry
        ▼
CPU怎么执行一条指令.md ──五段──► CPU流水线与乱序执行.md ──LOCK──► 底层同步/
        │  │                            │
        │  ├──ALU 内部怎么算──► 补码与整数运算.md
        │  └──同一套 ALU 的另一半──► 位运算.md
        │                               │
        │  ！编译器骗法                   │  IPC 概念
        ▼                               ▼
分支预测.md ◄───────────────────────────┘
        │
        ▼
向量化与SIMD.md ── 端口瓶颈 ──► 缓存与内存/CPU缓存与缓存行.md

时钟周期与频率.md ── 全册的单位与量具：ns ↔ 周期、标称 / TSC / 实际三种频率 ──► 上面六篇
```

- 各篇都依赖 [CPU缓存与缓存行.md](../缓存与内存/CPU缓存与缓存行.md) 的 L1/L2/L3 延迟表，但**不重复讲**缓存，只引用。
- [分支预测.md](分支预测.md) 的 `-O1` 反转实验与 [CPU怎么执行一条指令.md](CPU怎么执行一条指令.md) 的 `cmov` 判据是**同一处证据的两种用法**：前者用它证明「编译器会骗你」，后者用它证明「测分支前先确认还有分支」。
- [时钟周期与频率.md](时钟周期与频率.md) 是横切节点，不是流水线上的下一站：它不产出新的执行结论，只规定前面六篇的读数该怎么换算。六篇里出现「周期」的地方都以它的实测频率 2.45 GHz 为准，标称 2.60 只用于粗算。

## 五、实测坐标

**本节要点**：七篇共用一台实验台，绝对值不可跨机器引用，倍数关系比绝对值稳。

| 项 | 值 |
|---|---|
| 宿主 CPU | Intel Core i7-6700HQ @ 2.60 GHz（4 核 8 线程） |
| 容器看到的拓扑 | 4 个 vCPU = 2 核 × 2 线程（`lscpu`）；`/proc/cpuinfo` 的 `cpu MHz` 四行均为 2591.998，是标称不是当前值 |
| 实测频率 | 单线程 2.446~2.459 GHz、四线程 2.397~2.412 GHz、TSC 恒定 2.592 GHz（空载与满载都不变） |
| 容器 | `perf-lab` = debian:bookworm-slim + `linux-perf 6.1.190` + `gcc 12.2.0`，`--privileged`，无 CPU 配额 |
| SIMD 篇环境 | `elflab` = `golang:1.26-bookworm`（`go1.26.8`、`gcc 12.2.0`）；6.1~7.2 的 C 对照与 7.3 的 Go 标准库 A/B 都在这里，`nproc=4` |
| 位运算篇环境 | 同 `elflab`（`golang:1.26-bookworm`，`gcc 12.2.0`、`go1.26`）；`%` 四档用 `-O2 -fno-unroll-loops`，ALU 九档用 `asm volatile` 依赖链，Go 侧用 `go build -gcflags='-S'` 看指令 |
| 内核 | 6.18.54.1-microsoft-standard-WSL2 |
| `perf_event_paranoid` | `2`（可测自己启动的进程，不可 `-a` 全局） |
| 编译选项 | 第一节的对照实验用 `-O0`，`-O1` 只用于「编译器骗法」；**第 3 节起的所有微基准用 `-O2`**（被量的指令全写在 `asm volatile` 里，`-O2` 只把外层循环编紧），向量化篇另有 `-O3` 与 `-march=native` 两档 |

⚠️ **第一节那组对照（8.81 / 2.55 / 1.81、IPC、µop 比）各只跑 1 次**，没取多轮区间；第 3 节起的微基准**一律每档 3 轮取最快一轮**（WSL2 的干扰只会往慢的方向抖，所以取最快最接近「无干扰」）。同一档三轮之间的抖动普遍 ±5%，个别档（链数饱和的 `chain4`）到 ±20%，各篇的「校验口径」里逐条标了。⚠️ 时钟周期篇另有一条**整轮作废**的记录：4 进程同跑时撞上宿主负载，`wall`、`task-clock`、`cycles` 三个数互相矛盾，该轮不计入任何结论。

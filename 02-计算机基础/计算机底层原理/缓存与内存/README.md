# 缓存与内存

> 本册收**一次访存落在哪一层、为什么以「行」为单位被搬来搬去、两个核共享同一行时顺序靠什么保证，以及一条内存到底能搬多快**：存储层次的延迟台阶、64 字节的夹逼、MESI 四态、伪共享的判据与测法、四种重排只漏一种、各类屏障的单价、延迟与带宽怎么用「在飞请求数」接起来。判据是「**换语言也成立，但它不是 CPU 的执行逻辑**」——数据在哪、几个核怎么共享、总线能吞吐多少，属存储层次。

## 一、本册收什么

**本节要点**：一句话——「**数据从 L1 到内存要几纳秒，两个核想要同一份数据时会怎样，为此要付多少钱，以及这条内存总共能搬多快**」。执行逻辑在 [微架构/](../微架构/)，地址翻译在 [操作系统/](../../操作系统/)。

前两篇回答的是「单次访问」与「跨核共享」：数据在哪（延迟台阶 + 行宽 + MESI）、顺序怎么保（四种重排 + 屏障单价）。第三篇换了一把尺子，问的是「稳态吞吐」：同样这条内存，一次只能等 110 ns，但很多次同时在飞就能跑到 10.6 GB/s，两个数靠「在飞请求数」连起来。

## 二、分工表

**本节要点**：三篇的分工线是「**结构 → 代价 → 吞吐**」——第一篇讲缓存行是什么、怎么被抢；第二篇讲抢完之后要等多久、等的那条指令多少钱；第三篇讲把请求堆起来之后，整条内存能跑多快，以及 GB/s 这个数该怎么读。

| 篇 | 回答什么 | 状态 |
|---|---|---|
| [CPU缓存与缓存行.md](CPU缓存与缓存行.md) | 各级延迟差多少；缓存行为什么是 64 字节且能用间隔夹逼出来；MESI 四态怎么解释「写一个字节要抢整行」；伪共享怎么判、怎么测、哪四类假阴性；同一工作集只改访问顺序为什么差 29~132 倍；64 set × 8 路的冲突缺失 | ✅ 已落地（1.60 → 113.63 ns；间隔 56 慢 / 64 快；行宽 ∈ (56,64]；顺序 vs 随机 1 MB 差 29 倍、64 MB 差 132 倍；32 KB 步长同 set 慢 2.5~4.1 倍） |
| [内存屏障与内存序的代价.md](内存屏障与内存序的代价.md) | 四种重排 x86 只漏哪一种；不拦会被观测成什么样；`mfence` / `lfence` / `sfence` / `lock or` / `cpuid` 各多少钱；编译器屏障与硬件屏障差在哪；换成 NT store 后 `sfence` 为什么不再免费 | ✅ 已落地（无屏障 300 000 轮违反 29~41 次，加屏障三轮全 0；单价 0.46 → 2.46 → 5.37 → 7.5~8.1 → 15.21 → 725.57 ns；NT 写 20.34 vs 普通写 8.54 GB/s，每条 `sfence` 掉到 0.57） |
| [内存带宽与访存并行度.md](内存带宽与访存并行度.md) | 110 ns 的延迟与 10.6 GB/s 的带宽靠什么连接；一个核怎么用 8 条独立链把 103.6 ns 摊到 15.1 ns；读 / 写 / 拷贝 / 三数组的 GB/s 口径差在哪；为什么多核扩展比在本机测不出来 | ✅ 已落地（延迟 103~122 ns；8 链 6.9 倍；单线程读 7.1~10.6 GB/s；五档换算 DRAM 流量后收敛在 17~19.6 GB/s；1/2/4 线程同档，不可作扩展比证据） |

⚠️ 三篇靠两条线分开：**第一篇不讨论顺序与吞吐，第二篇不讨论一致性协议与字节口径，第三篇不讨论跨核一致性**。屏障篇第 1.3 节只用一句「写还在缓冲里，缓存里还是旧值」把 MESI 接过来，不重述四态；带宽篇第 4.2 节引用 NT store 的 `sfence` 单价时明确写「与屏障篇 3.4 的探针不同，不可互相代入」；缓存篇第 221 行把 `LOCK` 语义外链到 [原子操作.md](../底层同步/原子操作.md)，不重述前缀。

## 三、读序

**本节要点**：先结构、后代价、最后吞吐——不先建立「行」的概念，屏障篇的「还账」和带宽篇的「每次只用到 4/64 字节」都没有对象。

1. 先读 [CPU缓存与缓存行.md](CPU缓存与缓存行.md)：延迟台阶（16 KB 1.60 ns → 64 MB 113.63 ns）→ 64 字节怎么夹出来 → MESI 四态 → 伪共享四类假阴性；
2. 再读 [内存屏障与内存序的代价.md](内存屏障与内存序的代价.md)：从那个 0.01% 的观测开始，回到「四种重排只漏一种」，最后落到单价表；
3. 最后读 [内存带宽与访存并行度.md](内存带宽与访存并行度.md)：从「110 ns 算不出 10.6 GB/s」开始，用 Little 定律把两个数接上，再看 MLP、读写不对称与 GB/s 的三种口径。
4. 三篇之后接 [底层同步/](../底层同步/)：那里把「抢一条行」拆成 `lock` 前缀锁什么（原子操作），再往下变成「线程睡下」（互斥的实现）。

## 五、实测坐标

**本节要点**：三篇的读数都在同一台机器上测得，绝对值受虚拟化影响；**结论本身不受影响**（夹逼出的是区间判定，屏障与带宽比的是同进程倍数）。缓存篇分两个环境（第 1、3、5、6 节 Windows Go，2.4/3.5 容器 Go），屏障篇在同一个容器（环境 B）里用 gcc，带宽篇在 `perf-lab` 容器（环境 C），三套读数不可相减。

| 项 | 值 |
|---|---|
| 宿主 CPU | Intel Core i7-6700HQ（L1d 32 KB/核、L2 256 KB/核、L3 6 MB 共享） |
| 环境 A | `go1.26.5 windows/amd64`（缓存篇第 1、3、5、6 节） |
| 环境 B | 容器 `golang:1.26-bookworm`：`go1.26.8 linux/amd64`（缓存篇 2.4/3.5）/ `gcc 12.2.0`（屏障篇与 NT 探针） |
| 环境 C | 容器 `perf-lab`：`debian:bookworm-slim` + `gcc 12.2.0` + `linux-perf 6.1.190`，`nproc=4`（带宽篇全部读数） |
| 内核 | 6.18.54.1-microsoft-standard-WSL2，cgroup 限额 4 CPU |
| 关键方法 | 工作集逆序扫（延迟台阶）；**起点强制 64 对齐**后手工控间隔（夹逼）；`@Contended` 需 `-XX:-RestrictContended`；SB litmus 用手写汇编 + `pthread_barrier` 夹轮次；预取/冲突用**指针追逐**（依赖链）而不是 `acc += buf[i]`；NT 写用 `_mm256_stream_pd` 对照普通写；带宽用**8 个独立累加器**、MLP 用 1/2/4/8 条独立指针链、每线程 `sched_setaffinity` 绑核 |

⚠️ 四个已知坑：`new(T)` 的起点 mod 64 是随机的（0/16/32/48 各 1/4），不对齐会让「间隔 32」碰巧跨行；`internal/cpu.CacheLinePad` 外部不可引，`x/sys` 版的偏移与 size 都不同；`xchg` 的内联汇编**不能拿循环计数器当交换对象**，否则循环提前退出、读数是 0.000 ns；**`acc += buf[i]` 是串行 FP 加法链，测出来的是加法延迟（约 1.89 ns ≈ 4.9 周期）而不是访存延迟**，测缓存必须用指针追逐，测带宽必须拆成 8 个累加器。

⚠️ 三个容易读错的量：跨步探针的**足迹会随跨步缩小**（8 KB 档只剩 64 KB，落进 L2，读数回落到 4.4~4.9 ns），所以跨步表只列到 4 KB；WSL2 的**内存带宽本身有 ±40% 波动**（同一档五轮 12~20 GB/s），NT 写只比较三档之间的倍数，不引用绝对 GB/s；带宽篇因此只比「同进程内的倍数」与「五档收敛后的量级」，并把多线程扩展比标成**实测但不可作证**（cgroup 配额会拉长墙上时间）。

⚠️ 跨核 store 可见延迟（两核互等写入的 ping-pong）试过但放弃：三轮测出 15 / 26 / 84 ns 每跳，同一配置波动 6 倍，WSL2 的调度噪声盖过了要测的量。屏障篇因此改用 SB litmus 做主力证据。

# 数组与序列技巧

> 本目录（`算法/基础算法/数组与序列技巧/`）收**六个不依赖专门结构、只靠下标与序列性质**的公共技巧：
> [双指针.md](双指针.md)、[滑动窗口.md](滑动窗口.md)、[前缀和与差分.md](前缀和与差分.md)、
> [摩尔投票.md](摩尔投票.md)、[位运算.md](位运算.md)、[二分答案.md](二分答案.md)。
>
> ⚠️ 与姊妹目录的分工：[排序/](../排序/README.md) 是它们的**前置步骤**（把数据变成有序），
> [查找/](../查找/二分查找.md) 里的二分、B 树、哈希讲「在有序 / 结构化数据上找值」；本目录讲的是**怎么用两个指针、一个窗口、
> 一张前缀表、一个计数器、一组位或一次判定来把 `O(n²)` 压回 `O(n)` / `O(n log n)`**。
> ⚠️ 其中 [二分答案.md](二分答案.md) 与 [二分查找.md](../查找/二分查找.md) 共用同一份二分模板，
> 区别只在「二分的对象是下标还是答案空间」，判据见第七节。
>
> 本篇是**入口总纲** —— 回答「六个技巧各自靠什么成立、拿到题先看什么、什么时候该用哪个」。
> 各篇的推导、实现与实测在零件篇里，本篇不重复。基础算法目录的整体导读见 [README.md](../README.md)。

## 一、核心思想

**本节要点**：六个技巧看起来各不相同，但**成立条件只有三类** —— **单调性**（双指针 / 滑动窗口 / 二分答案）、
**端点可逆**（前缀和与差分）、**可编码 / 可抵消**（位运算 / 摩尔投票）。

| 技巧 | 成立依赖的性质 | 典型问法 | 复杂度收益 |
|---|---|---|---|
| [双指针.md](双指针.md) | **单调性**：移动某一侧有明确依据 | 两数之和、判环、三路分区 | `O(n²)` → `O(n)` |
| [滑动窗口.md](滑动窗口.md) | **单调性**：窗口合法性对左右端点单调 | 最长无重复子串、最小覆盖子串 | `O(n²)` → `O(n)` |
| [前缀和与差分.md](前缀和与差分.md) | **端点可逆**：区间和 = 两个前缀相减；区间改 = 两端打点 | 静态频繁区间和 / 只加型区间改 | 单次 `O(n)` → `O(1)` |
| [摩尔投票.md](摩尔投票.md) | **多数性**：某元素出现次数超过 `n/k` | 多数元素 | 空间 `O(n)` → `O(1)` |
| [位运算.md](位运算.md) | **位独立**：状态能用比特编码 | 状态压缩、位掩码、子集枚举 | 集合 → 一个整数 |
| [二分答案.md](二分答案.md) | **判定函数单调**：可行域是一个半边 | 「最小化最大值 / 最大化最小值」 | `O(n·答案范围)` → `O(n log 范围)` |

⭐⭐ **一个统一的洞察**：双指针、滑动窗口、二分答案**都建立在「单调性」上** ——
单调性保证「**一次判断就能永久排除一批候选**」，这正是它们能把 `O(n²)` 降下来的共同原因。
⚠️ 所以「这个技巧能不能用」的问题，几乎总能转化成「**这条性质成立吗**」。

> **位运算是横切件**：它不解决某一类问题，而是给其他技巧**提供状态表示** ——
> 状态压缩 DP、子集枚举、位图、权限掩码都靠它。

## 二、适用条件

**本节要点**：这六个技巧的「适用条件」是**性质前提** —— 前提不满足时，它们不是变慢，而是**静默给出错误答案**。

| 技巧 | 必须满足 | 不满足会怎样 |
|---|---|---|
| **双指针** | 移动某一侧有**单调依据** | **漏解** —— 比「多解」更危险，且很难发现 |
| **滑动窗口** | 窗口合法性对左右端点**单调** | 收缩只写 `if` 就漏解（实测穷举 62 个串**错 12 个**，最短反例 `abba`） |
| **前缀和** | 数据**静态**（查询之间不修改） | 查询与修改交替出现就得换线段树 / 树状数组（[区间与索引树.md](../../../数据结构/树/进阶与总结/区间与索引树.md)） |
| **差分** | 区间修改必须是**加法型** | 区间赋值 / 区间最值要换懒标记线段树 |
| **摩尔投票** | **确实存在**多数元素，且必须**二次验证** | 不存在多数元素时它也会返回一个候选（实测 `[1 2 3 4]` 给出 3） |
| **位运算** | 状态能编码进 ≤ 64 位 | 位宽不够；⚠️ 移位越界在 **Go 是编译期错误、Java 是回绕** |
| **二分答案** | `check(x)` 对答案**单调**（可行域是一个半边） | 不单调时二分**静默给错解** —— 动手前先证「`x` 可行 ⇒ 一侧全部可行」 |

> 拿到题先按规模定复杂度上限 —— 那张「`n` 的量级 → 可接受复杂度」的表在
> [README.md](../README.md) 第二节，本目录不重复。

## 三、解题模板

**本节要点**：四步 —— **看规模 → 看有没有「序」 → 看问题形状 → 验边界**。
第二步是最容易被跳过、也最值钱的一步：**有序 / 单调**直接决定了这六个技巧里哪些能用。

| 步骤 | 做什么 | 关键点 |
|---|---|---|
| **1. 看规模** | 按 `n` 定复杂度上限 | 决定了「`O(n²)` 还能不能救」 |
| **2. 看「序」** | 数据有序 / 单调吗？能不能先排序？ | 有序 → 双指针 / 二分；无序 → **先排序往往付得起**（`O(n log n)`） |
| **3. 看形状** | 连续子数组？区间查询？多数元素？最优化判定？ | 见下方决策 |
| **4. 验边界** | 空输入、单元素、全相同元素、极值 | 滑窗与二分的错几乎都出在这些用例上 |

### ⭐ 第 3 步：按问题形状选技巧

```text
问题的形状是什么？
├─ 连续子数组 / 子串，求最长、最短、是否满足
│   └─ 滑动窗口（前提：窗口合法性对端点单调）        [滑动窗口.md]
├─ 有序数组（或可排序）里找一对 / 三元组
│   └─ 双指针（对撞 / 同向 / 快慢）                  [双指针.md]
├─ 多次查询静态区间的和 / 多次对区间整体加一个值
│   ├─ 只查不改 → 前缀和                            [前缀和与差分.md]
│   └─ 只改后统一查 → 差分                          [前缀和与差分.md]
├─ 某元素出现次数超过 n/2（或 n/k）
│   └─ 摩尔投票 + 二次验证                          [摩尔投票.md]
├─ 状态是「选了哪些」的小集合（n ≤ 20 上下）
│   └─ 位掩码 / 子集枚举                            [位运算.md]
├─ 「最小化最大值 / 最大化最小值」
│   └─ 二分答案 + 贪心 check                        [二分答案.md]
└─ 在有序数组里找一个值 / 找边界
    └─ 不属于本目录 → 二分查找                      [二分查找.md](../查找/二分查找.md)
```

### ⭐ 三个自检

```text
□ 数据有序吗？（能不能先花 O(n log n) 换一个 O(n) 的主过程）
□ 「移动哪一侧 / 排除哪个候选」有依据吗？
  （有 → 双指针 / 滑动窗口；答不上来 → 大概率漏解）
□ 二分的是「下标」还是「答案」？
  （下标 → 二分查找；答案 → 二分答案）
```

## 四、经典问题

**本节要点**：下表按技巧分组 —— 每篇都给链接，可逐条对照实现与实测。

| 问题 | 关键技巧 | 在哪 |
|---|---|---|
| **两数之和 / 三数之和 / 判环 / 三路分区** | 对撞、快慢、同向三类指针 | [双指针.md](双指针.md) |
| **最长无重复子串 / 最小覆盖子串** | 左闭右开 `[lo, hi)` 的统一模板 | [滑动窗口.md](滑动窗口.md) |
| **静态数组的频繁区间和** | 前缀和查 `O(1)` | [前缀和与差分.md](前缀和与差分.md) |
| **多次区间加、最后统一查询** | 差分改 `O(1)`、前缀还原一次 | [前缀和与差分.md](前缀和与差分.md) |
| **多数元素（出现次数 > `n/2`）** | 两两抵消 + 二次验证 | [摩尔投票.md](摩尔投票.md) |
| **子集枚举 / 状态压缩 / 权限掩码** | 位掩码与 `sub = (sub − 1) & S` | [位运算.md](位运算.md) |
| **「最小化最大 / 最大化最小」最优化题** | 答案空间二分 + 贪心 `check` | [二分答案.md](二分答案.md) |
| **有序数组找值 / 找边界** | `lowerBound` / `upperBound` | [二分查找.md](../查找/二分查找.md)（姊妹目录） |
| **Top-K / 第 K 大** | 小顶堆、快速选择 | [Top-K问题.md](../Top-K问题.md)、[快速选择.md](../排序/快速选择.md) |

⚠️ **`前缀和` 与 `区间与索引树` 是一条连续的路线**：静态查询用前缀和；
「查改交替」就必须升级到树状数组 / 线段树 —— 判据见 [前缀和与差分.md](前缀和与差分.md) 第五节。

## 五、正确性证明

**本节要点**：这六个技巧的证明**主要靠三件工具** —— **循环不变式**（滑动窗口 / 二分答案）、
**排除论证**（双指针）、**抵消与定义展开**（摩尔投票 / 前缀和 / 位运算）。

| 技巧 | 走哪条路 | 核心不变量 |
|---|---|---|
| [双指针.md](双指针.md) | **单调性论证** | 被排除的那一侧**不可能存在更优解** |
| [滑动窗口.md](滑动窗口.md) | **单调性 + 不变式** | 窗口始终是「以 `hi-1` 结尾的、最长的合法窗口」⇒ 不漏解 |
| [前缀和与差分.md](前缀和与差分.md) | **定义展开 + 中间项相消** | `S[r] − S[l−1]` 中间项全消；差分前缀还原一次即回到原数组 |
| [摩尔投票.md](摩尔投票.md) | **抵消 / 鸽巢** | 每次抵消移除两个**不同**元素 ⇒ 多数元素抵消后仍占多数 |
| [位运算.md](位运算.md) | **按位归纳** | 每一位独立，运算可逐位验证；补码下减法 = 加负数 |
| [二分答案.md](二分答案.md) | **循环不变式**（承接二分查找） | 答案始终落在 `[lo, hi]` + `check` 单调 ⇒ 收敛点即最值可行解 |

⭐ **一条统一判据**：「看得出来对」不够，要说清「**被排除的候选为什么不可能成为答案**」——
这正是 [双指针.md](双指针.md) 第五节把「不变式论证」单独抽出来讲的原因。

## 六、常见陷阱

**本节要点**：这六个技巧的坑**具有高度重复性** —— 滑窗死在 `if` 上、摩尔投票死在忘记验证上、
二分死在区间收缩上。下表都能用一条规矩挡住。

| 陷阱 | 症状 | 怎么避免 |
|---|---|---|
| **滑窗收缩写成 `if`** | 漏解 | 必须用 `while`（实测穷举 62 个串错 12 个，最短反例 `abba`） |
| **双指针没证单调性** | 漏解，很难发现 | 说清「动哪一侧、为什么可以扔掉另一侧」 |
| **摩尔投票不二次验证** | 不存在多数元素时给出错误答案 | 拿到候选后**必须再扫一遍计数** |
| **前缀和左右端点差一** | 区间和差一格，样例能过大数炸 | 统一 `S[i]` = 前 `i` 个之和，查询写 `S[r] − S[l−1]` |
| **前缀和用在动态数据上** | 每次修改后查询都要重算 | 查改交替 → [区间与索引树.md](../../../数据结构/树/进阶与总结/区间与索引树.md) |
| **差分用在非加法修改上** | 区间赋值 / 最值完全错 | 差分只吃加法；赋值与最值换懒标记线段树 |
| **位运算忽略负数与位宽** | 结果与预期不符 | 用补码视角；⚠️ 移位越界在 Go 是编译期错误、Java 是回绕 |
| **二分答案没证 `check` 单调** | 二分到「不该可行」的一侧 | 先写清「`x` 可行 ⇒ `y > x` 也可行」再动手 |
| **二分区间不收缩** | 程序卡住 | 区间必须**严格变小**；⚠️ `lo = mid` 就是死循环（实测第 1001 步仍未收敛） |

## 七、与其他思想对比

**本节要点**：这六个技巧处在**最底一层** —— 策略层（DP / 贪心 / 回溯）决定「怎么走」，
它们负责「**把这一步实现得足够快**」。

### 二分答案 vs 二分查找

| 维度 | [二分查找.md](../查找/二分查找.md) | [二分答案.md](二分答案.md) |
|---|---|---|
| 二分对象 | **下标**（有序数组里的位置） | **答案空间**（一个数值范围） |
| 前提 | 数组有序 | `check(x)` 对 `x` 单调 |
| 每一步做什么 | 比较 `a[mid]` 与目标 | 用 `check(mid)` 判断可行域在哪半边 |
| 典型问法 | 找值 / 找左右边界 | 最小化最大值 / 最大化最小值 |

⭐ 两者**共用同一份循环模板**：模板的推导在 [二分查找.md](../查找/二分查找.md) 第四节，
[二分答案.md](二分答案.md) 只补「怎么构造 `check`」与「两种收缩方向」。

### 与动态规划、贪心

| 关系 | 说明 |
|---|---|
| **滑动窗口 / 双指针常是 DP 的降维替代** | 当状态只与窗口端点有关、且合法性单调时，不必开二维 DP |
| **前缀和是 DP 的常见优化** | 把「枚举区间起点」的 `O(n)` 转移降成 `O(1)`（如最大子段和） |
| **二分答案常与贪心配对** | `check(x)` 里往往是「按某个顺序贪心能否满足」 |
| **位运算是状压 DP 的底座** | `dp[mask]` 的枚举与转移全靠位运算（[状态压缩DP.md](../../动态规划/优化与高级/状态压缩DP.md)） |

### 与数据结构

| 技巧 | 升级方向 | 判据 |
|---|---|---|
| 前缀和 | 树状数组 / 线段树 | 查询与修改**交替**出现 |
| 差分 | 懒标记线段树 | 修改不是加法（赋值 / 最值） |
| 位运算 | 位图 / 布隆过滤器 | 需要**持久存储**状态而非只在内存里算 |

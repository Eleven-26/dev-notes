## 一、核心思想

**本节要点**：基础算法是「**公共零件**」—— 它们不针对某一类具体问题，而是后面所有专题（动态规划 / 贪心 /
图论 / 字符串）反复复用的手段。三条主线：

| 主线 | 篇目 | 回答什么 |
|---|---|---|
| **度量** | [复杂度分析.md](复杂度分析.md) | 这个解法**行不行**（够不够快、够不够省） |
| **组织** | [README.md](../../数据结构/README.md) | 数据该以什么**结构**存放 |
| **技巧** | 递归与分治 / 二分查找 / 排序算法 / 位运算 / 双指针 / 滑动窗口 / 摩尔投票 | 常见的「**问题形状**」对应什么套路 |

⭐ **技巧篇目的价值在于「识别形状」**：见到「有序 + 找某个值」想到二分；见到「连续子数组 + 最长/最短」
想到滑动窗口；见到「候选超过 `n/2`」想到摩尔投票。**写不出来往往不是不会写，而是没认出形状。**

### 七个技巧靠什么成立

| 技巧 | 成立依赖的性质 | 典型问法 |
|---|---|---|
| [二分查找.md](二分查找.md) | **单调性**（答案随位置单调） | 有序数组找值 / 最小化最大值 |
| [双指针.md](双指针.md) | **单调性**（动哪一侧有明确依据） | 两数之和 / 判环 / 三路分区 |
| [滑动窗口.md](滑动窗口.md) | **单调性**（窗口合法性对端点单调） | 最长无重复子串 / 最小覆盖子串 |
| [递归与分治.md](递归与分治.md) | **可分治**（子问题独立且能合并） | 归并排序 / 快速排序 |
| [位运算.md](位运算.md) | **位独立**（状态能用比特编码） | 状态压缩 / 位掩码 |
| [摩尔投票.md](摩尔投票.md) | **多数性**（某元素超过 `n/k`） | 多数元素 |
| [排序算法.md](排序算法.md) | —（它是别的算法的**前置步骤**） | 排序本身 / 为贪心与双指针铺路 |

⭐⭐ **一个统一的洞察**：二分、双指针、滑动窗口这三个技巧**都建立在「单调性」上** ——
单调性保证「**一次判断就能永久排除一批候选**」，这正是它们能把 `O(n²)` 降到 `O(n)` 的共同原因。
⚠️ 所以「这个技巧能不能用」的问题，几乎总能转化成「**单调性成立吗**」。

## 二、适用条件

**本节要点**：基础技巧的「适用条件」是**性质前提** —— 前提不满足时，多数技巧不是变慢，而是**静默给出错误答案**。

| 技巧 | 必须满足 | 不满足会怎样 |
|---|---|---|
| **二分查找** | 搜索区间**单调**（或判定函数单调，即「二分答案」） | 结果**静默出错**；⚠️ 错误写法还会**死循环**（实测第 1001 步仍未收敛） |
| **双指针** | 移动某一侧有**单调依据** | **漏解** —— 比「多解」更危险，且很难发现 |
| **滑动窗口** | 窗口合法性对左右端点**单调** | 收缩只写 `if` 就漏解（实测穷举 62 个串**错 12 个**，最短反例 `abba`） |
| **分治** | 子问题**独立** + **可合并** | 不能合并就退化成「减治」（如用快排分区找第 K 大） |
| **位运算** | 状态能编码进 ≤ 64 位 | 位宽不够；⚠️ 移位越界在 **Go 是编译期错误、Java 是回绕** |
| **摩尔投票** | **确实存在**多数元素，且必须**二次验证** | 不存在多数元素时它也会返回一个候选（实测 `[1 2 3 4]` 给出 3） |

### 拿到题的第一件事：按规模定复杂度上限

| `n` 的量级 | 可接受的复杂度 | 对应做法 |
|---|---|---|
| `n ≤ 10²` | `O(n³)` 都能过 | 三重循环 / Floyd |
| `n ≤ 10³` | `O(n²)` | 朴素 DP / 朴素串匹配 |
| `n ≤ 10⁵ ~ 10⁶` | `O(n log n)` | 排序、二分、堆、双指针 |
| `n ≤ 10⁷` | `O(n)` | 滑动窗口、单调栈、摩尔投票、位运算 |
| `n ≥ 10⁸` | 需要数学或概率方法 | 基数估计（[基数与频率估计.md](../../数据结构/高级数据结构/基数与频率估计.md)）、采样 |

⚠️ 这张表是**经验判据**（不是实测），但它决定了「一开始就往哪个方向想」，能省掉大量白写的代码。

## 三、解题模板

**本节要点**：四步 —— **看规模 → 看有没有「序」 → 看问题形状 → 验边界**。第二步是最容易被跳过、也最值钱的一步。

| 步骤 | 做什么 | 关键点 |
|---|---|---|
| **1. 看规模** | 按上一节的表定复杂度上限 | 决定了「`O(n²)` 还能不能救」 |
| **2. 看「序」** | 数据有序 / 单调吗？能不能先排序？ | 有序 → 直接上二分、双指针；无序 → **先排序往往付得起**（`O(n log n)`） |
| **3. 看问题形状** | 求最优 / 枚举所有解 / 计数或存在 | 见下方决策 |
| **4. 验边界** | 空输入、单元素、全相同元素、极值 | 二分与滑窗的错几乎都出在这些用例上 |

### ⭐ 第 3 步：按问题形状选路线

```text
求「最优值」还是「所有解」？
├─ 所有解 / 所有组合 / 所有路径
│   └─ 回溯（DFS + 撤销选择）                       [../回溯/README.md]
└─ 最优值
    ├─ 能证明「每步取局部最优即可」→ 贪心             [../贪心/README.md]
    └─ 不能证明 → 动态规划                            [../动态规划/README.md]

求「存在 / 计数 / 出现次数」？
├─ 精确 → 哈希表 / 位图                             [../../数据结构/哈希表/散列表.md]
│                                                   [../../数据结构/高级数据结构/位图与布隆过滤器.md]
├─ 出现次数有「多数性」保证 → 摩尔投票                [摩尔投票.md]
└─ 规模大到存不下 → 概率结构（HLL / CMS）           [../../数据结构/高级数据结构/基数与频率估计.md]

只需要「反复取极值」？
└─ 堆 / 优先队列                                    [../../数据结构/树/堆与优先队列.md]
```

### ⭐ 三个自检

```text
□ 数据有序吗？          （能不能先花 O(n log n) 换一个 O(n) 的主过程）
□ 「移动哪一侧 / 排除哪个候选」有依据吗？
                        （有 → 双指针 / 滑动窗口 / 单调栈；答不上来 → 大概率漏解）
□ 要返回「所有解」还是「一个值」？
                        （所有解 → 回溯；一个值 → DP / 贪心）
```

## 五、正确性证明

**本节要点**：基础技巧的证明**主要靠三件工具** —— **归纳法**（递归）、**循环不变式**（二分 / 滑窗）、
**单调性论证**（双指针 / 摩尔投票）。

| 技巧 | 走哪条路 | 核心不变量 |
|---|---|---|
| [递归与分治.md](递归与分治.md) | **结构归纳** | 假设子问题正确 ⇒ 组合后正确（所以必须先有**基准情形**） |
| [二分查找.md](二分查找.md) | **循环不变式** | `[lo, hi]` 写法：**答案始终落在区间内** ⇒ 区间收缩到空时即答案 |
| [滑动窗口.md](滑动窗口.md) | **单调性 + 不变式** | 窗口始终是「以 `hi-1` 结尾的、最长的合法窗口」⇒ 不漏解 |
| [双指针.md](双指针.md) | **单调性论证** | 被排除的那一侧**不可能存在更优解** |
| [摩尔投票.md](摩尔投票.md) | **抵消 / 鸽巢** | 每次抵消移除两个**不同**元素 ⇒ 多数元素抵消后仍占多数 |

⭐ **一条统一判据**：「看得出来对」不够，要说清「**被排除的候选为什么不可能成为答案**」。
这正是所有「看起来对但证不出来」的题的分水岭 —— [双指针.md](双指针.md) 第五节的「不变式论证」
就是把这套方法论单独抽出来讲的一节。

## 六、常见陷阱

**本节要点**：基础技巧的坑**具有高度重复性** —— 二分死在循环上、滑窗死在 `if` 上、摩尔投票死在忘记验证上。
下表都是可以用一条规矩挡住的。

| 陷阱 | 症状 | 怎么避免 |
|---|---|---|
| **复杂度算错** | 样例能过、真实数据超时 | 数「基本操作次数」，别只看循环层数（[复杂度分析.md](复杂度分析.md)） |
| **二分死循环** | 程序卡住 | 区间收缩必须**严格变小**；⚠️ `lo = mid` 就是死循环（实测第 1001 步仍未收敛） |
| **`mid` 溢出** | 大数组上行为随机 | 用 `lo + (hi - lo) / 2`（实测溢出值 `-147483648`） |
| **滑窗收缩写成 `if`** | 漏解 | 必须用 `while`（实测穷举 62 个串错 12 个） |
| **双指针没证单调性** | 漏解，很难发现 | 说清「动哪一侧、为什么可以扔掉另一侧」 |
| **摩尔投票不二次验证** | 不存在多数元素时给出错误答案 | 拿到候选后**必须再扫一遍计数** |
| **位运算忽略负数与位宽** | 结果与预期不符 | 用补码视角；⚠️ 移位越界跨语言行为不同 |
| **排序稳定性搞错** | 多关键字排序后顺序乱 | 逐算法记「为什么稳 / 为什么不稳」（[排序算法.md](排序算法.md) 实测保序 3 个、不保序 5 个） |
| **递归爆栈** | 深递归 `stack overflow` | ⚠️ 本机 Go 实测尾递归**没有 TCO**（[递归与分治.md](递归与分治.md)）→ 深递归要改显式栈或加记忆化 |

## 七、与其他思想对比

**本节要点**：基础技巧处在**最底一层** —— 策略层（贪心 / DP / 回溯）负责「决定怎么走」，
基础技巧负责「**把这一步实现得足够快**」。

### 基础技巧 vs 动态规划

| 关系 | 说明 |
|---|---|
| **DP = 递归 + 记忆化** | 递归与分治是 DP 的**写法基础**；加一张 `memo` 表把「重复子问题」去重，就是记忆化搜索（[递归与分治.md](递归与分治.md)） |
| **基础技巧常是 DP 的优化手段** | 二分答案优化决策（[二分查找.md](二分查找.md)）、位运算做状态压缩（[位运算.md](位运算.md)）、滑窗求区间最值 |
| **区别在「子问题是否重叠」** | 分治要求子问题**独立**；一旦重叠，就必须上 DP（[README.md](../动态规划/README.md) 第二节的判断链） |

### 基础技巧 vs 贪心

⭐ **排序是贪心的前置步骤** —— 「按什么键排序」本身就是贪心策略的核心
（活动选择按结束时间、Kruskal 按边权，见 [README.md](../贪心/README.md)）。
另外，**有序数组上的双指针 / 滑窗，常常等价于一种「有序后的贪心」**：每一步的选择都有单调依据，
所以能保证不走回头路。

### 基础技巧 vs 回溯

回溯 = DFS + 撤销选择（[README.md](../回溯/README.md)）；而它的**剪枝条件往往就是一个基础技巧**：

| 剪枝类型 | 用到哪个基础技巧 |
|---|---|
| 排序后跳过重复元素（避免重复解） | [排序算法.md](排序算法.md) |
| 位掩码判冲突（数独候选集） | [位运算.md](位运算.md) |
| 提前判断「不可能更优」 | [二分查找.md](二分查找.md)（若代价单调） |

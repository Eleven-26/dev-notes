## 一、核心思想

**本节要点**：匹配这件事本身很朴素 —— **在主串 `T` 里找模式串 `P` 出现的每个位置**。所有高级算法的功夫都花在同一件事上：**失配之后，能不能少比较一些字符**。

| 朴素匹配的做法 | 代价 |
|---|---|
| 把 `P` 对齐到 `T` 的每个位置，逐字符比 | 一旦失配，`P` **整体右移一格**，主串指针**回退**重比 |

最坏情况（如用 `aaaaaaab` 去匹配 `aaaa...`）会退化成 **`O(n × m)`**：

```text
T = a a a a a a a b
P = a a a a b
    ↑ 每一轮都先匹配 4 个 a，最后一个失配 → 白白重复比较
```

⭐ **所有改进算法都在回答同一个问题**：「已经比对过的那些字符，就没用了吗？」

- **KMP** 的答案是：失配点的**前面**已经匹配上了，那部分信息能告诉我们「`P` 该往右滑多远」，而且**主串指针永不回退**；
- **BM** 的答案是：**从右往左比**，失配时能根据「坏字符」和「好后缀」一次跳很多格；
- **AC 自动机** 的答案是：把多个模式串建成 Trie，**一次扫描主串就能同时匹配所有模式**（多模式）。

## 二、适用条件

**本节要点**：字符串匹配的「适用条件」不是数学性质，而是**场景 + 模式串数量** —— 选型几乎完全由「单模式还是多模式」「文本是否可预处理」决定。

| 场景 | 说明 | 典型算法 |
|---|---|---|
| **文本查找** | 编辑器 / 浏览器的「查找」、日志里的关键字定位 | BM 系（实践中快） |
| **敏感词过滤** | 一次要匹配**一本词典**（几千个词） | **多模式** → AC 自动机 |
| **DNA / 基因序列匹配** | 字母表极小（4 种）、串很长 | KMP / BM，或专门的生物信息学索引（后缀树/后缀数组） |
| **日志关键词搜索** | 多关键词 + 大文本 | AC 自动机（多模式）或倒排索引（全文检索场景） |
| **多模式匹配（任意）** | 模式串数 `k` 大于 1 | ⚠️ **不要跑 `k` 次单模式算法** —— 见 [AC自动机.md](AC自动机.md) 第一节 |

### ⭐ 选型决策：先问「几个模式」

```text
只有 1 个模式串？
   ├─ 是 → 文本长、字母表小（DNA）→ KMP（保证线性，最坏情况不退化）
   │        通用文本、追求平均快   → BM（一次跳很多格）
   └─ 否 → 多个模式串 → AC 自动机（Trie + fail 指针，一趟扫完）
```

⭐ **「多模式别跑 `k` 次单模式」** 是本目录最重要的一条判据：`k` 次 KMP 的复杂度是 `O(k(n+m))`，
而 AC 自动机是 `O(n + Σm + 命中数)` —— 差一个量级，且词典越大差得越多。

## 三、解题模板

**本节要点**：与其它算法族不同，字符串匹配**没有一个统一模板** —— 三种算法的结构差别很大。但它们的**骨架是同构的**：都是「先预处理模式串，再一趟扫描主串」。

### 通用骨架

```text
① 预处理模式串        —— 算出「失配时该往哪跳」的那张表
                          KMP：next（前缀函数）| BM：坏字符表 + 好后缀表 | AC：Trie + fail 指针
② 一趟扫描主串        —— 指针只前进不后退（KMP/BM/AC 都满足）
③ 匹配成功 → 记录位置；失配 → 查①的表，决定「模式串右移多少 / 跳到哪个状态」
④ 重复直到主串走完
```

各算法的差异**只在第 ① 步的表和第 ③ 步的跳法**：

| 算法 | 预处理产出 | 失配时怎么办 |
|---|---|---|
| [KMP.md](KMP.md) | `next[i]` = 最长的「既是前缀又是后缀」的长度 | 模式串指针按 `next` 回退，**主串指针不动** |
| [BM.md](BM.md) | 坏字符表 + 好后缀表 | **从右往左**比，失配时按两张表取**较大的跳跃** |
| [AC自动机.md](AC自动机.md) | Trie + `fail` 指针（BFS 构造） | 沿 `fail` 往回跳，直到能接上当前字符 |

### ⭐ 模板之外的两条通用要求

1. **边界必须想清楚**：模式串为空、模式串比主串长、主串为空 —— 这三种输入在真实调用里都会出现（见第六节）；
2. **跳过所有匹配位置**（而不只是第一个）：工程里常用的 `findAll` 是「命中后继续扫」，注意命中重叠的情况（[AC自动机.md](AC自动机.md) 第五节专门讲了**重叠命中**）。

## 四、经典算法

**本节要点**：按「预处理的是什么」分类，比按名字背要清楚 —— 换一种表，就是另一个算法。

| 算法 | 预处理 | 匹配方向 | 复杂度 | 在哪 |
|---|---|---|---|---|
| **朴素匹配** | 无 | 左 → 右 | `O(n × m)` | 作为对照写在 [KMP.md](KMP.md) 第一节 |
| **[KMP.md](KMP.md)** | `next`（前缀函数） | 左 → 右 | `O(n + m)` 上界，**无退化** | 本目录 |
| **[BM.md](BM.md)** | 坏字符 + 好后缀 | **右 → 左** | 最坏 `O(n × m)`，**实践常快得多** | 本目录 |
| **[AC自动机.md](AC自动机.md)** | Trie + `fail`（BFS 构造） | 左 → 右 | `O(n + Σm + 命中数)`，**多模式** | 本目录 |
| **Rabin-Karp** | 模式串的滚动哈希 | 左 → 右 | 平均 `O(n + m)`，最坏 `O(n × m)` | ⚠️ 待补（哈希思想见 [散列表.md](../../数据结构/哈希表/散列表.md)） |
| **Sunday** | 简化版 BM（只看「窗口后一位」） | 左 → 右 | 同 BM，实现更简单 | ⚠️ 待补（BM 的简化路线见 [BM.md](BM.md) 第四节） |

### ⭐ 三条容易混淆的对照

1. **KMP vs BM**：KMP 保证**最坏情况线性**（不退化），BM 最坏可能退化但在**自然语言文本上平均快得多** —— 因为一次能跳很多格。选谁取决于「你最坏情况敏感，还是平均性能敏感」；
2. **BM 家族 vs KMP**：Sunday / Horspool 都是 **BM 的简化版**，砍掉了复杂的「好后缀规则」，只留「坏字符规则」—— 实现简单、实践中也够用（[BM.md](BM.md) 第四节讲清了砍掉什么）；
3. **KMP vs AC 自动机**：AC 自动机的 `fail` 指针**本质就是「Trie 上的 KMP」** —— 一批模式串共享前缀后，失配跳转的逻辑与 `next` 完全同构（[AC自动机.md](AC自动机.md) 第三节）。

## 五、正确性证明

**本节要点**：三种算法的正确性都归结为同一句话 —— **「跳过的位置，一定不可能匹配成功」**。证明它，就证明算法不漏解。

| 算法 | 保证什么 | 证明的核心 |
|---|---|---|
| **[KMP.md](KMP.md)** | 主串指针不回退也不漏解 | `next[i]` 的定义保证「跳到的是**最长的**可行前缀」→ 比它短的都试过或不可能成功 |
| **[BM.md](BM.md)** | 跳跃是安全的 | 坏字符规则：跳跃后**坏字符不会被跳过**；好后缀规则：跳跃后**已匹配的后缀能对齐** |
| **[AC自动机.md](AC自动机.md)** | 所有模式串都被检查到 | `fail` 指向「最长真后缀」→ 沿 `fail` 链上溯等于枚举了所有可能的后缀匹配 |
| **Rabin-Karp** | 哈希相等时**再逐字符验证** | 哈希相等不等于串相等（有冲突）→ ⚠️ **必须二次验证**，否则漏解 |

### ⭐ 一条通用判据

**「跳跃的安全性」= 跳跃距离不能超过「最小的可行位移」**。

各算法的表，本质上都是**在安全的前提下把位移取到最大**：

- KMP 取「最长的 border」对应位移 → 既安全又跳得最远；
- BM 取坏字符/好后缀两规则算出的**较大者** → 跳得更远（但需要额外证明后者也安全）。

⭐ 还有一类「**摊还论证**」：KMP 的 `O(n + m)` 不是因为「每一步都快」，而是因为**主串指针只增不减**（总移动次数 `≤ n`），模式串指针虽会回退但**总回退量受 `next` 的结构约束**（[KMP.md](KMP.md) 第四节、第五节）。

## 六、常见陷阱

**本节要点**：字符串匹配的坑分两类 —— **边界**（空串、长度关系、编码）与**表算错**（`next` / 哈希 / Trie），两者都属于「不报错但结果错」。

| 陷阱 | 症状 | 怎么避免 |
|---|---|---|
| **边界处理错误** | 空串、模式串比主串长时越界或死循环 | 函数开头先判长度；⚠️ 明确「空模式串」的语义（匹配位置 0，还是视为无匹配） |
| **`next` 数组计算错误** | 漏匹配（该命中的没命中） | ⚠️ 本目录最经典的坑：`next` 有**多种变体**（整体右移一位 / 含不含自身）—— 见 [KMP.md](KMP.md) 第三节 |
| **哈希冲突未处理** | Rabin-Karp 报出**假的匹配位置** | 哈希相等后**必须逐字符复核** |
| **多模式 Trie 构建错误** | 部分模式串永远匹配不到 | 检查「一个模式串是另一个的前缀」这种情况（如 `he` 与 `hers`），命中要在**沿 `fail` 链上溯**时收集 |
| **忽略大小写 / 编码** | 中文、emoji、UTF-16 代理对下位置算错 | 明确「字符」的单位：`byte` / `rune` / `UTF-16 code unit` —— **位置定义不同，结果就不同** |

### 补两个工程上的坑

| 陷阱 | 说明 |
|---|---|
| **返回位置 vs 返回子串** | 不同语言的 API 语义不同（返回索引 / 返回匹配对象 / 返回原串切片），跨语言对照时**先统一语义** |
| **重叠匹配被漏掉** | 匹配 `aa` in `aaaa` 有 **3 个**位置（重叠），而很多实现默认只报不重叠的 2 个 —— [AC自动机.md](AC自动机.md) 第五节有实测 |

## 七、与其他思想对比

**本节要点**：字符串匹配与 DP / 回溯 / 贪心的关系，都出现在「同一类问题的不同解法」上 —— 分清楚**查找**与**求解**的差别就不会混。

### 字符串匹配 vs 动态规划

| | 字符串匹配 | 动态规划 |
|---|---|---|
| 目标 | **查找**（模式串出现的位置） | **求解**（最优值） |
| 典型 | KMP / BM / AC 自动机 | **编辑距离**、LCS |
| 关系 | `next` 数组的构造用了「递推」的思路，但整体不是 DP | 编辑距离也是「两个串的问题」，但目标是**最小代价**而不是定位 |

⭐ 一句话分界：**「在哪出现」是匹配，「差多少才一样」是 DP**。两个串同时出现在问题里时，先问自己求的是哪一个。

### 字符串匹配 vs 回溯

| | 字符串匹配 | 回溯 |
|---|---|---|
| 复杂度 | 多项式（`O(n + m)`） | 指数级 |
| 典型场景 | **正则匹配**常用回溯实现（⚠️ 效率低，可能指数退化） | 全排列、数独 |
| 关系 | 正则里的 `.*` 回溯是真回溯；而「固定模式串」的匹配有更快的专门算法 | — |

⭐ 工程提醒：**正则引擎的回溯可能被恶意输入打爆**（ReDoS）—— 能用字面量匹配就别用正则，能用 KMP/AC 就别用正则跑关键词过滤。

### 字符串匹配 vs 贪心

| | 关系 |
|---|---|
| **KMP 的 `next` 构造有贪心思想** | 每一步都取「**最长的**可行 border」（能延伸就延伸，失配就退到次长的）——「尽量多吃」的贪心直觉 |
| **BM 的跳跃取「较大者」** | 坏字符与好后缀各自给出一个安全位移，取大的那个 —— 也是「在当前约束下取最优」 |
| 但整体都不是贪心算法 | 没有「不回退」这个特征：KMP 的模式串指针会回退（只是有摊还保证） |

⭐ 所以正确的说法是：**字符串匹配算法里借用了贪心的思路，但它本身既不靠贪心正确性，也不需要交换论证** —— 它的正确性来自「跳跃安全」（第五节）。

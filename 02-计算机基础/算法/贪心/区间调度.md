# 区间调度

> 一个更大的家族：**合并区间、选最多不重叠区间、用最少的点覆盖所有区间、带权区间调度**——
> 它们看着都是「一堆区间」，但**能不能贪心、用哪个排序键、什么时候必须 DP**，各不相同。
> 本篇只讲这个家族与判据：**哪些能用贪心、哪些必须 DP、以及怎么一眼认出来**。
>
> ⭐ 与 [活动选择.md](活动选择.md) 的分工：**「按结束时间排序」在那一篇讲透了**
> （交换论证、三种错法的反例、二万组随机验证都在那里）。本篇是那个结论的**用户**，不再重复证明，
> 需要时引用它对应的小节。本篇独有的是：**带权版本为什么必须 DP**、**最少点覆盖怎么证**、**最少资源（对偶）**。
>
> 内容整理自个人学习笔记，素材见 [素材清单](../../../素材清单.md)。区间 DP 的复杂度口径见 [复杂度分析.md](../基础算法/复杂度分析.md)；
> 二分查找与排序的取舍见 [查找与排序对比.md](../基础算法/查找与排序对比.md)。
>
> 📎 本篇所有输出均为本机实跑逐字抄录：**Go 1.26.5（windows/amd64）** 与 **JDK 1.8.0_321** 各实现一份，
> 输出**逐行对齐**（diff 只剩实验五的耗时列）。

## 一、这一族问题到底有几种？

**本节要点**：先把家族摊开 —— 同一堆区间，目标不同就是**不同的算法**。这一节给出五个变体、各自的排序键、以及「贪心能不能用」的判据。

### 1.1 五个变体

| 变体 | 目标 | 排序键 | 能做贪心吗 | 本篇位置 |
|---|---|---|---|---|
| **区间合并** | 把重叠/相接的区间并成最少的几段 | **开始时间** | ✅ 能 | 第二节 |
| **最多不重叠区间** | 选个数最多的一批互不冲突区间 | **结束时间** | ✅ 能 | 见 [活动选择.md](活动选择.md) |
| **最少点覆盖** | 用最少的点，让每个区间都含有至少一个点 | **结束时间** | ✅ 能 | 第三节 |
| **带权区间调度** | 选一族互不冲突区间，使**权值和最大** | — | ❌ **不能，必须 DP** | 第四节 |
| **最少资源（对偶）** | 至少几份资源才排得下（如最少几个会议室） | **开始时间** + 最小堆 | ✅ 能 | 见下方 1.2 |

⭐ 看清楚：**同一堆区间，目标一换，排序键就换、算法类别也换**。把这张表记住，比记住任何单个算法都值。

⚠️ 最容易混的一对是「最多不重叠区间」（按**结束**排序）与「最少资源」（按**开始**排序）——它们是**对偶**问题，答案互为线索，但排序键正好相反。

### 1.2 判据：什么信号说明「贪心不成立」

这是本篇最该带走的一段。**判据只有一个，问的是「第一步」**：

> **能不能找到一个排序键，使得「排在最前的那个」总能被某个最优解采纳？**
> 能 → 贪心可用；不能 → 必须 DP。

具体拆成三条可操作的信号：

| 信号 | 结论 | 例 |
|---|---|---|
| 目标是**计数 / 可行性**（最多几个、能不能覆盖） | 多半能贪心 | 活动选择、最少点覆盖 |
| 目标是**加权和 / 总代价** | **几乎一定不能**贪心 | 带权区间调度（第四节） |
| 某一步的**局部最优依赖后面的权值** | 必须 DP | 带权版本：现在舍弃哪个，取决于后面谁权重大 |

⚠️ **为什么「加权和」会杀死贪心**：贪心能用，是因为「第一个」可以无条件留下（见 [活动选择.md](活动选择.md) 第 2.4 节的交换论证）。可一旦目标是权值和，**要不要留第一个，取决于「留了它会错过多少权值」**——而这只有把后面全算一遍才知道。**局部看不到全局，键就无从定**。

⭐ 一句话判据：**当你发现「先选谁」这个决定需要回头看后面的数据时，贪心就不成立，该上 DP 了。**

### 1.3 与「活动选择」篇的分工

- **那一篇讲**：「按结束时间排序」的证明（交换论证）、按开始/按持续时长会错的反例、随机验证、复杂度实测；
- **本篇讲**：同族里**其他变体**，以及**边界在哪**——尤其是「带权版本必须 DP」这个反例。

⭐ 所以两篇合起来读的顺序是：先 [活动选择.md](活动选择.md)（把「结束时间」这把键吃透）→ 再本篇（看它在家族里的适用范围与失效点）。

## 二、区间合并：排序键换成「开始时间」

**本节要点**：合并是家族里最「结构性」的一个 —— 它不需要交换论证，规则本身就直观。⚠️ 但它的排序键是**开始时间**，与活动选择相反，别混。

### 2.1 规则

| 步骤 | 动作 |
|---|---|
| ① | 所有区间**按开始时间升序**排序 |
| ② | 维护一个「当前段」。下一个区间的**开始 ≤ 当前段的结束**，就合并（把当前段结束时间延到两者较大值） |
| ③ | 否则当前段「封口」输出，用新区间另起一段 |

⚠️ **为什么必须是开始时间**：合并要能把「可能重叠的区间排在一起、逐个试接」。按开始排序后，**能接上的区间一定紧挨着当前段**（因为更晚开始的都排在后面），一次线性扫描就够。若按结束排序，重叠的区间会被打散，接不上。

### 2.2 逐步推演（本机实跑）

```text
================ 实验一：区间合并（按开始排序） ================

  输入：1[1,3] 2[2,6] 3[8,10] 4[15,18] 5[9,12] 6[0,1]
  按开始排序：6[0,1] 1[1,3] 2[2,6] 3[8,10] 5[9,12] 4[15,18]

    新区间 6[0,1] 与前一段接不上 → 另起一段
    区间 1[1,3] 与前一段重叠/相接 → 并入，当前段 [0,3]
    区间 2[2,6] 与前一段重叠/相接 → 并入，当前段 [0,6]
    新区间 3[8,10] 与前一段接不上 → 另起一段
    区间 5[9,12] 与前一段重叠/相接 → 并入，当前段 [8,12]
    新区间 4[15,18] 与前一段接不上 → 另起一段

  合并结果：0[0,6] 0[8,12] 0[15,18]（3 段）
  ⭐ 区间合并的正确排序键是**开始时间**（不是结束时间）—— 这是同族里排序键唯一变化的一个
```

⭐ 两处细节：

- **`[0,1]` 与 `[1,3]` 相接**（`1 ≤ 1`）也算重叠 —— 「相接是否合并」由一个 `≤` / `<` 决定，⚠️ 这与 [活动选择.md](活动选择.md) 里「端点相接算不算冲突」是同一个边界问题，只是取了相反的约定；
- **复杂度 `O(n log n)`**：瓶颈仍在排序；合并本身是 `O(n)` 的线性扫描。

## 三、最少点覆盖：同一把「结束时间」的贪心

**本节要点**：这个变体和活动选择**共用同一把排序键（结束时间）**，但用的位置不同 —— 这里放的是「点」，不是「活动」。这一节给出规则与精确解对照。

### 3.1 规则

| 步骤 | 动作 |
|---|---|
| ① | 区间**按结束时间升序**排序 |
| ② | 取**第一个还没被覆盖**的区间，把点放在它的**右端点** |
| ③ | 这个点覆盖到的所有区间（含该点的）全部标记为「已覆盖」 |
| ④ | 重复 ②③ 直到全部覆盖 |

⚠️ **为什么点放在右端点**：右端点是「这个区间能被覆盖的最靠右位置」，放得越右，越有可能顺带覆盖到后面那些「左端点更大」的区间。这是交换论证在这里的具体形态 —— 与 [活动选择.md](活动选择.md) 第 2.4 节「结束最早的占用未来最少」是同一句话的对偶版。

### 3.2 逐步推演 + 精确解对照（本机实跑）

```text
================ 实验二：最少点覆盖（按结束排序）+ 精确解对照 ================

  输入：1[1,4] 2[2,3] 3[3,6] 4[5,7] 5[6,8] 6[9,11]
  按结束排序：2[2,3] 1[1,4] 3[3,6] 4[5,7] 5[6,8] 6[9,11]

    取第一个未覆盖区间 2[2,3]，把点放在它右端 p=3
      → 覆盖 2[2,3]
      → 覆盖 1[1,4]
      → 覆盖 3[3,6]
    取第一个未覆盖区间 4[5,7]，把点放在它右端 p=7
      → 覆盖 4[5,7]
      → 覆盖 5[6,8]
    取第一个未覆盖区间 6[9,11]，把点放在它右端 p=11
      → 覆盖 6[9,11]

  贪心取点：{3, 7, 11}（3 个点）
  精确解（比特集覆盖 DP）= 3  →  贪心是否最优 = true
```

⭐ **注意 `p=3` 一次性覆盖了三个区间**（`2[2,3]`、`1[1,4]`、`3[3,6]`）—— 这正是「点放右端点」的收益：`3` 是 `[2,3]` 的右端，却恰好落在 `[1,4]` 与 `[3,6]` 内部。若把点放在左端 `2`，就漏掉 `[3,6]` 了。

⚠️ 这里的「精确解」是**比特集覆盖 DP**（候选点取所有端点，对 `2^m` 个覆盖状态取最少的点数），它是**指数级**的，只用来在小规模上当裁判。

### 3.3 二万组随机验证（本机实测）

「一个例子对上」还不够。下面这段随机实验**同时跑了「带权」与「点覆盖」两组对照**，正好把「哪些能贪心」一并测了出来：

```text
================ 实验四：随机对照（带权贪心 vs DP；点覆盖贪心 vs 精确） ================

  带权区间调度：随机用例 20000 个（区间 3~12 个，权 1~20）
    贪心与 DP 权值不符 13087 次（占 65.4%），最大差 54
    其中「贪心选的个数更多、权值却更低」占 1889 次
  最少点覆盖：随机用例 20000 个（区间 3~10 个）
    贪心与精确解不符 0 次（最大差 0）
  ⭐ 同一个「按结束排序」的贪心：用在**最少点覆盖**上从不出错，用在**带权**上错得离谱
```

⭐ **同一个「按结束排序」的贪心，在 2 万次里：点覆盖 0 次出错、带权错 65.4%** —— 这是 1.2 判据的一次正面对照：**目标不同，同一把键成立与不成立**。（带权那一半的读法见 4.3。）

⚠️ 和 [活动选择.md](活动选择.md) 第 3.2 节同样的提醒：**随机测试只能证伪、不能证明**。「点覆盖 0 错」不能替代交换论证，「带权 65.4% 错」则**足以证伪**贪心在带权版本上成立 —— 方向不对称，别记反。

## 四、带权区间调度：贪心失效，必须 DP

**本节要点**：全篇的重点。前三个变体都能贪心，唯独**加权和**这一变体让「按结束时间」的贪心彻底失效 —— 这一节用本机实测把它打出来。

### 4.1 「按结束时间」贪心的失败（本机实测）

![带权区间调度的贪心与DP](images/带权区间调度的贪心与DP.svg)

还是那把「按结束时间」的贪心，只是给每个区间加了权值：

```text
================ 实验三：带权区间调度 —— 贪心失效（本机实测） ================

  输入（编号 [开始,结束] 权值）：
    1[1,4]  权值 100
    2[1,2]  权值 1
    3[2,3]  权值 1
    4[3,4]  权值 1
    5[4,5]  权值 1

  按结束时间贪心：选中 {2, 3, 4, 5}，权值和 = 4
  精确 DP        ：选中 {1, 5}，权值和 = 101
  两者权值差 = 97  →  贪心是否最优 = false
  ⚠️ 贪心选出的活动**个数更多**（4 个 vs 2 个），但权值和只有 4 —— 与最优 101 差了 25 倍
```

⚠️ **这个结果是「个数最优」与「权值最优」分道扬镳的最短证据**：

- 贪心选出的 **4 个**区间，恰好就是**个数最多**的解 —— 所以它**在旧目标（个数）下是完美的**；
- 但那 4 个的权值全是 1，加起来才 4；而 DP 只选 **2 个**（`[1,4]` 权 100 + `[4,5]` 权 1），权值和 101；
- **`25 倍`的差距，来自「贪心为了多选几个轻区间，丢掉了那个重区间」**。

⭐ 这正是 1.2 判据的现场：**「要不要留 `[1,4]`（权 100）」这个决定，取决于「后面有没有更好的组合」—— 而这要回头看完才知道，局部看不到。** 所以没有一把排序键能一概而论，贪心在这里**结构性地**不成立。

### 4.2 DP 的递推式

按结束时间排序后（记作 `1..n`）：

1. **`p(j)`** = 最大的下标 `i < j`，使得 `f_i ≤ s_j`（即「与 `j` 兼容的、最靠后的那个」）；
2. **`OPT(j) = max( w_j + OPT(p(j)), OPT(j−1) )`** —— 要么**选** `j`（再拼上它前面能兼容的最优），要么**不选** `j`（看前 `j−1` 个）；
3. 答案 = `OPT(n)`。

⭐ 与 [活动选择.md](活动选择.md) 的 DP 对照着看：**活动选择是它的 `w ≡ 1` 特例**。所以「活动选择能不能也用这个 DP」的答案是「能，但没必要」——贪心更快更简单，而 DP 才是那个能扩展到带权情形的通用形式。

⚠️ **`p(j)` 是这道题的枢纽**：它把「兼容性」这个二维关系压成了一维下标，DP 才成立。`p(j)` 用线性回溯是 `O(n²)`、用二分是 `O(n log n)`（见第五节）。

### 4.3 随机对照：错 65.4%

带权那一半的随机结果（完整输出与「点覆盖 0 错」的对照一起在 3.3）：

⭐ 三处读法：

- **错 65.4%**（13087 / 20000）：带权版本上，「按结束时间」贪心**大部分时候都是错的**，不是偶发；
- **最大差 54**：小规模（权值上限才 20）就能差出 54 —— 说明损失是**系统性的**，随规模放大；
- ⚠️ **1889 次是「贪心个数更多、权值却更低」**：这是最典型的失败形态 —— 你的贪心**在旧目标下看起来更好**（选了更多区间），**在新目标下更差**。**目标一换，原来的「好」就变成了陷阱。**

## 五、DP 也能做到 O(n log n)

**本节要点**：说「必须 DP」不等于「一定要 `O(n²)`」。这一节把 `p(j)` 用二分加速，实测它与朴素实现的差距。

### 5.1 朴素 O(n²) vs 二分 O(n log n)（本机实测）

```text
================ 实验五：带权 DP 的两种规模实现 ================

  区间数      结果(权值)      朴素 O(n²) ms/次      二分 O(n log n) ms/次      朴素/二分
  4000        295234              25.7302                  2.5457          10.11×   （重复 4/33 轮）
  8000        434610             108.5658                  5.2125          20.83×   （重复 1/20 轮）
  16000       626502             457.4832                 12.3231          37.12×   （重复 1/9 轮）
  两实现结果一致 = true

  ⚠️ 耗时列两语言必然不同（本机 Go time.Now 分辨率约 1ms，多轮累加取平均）；
     结果列（权值）与「两实现结果一致」两语言逐字相同。
```

本机多轮运行的范围（5 次）：

| 区间数 | 朴素 `O(n²)` | 二分 `O(n log n)` | 倍数 |
|---|---|---|---|
| 4000 | 24.3 ~ 46.3 ms | 2.3 ~ 3.3 ms | **10 ~ 16×** |
| 8000 | 93.6 ~ 145.8 ms | 4.7 ~ 5.6 ms | **18 ~ 27×** |
| 16000 | 457 ~ 962 ms | 12.2 ~ 25.0 ms | **34 ~ 40×** |

⭐ **只断言趋势**（`time.Now` 粒度问题，见 [Dijkstra.md](../图论算法/最短路/Dijkstra.md) 第 4.3 节）：

- **区间数翻倍，朴素版约变 4 倍**（`26 → 109 → 457`，典型平方增长）；二分版只变约 2~2.3 倍（`n log n`）；
- **倍数随规模上升**（10× → 21× → 37×）。⚠️ 小规模上两者都在几毫秒内、看不出差别 —— 复杂度要**靠规模才显形**；
- 「两实现结果一致 = true」：加速没有改变答案，只是换掉了 `p(j)` 的求法。

⚠️ **小结这一族算法的复杂度**：

| 变体 | 复杂度 | 瓶颈 |
|---|---|---|
| 区间合并 | `O(n log n)` | 排序 |
| 最多不重叠区间（贪心） | `O(n log n)` | 排序 |
| 最少点覆盖（贪心） | `O(n log n)` | 排序 |
| 带权区间调度（DP） | `O(n log n)` | 排序 + 二分求 `p(j)` |
| 带权区间调度（朴素 DP） | `O(n²)` | `p(j)` 的线性回溯 |

⭐ 看出来了没有：**差距不在「贪心 vs DP」，而在「有没有把子结构算对」** —— 带权 DP 优化到 `O(n log n)` 后，与贪心同阶。**所以选型的依据从来不是「谁的复杂度低」，而是「这个问题允许不允许贪心」。**

## 使用：这一族问题在系统里长什么样

「区间」在工程里几乎无处不在，只是很少被叫「区间」。按变体逐层看：

**第一层：区间合并 —— 让数据变紧凑**。压缩里的 RLE 会把**相邻的相同取值**并成一段「游程」（见 [../压缩算法.md](../压缩算法.md)）；时序数据落库前把相邻的连续区间并成一条；权限/网段的白名单区间归并。⚠️ **判据**：只要你在做「把重叠或相接的段并起来」，它就是区间合并，排序键是**开始时间**。

**第二层：最多不重叠 / 最少资源 —— 资源编排**。会议室排期、单核任务窗口、时隙分配是活动选择（见 [活动选择.md](活动选择.md)）；它的对偶「最少几个会议室」则是按开始时间 + 最小堆。⚠️ **别把两者排序键记混**：一个是结束时间、一个是开始时间。

**第三层：带权区间调度 —— 带收益的排期**。这才是工程里更常见的那一种：任务有优先级 / 收益 / 权重，排期要**总收益最大**而不是**个数最多**。广告位投放（每个广告位有预估收益）、带宽租赁（每条链路有价格）、机位/仓位分配（每个仓位有利润）——全是带权区间调度。⚠️ **只要目标里出现了「收益/权重/优先级」，就别再套贪心**，照 4.2 上 DP。

⭐ **归纳成一条判断**：**先问目标，再选算法**。

| 你要的 | 用什么 |
|---|---|
| 把段并起来 | 区间合并（按开始排序） |
| 「最多几个 / 最少几个」 | 贪心（活动选择用结束时间、最少资源用开始时间） |
| 「收益最大 / 代价最小」 | **DP**（4.2 的递推式） |

⚠️ 换目标不换算法的后果，本机在 4.1 已经量化：**同一个贪心，换个目标就从「最优」变成「差 25 倍」**。

## 延伸追问

- **为什么「按结束时间」在活动选择里对、在带权版本里错？** → 因为活动选择的交换论证只保证「结束最早的可以被留下」，**从没说过「留下的权值最大」**（见 [活动选择.md](活动选择.md) 第 2.4 节）。⚠️ 目标一换成权值和，这条论证就不再回答问题了。
- **带权版本的判据是什么？** → 一句话：**「选不选第一个」取决于后面全部区间的权值**（本篇 1.2、4.1）。局部决策依赖全局数据，键就定不下来，只能 DP。
- **那 DP 具体怎么做？** → 按结束时间排序，`p(j)` = 与 `j` 兼容的最靠后下标，`OPT(j) = max(w_j + OPT(p(j)), OPT(j−1))`（本篇 4.2）。⭐ 活动选择就是这个递推在 `w ≡ 1` 时的特例。
- **`p(j)` 怎么求？** → 因为排序后结束时间非降，`p(j)` 就是「结束时间 ≤ `s_j` 的最大下标」，**天然的二分点**。线性回溯 `O(n²)`、二分 `O(n log n)`（本篇第五节实测：规模一大差 10~40 倍）。
- **最少点覆盖为什么能贪心？** → 点放右端点能让它覆盖到「左端点尽可能大」的后续区间，可用与活动选择同型的交换论证证明（本篇 3.1）。⚠️ 它是「计数型」目标，所以落进了 1.2 判据的「能贪心」一侧。
- **「最少几个会议室」怎么做？** → 按**开始时间**排序，用一个最小堆存各房间的当前结束时间；新会议来就复用已腾出的房间，堆的最大长度即答案。⚠️ 这是活动选择的**对偶**，排序键**正好相反**，别混。
- **区间合并为什么不能用「按结束时间」排序？** → 因为合并要求「可能相接的区间挨在一起逐个试接」。按结束排序会把重叠区间打散，接不上（本篇 2.1）。⚠️ 同一族里，排序键是**跟着目标走的**。
- **端点相接到底算不算重叠？** → **由业务定**，不是算法定。本篇合并取「相接即合并」（`≤`），活动选择取「相接即兼容」（`f ≤ s`）。⚠️ 一个 `≤` / `<` 的差别就能改变结果，与 [限流算法.md](../../../04-架构与系统/分布式/服务治理/限流算法.md) 里「窗口边界算哪边」是同一类坑。
- **为什么随机测试能发现贪心失效？** → 因为失效是**结构性**的、不是偶发的：本机 2 万个带权用例里错了 65.4%（本篇 4.3）。⚠️ 但反过来说：**计数型的变体（最少点覆盖）2 万次一次没错** —— 同一个随机实验，正好把「哪些能贪心」也测了出来。
- **和 [Dijkstra.md](../图论算法/最短路/Dijkstra.md) 有什么共通点？** → 都是「先排序/取极值，再线性扫描」，且正确性都依赖一个**具体的不变量**；两篇也都靠 `seq` 之类的确定性 tiebreak 来保证跨语言输出可复现。
- **活动选择为什么不用本节的 DP？** → 能用，但没必要：`w ≡ 1` 时它退化成 [活动选择.md](活动选择.md) 的贪心，而贪心更快、更简单、还能流式处理。**能用贪心就别上 DP** —— 判据见 1.2。

# 树形 DP

> 状态定义在**树节点**上的 DP：自底向上递归，先算子树再把结果汇总到当前节点。典型题有打家劫舍 III、树的直径、最大路径和。

## 一、树形 DP 的核心思想

**本节要点**：四步法一样，只是「阶段图」从数组下标换成了树形 —— 依赖沿父子边从叶子往根传，所以骨架天然是后序遍历。

- 状态定义在**节点**上：`dp[u][state]`
- 转移：**先递归处理所有子树**，再合并到当前节点（**后序遍历**）
- 常见状态：选 / 不选、颜色、路径长度、覆盖情况

⭐ **后序遍历是树形 DP 的自然骨架**：子节点算完，父节点才能汇总。

⚠️ 例外是「换根」类问题：父节点的状态要依赖「去掉自己子树后的全树信息」，单趟后序不够 —— 见延伸追问最后一条。

---

## 二、模板：为什么骨架是一段后序 DFS？

**本节要点**：模板就是把「合并 dp[v]」塞进后序 DFS 的递归返回点之前，dp[u] 的初始化放在函数开头。

```go
func dfs(u int) {
	// 初始化 dp[u]
	for _, v := range children(u) {
		dfs(v)
		// 把 dp[v] 合并到 dp[u]
	}
}
```

⭐ `children(u)` 和循环体里的合并逻辑由题目决定，骨架不变。

⚠️ 与 [记忆化搜索.md](../记忆化搜索.md) 的分工：树形 DP 的每个子树**天然只被访问一次**（树上没有两条路径汇到同一个节点），没有重叠子问题，所以通常**不需要缓存**；一旦题目背景是「图 / 带重复子问题的递归」，才需要补 memo —— 那条路走的是记忆化搜索。

## 三、典型题有哪些？

**本节要点**：五类题共用 `dp[u][有限状态]` 的形状，差别在状态含义 —— 选/不选（独立集）、单值深度（直径 / 路径和）、多色覆盖、容量维度（树上背包）；第一节先用小树手推一遍自底向上的汇总。

### 3.1 打家劫舍 III

- 每个节点可选 / 不选
- `dp[u][0]` = 不选 u 的最大收益；`dp[u][1]` = 选 u
- 转移：
  - `dp[u][0] = Σ max(dp[v][0], dp[v][1])`
  - `dp[u][1] = val[u] + Σ dp[v][0]`

```text
小例子（问最多能偷多少）：
            3
           / \
          2   3
           \   \
            3   1

后序自底向上算 dp[u] = (不选, 选)：
  叶 3（左下）：(0, 3)          叶 1（右下）：(0, 1)
  节点 2：   不选 = max(0,3) = 3；选 = 2 + 0 = 2   → (3, 2)
  节点 3（右）：不选 = max(0,1) = 1；选 = 3 + 0 = 3  → (1, 3)
  根 3：    不选 = max(3,2) + max(1,3) = 6；选 = 3 + 3 + 1 = 7
答案 = max(6, 7) = 7（偷根和两个叶子）
```

![后序汇总的小树](images/树形DP的后序遍历与打家劫舍III.svg)

后序自底向上：两个叶子 dp = (0,3)、(0,1)，节点 2 得 (3,2)、节点 3（右）得 (1,3)，根得 (6,7)，答案 = max(6,7) = 7；右栏写出 dp[u][0] / dp[u][1] 的合并式。

⭐ 与 [线性DP.md](../线性与序列/线性DP.md) 2.3 的打家劫舍转移**完全同形** —— 链就是一棵退化的树，两篇合起来看就是「同一转移、不同阶段图」。

![链版与树版同形](images/树形DP与线性版的同形对照.svg)

链版与树版是同一副转移方程：链上 dp[i][0] = max(dp[i-1][0], dp[i-1][1])、dp[i][1] = dp[i-1][0] + val[i]；树上换成 dp[u][·] 对各个子节点求和 —— 链就是一棵退化的树。

### 3.2 树的直径

- 一条路径经过某节点时，长度 = 该节点两个最长子树深度之和 + 1
- 一次 DFS 维护「最深路径」并更新全局答案

⭐ 答案**不在根上、在途中**：与 [LIS.md](../线性与序列/LIS.md) 1.2 的「答案是 `max(dp)` 而不是 `dp[n-1]`」是同一个坑 —— 只要最优解可能"停在半路"，就得边走边更新全局值。

### 3.3 二叉树的最大路径和

- 类似直径，但节点值可正可负
- `dp[u]` 表示从 u 向下延伸的最大路径和

### 3.4 树的最小覆盖 / 独立集

- `dp[u][0/1/2]` 表示 u 的不同状态
- 典型：没有上司的舞会、监控二叉树

### 3.5 树上背包（依赖背包）

- 每个节点是一个物品：重量 `w[u]`、价值 `v[u]`
- 约束：**选子节点必须先选它的父节点**（依赖关系是一棵树）
- 求总重量 ≤ `K` 时的最大价值

⭐ **状态定义**：`dp[u][j]` 在 `j > 0` 时表示**在「u 必选」的前提下**、子树 `u` 内总重量恰好为 `j` 的最大价值；`dp[u][0] = 0` 是**「不选 u」的哨兵**（此时子树里一个节点都不能选）。

- 初始化：`dp[u][0] = 0`；`dp[u][w[u]] = v[u]`（`w[u] > K` 时不设这一项）
- 合并孩子 `v`：`ndp[j+k] = max(ndp[j+k], dp[u][j] + dp[v][k])`，其中 `k = 0` 表示**不选 `v`**（贡献 0），`k > 0` 表示选了 `v`
- 答案：`max_j dp[root][j]`（`dp[root][0] = 0` 已包含「什么都不选」）

⚠️ **最容易写错的一处**：`dp[u][0]` 这个哨兵只能和孩子的 `k = 0` 合并；一旦让它吸收 `k > 0`，就等于允许「父节点不选、却选了子节点」，依赖约束被直接破坏。本机代码显式挡住了这条边：

```go
for j := 0; j <= K; j++ {
	if dp[j] < 0 {
		continue
	}
	for k := 0; k <= K-j; k++ {
		if cdp[k] < 0 {
			continue
		}
		if j == 0 && k > 0 { // ⭐ u 不选时，孩子一个都不能选
			continue
		}
		if val := dp[j] + cdp[k]; val > ndp[j+k] {
			ndp[j+k] = val
		}
	}
}
```

⭐ **为什么它本质上是一次「分组背包的卷积」**：每个孩子 `v` 提供一组互斥选项「不选 `v`（`k = 0`）」或「选 `v` 且用掉 `k` 的重量（`k > 0`）」，父节点把各组逐个卷起来 —— 与 [背包问题.md](背包问题.md) 里的分组背包同形，只是「组」由树的边决定。

![树上背包：子树 dp 表逐组合并，以及 dp[0] 的依赖陷阱](images/树上背包的子树合并.svg)

左侧是节点 `u` 与两个孩子；中间把 `dp[v1]`、`dp[v2]` 依次卷进 `dp[u]`（`k = 0` 这一列代表不选该孩子）；右侧标出 `j = 0` 时禁止吸收 `k > 0` 的那条边 —— 这正是依赖约束的落点。

**本机实测**（固定种子随机树，重量与价值均取 `1..10`）：

```text
小树对拍：100 棵（n=12，容量 20）
  不一致=0；DP 平均内层循环=541；暴力平均合法子集=247（全子集 4096）

规模实验：n=20，容量 100
  答案 DP=110，暴力=110，一致=true
  DP 内层循环=14185；暴力枚举=1048576 个子集，其中依赖合法=9661
```

⚠️ **两个数字要读对**：`541 > 247` 并不说明 DP 更差 —— 暴力要枚举**全部 `4096` 个子集**，其中只有 `247` 个满足依赖；DP 的 `541` 次内层循环是在**容量表**上做卷积，规模由 `K` 决定而不是 `2^n`。`n = 20` 时差距更明显：`14185` 次对 `1048576` 次枚举。

⚠️ **复杂度不是线性的**：每个节点合并孩子时要做一次 `O(K²)` 的卷积，最坏 `O(nK²)`（本节代码按满容量循环）。把 `j`、`k` 的上界收紧到「当前子树大小」与「孩子子树大小」能减少大量无效枚举，但一般情形的最坏界仍是 `O(nK²)` —— 这也是下一节「树形 DP 通常线性」的唯一例外。

## 四、复杂度

**本节要点**：每节点恰好访问一次，总代价 = 节点数 × 单点合并代价，所以状态数固定的题大多是线性的；**树上背包是例外** —— 合并的是两张容量表，代价多出一个 `K²`。

| 维度 | 值 |
|---|---|
| 时间 | O(n) 或 O(n × 状态数)；**树上背包 O(nK²)** |
| 空间 | O(n × 状态数)（递归栈 + DP 数组）；树上背包 O(nK) |

⭐ **树形 DP 的复杂度通常是线性的**：每个节点只被访问一次。⚠️ 但「访问一次」不等于「常数代价」—— 3.5 每次合并要做 `K²` 的卷积，总代价是 `O(nK²)`。

## 延伸追问

- **树形 DP 为什么用后序遍历？** → 父节点的状态依赖子树结果，必须等子树算完（第一节的骨架）。
- **树形 DP 和普通 DP 的区别？** → 依赖结构由树决定，不是数组下标顺序；递归是自然的实现方式。对照：阶段图是线的见 [线性DP.md](../线性与序列/线性DP.md)、是区间的见 [区间DP.md](../线性与序列/区间DP.md)、是集合的见 [状态压缩DP.md](../优化与高级/状态压缩DP.md)。
- **如何避免递归爆栈？** → 用迭代式后序遍历（实现细节见 [树的遍历.md](../../../数据结构/树/树的遍历.md)），或加栈深度限制（Go 的 goroutine 栈会动态增长）。
- **树形 DP 的状态怎么设计？** → 从「当前节点的哪些属性会影响父节点」反推。常见：选 / 不选、颜色、是否被覆盖 —— 还是「转移要用到的信息必须进状态」那条原则（[背包问题.md](背包问题.md) 2.1）。
- **换根 DP 是什么？** → 先求以 1 为根的答案，再通过「换根」递推其他节点为根时的答案，避免每个节点重跑一遍 DFS 的 O(n²)。
- **树上背包和普通背包是什么关系？** → 每个孩子 `v` 是一组互斥选项（不选，或选 `v` 并用掉 `k` 的重量），父节点把各组卷起来 —— 与 [背包问题.md](背包问题.md) 的分组背包同形，只是分组由树边决定。⚠️ 它比普通背包多一条「选子必先选父」，实现上靠「`j = 0` 不吸收 `k > 0`」这条判断兜住（3.5）。

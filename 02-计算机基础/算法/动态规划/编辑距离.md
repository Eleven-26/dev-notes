# 编辑距离

> 两个字符串之间「最少几次增删改」才能互相转换 —— 经典二维 DP，也是 diff、拼写纠错、DNA 比对的基础。

> 其他 DP 分类见 [README.md](README.md)。

## 一、编辑距离到底在算什么？

**本节要点**：给定两个串，求「插入 / 删除 / 替换一个字符」三种操作下把一个变成另一个的最少步数 —— 操作集合决定距离的定义，先把边界划清再动手。

### 1.1 问题陈述

给定字符串 `a`（长度 m）和 `b`（长度 n），求把 `a` 变成 `b` 的最少操作数。允许的操作：

- 插入一个字符
- 删除一个字符
- 替换一个字符

⭐ 不同操作集合下的答案不同 —— 第四节的变体表全是「操作集合」的**子集关系**：允许的操作越多，距离只会更小或相等。

### 1.2 与几个近邻的分工

⚠️ 本篇算的是**容错匹配**（允许对不上），与「子串精确匹配」（KMP 那一类）是两个方向的问题 —— 这条边界在 [LCS.md](LCS.md) 开篇已经划过，本篇沿用它的口径。

## 二、二维 DP 怎么定状态、怎么写转移？

**本节要点**：状态是「前缀 vs 前缀」，与 LCS 同一套起手式；转移在**上、左、左上**三个邻居里取 `min`；再拿一张 6×4 的小表手推一遍填表顺序。

### 2.1 状态、初始化、转移

- 状态：`dp[i][j]` = `a` 前 i 个字符变成 `b` 前 j 个字符的最少操作数
- 初始化：
  - `dp[i][0] = i`（删掉 i 个字符）
  - `dp[0][j] = j`（插入 j 个字符）
- 转移：
  - 若 `a[i-1] == b[j-1]`：`dp[i][j] = dp[i-1][j-1]`（这一位白配，不花钱）
  - 否则：`dp[i][j] = 1 + min(dp[i-1][j], dp[i][j-1], dp[i-1][j-1])`
    - `dp[i-1][j]`：删除 `a[i-1]`
    - `dp[i][j-1]`：插入 `b[j-1]`
    - `dp[i-1][j-1]`：把 `a[i-1]` 替换成 `b[j-1]`

⚠️ 下标写 `i-1`、`j-1` 是因为 `dp` 按「前几个字符」计数、而字符串从 0 数起 —— 与 [LCS.md](LCS.md) 1.2 的「前缀长度即阶段」是同一个约定。

### 2.2 实现

```go
func minDistance(a, b string) int {
	m, n := len(a), len(b)
	dp := make([][]int, m+1)
	for i := range dp {
		dp[i] = make([]int, n+1)
		dp[i][0] = i
	}
	for j := 0; j <= n; j++ {
		dp[0][j] = j
	}
	for i := 1; i <= m; i++ {
		for j := 1; j <= n; j++ {
			if a[i-1] == b[j-1] {
				dp[i][j] = dp[i-1][j-1]
			} else {
				dp[i][j] = 1 + min(dp[i-1][j], dp[i][j-1], dp[i-1][j-1])
			}
		}
	}
	return dp[m][n]
}
```

⭐ `min` 直接吃三个参数 —— Go 1.21+ 内置了变参 `min` / `max`，不用再手写 `min3`。

### 2.3 手推一张小表：`horse → ros`

```text
a = horse（行）  b = ros（列）；ε 表示空串，答案在右下角 = 3

       ε    r    o    s
  ε    0    1    2    3
  h    1    1    2    3
  o    2    2    1    2
  r    3    2    2    2
  s    4    3    3    2
  e    5    4    4    3   ← dp[5][3]

逐格只看三个邻居（上、左、左上）：
  dp[2][2]（o 对 o，命中）= dp[1][1] = 1          —— 相等不花操作
  dp[3][1]（r 对 r，命中）= dp[2][0] = 2
  dp[5][3]（e 对 s，未中）= 1 + min(上 2, 左 4, 左上 3) = 3
还原成操作：替换 h→r、删 o、替换 e→s（horse→rorse→rose→ros），恰好 3 步
```

⭐ 读法：**行、列都从前到后扫，三个依赖（上 / 左 / 左上）永远落在已算好的格子里** —— 这就是「前缀 vs 前缀」类状态自带的填表顺序。依赖不再天然是「更小前缀」的问题（比如按区间长度填表），见 [区间DP.md](区间DP.md) 第二节。

## 三、复杂度与空间优化

**本节要点**：时间 `O(m × n)`、每格 `O(1)`；空间可以压到一维滚动，但**要先留住左上角的旧值**，且内层方向与 0-1 背包相反。

| 维度 | 值 |
|---|---|
| 时间 | O(m × n) |
| 空间 | O(m × n)，可滚动数组优化到 O(min(m,n)) |

⭐ **滚动数组**：`dp[i][j]` 只依赖上一行与本行，可用一维数组优化空间，但要注意**先保存 `dp[i-1][j-1]` 的旧值**再覆盖。

⚠️ 内层必须**正序**（左邻格要读「本行新值」）—— 方向判据与「0-1 背包要逆序」的完整对照表写在 [LCS.md](LCS.md) 3.4 与 [背包问题.md](背包问题.md) 第三节，本篇不重讲。

## 四、有哪些常见变体？

**本节要点**：变体全部是「换操作集合」—— 其中 LCS 距离与 Levenshtein 的关系（恒等式 + 转移对照）已在 [LCS.md](LCS.md) 第四节完整推过，本篇只留速查表。

| 变体 | 操作 | 备注 |
|---|---|---|
| Levenshtein | 增 / 删 / 改 | 本篇 |
| LCS 距离 | 只允许增删 | 等于 `m + n - 2*LCS`，推导见 [LCS.md](LCS.md) 第四节 |
| Hamming 距离 | 只允许改 | 等长字符串 |
| Damerau-Levenshtein | 加相邻字符交换 | 拼写纠错更准 |
| 加权编辑距离 | 每种操作不同代价 | 更贴近实际 |

## 五、它出现在哪些真实场景里？

**本节要点**：一切「量两条有序序列有多像」的问题，都能套进这套二维 DP。

- `diff` 命令与 Git 变更展示
- 拼写纠错、搜索建议
- DNA / 蛋白质序列比对
- 语音识别结果纠错

⭐ 其中 `diff` 为什么不直接跑 `O(m×n)` 的表、而要按「编辑脚本」做剪枝，展开在 [LCS.md](LCS.md) 的「使用」一节与 [Git命令与使用场景.md](../../../06-工程实践/版本控制/Git命令与使用场景.md)。

## 延伸追问

- **编辑距离的空间怎么优化？** → 一维数组滚动，先保存左上角旧值再覆盖（第三节）。⚠️ 方向是正序，判据见 [LCS.md](LCS.md) 3.4。
- **LCS 距离和编辑距离什么关系？** → 只允许增删时 `距离 = m + n - 2*LCS`；恒等式与 Levenshtein 的对照推导在 [LCS.md](LCS.md) 第四节，本篇不重复。
- **为什么初始化是 `dp[i][0] = i`？** → 前 i 个字符变到空串只能全删掉，要删 i 次；`dp[0][j] = j` 同理只能全插入。
- **编辑距离能处理长度不等的字符串吗？** → 能，天然支持 —— 插入与删除两个操作就是消化长度差的。
- **超长字符串怎么算编辑距离？** → 用带剪枝的算法（如 Ukkonen：只算距离不超过阈值 k 的对角带），或先做分块近似。

# 数位 DP

> 统计「在 [L, R] 区间内，满足某种数位约束」的数的个数 —— 把数字拆成一位一位，用「是否贴着上界」作为状态，避免枚举所有数。
>
> ⭐ 边界先说清：本篇讲数位 DP 的通用模板（limit / lead / state 三件套）与典型题。
> 其他 DP 分类见 [线性DP.md](线性DP.md)、[状态压缩DP.md](状态压缩DP.md)；
> 组合计数见 [组合数学.md](../数学基础/组合数学.md)。
>
> 内容整理自个人学习笔记，素材见 [素材清单](../../../素材清单.md)。复杂度口径见 [复杂度分析.md](../基础算法/复杂度分析.md)。

## 一、什么时候用数位 DP？

**本节要点**：问的是「计数」，条件作用在数的**逐位形态**上，而数位长度只有 18~19 位 —— 状态空间极小，代价几乎可以忽略。

- 问「在 [L, R] 内有多少个数满足条件」
- 条件与**数位本身**相关（如「不含 4」「相邻两位差为 1」「数位和为 K」）
- 直接枚举 O(R−L) 太大，但数位长度只有 18~19 位

⭐ **判据**：**问区间内满足数位约束的数的个数 → 数位 DP。**

---

## 二、状态里的三个关键位

**本节要点**：`pos` 管「处理到哪一位」，`limit` 管「当前位最多能枚举到几」，`lead` 管「前导零算不算进数位」—— 前两项每个题都有，第三项按题目取舍。

把数字按位（高位到低位）处理，状态包含三个关键信息：

| 状态位 | 含义 |
|---|---|
| `pos` | 当前处理到第几位 |
| `limit` | 是否贴着上界（true = 前面所有位都等于上界） |
| `lead` | 是否有前导零（true = 前面全是 0） |
| `state` | 与题目相关的额外状态（如「上一位是多少」「数位和」） |

- `limit = true` 时，当前位只能枚举 `0..digits[pos]`
- `limit = false` 时，当前位可以枚举 `0..9`
- `lead = true` 时，当前位是 0 不能当作真正的数位处理

### 2.1 「贴界」怎么走：一个手推例子

```text
统计 [1, 257] 中不含数字 4 的数：拆位 digits = [2, 5, 7]（高位在前）

pos0：选 2 → 仍贴界（limit = true）      选 0/1 → 解除贴界，后面每位都可取 0..9
pos1（沿 2 的分支）：选 5 → 仍贴界       选 0..3 → 解除贴界
pos2（沿 25 的分支）：可取 0..7 里的合法值，逐个计入答案

⭐ 一旦贴界解除，剩下几位与上界再无关系 —— 结果只由 (pos, state) 决定，进 memo
⭐ 求 [L, R] 用前缀做差：f(R) − f(L−1)
```

## 三、模板

**本节要点**：一个四参数的 dfs（pos / limit / lead / state），缓存**只在「不贴界且无前导零」时读写** —— 这是整个模板最容易写错的一处。

```go
func digitDP(n int) int {
	digits := toDigits(n) // 高位在前
	// 键 = (pos, state)，只缓存「既不贴界也无前导零」的状态；state 维度按题目增删
	memo := map[[2]int]int{}
	var dfs func(pos int, limit, lead bool, state int) int
	dfs = func(pos int, limit, lead bool, state int) int {
		if pos == len(digits) {
			return 1 // 已定完所有位：凑成一个合法数（返回值视题目）
		}
		if !limit && !lead {
			if v, ok := memo[[2]int{pos, state}]; ok {
				return v
			}
		}
		up := 9
		if limit {
			up = digits[pos] // 贴着上界：当前位最多取 digits[pos]
		}
		res := 0
		for d := 0; d <= up; d++ {
			next := limit && d == up
			if lead && d == 0 {
				res += dfs(pos+1, next, true, state) // 前导零不算进 state
			} else {
				newState := state*10 + d // 占位：按题目更新（如只记上一位 / 数位和）
				res += dfs(pos+1, next, false, newState)
			}
		}
		if !limit && !lead {
			memo[[2]int{pos, state}] = res
		}
		return res
	}
	return dfs(0, true, true, 0)
}
```

⭐ **`limit` 和 `lead` 为 false 时才能查 memo** —— 因为它们会限制后续位的取值范围，此时同一个 `(pos, state)` 的答案**不再只由自己决定**，缓存就会串味。

⚠️ 这个模板就是 [记忆化搜索.md](记忆化搜索.md) 第二节三要素（状态定义 / 边界条件 / 转移方程）的直接套用 —— dfs 里的三段与之逐一对应。

## 四、典型题有哪些？

**本节要点**：典型题只换 `state` 那一维，模板骨架一字不动 —— 认出「要记住什么才能判断下一位」就算建模完成。

| 题 | 状态 |
|---|---|
| 数字 1 的个数 | 统计 1 出现的次数 |
| 不含 4 的数字 | 简单约束 |
| 数位和等于 K | state = 当前数位和 |
| 相邻两位差不超过 1 | state = 上一位数字 |
| 数字中至少出现一次 3 | state = 是否已出现 |

## 五、复杂度

**本节要点**：位数 ≤ 19、状态数通常 ≤ 100，再乘每位 10 种取值 —— 总量小到可以对任意 64 位上界「想算就算」。

| 维度 | 值 |
|---|---|
| 时间 | O(位数 × 状态数 × 10) |
| 空间 | O(位数 × 状态数) |

⭐ 位数 ≤ 19，状态数通常 ≤ 100，所以总复杂度极小。

## 延伸追问

- **数位 DP 为什么用记忆化？** → 大量状态重复（尤其是 limit=false 时），记忆化能把指数级降到多项式 —— 骨架见 [记忆化搜索.md](记忆化搜索.md)。
- **`limit` 和 `lead` 有什么区别？** → `limit` 控制枚举上界，`lead` 控制前导零是否被当作数位（第二节的表）。
- **为什么状态要包含 limit？** → limit=true 时枚举范围被上界的这一位卡住，与 limit=false 时的结果不同，两种状态**不能共用缓存**。
- **求 [L, R] 的答案怎么做？** → 拆成 `f(R) - f(L-1)`（2.1 末行），做一次「前缀做差」。
- **和「状态压缩」里的位运算怎么区分？** → 状压的 bit 是「集合成员」，数位 DP 的位是「十进制的一位」，语义完全不同 —— 判据见 [状态压缩DP.md](状态压缩DP.md) 3.4。

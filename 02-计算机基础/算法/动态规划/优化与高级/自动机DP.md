# 自动机 DP

> 覆盖：把 **AC 自动机的状态**作为 DP 的一维，统计「长度为 `n` 的串里有多少个不含（或至少含一个）给定模式」——
> 核心是**先把 goto 补全、把 `bad` 沿 fail 链传下去**，再按长度逐层转移。
>
> 不覆盖：AC 自动机的 Trie、fail 指针与输出链构造见 [AC自动机.md](../../字符串匹配/AC自动机.md)；
> Trie 的结构与内存代价见 [Trie.md](../../../数据结构/树/空间与字符串树/Trie.md)；
> 集合状态类的 DP 见 [状态压缩DP.md](状态压缩DP.md)，逐位约束计数见 [数位DP.md](数位DP.md)。
>
> 内容整理自个人学习笔记，素材见 [素材清单](../../../../素材清单.md)。复杂度口径见 [复杂度分析.md](../../基础算法/复杂度分析.md)。
>
> ✅ **实测口径**：本篇计数结果均在容器 `golang:1.26-alpine`（**Go 1.26.8 linux/amd64**）中实跑，
> 模数固定 `10^9 + 7`；前两组与**逐串暴力枚举**对拍，第三组用 `避开 + 含至少一个 = 全集` 对账。
> 结果值可整篇重跑复现。

## 一、自动机 DP 把什么当成「阶段」？

**本节要点**：直接枚举所有长度为 `n` 的串是指数级的；但扫描过程中**真正影响后续的只有「当前停在 AC 的哪个状态」**——于是把「长度」当阶段、「状态编号」当状态，指数枚举就被压成了多项式 DP。

### 1.1 从「枚举串」到「枚举状态」

要判断一个串是否包含任何模式，AC 自动机从左到右扫一遍即可（见 [AC自动机.md](../../字符串匹配/AC自动机.md) 第五节）。扫描时**已经读过的内容只通过一个东西影响未来**：当前停在哪个节点。理由很直接 —— 下一个字符能转到哪、会不会命中，只取决于这个节点，而不取决于前面具体长什么样。

⭐ **这就是 DP 可以做的前提**：把「已读前缀」这一整段信息压缩成状态编号，相同状态的串被合并计数，指数级的枚举变成「状态数 × 长度」。

### 1.2 状态定义

设 AC 自动机共有 `m` 个状态（`m ≤ 总模式长度 + 1`），`next[s][c]` 是状态 `s` 读到字符 `c` 后的转移（已补全，见第二节）：

```text
dp[i][s] = 长度为 i、扫描结束后停在状态 s 的「合法」串的个数
```

- 起始：`dp[0][0] = 1`（空串停在根）
- 阶段：`i = 0 → 1 → … → n`
- 转移：枚举字符 `c`，`dp[i+1][next[s][c]] += dp[i][s]`
- 答案（不含任何模式）：`Σ dp[n][s]`

⭐ **「合法」的定义决定了哪些转移被丢掉** —— 下一节先把这件事说清楚。

## 二、为什么必须先把 AC 自动机「补全」？

**本节要点**：DP 里每步只允许**一次查表**。如果 `next[s][c]` 还留着 `-1`，转移时就得跑一遍 `while (fail)` 才能找到下一个状态 —— 那等于把「失配跳转」塞进了 DP 的每个转移里。**先补全 goto，DP 的每个转移才是 `O(1)`。**

### 2.1 补全 goto：让「失配」变成一条边

AC 自动机的原始 Trie 只有真实存在的边。补全的做法（在 BFS 构造 fail 时顺手做完）：

```text
根节点缺失的边 → 指向根（0）
其余节点 v 缺失的边 → next[fail[v]][c]
```

⭐ **补全后 `next` 的含义变了**：`next[s][c]` 不再是「Trie 里有没有这条边」，而是「**从 `s` 读入 `c` 后，最长的是模式前缀的后缀停在哪个节点**」。失配跳转已经被预先算进了边里，扫描（以及 DP 转移）都**不再需要 while 循环**。

⚠️ **顺序要求**：`next[fail[v]][c]` 必须已经补全，所以 `fail[v]` 要比 `v` 先处理 —— 这正是 BFS 按层推进的顺序（[AC自动机.md](../../字符串匹配/AC自动机.md) 第四节）。DFS 构造会用到还没补全的行，结果是错的。

### 2.2 对 DP 的实际影响

| 写法 | 单次转移 | `n` 步总代价 |
|---|---|---|
| 未补全，转移时沿 fail 跳 | `O(高度)` 最坏 | `O(n × m × 高度)` |
| **补全 goto** | **`O(1)` 查表** | **`O(n × m × |Σ|)`** |

⭐ 补全的代价是预处理多填一些边（`m × |Σ|` 个槽位），换来的是 DP 主体里**没有任何内层循环**。这是自动机 DP 的标准形态。

## 三、状态里的 `bad` 为什么能表达「已经命中」？

**本节要点**：命中不只看「当前节点是不是词尾」——**当前节点的 fail 链上任何一个是词尾，都说明刚才读入的后缀已经命中**。所以要在 BFS 时把 `bad` 沿 fail 链传下去，DP 里只用一个布尔位就能判断「这个状态是否已经完蛋」。

### 3.1 两个来源

一个状态 `s` 是「坏状态」（`bad[s] = true`），当且仅当：

1. `s` 本身是某个模式的结尾（Trie 插入时标记）；**或**
2. `fail[s]` 是坏状态（说明 `s` 的某个真后缀已经命中）。

第 2 条就是「输出链」在计数问题里的形态：AC 扫描时要把 fail 链上的词尾都报出来（[AC自动机.md](../../字符串匹配/AC自动机.md) 3.3），而这里只需要知道「链上有没有词尾」，压成一个布尔值即可。

### 3.2 为什么必须在 BFS 里传

`bad[s]` 依赖 `bad[fail[s]]`，而 `fail[s]` 一定比 `s` 浅 —— 又是「按层处理」的依赖顺序。正确写法是在节点**出队时**执行：

```text
bad[v] = bad[v] || bad[fail[v]]
```

⭐ **漏传的后果是静默漏算**：某些状态明明已经命中，却被当成合法状态继续转移，最终「避开数」偏大、且不会报任何错。用一个反例记住它：

```text
模式 = {b, abc}
Trie 里有节点 "ab"（abc 的前缀），它本身不是词尾
但 fail["ab"] = "b"，而 "b" 是模式 → 所以 "ab" 也必须是 bad
扫描到 "ab" 时，后缀 "b" 已经命中
```

⚠️ **`bad` 一旦为真就永远为真**：字符串只会越读越长，已经出现的模式不会消失。所以 DP 里遇到 `bad` 状态**直接丢弃**，不需要再往外转移 —— 这既是正确性，也是剪枝。

## 四、转移与答案怎么算？

**本节要点**：主体只有三层循环（长度 × 状态 × 字符），答案分「避开」与「至少含一个」两种；后者用全集减去前者，避免再写一遍 DP。

### 4.1 避开的计数

```text
dp[0][0] = 1
for i = 0 .. n-1:
    for s = 0 .. m-1:
        if dp[i][s] == 0 or bad[s]: continue
        for c in 字母表:
            ns = next[s][c]
            if not bad[ns]:
                dp[i+1][ns] += dp[i][s]
answer = Σ dp[n][s]
```

⭐ **为什么从 `bad[s]` 直接 `continue`**：能停在坏状态上的串已经包含模式，不属于「避开」的集合；再往下转移只会产生更多非法串，全部丢弃即可。

### 4.2 至少含一个的计数

```text
含至少一个 = |Σ|^n − 避开
```

⭐ 这是**补集**，不需要为「已经命中」单独建状态。⚠️ 如果题目要求「**每个**模式都至少出现一次」，补集法就不够了 —— 那要把「已命中哪些模式」做成 `2^k` 的位掩码状态，规模随模式数指数增长；那是另一种题，不在本篇范围。

### 4.3 复杂度

| 项 | 复杂度 | 说明 |
|---|---|---|
| 建 AC（含补全与 `bad` 传播） | `O(m × |Σ|)` | `m ≤ 总模式长度 + 1` |
| DP | `O(n × m × |Σ|)` | 每层每个状态枚举一遍字母表 |
| 空间 | `O(m)`（滚动数组） | 只需要 `dp[i]` 与 `dp[i+1]` 两层 |

⭐ **状态数由「总模式长度」决定，不由「模式个数」决定**：模式共享前缀越多，`m` 越小。这也是 AC 相比「对每个模式单独跑 KMP」的优势在 DP 里的延续。

## 五、实测：DP 的计数与暴力枚举对得上吗？

**本节要点**：计数题的错法不会崩，只会算错。所以每组都用**独立的暴力枚举**做基准，最后一组再用「避开 + 含至少一个 = 全集」对账。

### 5.1 与逐串暴力对拍

```text
模式 {he, she, his, hers}，字母表 5，n=9
  DP 状态数=10，转移次数=195，避开=1301093；暴力=1301093；一致=true

模式 {ab, cd}，字母表 4，n=10
  DP 状态数=5，转移次数=112，避开=259808；暴力=259808；一致=true
```

⭐ 第一组的字母表是 `{h, e, s, i, r}`（5 个），暴力枚举 `5^9 = 1953125` 个串逐个判断；DP 只走了 `195` 次转移就得到同一个数 —— **压缩比来自「同状态合并」**。

### 5.2 规模实验与对账

```text
模式 {he, she, his, hers}，字母表 26，n=20
  AC 状态=10（其中词尾/后缀命中状态 4），DP 转移=2444
  避开=370204243，含至少一个模式=983418106，总数=353622342
  对账：避开 + 含至少一个 = 353622342（应等于总数 353622342）
```

⭐ **两组校验各自管一件事**：

- **暴力对拍**管「转移写没写错」—— 状态定义、`bad` 传播、字母表范围，任何一处错都会让数字对不上；
- **全集对账**管「答案口径」—— 它验证 `avoid + contain = |Σ|^n (mod p)`，能抓住「忘记取模」「补集算反」这类错误。

⚠️ **对拍规模不能太大**：暴力是指数级的，`n = 9`、字母表 5 已经是 `195 万` 个串；规模实验只能靠对账，不能再暴力。

## 六、应用场景

**本节要点**：自动机 DP 的落点是**「长度固定、禁止/要求某些子串出现」的计数**。只要问题能表述成「在一串字符上逐位选择，且某些子串不能出现」，就可以套这个框架。

| 场景 | 模式集合是什么 | 计数目标 |
|---|---|---|
| **敏感词过滤的容量估算** | 词表（如 `{he, she, his, hers}`） | 长度为 `n` 的串里有多少个**完全不含**任何敏感词 |
| **协议 / 报文合法性计数** | 禁止出现的保留字段、非法指令序列 | 合法报文的总数（避开所有禁用子串） |
| **密码 / 验证码策略** | 禁止的连续字符组合（如 `123`、`abc`） | 满足约束的串数量 |
| **DNA / 序列模式统计** | 禁止的 k-mer 集合 | 长度为 `n` 的序列中避开这些片段的条数 |
| **含至少一个关键词** | 同上 | `|Σ|^n − 避开`（补集） |

⭐ **与 AC 自动机本身的分工**：AC 回答「**给定一个文本**，它命中了哪些模式」；自动机 DP 回答「**所有长度为 `n` 的文本里，有多少个会 / 不会命中**」。前者是单点判定，后者是整体计数 —— 共用同一张自动机，问题的量词不同。

⚠️ **失效边界**：

- 模式集合需要**动态增删** → 自动机要重建，DP 结果全部作废；
- 要求「每个模式至少命中一次」→ 状态要带 `2^k` 掩码，规模爆炸；
- 字母表很大且稀疏 → `m × |Σ|` 的补全表可能过大，需要改成哈希边或只枚举实际边；
- `n` 极大（如 `10^18`）→ 长度维不能逐层推，要用**矩阵快速幂**（转移矩阵是 `m × m`，见 [DP优化.md](DP优化.md) 的矩阵加速）。

## 七、具体使用：Go 里怎么落地？

**本节要点**：全篇代码只有三段 —— 建 AC（插入 + BFS 补全 + `bad` 传播）、滚动数组 DP、以及可选的暴力对拍器。下面三段与第五节的输出一一对应。

### 7.1 建 AC：补全 goto 并传播 `bad`

```go
type acNode struct {
	next [26]int
	fail int
	bad  bool
}

func newNode() acNode {
	n := acNode{}
	for i := range n.next {
		n.next[i] = -1
	}
	return n
}

func buildAC(patterns []string) []acNode {
	nodes := []acNode{newNode()}
	for _, p := range patterns {
		v := 0
		for i := 0; i < len(p); i++ {
			c := int(p[i] - 'a')
			if nodes[v].next[c] == -1 {
				nodes = append(nodes, newNode())
				nodes[v].next[c] = len(nodes) - 1
			}
			v = nodes[v].next[c]
		}
		nodes[v].bad = true
	}

	queue := make([]int, 0, len(nodes))
	for c := 0; c < 26; c++ {
		if nodes[0].next[c] != -1 {
			nodes[nodes[0].next[c]].fail = 0
			queue = append(queue, nodes[0].next[c])
		} else {
			nodes[0].next[c] = 0
		}
	}
	for len(queue) > 0 {
		v := queue[0]
		queue = queue[1:]
		nodes[v].bad = nodes[v].bad || nodes[nodes[v].fail].bad
		for c := 0; c < 26; c++ {
			u := nodes[v].next[c]
			if u != -1 {
				nodes[u].fail = nodes[nodes[v].fail].next[c]
				queue = append(queue, u)
			} else {
				nodes[v].next[c] = nodes[nodes[v].fail].next[c]
			}
		}
	}
	return nodes
}
```

⚠️ **注意 `nodes[v].bad` 的更新位置**：必须在 `v` 出队时、处理它的孩子之前。`fail[v]` 一定更浅，此时已经出过队，`bad[fail[v]]` 是最终值。

### 7.2 DP：滚动数组与字母表

```go
const mod = 1000000007

func countAvoid(nodes []acNode, letters []int, n int) int64 {
	dp := make([]int64, len(nodes))
	dp[0] = 1
	for i := 0; i < n; i++ {
		ndp := make([]int64, len(nodes))
		for st, cnt := range dp {
			if cnt == 0 || nodes[st].bad {
				continue
			}
			for _, c := range letters {
				ns := nodes[st].next[c]
				if !nodes[ns].bad {
					ndp[ns] = (ndp[ns] + cnt) % mod
				}
			}
		}
		dp = ndp
	}
	var sum int64
	for _, v := range dp {
		sum = (sum + v) % mod
	}
	return sum
}
```

⭐ **字母表按需传入**：自动机的 `next` 按 26 个字母建，但 DP 可以只枚举题目允许的字符（5.1 的第一组就是 5 个字母）。⚠️ 两者必须一致 —— 建表用 26、DP 用 5 没问题（只选这 5 列），但如果题目字母超出了 `a..z`，要先做字符映射。

### 7.3 校验：暴力对拍与全集对账

```go
func brute(patterns []string, letters string, n int) int64 {
	var count int64
	buf := make([]byte, n)
	var dfs func(pos int)
	dfs = func(pos int) {
		if pos == n {
			s := string(buf)
			for _, p := range patterns {
				if strings.Contains(s, p) {
					return
				}
			}
			count++
			return
		}
		for i := 0; i < len(letters); i++ {
			buf[pos] = letters[i]
			dfs(pos + 1)
		}
	}
	dfs(0)
	return count
}
```

调用时**字母表必须与 DP 用的一致**：DP 传 `{'h'-'a', 'e'-'a', 's'-'a', 'i'-'a', 'r'-'a'}`，暴力就传 `"hesir"`。⚠️ 本机第一版就错在这里 —— DP 用下标 `0..4`、暴力用 `"hesir"`，两边字母集不同，结果一个对一个错；修法是把同一份字母表喂给两边。

## 延伸追问

- **自动机 DP 和普通字符串 DP 的区别？** → 普通字符串 DP 的状态是「前 `i` 个字符」，转移要比较字符；自动机 DP 把「前 `i` 个字符**在模式集合下的匹配进度**」压成 AC 状态，从而能处理「任意模式集合」而不必为每个模式单独设计状态。
- **为什么 DP 里不需要再沿 fail 链找命中？** → 因为 `bad` 已经在预处理时沿 fail 链传下去了（第三节）。扫描阶段沿 fail 链输出是「要报出所有命中」，计数阶段只关心「有没有命中」，一个布尔位就够。
- **`bad` 不传播会怎样？** → **答案偏大且不报错**。像模式 `{b, abc}` 里的节点 `ab`，自身不是词尾但后缀 `b` 已命中；不传播就会把它当合法状态继续计数（3.2 的反例）。
- **为什么转移前必须补全 goto？** → 否则每步转移都要沿 fail 找下一个状态，单次不再是 `O(1)`，DP 的复杂度会多乘一个树高。补全后 `next[s][c]` 直接给出「读入 `c` 后的最长模式前缀后缀」。
- **「至少含一个」为什么不重新跑一遍 DP？** → 补集更省：全集 `|Σ|^n` 减去「避开」即可。⚠️ 只有「每个模式都至少一次」才需要把命中集合做成掩码状态。
- **`n` 很大（`10^18`）怎么办？** → 把 DP 的逐层转移写成矩阵，用矩阵快速幂把 `O(n)` 降到 `O(log n)`；矩阵大小是 `m × m`，`m` 是 AC 状态数（见 [DP优化.md](DP优化.md)）。
- **多个模式重复或互为前缀会怎样？** → AC 天然处理：互为前缀的模式会在 Trie 的同一条链上，短模式是长模式路径上的词尾；`bad` 会沿 fail 链把「短模式已命中」传给长模式的后代。重复模式只会让同一节点被标记多次，不影响计数。
- **空间能不能再省？** → 能，DP 只需要相邻两层（7.2 的滚动数组）；AC 的 `next` 表是主要开销，字符集大时改成哈希表或只存真实边，但转移会从 `O(1)` 退化。

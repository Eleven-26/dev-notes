# DP 优化

> 转移方程写对之后，`O(n²)` 甚至 `O(n³)` 还能不能降下来？—— 能。
> 四类手法（单调队列 / 斜率 / 决策单调性 / 数据结构）的共同点只有一句：
> **把转移里被反复算的东西，用结构或单调性一次性吃掉**。
>
> ⭐ 边界先说清：DP 的**三性质与五步模板**见 [README.md](README.md)；
> 状态形状的分类（线性 / 区间 / 背包 / 树形…）见各零件篇，
> 本篇**只讲「已经写对转移之后怎么加速」**。
> 单调队列的本体（结构层）见 [单调栈与单调队列.md](../../数据结构/高级数据结构/单调栈与单调队列.md)，
> 线段树 / 树状数组的本体见 [区间与索引树.md](../../数据结构/树/区间与索引树.md)。
>

## 一、优化之前，先问「重复计算在哪」？

**本节要点**：四类手法针对的是**四种不同的重复来源** —— 先认出是哪一种，再选对应的刀。

把常见的转移写成这个样子，就能一眼看出该用哪把刀：

```text
dp[i] = min / max { dp[j] + cost(i, j) }        j 取某个范围
```

| 重复来源 | 长相 | 用哪把刀 |
|---|---|---|
| 每次都要**重新扫一遍窗口** | `cost` 与 `j` 无关，只是「窗口内的最值」 | **单调队列** |
| `cost` 里有 `i` 与 `j` **相乘**的项 | 例如 `dp[j] + (S[i] − S[j] − L)²` | **斜率优化** |
| 断点枚举范围**巨大但单调移动** | `opt[i][j−1] ≤ opt[i][j] ≤ opt[i+1][j]` | **决策单调性** |
| `cost` 是「某个前缀上的最值 / 和」 | 例如 `1 + max{ dp[j] : a[j] < a[i] }` | **数据结构优化**（BIT / 线段树） |

⭐ **一句话判据**：**先看 `cost(i, j)` 里有没有 `i`**——

- 完全**没有** `i`（只是「取窗口里的最值」）→ 单调队列；
- 有 `i·j` 这种**乘积项** → 斜率优化；
- 就是「前缀上的聚合」→ 数据结构优化；
- 都不像、但断点**单调** → 决策单调性。

![DP 优化的四类手法：单调队列、斜率优化、决策单调性、数据结构优化各自针对的重复来源与实测核心操作次数](images/DP优化的四类手法.svg)

> 图怎么读：四格各是一种把 `O(n²)` / `O(n³)` 降下来的路线，括号里的两个数字是**同一份输入下朴素写法与优化写法的核心操作次数**（容器实测，Go 1.26.8）：
> 
> 单调队列 **1 995 050 → 59 991**、斜率优化 **200 010 000 → 59 908**、决策单调性 **10 666 600 → 160 652**、数据结构优化 **199 990 000 → 293 865** —— 四组读数分别来自 2.2 / 3.2 / 4.2 / 5.2。
> 
> ⭐ 四条路线的**共同前提是优化前后 `dp` 值逐项一致**：本文四个场景实测全部 `true`，不一致就说明"改快了但改错了"。

## 二、单调队列优化：转移只看窗口里的最值

**本节要点**：当「候选集是一个**滑动窗口**」时，**窗口里的最小值不需要每次重扫** —— 维护一个单调队列，队首就是答案。

### 2.1 判据与做法

```text
dp[i] = min_{j ∈ [i−m, i−1]} dp[j] + a[i]        ← cost 完全不含 j 的信息
```

⚠️ **两个前提**（缺一不可）：

1. **候选集是一个连续窗口**（左右端点都单调移动）；
2. **要的是窗口里的最值**（不是任意聚合 —— 求「区间众数」这种就做不了）。

做法就是维护一个**存下标的双端队列**：入队前把「比新值更差」的队尾弹掉，出队时把过期下标弹掉。
⭐ **复杂度从 `O(n·m)` 变成 `O(n)`**，因为每个下标**进出各一次**。

### 2.2 实测

**✅ 实测口径**：容器 `golang:1.26-alpine`，Go 1.26.8，纯标准库、无第三方依赖；两遍运行逐行相同。
统计口径是**核心操作次数**（朴素数「比较次数」，优化版数「入队 / 出队 / 取值次数」）。

| 做法 | 操作次数 |
|---|---|
| 朴素（每个 `i` 重扫窗口） | **1 995 050** |
| 单调队列（每元素进出各一次） | **59 991** |

`n = 20000`、窗口 `m = 100`，**省 33.3 倍**；且 **dp 值逐项一致**。

⚠️ 注意这里的倍数**取决于窗口大小**：`m` 越大朴素越贵、收益越大。**它省的是「重复扫描」，不是渐近复杂度以外的东西** ——
窗口退化成 `n` 时，单调队列相对朴素才是真正的 `O(n)` vs `O(n²)`。

## 三、斜率优化：把候选点摆成凸壳

**本节要点**：当转移里出现 `S[i]·S[j]` 这种**交叉项**时，把它改写成「直线求截距」，候选点就摆成一个凸壳 —— 用**切线**找最优，`O(n)` 扫完。

### 3.1 推导：为什么能变成几何问题

以经典的「分段平方代价」为例：

```text
dp[i] = min_{j<i} dp[j] + (S[i] − S[j] − L)²
```

展开平方，把**与 `j` 有关**的部分打包成 `y_j`、与 **`i` 和 `j` 都有关**的部分打包成 `x_j`：

```text
dp[i] = S[i]² + min_{ j } ( y_j − 2·S[i]·x_j )
其中  x_j = S[j] + L          y_j = dp[j] + (S[j] + L)²
```

⭐ 现在看清楚了：`y_j = 2·S[i]·x_j + b` 就是一条**斜率为 `2·S[i]` 的直线**，
而我们要最小化它的**截距 `b`**。所有候选点 `(x_j, y_j)` 构成一个**下凸壳**，
最小值就落在**切线**上。

因为 `a[i] > 0` → `S[i]` 单调递增 → 斜率单调递增 → **可以用单调指针 + 单调队列维护凸壳**，整体 `O(n)`。

### 3.2 实测

**✅ 实测口径**（同上容器）：`n = 20000`，`dp[i] = min_{j<i} dp[j] + (S[i]−S[j]−500)²`。

| 做法 | 操作次数 |
|---|---|
| 朴素（枚举全部 `j`） | **200 010 000** |
| 斜率优化（下凸壳 + 单调指针） | **59 908** |

**省 3338.6 倍**，`dp[n] = 912`、**dp 值逐项一致**。

⚠️ **斜率优化的三个必查项**（都是「不报错但结果错」的那类）：

| 坑 | 症状 |
|---|---|
| **凸壳方向搞反** | 求 `min` 要维护**下**凸壳，求 `max` 是**上**凸壳；维护错方向只是「永远选到次优」 |
| **`x` 不单调时不能用单调队列** | 若 `S[j]` 不单调，斜率不单调 → 得改用**二分**查切线，复杂度变成 `O(n log n)` |
| **交叉相乘的溢出** | 判斜率大小要交叉相乘（`(y2−y1)·(x−x2)`），数值量级会放大 —— **用 `int64` 并估算量级** |

## 四、决策单调性 / 四边形不等式：把断点的枚举范围夹住

**本节要点**：区间 DP 的 `O(n³)` 瓶颈在「枚举断点」；**当最优断点随区间单调移动时，枚举范围可以被上下界夹住**，总量降到 `O(n²)`。

### 4.1 判据

以石子合并为例：`dp[i][j] = min_{i≤k<j} dp[i][k] + dp[k+1][j] + cost(i,j)`，
设 `opt[i][j]` 是取到最小值的那个 `k`。**如果 `opt` 满足单调性**：

```text
opt[i][j−1] ≤ opt[i][j] ≤ opt[i+1][j]
```

那么枚举 `k` 时**只需在 `[opt[i][j−1], opt[i+1][j]]` 这个区间里找**，不必从 `i` 扫到 `j−1`。

⚠️ **这条单调性不是「看起来对」就能用** —— 它由 **四边形不等式**（`cost` 满足 `w(a,c) + w(b,d) ≤ w(a,d) + w(b,c)`）推出。
**先验证 `opt` 单调，再上优化**（下面的实测就带了这个校验）。

### 4.2 实测

**✅ 实测口径**（同上容器）：石子合并，`n = 400`，权值随机 `1..100`。

| 做法 | 枚举断点次数 |
|---|---|
| 朴素 | **10 666 600** |
| 四边形不等式（断点夹逼） | **160 652** |

**省 66.4 倍**；且实测 **`opt[i][j]` 的单调性成立**、**dp 值一致**。

⭐ 两条重要边界：

- 这里的收益**随 `n` 放大**：朴素是 `O(n³)`、优化后是 `O(n²)`，`n` 越大差距越大；
- ⚠️ **四边形不等式对本例成立 ≠ 对一切 `cost` 成立**。换一种代价函数必须**重新验证** `opt` 的单调性，
  不能「上次能用这次也照抄」—— 那会静默给出错误答案。

## 五、数据结构优化：用 BIT / 线段树维护「前缀上的答案」

**本节要点**：当转移需要「**在某个前缀范围里的最值 / 和**」时，把它交给树状数组 / 线段树 —— 单次转移从 `O(n)` 变成 `O(log n)`。

### 5.1 典型：LIS 的 `O(n log n)` 写法

朴素 LIS 的转移是：

```text
dp[i] = 1 + max{ dp[j] : j < i 且 a[j] < a[i] }
```

⭐ 把它重读一遍：**「在所有比 `a[i]` 小的值里面，找最大的 `dp`」** ——
这是「按**值域**做前缀最大值查询」，正是树状数组 / 线段树的活。

做法：把 `a` 离散化到 `1..m`，用树状数组维护 `tree[k] = 值域前缀 [1..k] 的最大 dp`；
每算完一个 `dp[i]`，就在 `rank(a[i])` 位置上**更新**该位置的最大值。

### 5.2 实测

**✅ 实测口径**（同上容器）：`n = 20000` 的随机序列（值域 `1..100000`）。

| 做法 | 操作次数 |
|---|---|
| 朴素 `O(n²)` | **199 990 000** |
| 树状数组 `O(n log n)` | **293 865** |

**省 680.6 倍**；**LIS 长度一致（266 = 266）**。

⚠️ **两个容易搞错的细节**：

1. **要查的是「严格小于」还是「小于等于」** —— 这决定查 `rank−1` 还是 `rank`，
   也是「最长**上升**子序列」与「最长**不下降**子序列」的唯一区别；
2. **树状数组维护的是「最值」不是「和」** —— 最值版本**不能做区间减法**（`query(r) − query(l−1)` 对最值无意义），
   只能做**前缀**查询。要做区间最值必须换**线段树**。

## 六、四类手法怎么选？

**本节要点**：按第一节的判据选；选不出来时，先回去看**转移里到底哪一项贵**。

```text
转移是什么形状？
├─ cost 与 j 无关，只是窗口里的最值          → 单调队列        O(n)
├─ cost 含 S[i]·S[j] 的交叉项                → 斜率优化        O(n)（x 单调）/ O(n log n)
├─ 决策点随区间单调移动（区间 DP 的断点）      → 决策单调性      O(n²)
├─ 要「值域 / 下标前缀上的最值或和」           → BIT / 线段树    O(n log n)
└─ 以上都不像
    ├─ 状态数本身爆炸                        → 回 DP 本体：换状态定义 / 状压（见 README.md）
    └─ 只是常数大                            → 先别优化，把 O(n²) 写对更重要
```

⭐ **三条通用铁律**：

| 铁律 | 为什么 |
|---|---|
| **① 先有正确的朴素版，再优化** | 优化后的代码更短、更难查错；没有朴素版就没有对照物 |
| **② 优化前后 dp 值必须逐项一致** | 四类优化都有「不报错、只是算错」的失败形态 |
| **③ 先估数量级，再决定值不值得** | `n` 只有几百时，朴素 `O(n²)` 可能比重写凸壳更快 —— **优化的收益要 `n` 够大才兑现** |

## 使用：这些优化在工程里出现吗

**本节要点**：大多数业务代码不写斜率优化，但**「用结构吃掉重复计算」这个念头本身**在工程里到处都是。

| 场景 | 用的是哪条思路 | 说明 |
|---|---|---|
| 滑动窗口聚合（限流计数、移动平均） | **单调队列 / 双端队列** | 窗口端点单调移动、只求最值 —— 与第二节同构 |
| 监控指标的「区间最值 / 前缀统计」 | **线段树 / 树状数组** | 与第五节同构，只是被封装进了时序库 |
| 编译器的指令选择 / 最优分段 | **决策单调性** 的远亲 | 「代价函数满足某些凸性 → 可用分治 / 单调栈加速」 |
| 排产 / 库存的分批优化 | **斜率优化** | 代价里带「批次 × 时长」这类交叉项时就是它 |

⚠️ **本篇的写法说明**：上表是按**问题形状**给出的对应关系；
真实系统里这些优化通常被封装成库，**具体实现以各自文档 / 源码为准**。

## 延伸追问

- **什么时候能用单调队列优化 DP？** → 候选集是连续窗口、且只要窗口里的最值（不是任意聚合）。两个条件缺一不可。
- **斜率优化的本质是什么？** → 把 `dp[j] + f(i,j)` 改写成「斜率为 `S[i]` 的直线求截距」；候选点是凸壳上的点，最优解在切线上。
- **斜率优化什么时候不能用单调队列？** → 当 `x_j` 不单调（斜率不单调）时，切线位置不再单调移动，只能改用二分 → 复杂度退到 `O(n log n)`。
- **决策单调性可以随便用吗？** → 不行。它由四边形不等式推出，**必须先验证 `opt` 单调**；换个 `cost` 就要重新验证。
- **LIS 为什么能用树状数组？** → 转移是「值域前缀上的最大值查询」，这正是树状数组的活；离散化之后每次 `O(log n)`。
- **树状数组能维护区间最小 / 最大值吗？** → 只能做**前缀**最值；区间最值必须用线段树（最值没有「可减」性质）。
- **优化之后怎么知道没写错？** → 与朴素版逐项比对 dp 值 —— 四类优化的失败都是「不报错只算错」，只能靠对照发现。
- **小数据要不要优化？** → 不要。`n` 只有几百时朴素更快，重写凸壳只是徒增出错面。

# 算法地图（本目录索引）

> 本目录收「**语言无关、有独立原理层**」的通用算法；**具体语言的实现与工程用法留在对应语言目录**
> （[go/](../../01-编程语言/go/)、[java/](../../01-编程语言/java/)、[php/](../../01-编程语言/php/)、[linux/](../linux/)），两边互相引用。
>
> 目录内部按主题分成 **8 个二级目录**：`基础算法/`（复杂度 / 查找与排序 / 二分 / 双指针 / 位运算）、`动态规划/`、`贪心/`、
> `回溯/`、`字符串匹配/`、`图论算法/`（下含 `图的遍历/`、`最短路/`、`最小生成树/`）、
> `数学基础/`（数论 / 组合 / 概率期望 / 博弈）、`高级技巧/`（离散化 / 分块 / 莫队 / 扫描线 / 矩阵快速幂）；
> [压缩算法.md](压缩算法.md) 不属以上任何一类，**留在本目录根下**。
>
> ⭐ **2026-10-02 起，「数据怎么存」的一半已独立成姊妹目录 [数据结构/](../数据结构/)** ——
> 结构本身（数组 / 链表 / 栈队列 / 树 / 堆 / 哈希 / 图的表示 / 概率结构）在那边，本目录只留「用结构解题」。
> 判据见 [README.md](../数据结构/README.md) 第一节；本目录里指向结构篇的链接**一律是跨目录链接**。
>
> 这篇是本目录的索引，也是**全仓算法原理的入口**：—— 按「算法」复习时从这里进，按「技术栈」复习时从 [全仓知识点目录](../../目录.md) 进。

## 四、收录门槛：一个知识点该不该进本目录

按这四条依次判：

1. **语言无关吗？** 只对某个语言 / 框架成立 → 归对应语言目录，那是**机制**不是算法（如 `context`、`Stream`、`channel`）；
2. **有独立原理层吗？** 能写出 ≥1 屏的原理（模型 / 参数 / 复杂度 / 优缺点 / 选型）→ 才值得独立成篇；
3. **≥2 个场景或语言会用到吗？** 只有一个组件用到的，跟着那个组件走；
4. 是某个**已成体系领域**的底座吗（GC / 密码学 / 数据库内核）？→ 留在该领域，不要搬散。

⭐ **前置判据（第 0 条）**：先问「这知识点回答的是**怎么存**还是**怎么算**」——
「东西放在哪儿、按什么关系连、代价在哪」→ 进 [数据结构/](../数据结构/)；
「按什么步骤走完 / 算出结果」→ 留在本目录。同一结构两边各一篇、互相引用，**不重复讲**。

### 反过来：什么时候"实现"要拆出去

| 情况 | 处理 | 例 |
|---|---|---|
| 某语言的实现 / 工程用法 **≥1 屏**，且与该语言生态有关联 | **拆**：原理留本目录，实现进语言目录，**双向引用** | [限流算法.md](../../04-架构与系统/分布式/服务治理/限流算法.md) ↔ [限流器.md](../../01-编程语言/go/并发编程/限流器.md) |
| 实现只是原理的**短示例**（直译、不足 1 屏） | **不拆**，同篇放一起 | [位图与布隆过滤器.md](../数据结构/高级数据结构/位图与布隆过滤器.md) 里的 Go / Java 位图 |
| 是"**用某语言解决的具体问题**"（面试题、业务场景） | 写在语言目录 / **面试目录**，不进本目录 | [Go算法题.md](../../07-面试/Go算法题.md)、[并发控制实战.md](../../01-编程语言/go/并发编程/并发控制实战.md) |

# 最小生成树

> 本目录收**最小生成树（MST）**的两篇零件：[Kruskal.md](Kruskal.md)（按边贪心）与 [Prim.md](Prim.md)（按点贪心）。

## 一、核心思想

**本节要点**：在**带权无向图**里找一棵包含**所有顶点**的树，使**边的总权重最小**。它的全部理论压在一句话上 —— **割性质**。

| 要素 | 含义 |
|---|---|
| **包含所有顶点** | 不能漏点 —— 这是 MST 与「最短路」最根本的区别 |
| **是一棵树** | 恰好 `V − 1` 条边、无环、连通（多一条必有环，少一条必不连通） |
| **总权重最小** | 在「所有生成树」里取最小 —— 注意是**总和**最小，不是某条路径最小 |

### ⭐ 割性质（Cut Property）——MST 的地基

```text
把顶点任意分成两部分（这叫一个「割」）。
横跨这个割的所有边里，权重最小的那条，一定属于某棵最小生成树。
```

直觉版：**「连接两个连通块的最便宜的那条边，不可能不用」** —— 因为如果不用它，用另一条更贵的边连通这两块，把它换回来只会更省。

Kruskal 与 Prim 都是这条性质的**不同用法**：

| 算法 | 对「割」的用法 |
|---|---|
| **[Kruskal.md](Kruskal.md)** | 每次取**全局最小**的边 —— 它一定是「某个割上的最小边」（只要两端还不连通） |
| **[Prim.md](Prim.md)** | 显式维护一个割：**已选点集 vs 未选点集**，每次取横跨它的最小边 |

⚠️ **割性质的前提是「无向」**。有向图上的对应问题叫**最小树形图**（朱刘算法），是另一套东西 —— 有向图**不能**直接套 MST。

## 二、适用条件

**本节要点**：MST 的门槛只有三条 —— **无向、连通、带权**。但这三条都是**硬前提**，不满足就得换问题而不是换算法。

| 条件 | 说明 |
|---|---|
| **无向图** | ⚠️ 有向图不适用（要用最小树形图）。把有向图当无向图跑 MST 是最常见的错误 |
| **连通** | 不连通时得到的是**最小生成森林**（每个连通分量各一棵树），不再是「一棵树」 |
| **带权** | 无权重时「生成树」都等价，随便一棵 DFS 树都行 |

### 允许的情况（不必额外处理）

| 情况 | 影响 |
|---|---|
| **边权相等** | MST **可能不唯一**，但**总权重相同** —— 所以「求总权重」的答案唯一，「求边集」的答案可能不唯一 |
| **有重边** | 正常处理（最小权的那条会被选中） |
| **有负权边** | ⚠️ **不影响正确性** —— 与最短路不同，MST 对负权**不敏感**（贪心仍安全） |

⭐ **负权这条值得记住**：MST 的结论**不依赖边权非负**，所以它比 Dijkstra「皮实」。原因也简单 —— MST 比较的是「边的大小」，而不是「路径的累加」。

### 典型场景

| 场景 | 为什么是 MST |
|---|---|
| **铺设光缆 / 电缆** | 连通所有城市且总成本最小 —— 标准的 MST 问题 |
| **电路板布线** | 连接所有元件且导线总长最短 |
| **聚类分析** | 建 MST 后**删掉最长的几条边**，剩下的连通块就是簇 |
| **网络设计** | 保证连通性的最小代价（不求两点间最短，只求总代价最小） |

## 三、解题模板

**本节要点**：四步 —— 其中第 2 步（选算法）由**图的稠密程度**决定，这是唯一需要判断的地方。

| 步骤 | 做什么 | 关键点 |
|---|---|---|
| **1. 确定图的表示** | Kruskal 要**边列表**（要排序）；Prim 要**邻接表**（要查邻居） | 表示选错会让算法写起来别扭 |
| **2. 选择算法** | 稀疏图 → Kruskal；稠密图 → Prim | 见下方判据 |
| **3. 逐步加边** | 每次加入一条**不构成环**的边，直到选了 `V − 1` 条 | Kruskal 用**并查集**判环；Prim 用**优先队列**取最小边 |
| **4. 返回** | 总权重或边集（⚠️ 边集可能不唯一） | 收不满 `V − 1` 条 ⇒ 图**不连通**（生成森林） |

### ⭐ 第 2 步：Kruskal vs Prim

| | [Kruskal.md](Kruskal.md) | [Prim.md](Prim.md) |
|---|---|---|
| 视角 | **按边贪心**（全局最小边） | **按点贪心**（离树最近的点） |
| 需要的数据结构 | **并查集**（判环） | **优先队列**（取最小边） |
| 复杂度 | `O(E log E)`（瓶颈在排序） | 朴素 `O(V²)` / 堆 `O(E log V)` |
| 适合 | **稀疏图**（`E` 小） | **稠密图**（`E ≈ V²` 时 `O(V²)` 优于排序） |
| 提前终止 | 收到 `V−1` 条边即停 | 所有点进树即停 |
| 特殊优势 | 天然支持**生成森林**（不连通时） | 从任意点起，适合「已知从某点开始建网」 |

⭐ **一家之言**：两者结果的总权重**必然相同**（都是 MST），差别只在**常数与适用稠密度**。工程上如果图不大，**Kruskal 更好写**（排序 + 并查集），出错的地方少。

## 四、经典问题

**本节要点**：MST 的应用集中在「**连通所有点的总代价最小**」这一类 —— 注意它**不解决**「两点之间怎么走最省」。

| 问题 | 建模方式 | 在哪 |
|---|---|---|
| **铺光缆 / 电缆** | 城市 = 顶点，可铺设线路 = 带权边，求 MST | [Kruskal.md](Kruskal.md)、[Prim.md](Prim.md) |
| **电路板布线** | 元件 = 顶点，可连导线 = 带权边 | 同上 |
| **聚类（层次聚类的一种）** | 建 MST 后删除最长的 `k − 1` 条边 → `k` 个簇 | [Kruskal.md](Kruskal.md) 第 1 节 |
| **网络设计（最小代价连通）** | 保证连通性的最小总代价 | [Prim.md](Prim.md) |
| **单链接聚类** | 与「删最长边」等价 —— MST 是它的核心结构 | — |
| **斯坦纳树** | 允许引入额外顶点 —— ⚠️ **NP-hard**，与 MST 不是一回事 | ⚠️ 待补 |

⚠️ **不要用 MST 解最短路**：目标不同（见第七节）。如果题目问的是「两点之间怎么走最省」，那是 [README.md](../最短路/README.md) 的事。

## 五、正确性证明

**本节要点**：全部归结为**割性质** + **归纳**。两篇零件篇用的是同一条性质，只是「割」的取法不同。

### 割性质（核心）

```text
设 (S, V−S) 是任意一个割。
若 e 是横跨该割的权最小边，则存在一棵 MST 包含 e。
```

**证明思路（交换论证）**：假设最优树 `T` 不含 `e`。把 `e` 加进 `T` 会形成一个环；这个环上必有一条**另一条横跨同一割**的边 `f`（因为环从 `S` 出发又回到 `S`）。由 `e` 的最小性，`w(e) ≤ w(f)`，于是用 `e` 换掉 `f` 得到的树不会更差 —— 矛盾。

### 归纳：每一步都是安全的

MST 的两个算法都遵循同一模式：

```text
① 当前已选边集是「某棵 MST 的子集」（归纳假设）
② 这一轮选的边 e 由割性质保证安全（e 属于某棵含①的 MST）
③ 加入 e 后，归纳假设仍成立
④ 选够 V−1 条时，已是一棵完整的 MST
```

| 算法 | 这一步的「割」怎么取 |
|---|---|
| **[Kruskal.md](Kruskal.md)** | 取「当前已连通分量 vs 其余点」—— 全局最小的不成环边一定是某个这类割上的最小边（**环性质**的等价说法） |
| **[Prim.md](Prim.md)** | 取「已进树的点集 vs 未进树的点集」—— 每轮取横跨它的最小边 |

### Kruskal 的等价视角：环性质

**「环性质」**：在一个环上，**权最大的边**一定**不属于**任何 MST。Kruskal「从小到大取、成环就跳过」正是不断用这条性质排除边 —— 与割性质互为对偶。

### 为什么 Prim 和 Dijkstra 长得几乎一样

两篇的核心循环**只差一行**（[Prim.md](Prim.md) 第二节）：

```text
Prim     ：dist[v] = w(u, v)              ← 只关心「这条边多重」
Dijkstra ：dist[v] = dist[u] + w(u, v)    ← 关心「从源点累加到多重」
```

⚠️ 但**它们证明的东西完全不同**：Prim 用割性质（保证 MST 最优），Dijkstra 用「非负权 ⇒ 出堆即定稿」。
**代码相似是巧合，不要因为「像」就把两者的结论互相套用** —— 这也是最常见的混淆之一。

## 六、常见陷阱

**本节要点**：MST 的坑集中在「**前提**」与「**数据结构**」两处 —— 前者决定算得对不对，后者决定跑不跑得动。

| 陷阱 | 症状 | 怎么避免 |
|---|---|---|
| **有向图用 MST** | 结果是错的（有向图要最小树形图 / 朱刘算法） | 建图前先确认**无向** |
| **图不连通** | 得到的不是树而是**森林** | 显式检查「是否收满 `V − 1` 条边」；不连通时按森林处理 |
| **边权相等时以为解唯一** | 两次运行结果不同 | ⚠️ 总权重唯一、**边集可能不唯一**；做逐行比对时要给**确定的 tiebreak**（如按边的输入顺序） |
| **Kruskal 的并查集写错** | 产生了环 / 漏了边 | 用**路径压缩 + 按秩合并**；加边前先 `find(u) != find(v)`（[Kruskal.md](Kruskal.md) 第四节） |
| **Prim 的优先队列未及时更新** | 选到过期的边，结果偏大 | ⚠️ 与 Dijkstra 同一个坑：**懒惰删除**（出堆时判 `dist` 是否过期）或**及时更新键值** |
| **节点编号 0 起 / 1 起混用** | 越界或漏一个点 | 建图时统一转换 |

### 补两条容易忽略的

| 陷阱 | 说明 |
|---|---|
| **把「MST」当成「最短路树」** | 两者都是「树」，但 MST 不保证任何两点间路径最短（见第七节的经典反例） |
| **只算总权重，不返回边集** | 工程上（铺设方案）需要具体的边；返回边集时注意「解不唯一」的处理 |

## 七、与其他思想对比

**本节要点**：`MST vs 最短路` 是本目录**最高频的误区**，必须有具体反例撑腰；`MST vs 贪心 / DP` 则是「它属于哪一类」的问题。

### MST vs 最短路 —— 差在哪（⭐ 高频误区）

| 维度 | 最小生成树 | 最短路 |
|---|---|---|
| 目标 | **连通所有点**，使**边权总和**最小 | 求**两点之间**的路径代价最小 |
| 结果 | 一棵树（`V − 1` 条边） | 一棵「最短路树」或一张距离表 |
| 关心什么 | **全局总代价** | **某条路径的累加代价** |
| 边权非负是前提吗 | ❌ 不需要（负权也安全） | ✅ Dijkstra 需要 / Bellman-Ford 不需要 |
| 典型算法 | Kruskal、Prim | Dijkstra、Bellman-Ford、Floyd |

**经典反例**（说明「MST 上的路径 ≠ 最短路」）：

```text
三角形：A—B 权 2、B—C 权 2、A—C 权 3

MST 会选 A—B(2) 与 B—C(2)，总权 4（不选更贵的 A—C）
        ↓
但 A 到 C 在 MST 上的路径是 A→B→C = 4，而原图里 A→C 直接走只要 3
```

⭐ 所以：**MST 是最小化「总和」，代价就是「某些点对之间的路径会变长」**。看到「连接所有点、总代价最小」才是 MST；看到「从 X 到 Y 最省」就是最短路。

### MST vs 贪心

| 关系 | 说明 |
|---|---|
| **Kruskal 和 Prim 都是贪心** | 每步做局部最优选择、不回退 |
| **安全性的依据是割性质** | 这是图上的「贪心选择性质」（[README.md](../../贪心/README.md) 第二节） |
| **负权不影响正确性** | 与一般贪心一致：只要安全性成立，边权是正是负都无所谓 |

### MST vs 动态规划

| 关系 | 说明 |
|---|---|
| **MST 本身不用 DP** | 它是贪心 + 割性质，没有「阶段」的概念 |
| **但它的变体会用** | 如**最小斯坦纳树**（可引入额外顶点）是 NP-hard，常用**状压 DP** 求小规模精确解（[README.md](../../动态规划/README.md) 的状压一类） |
| 与 `Dijkstra` 的代码相似是巧合 | 见第五节的对照，证明工具完全不同 |

### MST vs 并查集

**并查集不是「另一种算法」，而是 Kruskal 的零件**：它负责回答「加这条边会不会成环」——
即 `find(u) == find(v)` 吗？用**路径压缩 + 按秩合并**后单次操作接近 `O(1)`（严格说 `O(α(n))`），
使 Kruskal 的总复杂度由**排序**决定（`O(E log E)`）。实现与实测见 [Kruskal.md](Kruskal.md) 第四节、
基础结构见 [README.md](../../../数据结构/README.md)。

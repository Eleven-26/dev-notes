## 一、核心思想

**本节要点**：回溯 = **在解空间树上做深度优先搜索 + 撤销选择**。它不是「一种新算法」，而是 DFS 的一种用法：把「做选择」当成往下走，把「撤销」当成往后退。

| 要素 | 含义 |
|---|---|
| **解空间树** | 把「所有可能的解」组织成一棵树：根是空解，每往下一层做一次选择，叶子是一个完整解（或一个死路） |
| **逐步构建解** | 每层只决定一件事（放哪个数、哪一行放哪一列），**不提前决定后面** |
| **不合法就撤销** | 发现当前分支不可能有解 → 退回来，把「刚才做的选择」抹掉，恢复现场 |
| **尝试其他分支** | 一路试完所有候选，直到找到所有解、或确定无解 |

⭐ 一句话本质：**「做选择 → 递归 → 撤销选择」** —— 中间那步递归负责往下探，最后那步撤销负责「把现场恢复成进去之前的样子」，这样下一个候选才能在**同一份干净状态**上开始。

> ⚠️ **「撤销选择」是回溯的灵魂**。只往下走、不撤销，那是**遍历**（每个分支会看到被前一个分支污染的状态），不是回溯。

## 二、适用条件

**本节要点**：回溯适合**「要求枚举所有解 / 组合 / 排列 / 子集」或「约束满足」**的问题；它的代价是指数级的，所以**必须配合剪枝**才实用。

### 什么时候用

| 场景 | 说明 |
|---|---|
| **求所有解 / 组合 / 排列 / 子集** | 「列出全部方案」这类问题**没有多项式算法**，只能枚举 —— 回溯是枚举的标准写法 |
| **约束满足问题** | 八皇后、数独、地图着色：要在一堆**互相制约**的选择里找可行解 |
| **需要「找第一个可行解」** | 数独只要填出一个解就返回（找到即停，不必枚举完） |

### 什么时候不用

| 情况 | 为什么 | 出路 |
|---|---|---|
| **只求最优值** | 回溯会枚举所有解，而最优值只需要「最好的那个」 | 换 **DP**（[README.md](../动态规划/README.md)） |
| **有可证明的贪心性质** | 那直接贪，不用搜 | 换 **贪心**（[README.md](../贪心/README.md)） |
| **规模太大** | 分支因子 `b`、深度 `d` → `b^d` 个节点 | 加剪枝 / 换启发式（如 [数独.md](数独.md) 的 MRV）/ 换 DP |

### ⭐ 规模警戒线

回溯的复杂度是**指数级**的。`n = 8` 的全排列是 `40320`，`n = 12` 就是 `4.79 亿` —— 所以：

- 必须在**会做剪枝**的前提下才用它；
- 实测时**先小规模试跑再决定上限**（本项目写 [八皇后.md](八皇后.md)、[数独.md](数独.md) 时都刻意控制了规模，避免实验跑几分钟）。

## 三、解题模板

**本节要点**：五步固定动作 —— 其中 **路径 / 选择列表 / 结束条件**（三要素）与**剪枝**是关键，前者决定代码结构，后者决定能不能跑完。

| 步骤 | 做什么 | 容易错在哪 |
|---|---|---|
| **1. 确定解空间** | 想清楚「一个完整解长什么样」（全排列是一个序列、八皇后是一组列号） | 解空间没想清 → 后面路径与选择列表都定义不准 |
| **2. 定路径与选择列表** | **路径** = 已做的选择；**选择列表** = 当前还能做的选择 | 选择列表漏了约束（如八皇后没排除同列）→ 会生成非法解 |
| **3. 定结束条件** | 「路径长度到齐」或「满足所有约束」时收集答案 | 收集时机错（在叶子之前收集、或忘了 `return`）→ 漏解或多解 |
| **4. 剪枝** | 提前排除不可能的分支 | ⚠️ **剪错会丢解**，而且不报错（[全排列.md](全排列.md) 第四节、[八皇后.md](八皇后.md) 第三节有对照实测） |
| **5. 递归 + 回溯** | 做选择 → 递归 → **撤销选择** | ⚠️ 忘记撤销 → 状态被污染，后续分支全错 |

### ⭐ 骨架（三要素的具体形状）

```text
backtrack(路径, 选择列表):
    if 满足结束条件:
        收集(路径)
        return
    for 选择 in 选择列表:
        if 不满足约束:  continue      # ← 剪枝
        做选择（路径.push(选择)）
        backtrack(新路径, 新选择列表)
        撤销选择（路径.pop()）          # ← 回溯的灵魂
```

这套骨架的**逐行讲解与实测**在 [全排列.md](全排列.md) 第二节 —— [八皇后.md](八皇后.md) 与 [数独.md](数独.md) 都复用它，不再重复。

### ⭐ 剪枝的两类

| 类型 | 判断什么 | 例子 |
|---|---|---|
| **可行性剪枝** | 「这条路走下去**不可能合法**」 | 八皇后：同列 / 同对角线已被占（[八皇后.md](八皇后.md) 第二节） |
| **最优性剪枝** | 「这条路走下去**不可能更优**」（分支限界） | 求最短/最小解时，当前代价已超过已知最优 → 剪 |

⚠️ 还有一类「**对称性剪枝**」：利用解的对称性去掉重复搜索（八皇后第一行只需放前一半列）。它**会改变解的输出**，所以只在「只关心解的个数」时用。

### ⭐ 第 5 步的自检：撤销是否对称

「做选择」与「撤销选择」必须是**严格对称**的两行。写完后自检：

```text
做选择的地方改了几个变量？（路径 push、used 标记、占用集合…）
撤销的地方是不是把这几个都恢复了？
```

少恢复任何一个 → 状态污染，后续分支出错 —— 而且**小数据可能看不出来**。

## 四、经典问题

**本节要点**：回溯的题型按「**约束的复杂度**」递增 —— 从无约束的枚举（全排列），到局部约束（八皇后），再到全局约束 + 启发式（数独）。

| 问题 | 约束特点 | 在哪 |
|---|---|---|
| **全排列** | 无额外约束，只是「每个数用一次」——**母模板** | [全排列.md](全排列.md) |
| **八皇后 / N 皇后** | 局部约束（同行列对角冲突），可 O(1) 判定 | [八皇后.md](八皇后.md) |
| **数独求解** | 全局约束 + 候选集，**靠启发式才跑得动** | [数独.md](数独.md) |
| **组合总和** | 元素可重复 / 不可重复 + 目标和 | ⚠️ 待补 |
| **子集** | 每个元素「选 / 不选」—— 最简的决策树 | ⚠️ 待补 |
| **单词搜索** | 网格上的路径搜索 + 不能重复走 | ⚠️ 待补（遍历骨架见 [DFS深度优先遍历.md](../图论算法/图的遍历/DFS深度优先遍历.md)） |
| **括号生成** | 约束是「任意前缀里左括号不少于右括号」——**剪枝条件是问题的核心** | ⚠️ 待补 |

本目录已交付的三篇：

- [全排列.md](全排列.md) —— **回溯的母模板**：三要素与骨架、`used` 数组法 vs 交换法、**输入有重复元素时怎么不产生重复解**、剪枝实测；
- [八皇后.md](八皇后.md) —— 在模板上**加约束剪枝**：三个集合判冲突、对角线索引公式（注意负数偏移）、**`n = 8` 是 92 个解**（可当正确性断言）；
- [数独.md](数独.md) —— 回溯第三站：把选择列表换成**位运算候选集**、把固定顺序换成 **MRV 启发式**，并实测快了多少。

⚠️ 「待补」的四篇尚未落盘，**本篇不留链接**（避免断链），写完会回补。

## 五、正确性证明

**本节要点**：回溯**本质上就是穷举**，所以「正确性」不需要像贪心那样证明 —— 要证明的是**剪枝没有剪掉正确的解**。

### 为什么通常不需要严格证明

只要满足两条，回溯的解就**不会遗漏**：

1. **解空间被完整枚举**：每一层的选择列表覆盖了所有合法可能；
2. **结束条件与解的定义一致**：叶子收集的就是「一个完整解」。

因为它是系统性地走遍整棵树（而不是像贪心那样「赌一个方向」），**只要结构对，就必然枚举到所有解**。

### 真正需要小心的是剪枝

⚠️ **剪枝是唯一能引入错误的地方**。必须满足：

```text
被剪掉的分支，一定要能证明「它下面的所有叶子都不是合法解（或都不是更优解）」
```

- **可行性剪枝**的安全性：判定条件必须是**必要条件的否定**（如「同列已有皇后 ⇒ 这条路绝不可能合法」）；
- **最优性剪枝**的安全性：上界/下界必须是**真正的界**（估小了会剪掉最优解）。

⭐ 验证手法：**同一个问题跑「带剪枝」与「不带剪枝」两版，比较解集是否完全相同**。零件篇里就是这么做的：

- [全排列.md](全排列.md) 第五节 —— 剪枝前后的**节点数对照**；
- [八皇后.md](八皇后.md) 第四节 —— 用 `n = 8` 必须是 **92 个解**当断言；
- [数独.md](数独.md) 第五节 —— MRV 优化前后的搜索节点数。

### 为什么「路径和选择列表定义正确」就够了

这是上面第 1 条的同义说法：**只要「当前有哪些选择」没漏、没多**，搜索就是完备的。所以写回溯时，与其纠结证明，不如反复检查**选择列表的定义**与**撤销的对称性**。

## 六、常见陷阱

**本节要点**：回溯的坑集中在「状态」上 —— **忘了恢复**（污染后续分支）、**剪得太狠**（丢解）、**没去重**（多解）。

| 陷阱 | 症状 | 怎么避免 |
|---|---|---|
| **忘记撤销选择** | 拿到一堆「不可能的」解，或解数偏少 | 做/撤销**严格对称**（第三节的自检）；⭕ 这是回溯第一大坑 |
| **剪枝条件错误** | **漏解**（剪多了）或**重复解**（剪少了） | 剪枝条件必须是「必要条件的否定」；用「带剪枝 vs 不带剪枝」对照验证 |
| **递归深度过大** | 栈溢出（`StackOverflowError` / `stack overflow`） | 深度与问题规模同阶时改成**显式栈**；或加剪枝把深度压下来 |
| **未处理重复元素** | 同一组解被输出多次 | 先**排序**，再用「同一层相同元素只用第一个」的判据去重（[全排列.md](全排列.md) 第四节） |
| **边界条件处理不当** | 空输入、单元素、全同元素时出错 | 专门测这几类输入（这是最省事的自检） |

### 补两个容易忽略的

| 陷阱 | 说明 |
|---|---|
| **收集答案时忘了深拷贝** | 直接 `结果.add(路径)` 会把**引用**存进去，后续撤销会把它一起改掉 → 最终收集到的全是空列表。必须 `结果.add(new ArrayList<>(路径))`（[全排列.md](全排列.md) 第二节） |
| **解的输出顺序不确定** | 选择列表的遍历顺序决定解得出的顺序。要做跨语言逐行比对，**候选的遍历顺序必须一致**（这是本项目 Go/Java 双实现对齐的前提之一） |

## 七、与其他思想对比

**本节要点**：回溯与 DFS 是「用法与骨架」的关系，与 DP 是「枚举全部 vs 求最优」的关系，与贪心是「全试 vs 只试一条」的关系。

### 回溯 vs DFS

| | DFS | 回溯 |
|---|---|---|
| 关系 | 一种**遍历**顺序（走遍所有节点） | DFS 的**一种应用**：把「做选择 / 撤销选择」当作前进与后退 |
| 关注点 | 访问每个节点 | 在**解空间树**上搜索，并在过程中维护「当前部分解」 |
| 状态处理 | 通常只需 `visited` | 需要**完整的现场恢复**（路径、占用集合、候选集…） |

⭐ 没有「撤销」的需求时（只是遍历一张图），用 [DFS深度优先遍历.md](../图论算法/图的遍历/DFS深度优先遍历.md) 的骨架就够；一旦要「枚举所有解」，就得按本篇的模板加上撤销。

### 回溯 vs 动态规划

| | 回溯 | DP |
|---|---|---|
| 目标 | **枚举所有解**（或找第一个可行解） | 求**一个最优值** |
| 重复计算 | 会重复（同一子问题可能被多条路径到达） | 天然不重复（每个状态只算一次） |
| 复杂度 | 指数级，靠**剪枝**活下来 | 多项式级，靠**状态合并**活下来 |
| 典型 | 全排列、八皇后、数独 | 0-1 背包、LCS、LIS |

⭐ **两者是同一个东西的两面**：给回溯加一张 `memo`（记录「这个状态已经算过」），它就变成**记忆化搜索** —— 也就是 DP 的递归写法。区别只在「要不要枚举所有解」：要 → 回溯；只要最优值 → 加 `memo` 变成 DP。

### 回溯 vs 贪心

| | 贪心 | 回溯 |
|---|---|---|
| 决策 | 每步取当前最优，**不回头** | **尝试所有分支**，走不通就退回来 |
| 失败的表现 | 静默给出次优解 | 遍历更多节点（慢），但**不会漏解** |
| 复杂度 | 多项式 | 指数级 |
| 典型 | 活动选择、霍夫曼编码 | 全排列、数独 |

⭐ 取舍顺序：**能贪就贪**（快）→ **贪不了但要最优值就 DP**（不重复算）→ **要枚举所有解就回溯**（全试）。

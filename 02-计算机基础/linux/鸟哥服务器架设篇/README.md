> 覆盖虚拟化环境搭建、主机安全强化、网络规划与防火墙、SSH 远程管理、
> DHCP / NTP / DNS 基础服务，以及 WWW / 文件共享 / 邮件等常见服务器的架设与维护。

> 内容整理自个人学习笔记。**基础框架**参考鸟哥官网《服务器架设篇 - RockyLinux 9》
> （2023-11-30 更新）与《鸟哥的 Linux 私房菜：服务器架设篇（第三版修订）》（清华大学出版社，2024，基于 CentOS 7.x）的读后整理；

## 版本坐标速查

**本节要点**：在线版基于 Rocky 9，纸质书基于 CentOS 7；结构性差异最大的是「在线版从搭云系统开始」与「在线版把容器化当作衔接方向」。

| 特性 | 在线版（Rocky 9） | 纸质书第三版修订（CentOS 7） | 备注 |
|------|-------------------|----------------------------|------|
| 基础系统 | Rocky Linux 9.x | CentOS 7.x | CentOS 8 已停止维护 |
| 虚拟化入门 | ✅ 从搭建云系统开始 | ❌ 直接从网络基础开始 | 在线版结构性变化最大之处 |
| SELinux | ✅ 专章 | ✅ 专章 | 两者均强调 |
| 防火墙 | firewalld | firewalld + iptables | 在线版更聚焦 firewalld |
| 服务管理 | systemd（systemctl） | systemd（systemctl） | 基础篇已覆盖，本篇不重复 |
| 容器化 | ✅ 作为衔接方向提及 | ❌ | 在线版新增 |
| 纸质书 | 在线版不打算出版 | ✅ 有纸质书 | 两者内容以在线版为准更稳妥 |

## 延伸追问

- **为什么在线版要先搭「云系统」？**
  → 因为「一个服务一个 OS」是真实运维的心智模型：把服务之间的边界（网络、端口、独立升级）用虚拟机显式表达出来，比把所有东西塞在一台机器上更容易理解「服务之间怎么互动」。这也是后来上容器的前提。
- **自建服务器还有必要吗？还是都上云 / 上容器？**
  → 原理仍是必需品。云与容器把「部署形态」换了，但 DNS 怎么解析、NAT 怎么改包、证书怎么校验、权限怎么收敛这些**机制**没变；排障时也是靠这些原理。本篇的意义正在于把「机制」讲清楚，形态各篇末尾各自标注。

# 虚拟化与云系统搭建

> 先在一台物理机上装一个「云系统」宿主机，再在上面创建虚拟机模拟整个机房；
> 含 KVM / libvirt、虚拟机网络模式、克隆与快照。
>
> 内容整理自个人学习笔记。**基础框架**参考鸟哥官网《服务器架设篇 - RockyLinux 9》
> 相关章节（从搭建云系统开始）的读后整理；KVM / libvirt / virsh 的用法基于官方文档独立整理。

## 一、为什么先学虚拟化？

**本节要点**：在线版最显著的结构性变化——不从「怎么配 IP」开始，而是**先搭一台虚拟机母机**，理由是「一个服务一个 OS」更接近真实运维。

- 虚拟化环境成熟、单机性能足够跑好几台虚拟机；
- 一台 PC 就能模拟「多台机器 + 内网 + 各类服务」的机房；
- 逼你思考「服务之间怎么互动」，而不是把所有东西堆在一台机器上；
- 也是理解容器的前置：先懂「机器级隔离」，再看「进程级隔离」。

| 形态 | 隔离级别 | 启动速度 | 适合 |
|------|----------|----------|------|
| 虚拟机 | 硬件级（各自内核） | 慢（秒~分钟） | 完整 OS、异构内核、教学 |
| 容器 | 进程级（共享宿主内核） | 快（毫秒~秒） | 微服务、弹性伸缩 |

## 二、云系统母机怎么装？

**本节要点**：母机 = 装好虚拟化组件的最小化宿主机；关键是**装最小化系统 + 开虚拟化扩展 + 配好网络**。

```bash
# ① 确认 CPU 支持并开启了虚拟化（宿主机 BIOS 里要开 VT-x / AMD-V）
grep -E "vmx|svm" /proc/cpuinfo | head -1

# ② 装虚拟化组件（Rocky 9）
sudo dnf install -y qemu-kvm libvirt virt-install virt-manager
sudo systemctl enable --now libvirtd
sudo systemctl status libvirtd --no-pager

# ③ 确认 libvirt 能建虚拟机
sudo virsh list --all
sudo virsh net-list --all
```

- **KVM** 是内核里的虚拟化模块，**QEMU** 负责设备模拟，**libvirt** 是统一管理层（`virsh` / `virt-manager` 都是它的前端）；
- 母机建议**最小化安装**：虚拟化宿主上跑的服务越少，攻击面越小、资源越集中给虚拟机。

## 三、创建第一台虚拟机

**本节要点**：核心是选对**网络模式**——它决定虚拟机能不能被外面访问、能不能上网。

| 模式 | 虚拟机能否上网 | 外面能否直连虚拟机 | 类比 |
|------|----------------|--------------------|------|
| NAT（默认 `default`） | ✅ | ❌（需端口转发） | 家庭路由器后的设备 |
| 桥接（bridge） | ✅ | ✅（与母机同网段） | 局域网里的一台独立机器 |
| 仅主机（host-only / isolated） | ❌ | 仅母机可访问 | 纯内网实验 |

```bash
# 用 virt-install 从 ISO 建一台虚拟机（NAT 网络）
sudo virt-install \
  --name web01 --memory 2048 --vcpus 2 \
  --disk size=20,path=/var/lib/libvirt/images/web01.qcow2 \
  --cdrom /var/lib/libvirt/images/Rocky-9.iso \
  --network network=default --graphics none --console pty,target_type=serial
```

⭐ **做「模拟机房」的教学环境**：用 **桥接** 让每台虚拟机拿到局域网 IP、互相可访问，最接近真实机房；**NAT** 适合只在母机内部实验。

## 四、虚拟机怎么管理？

**本节要点**：`virsh` 是命令行管理入口；**克隆**用于快速铺多台同类机器，**快照**用于「试验前存档」。

```bash
sudo virsh list --all               # 所有虚拟机及状态
sudo virsh start web01
sudo virsh shutdown web01           # 优雅关机
sudo virsh reboot web01
sudo virsh console web01            # 进串口控制台（退出：Ctrl+]）

# 克隆（要先关机）
sudo virt-clone --original web01 --name web02 --file /var/lib/libvirt/images/web02.qcow2

# 快照（qcow2 支持内部快照）
sudo virsh snapshot-create-as web01 before-upgrade
sudo virsh snapshot-list web01
sudo virsh snapshot-revert web01 before-upgrade
```

⚠️ **克隆后必须改**：主机名、`/etc/machine-id`、`/etc/ssh/ssh_host_*`、静态 IP——否则多台机器会「撞身份」，SSH 互连也会报 host key 冲突。

## 使用：从零铺一个三节点实验环境

**本节要点**：一台母机 → 桥接网络 → 一台模板机 → 克隆成多台，是搭实验环境的标准流程。

```bash
# ① 确认桥接网络存在（若没有，先建 br0）
sudo virsh net-list --all

# ② 装模板机（桥接）
sudo virt-install --name tmpl --memory 2048 --vcpus 2 \
  --disk size=20,path=/var/lib/libvirt/images/tmpl.qcow2 \
  --cdrom /var/lib/libvirt/images/Rocky-9.iso \
  --network bridge=br0 --graphics none --console pty,target_type=serial

# ③ 模板机里改好基础设置后关机，克隆
sudo virsh shutdown tmpl
sudo virt-clone --original tmpl --name node01 --file /var/lib/libvirt/images/node01.qcow2
sudo virt-clone --original tmpl --name node02 --file /var/lib/libvirt/images/node02.qcow2

# ④ 启动并逐个改身份（主机名 / machine-id / ssh host key）
sudo virsh start node01 && sudo virsh console node01
```

判据：`virsh list` 三台都在 running；每台 `hostname` 不同、`ip addr` 拿到独立 IP、能互相 `ping` 通。

## 延伸追问

- **虚拟机网络模式怎么选？**
  → 要「像局域网里的一台真机」用**桥接**（有独立 IP、可被外部访问，教学机房首选）；只要「能上网、不想暴露」用 **NAT**（默认网络，外部要访问得靠端口转发）；只做「母机与虚拟机之间」的实验用**仅主机 / 隔离**。
- **快照能当备份用吗？**
  → 不能。快照依赖**同一份镜像文件**（内部快照写在 qcow2 内部），镜像一损坏，快照一起没；它只适合「升级 / 试验前打个存档，出事就回滚」。真正的备份要把 qcow2 拷贝到**别的介质**（先关机或配合外部快照）。
- **KVM 和 VMware 的区别？**
  → KVM 是 **Linux 内核自带的虚拟化模块**（配合 QEMU + libvirt），免费、开源、与云平台（OpenStack / K8s 的虚拟机方案）契合；VMware（ESXi / Workstation）是商业产品，管理界面与生态成熟、企业支持好。功能上现代 KVM 已能覆盖绝大多数场景，云厂商的虚拟机底层大量用 KVM。

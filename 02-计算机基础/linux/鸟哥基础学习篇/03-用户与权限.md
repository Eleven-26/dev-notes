## 一、用户与组是怎么存的？

**本节要点**：账号体系就是四个文件——`/etc/passwd` 存账号、`/etc/shadow` 存密码、`/etc/group` 存组、`/etc/gshadow` 存组密码。

| 文件 | 存什么 | 权限 |
|------|--------|------|
| `/etc/passwd` | 用户名 : 密码占位符 `x` : UID : GID : 描述 : 家目录 : 登录 shell | 644 |
| `/etc/shadow` | 用户名 : 加密密码 : 最后修改 : 最短/最长有效期 : 警告 : 失效 : 保留 | ⚠️ 600 |
| `/etc/group` | 组名 : 密码占位符 : GID : 附加成员列表 | 644 |
| `/etc/gshadow` | 组名 : 加密密码 : 管理员 : 成员 | 600 |

```bash
sudo useradd -m -s /bin/bash -G docker,sudo deploy   # 建账号并加附加组
sudo passwd deploy                                    # 设密码
sudo usermod -aG docker deploy                        # ⚠️ 追加组，-a 不能漏
sudo userdel -r olduser                               # 连家目录一起删
id deploy && groups deploy                            # 看 UID/GID 与所属组
```

⚠️ `usermod -G` **不带 `-a`** 会把用户的附加组**整体替换**掉（经典事故）；GID 1000 通常是第一个普通用户，0 是 root。

## 二、权限模型：rwx 与目录的特殊含义

**本节要点**：`rwx` 对**文件**和**目录**的含义完全不同——目录的 `x` 是「能不能进入」，这是最容易记错的一点。

| 权限 | 对文件 | 对目录 |
|------|--------|--------|
| `r` | 读内容 | 列出目录里有哪些名字（`ls`） |
| `w` | 改内容 | 在目录里**新建 / 删除 / 改名**文件 |
| `x` | 执行 | **进入目录**（`cd`）、访问其中的文件 |

数字权限：`r=4, w=2, x=1`，三位分别对应 属主 / 属组 / 其他人。`chmod 755` = `rwxr-xr-x`；`chmod 644` = `rw-r--r--`。

```bash
chmod 640 secret.txt            # 属主 rw，属组 r，其他人无
chmod u+x run.sh                # 只给属主加执行
chown deploy:deploy app/ -R     # 递归改属主属组
```

⭐ **umask**：新建文件 / 目录时「**去掉**哪些权限位」。默认 `022` → 文件 `644`、目录 `755`；改成 `027` → 目录 `750`、文件 `640`（同组可读、其他人无）。

```bash
umask              # 看当前值
umask 027          # 临时设置（写入 /etc/profile 才持久）
```

⚠️ 文件默认**不带执行位**：新建文件的基准是 `666`，目录是 `777`，再减去 umask。

## 三、特殊权限：SUID / SGID / SBIT

**本节要点**：三个特殊位分别解决「以文件属主身份运行」「以目录属组身份新建」「只有属主能删自己的文件」三个问题。

| 特殊位 | 对文件 | 对目录 |
|--------|--------|--------|
| SUID（4） | 执行时**临时获得文件属主**权限（如 `passwd`） | 无意义 |
| SGID（2） | 执行时获得文件属组权限 | 目录里新建的文件**继承目录属组** |
| SBIT（1，粘滞位） | 无意义 | 目录里的文件**只有属主 / root 能删** |

```bash
ls -l /usr/bin/passwd      # -rwsr-xr-x 里的 s 就是 SUID
ls -ld /tmp                # drwxrwxrwt 末尾的 t 就是粘滞位
chmod u+s app              # 加 SUID
chmod +t shared/           # 加粘滞位
```

⭐ `/tmp` 就是 `1777`：谁都能建文件、都能改自己的，但删不了别人的——这正是粘滞位的用途。

## 四、ACL：给「单个用户」开权限

**本节要点**：传统权限只能分「属主 / 属组 / 其他人」三类；ACL 让你给**任意用户或组**单独授权，并支持**默认继承**。

```bash
sudo setfacl -m u:alice:rw /data/report.txt     # 给 alice 单独 rw
sudo setfacl -m g:dev:rx /data/tools            # 给 dev 组 rx
getfacl /data/report.txt                        # 查看 ACL（会看到 +）
ls -l /data/report.txt                          # 权限位的第 11 位变成 +

# 默认 ACL：目录里新建的文件/目录自动继承
sudo setfacl -d -m u:alice:rw /data/shared
```

- `-m` 改规则、`-x` 删规则、`-b` 清空所有 ACL；
- 默认 ACL（`-d`）只对**目录**有意义，且**不继承给已存在的文件**；
- ⚠️ 复制文件时 `cp` **默认不带 ACL**，要 `cp -a` 或 `--preserve=all`。

## 五、sudo：给权限而不是给密码

**本节要点**：相比于共享 root 密码，`sudo` 能做到「指定人能执行指定命令、且留审计日志」。

```bash
sudo visudo            # ⚠️ 只能用 visudo 改，它带语法检查
```

```text
# 在 /etc/sudoers 里（或 /etc/sudoers.d/ 下新建文件）
deploy  ALL=(ALL:ALL) NOPASSWD: /usr/bin/systemctl restart nginx
%dev    ALL=(ALL)      ALL
```

| 写法 | 含义 |
|------|------|
| `user ALL=(ALL) ALL` | 该用户可在任何主机以任何用户执行任何命令 |
| `%group ...` | `%` 前缀表示用户组 |
| `NOPASSWD:` | 免密码（适合脚本，但风险更高） |
| 末列写具体命令 | ⭐ **最小权限**：只授权需要的命令 |

- `sudo -l` 看当前用户被授权了什么；`sudo -u www data cmd` 以指定用户执行；
- ⚠️ 授权「具体命令」时要小心：允许 `sudo vim` 等价于给了 root（vim 里能 `:!sh`），要按「能否逃逸出 shell」判断。

## 使用：给一个服务账号配最小权限

**本节要点**：典型场景——应用以 `app` 运行，只允许它读写自己的数据目录、并由部署用户 `sudo` 重启它的服务。

```bash
# ① 建账号（无登录 shell，防被拿去登录）
sudo useradd -r -s /sbin/nologin -M app

# ② 数据目录归属 app，属组 dev 可读
sudo mkdir -p /srv/app/data
sudo chown -R app:dev /srv/app
sudo chmod 750 /srv/app/data

# ③ 用 ACL 给临时协作者 alice 只读
sudo setfacl -m u:alice:r-x /srv/app/data
getfacl /srv/app/data

# ④ 授权部署用户只重启该服务
echo 'deploy ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart app' | sudo tee /etc/sudoers.d/app
sudo chmod 440 /etc/sudoers.d/app
sudo visudo -c        # 校验语法
```

判据：`id app` 显示 nologin、`getfacl` 能看到 alice 的条目、`sudo -l`（以 deploy 身份）只列出那一条命令。

## 延伸追问

- **SUID 有什么风险？**
  → SUID 让「任何用户执行它时都获得属主权限」。若属主是 root，程序里任何**命令注入、缓冲区溢出、对可控路径的写**都会被放大成 root 权限。所以：能不用 SUID 就不用（现代更推荐 capabilities，如 `sbin/cap_net_bind_service`），并且**绝不给可写的脚本配 SUID**（内核根本不认脚本的自 SUID）。
- **ACL 和传统权限冲突时谁生效？**
  → 两者不是「谁覆盖谁」，而是**同一条判定链上的先后**：先比属主位 → 再比 ACL 里的 `user` 条目 → 再比属组位与 `mask` → 再比 ACL 里的 `group` 条目 → 最后比其他人位。⭐ `mask` 是 ACL 的「有效权限上限」，`getfacl` 里 `mask::` 会限制 `group::` 与所有 `user:`/`group:` 条目的实际生效值。
- **sudo 和 su 的区别？**
  → `su` 是「**切换身份**」，需要目标用户的密码（切 root 即 root 密码），切过去后是完整会话、无命令级审计；`sudo` 是「**以他人身份执行一条命令**」，用调用者自己的密码，可按命令授权、有日志。生产上更推荐 `sudo` + 具体命令，而非共享 root 密码。
- **为什么服务账号要用 `/sbin/nologin`？**
  → 服务账号只需「拥有文件和进程」，不需要交互登录。给它 nologin shell，即使密码泄露也无法登录系统，缩小攻击面；配合 `-r` 建系统账号（UID < 1000）更规范。

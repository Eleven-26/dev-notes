## 一、开机流程分几步？出问题在哪一步救援？

**本节要点**：从按下电源到登录，依次经过**固件 → GRUB2 → initramfs → systemd → 默认 target** 五步；每步都有对应的救援入口。

| 步骤 | 做什么 | 出问题的表现 | 救援 |
|------|--------|--------------|------|
| 固件（BIOS / UEFI） | 自检、按顺序找启动设备 | 找不到盘 | 进 BIOS 改启动项 / 修复 EFI 分区 |
| GRUB2 | 载入内核与 initramfs | 卡在 grub 提示符 | grub 命令行手动指内核 |
| initramfs | 加载挂载根所需驱动 | `dracut` 报警、找不到根 | 在 grub 里改内核参数加 `rd.break` |
| systemd | 按依赖并行拉起单元 | 卡在某个 unit | rescue / emergency target |
| 默认 target | 进入 `multi-user` / `graphical` | 进了但服务异常 | `systemctl --failed` 逐项修 |

```bash
# 查看默认 target 与当前 target
systemctl get-default
systemctl isolate rescue.target        # 切到救援模式（需 root 密码）
```

- **rescue** 会挂载本地文件系统、启动基本服务；**emergency** 只挂根（只读）、起极少进程；
- ⚠️ 忘了 root 密码：在 grub 编辑内核行加 `rd.break`，进 initramfs 后 `mount -o remount,rw /sysroot` + `chroot` 重置密码。

## 二、例行性任务怎么调度？

**本节要点**：周期任务有两套——`cron`（传统、安防在 `crontab` 里）与 **systemd timer**（现代、有日志、依赖更清晰）。一次性任务用 `at`。

### 2.1 cron

```text
# 分 时 日 月 周   命令
  0  3  *  *  *   /usr/local/bin/backup.sh >> /var/log/backup.log 2>&1
*/5  *  *  *  *   /usr/local/bin/check.sh
```

```bash
crontab -e          # 编辑当前用户的任务
crontab -l          # 列出
sudo crontab -u www -l   # 看某用户的任务
```

⚠️ cron 的三个坑：① **环境变量极简**（PATH 常只有 `/usr/bin:/bin`，脚本里用绝对路径）；② **没有终端**（要显式重定向输出，否则邮件堆积）；③ 服务器**停机错过的时间点不会补跑**。

### 2.2 systemd timer（推荐）

```text
# myapp-backup.timer
[Unit]
Description=Daily backup

[Timer]
OnCalendar=*-*-* 03:00:00
Persistent=true          # ⭐ 错过的任务开机后补跑

[Install]
WantedBy=timers.target
```

```bash
systemctl list-timers --all       # 看所有定时器与下次触发时间
journalctl -u myapp-backup        # 定时任务的日志直接在 journal 里
```

| 维度 | cron | systemd timer |
|------|------|---------------|
| 补跑错过的 | ❌ | ✅ `Persistent=true` |
| 日志 | 要自己重定向 | ✅ 进 journal |
| 依赖 / 资源限制 | ❌ | ✅ 同 service |

## 三、基础系统设置有哪些？

**本节要点**：主机名、时区 / 时间同步、语言与字符集是「新机器初始化」的三件套，现代都用 `*ctl` 类命令管理。

```bash
sudo hostnamectl set-hostname web01          # 主机名
sudo timedatectl set-timezone Asia/Shanghai  # 时区
timedatectl                                  # 看时间同步状态（NTP 是否 active）
localectl status                             # 语言与键盘
```

| 项 | 命令 | 备注 |
|----|------|------|
| 主机名 | `hostnamectl` | 改 `/etc/hostname` |
| 时间 / 时区 | `timedatectl` | 建议开启 NTP 同步 |
| 语言 / 字符集 | `localectl` | 服务器建议 `en_US.UTF-8` + 注意 LANG |

⚠️ **时间不同步是很多「莫名其妙」问题的根**：证书校验失败、日志时间对不上、集群选举异常，先 `timedatectl` 确认同步。

## 四、例行巡检该查什么？

**本节要点**：巡检不是「随便 top 一下」，而是**固定清单 + 固定阈值**；下面这张表可直接做成脚本每日跑。

| 类别 | 命令 | 关注点 |
|------|------|--------|
| 负载 / CPU | `uptime`、`vmstat 1 5` | 负载与核数比、`r` 队列 |
| 内存 | `free -h` | 可用内存、swap 使用 |
| 磁盘 | `df -h`、`df -i` | 容量与 **inode** 双查 |
| I/O | `iostat -x 1 3` | `%util`、`await` |
| 服务 | `systemctl --failed` | 有没有失败的单元 |
| 日志 | `journalctl -p err -b --no-pager` | 本次开机的错误 |
| 安全 | `last`、`who`、`journalctl -u sshd` | 异常登录 |
| 更新 | `dnf check-update` | 待更新与安全公告 |

⭐ 巡检脚本的判据要**可机读**（如 `df -h` 使用率 > 80% 告警），而不是人肉看；具体排查套路见 [性能排查.md](../性能排查.md)。

## 使用：新服务器初始化 + 日常巡检脚本

**本节要点**：把本目录各篇的收尾动作固化成两段可复用的命令。

```bash
# ===== 初始化 =====
sudo hostnamectl set-hostname web01
sudo timedatectl set-timezone Asia/Shanghai
sudo useradd -r -s /sbin/nologin app
sudo systemctl enable --now chronyd        # 时间同步
sudo dnf -y update && sudo dnf -y install epel-release

# ===== 巡检 =====
echo "== uptime =="; uptime
echo "== disk ==";  df -h /; df -i /
echo "== failed units =="; systemctl --failed --no-pager
echo "== recent errors =="; journalctl -p err -b --no-pager | tail -20
echo "== listening =="; ss -tulnp | head
```

判据：初始化后 `timedatectl` 显示 `NTP service: active`、主机名 / 时区正确；巡检输出里 `df -i` 与 `df -h` 都不紧张、`--failed` 为空、无成片 error。

## 延伸追问

- **cron 和 systemd timer 该用哪个？**
  → 新系统优先 **timer**：能补跑错过的任务（`Persistent=true`）、日志自动进 journal、能复用 service 的资源限制与依赖。`cron` 的优势是跨发行版一致、极简、老系统必备。⚠️ 容器里通常**没有** systemd，这时 cron / 应用内调度更现实。
- **为什么 `df` 显示有空间却写不进去？**
  → 常见两种：① **inode 耗尽**（`df -i` 看，ext4 定死、小文件多时先耗尽）；② 进程删了文件但**还持有 fd**，空间未释放（`lsof +L1` 找到后重启 / 断开该进程）。原理见 [文件系统与IO.md](../文件系统与IO.md)。
- **系统起不来怎么最快定位？**
  → 不用猜：进 rescue / emergency 后 `journalctl -xb` 看当次启动日志，`systemctl --failed` 找失败单元，`systemctl get-default` 确认目标。若是驱动 / initramfs 问题，grub 里加 `rd.break` 或 `systemd.unit=rescue.target` 进去修。
- **例行任务没跑，怎么查？**
  → cron：看 `/var/log/cron`（或 `journalctl -u crond`），确认任务是否被触发、脚本是否因 `PATH` / 权限失败；timer：`systemctl list-timers --all` 看下次触发、`journalctl -u <name>` 看上次执行结果。

## 一、rpm 能做什么、不能做什么？

**本节要点**：`rpm` 管「单个包」，能装、能查、能卸，但**不解决依赖**——依赖问题交给 yum / dnf。

```bash
rpm -qa | grep nginx              # 列出已装的包
rpm -ql nginx                     # 这个包装了哪些文件
rpm -qf /usr/sbin/nginx          # 这个文件属于哪个包（反向查，很常用）
rpm -qi nginx                     # 包的元数据（版本、来源）

sudo rpm -ivh pkg.rpm             # 安装
sudo rpm -Uvh pkg.rpm             # 升级（没装过则安装）
sudo rpm -e nginx                 # 卸载（不处理依赖）
```

| 场景 | 命令 |
|------|------|
| 这个文件是哪来的 | `rpm -qf <文件>` |
| 这个包装了啥 | `rpm -ql <包>` |
| 校验包有没有被改 | `rpm -V <包>` |

⚠️ `rpm -e` 卸载时会报「被依赖阻止」；`rpm -ivh` 装本地包时若缺依赖会直接失败——两种都该改用 `yum localinstall` / `dnf install ./pkg.rpm`。

## 二、yum / dnf 怎么用？

**本节要点**：yum（及继任者 dnf）在 rpm 之上加了**仓库 + 依赖求解**；`dnf` 是 `yum` 的现代化重写，命令基本兼容。

```bash
sudo yum install nginx            # 安装（自动装依赖）
sudo yum update                   # 更新所有
sudo yum update nginx             # 只更新一个
sudo yum remove nginx             # 卸载
yum search nginx                  # 搜包
yum info nginx                    # 看包信息
yum provides "*/nginx"            # 哪个包提供这个文件（对应 rpm -qf 的仓库侧）

sudo yum groupinstall "Development Tools"   # 组安装（一整组工具）
```

| 维度 | yum（CentOS 7） | dnf（CentOS 8+ / Rocky / Fedora） |
|------|-----------------|-----------------------------------|
| 依赖求解 | 较慢、内存占用高 | **libsolv**，更快更省内存 |
| 事务回滚 | 弱 | 支持 `dnf history undo` |
| 模块化 | ❌ | ✅ `dnf module`（同包多版本并存） |
| 命令 | `yum ...` | `dnf ...`（`yum` 通常是软链） |

### 2.1 仓库配置

```bash
yum repolist                      # 看启用了哪些仓库
ls /etc/yum.repos.d/              # 仓库配置文件目录
```

```text
[myrepo]
name=My Repo
baseurl=https://example.com/repo/$releasever/$basearch
enabled=1
gpgcheck=1
gpgkey=file:///etc/pki/rpm-gpg/RPM-GPG-KEY-myrepo
```

⚠️ `gpgcheck=1` 校验包签名，**不要图省事关掉**——那是供应链攻击的第一道闸。

## 三、源码编译怎么做？

**本节要点**：官方源里没有的版本 / 需要自定义编译选项时走源码：`configure → make → make install` 三步，风险是「不受包管理器管理」。

```bash
./configure --prefix=/usr/local/myapp --with-xxx   # 检测环境、生成 Makefile
make                                               # 编译
sudo make install                                  # 安装到 prefix
```

- 三件套的依赖：`gcc` / `make` / `autoconf`（多数项目还需要 `-devel` 头文件包）；
- `--prefix` 装到 `/usr/local/*`，与系统包**隔离**，好卸载（`make uninstall` 不一定有）；
- ⚠️ `make install` 装的文件**不可被 `rpm -qf` / `yum` 追踪**，容易与系统包冲突；
- 现代替代：用官方预编译二进制、容器镜像，或自己打 `rpm`（`fpm` / `rpmbuild`）。

## 四、第三方仓库该不该加？

**本节要点**：EPEL 补「系统自带没有但很常用」的包，Remi / SCL 提供**更新版本的 PHP 等语言运行时**；加上就要承担「与官方源冲突」的代价。

| 仓库 | 内容 | 场景 |
|------|------|------|
| EPEL | Extra Packages for Enterprise Linux | 常用工具（`htop`、`jq` 等） |
| Remi | 新版 PHP / MySQL 等 | 系统自带的 PHP 版本太旧 |
| SCL / AppStream | Software Collections / 模块流 | 同语言多版本并存 |

```bash
sudo yum install epel-release                    # CentOS 7
sudo dnf install epel-release                    # Rocky 9
sudo dnf module list php                         # 看可选的 PHP 模块流
sudo dnf module enable php:8.1                   # 切到 8.1 流
```

⚠️ 第三方源包名可能与官方源**同名不同源**，导致 `yum update` 时版本漂移；生产建议用 `priority` / `includepkgs` 约束，或干脆**用容器跑新版本运行时**。

## 使用：装一个不在默认源里的工具

**本节要点**：决策顺序——先搜官方源，没有再考虑 EPEL / 第三方，仍不行才源码或容器。

```bash
# ① 先搜官方源
sudo dnf search ripgrep

# ② 官方源没有 → 加 EPEL 再搜
sudo dnf install -y epel-release
sudo dnf search ripgrep

# ③ 装并验证
sudo dnf install -y ripgrep
rpm -qf $(which rg)            # 确认来自哪个包（可追溯）
rg --version

# ④ 离线场景：下载 rpm 及其依赖一起带过去
dnf download --resolve ripgrep -y --destdir=/tmp/rpms
sudo rpm -ivh /tmp/rpms/*.rpm  # 或在目标机 dnf install ./*.rpm
```

判据：`rpm -qf $(which rg)` 能报出包名（说明被包管理器追踪），版本符合预期。

## 延伸追问

- **rpm 和 yum 的关系？**
  → `rpm` 是**底层包格式与工具**（安装单个包、查询、校验），`yum` / `dnf` 是**上层管理器**（从仓库拉包、解析依赖、成组安装）。⭐ yum / dnf 最终仍调用 rpm 完成安装，只是先替你解决了依赖；所以「`rpm -qf` 能查到」意味着包被 rpm 数据库追踪，无论它是 rpm 直装的还是 yum 装的。
- **dnf 比 yum 强在哪？**
  → 三点：**依赖求解引擎换成 libsolv**（更快、内存更省）、**事务可回滚**（`dnf history` / `dnf history undo`）、**模块化**（`dnf module`，同一仓库里 PHP 7.4 / 8.0 / 8.1 并存可选）。日常命令基本与 yum 兼容。
- **怎么离线安装？**
  → `dnf download --resolve <包>`（或 `yumdownloader --resolve`）把包**连同依赖**下到本地目录，拷到目标机后 `dnf install ./*.rpm` 或 `rpm -ivh *.rpm`。⚠️ 目标机架构 / 发行版版本要与下载机一致，否则依赖对不上。
- **`gpgcheck=0` 有什么风险？**
  → 等于放弃「包来源校验」。仓库被劫持或镜像投毒时，恶意 rpm 会被静默安装——这是典型的供应链攻击面。宁可多配一次 `gpgkey`，也不要关校验。

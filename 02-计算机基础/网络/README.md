# 网络笔记索引（本目录导读）

> 本目录是「一次请求怎么从本机走到服务端」的完整链条：**纵向（分层与封装）** 与 **横向（链路与节点）**
> 各有一篇总纲，其余篇目都是这条链上的某个环节。
>
> 内容整理自个人学习笔记。**本文件只给阅读顺序与依赖关系**——每篇的知识点描述见
> [全仓知识点目录](../../目录.md)，本目录**不重复描述**；跨目录的延伸见「三、与其它目录的分工」。

## 二、推荐阅读顺序

### 2.1 主线：跟着一个请求走（第一次通读走这条）

```text
① 网络分层与数据包旅程      ← 纵向总纲：层是什么、包怎么被造出来
② 网络通信链路详解          ← 横向总纲：链路上有谁、13 步怎么走
        ↓
③ DHCP                      ← 想出门先拿到四个参数（IP / 掩码 / 网关 / DNS）
④ DNS 解析                  ← 拿到域名对应的 IP（可能是 CDN 的就近节点）
        ↓
⑤ tcp/TCP报文结构           ← 首部字段与序号：后面三篇的共同基础
⑥ tcp/TCP三次握手           ← 建连接
⑦ tcp/TCP滑动窗口           ← 传数据（窗口决定吞吐上限）
⑧ tcp/TCP的Nagle与延迟确认   ← 小包优化（这两条一起看才懂为什么"互相伤害"）
⑨ tcp/TCP四次挥手           ← 断连接（TIME_WAIT / CLOSE_WAIT 都在这一步）
        ↓
⑩ HTTPS与TLS               ← 连接之上的加密与证书
⑪ HTTP与gRPC               ← 应用层的请求/响应与多路复用
⑫ QUIC与HTTP3              ← 为什么把 TCP 换掉；浏览器怎么知道该不该走 h3
⑬ 数据序列化                ← 请求体到底怎么编码（JSON / Protobuf）
        ↓
⑭ IO多路复用                ← 换个视角：服务端怎么同时接住成千上万条连接
⑮ 通信选型                  ← 最后做决策（见过各层才有判断依据）
        ↓
⑯ 反向代理原理与实现          ← 换一层视角：服务端怎么把请求转给上游、头部怎么治理
⑰ 客户端真实IP与可信代理       ← 代理链上「客户端到底是谁」（与 ⑯ 是一对）
        ↓
🧰 抓包实战                  ← 手上功夫：在哪抓、怎么读（随时可插入）
```

### 2.2 专题线：只想补某一块

| 目的 | 按这个顺序读 |
|---|---|
| **排查"慢 / 不通"** | 网络通信链路详解（三、四、五节与其「使用」段）→ DNS 解析（排查命令速查）→ tcp/TCP四次挥手（`CLOSE_WAIT` 堆积） |
| **复习 TCP** | TCP报文结构 → 三次握手 → 滑动窗口 → Nagle 与延迟确认 → 四次挥手 |
| **做技术选型** | 通信选型 → HTTP与gRPC → 数据序列化 |
| **只想搞懂一次访问** | ① ② 两篇总纲 + 网络通信链路详解的「13 步全景」表 |
| **只看 HTTP/3 相关** | QUIC与HTTP3 → HTTPS与TLS（ALPN 与证书）→ tcp/TCP三次握手（对照它被压成 1-RTT） |
| **要动手抓一次包** | 抓包实战 → 网络通信链路详解（五、分层观测点，先定位再抓） |
| **做反向代理 / 网关** | 反向代理原理与实现 → 客户端真实IP与可信代理 → 通信选型 |
| **排查「客户端 IP 不对 / 限流按 IP 误伤」** | 客户端真实IP与可信代理（可信代理链）→ 反向代理原理与实现（XFF 由谁写、为什么不能手写） |

### 2.3 依赖关系（谁要前置）

| 本篇 | 建议先读 | 为什么 |
|---|---|---|
| 网络通信链路详解 | 网络分层与数据包旅程 | 先有「层」，才看得懂「每跳改的是哪一层」 |
| tcp/TCP三次握手 | tcp/TCP报文结构 | 握手报文就是带 `SYN` / `ACK` 标志位的首部 |
| tcp/TCP滑动窗口 | tcp/TCP报文结构、三次握手 | 窗口字段在首部里；连接建好才谈吞吐 |
| tcp/TCP的Nagle与延迟确认 | tcp/TCP滑动窗口 | 都是传输效率问题，放一起看 |
| tcp/TCP四次挥手 | tcp/TCP三次握手 | 关闭是握手的镜像，`TIME_WAIT` 在这一步出现 |
| HTTPS与TLS | tcp/TCP三次握手、DNS解析 | TLS 跑在 TCP 之上；证书要靠 SNI 选 |
| HTTP与gRPC | HTTPS与TLS | 应用层在 TLS 之上；HTTP/2 是 gRPC 的地基 |
| 数据序列化 | HTTP与gRPC | 请求体怎么编码 |
| 通信选型 | 前面大部分 | 没见过各层，选型表看不出取舍 |
| QUIC与HTTP3 | HTTPS与TLS、tcp/TCP三次握手 | 要懂 1-RTT / 0-RTT 的价值，先知道 TCP + TLS 要几次往返 |
| 抓包实战 | 网络通信链路详解、tcp/ 五篇 | 先知道"该看什么"，抓包才有意义 |
| 反向代理原理与实现 | HTTP与gRPC、tcp/TCP报文结构 | 要懂逐跳头与连接复用，才看得懂「哪些头必须剥、哪些必须补」 |
| 客户端真实IP与可信代理 | 反向代理原理与实现 | 先知道代理这一跳写了什么头，再谈「信哪个」 |
| DHCP、DNS解析、IO多路复用 | — | 独立成篇，随时可读 |

> ⚠️ **两条"反直觉"的顺序提醒**：
> 1. **DHCP 排在 DNS 之前**——没有 IP / 掩码 / 网关 / DNS 这四参数，连 DNS 查询都发不出去；
> 2. **DHCP 与 DNS 都在 TCP 之前**——它们是"建连接之前"的准备动作，不是 TCP 的一部分。

## 四、本目录的边界与缺口

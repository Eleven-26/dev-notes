## 三、选型决策框架（三问定结构）

不要背结构清单，按**三个问题**依次筛：

| # | 问题 | 答案 → 指向 |
|---|---|---|
| ① | 数据在**内存**还是**磁盘**？ | 磁盘 → B+ 树（高扇出、层数少）；内存 → 红黑树 / AVL / 跳表 |
| ② | **读多**还是**写多**？ | 读远多于写 → AVL；写也不少 → 红黑树；写极多（磁盘）→ LSM；写极多 + 并发（内存）→ 跳表 |
| ③ | 需求里有没有「**序**」？ | 要范围 / 有序枚举 → 平衡树 / B+ 树；要前缀 / 最长匹配 → Radix / Trie；要区间聚合 → 线段树 / 树状数组；只要等值 → 哈希表 |

⭐ **一句话口诀**：**内存有序用红黑树，磁盘索引用 B+ 树，写多读少用 LSM，并发写用跳表，多维空间用 R 树，前缀匹配用 Radix，区间统计用线段树，只要等值用哈希。**

> 完整场景对照表与隐藏代价总表见 [树的形态与选型.md](树的形态与选型.md) 第二节、第三节。

## 五、延伸追问（通用）

- **同样是 O(log n)，B+ 树和红黑树怎么选？** → 看介质：磁盘上 B+ 树层数即 I/O 次数，高扇出把层数压到 2~4 层；内存里红黑树更简单、写更省。⭐ 完整推导见 [B树与B+树.md](B树与B+树.md)。
- **LSM 树会取代 B+ 树吗？** → 不会。两者为不同读写比与延迟要求优化，真实趋势是混用（MyRocks / TiKV 用 LSM，TiFlash 用列存）。见 [LSM树.md](LSM树.md) 第五节。
- **为什么没有一种树能通吃所有场景？** → 查询、写入、空间、实现复杂度四种代价不可能同时最优；每种结构都在为某一类访问模式优化常数与局部性，而这些优化彼此冲突。
- **什么时候「不用树」才是对的答案？** → ① 数据量小且几乎不变 → 排序数组 + 二分；② 离线一次性区间合并 → 排序 + 贪心；③ 只要等值命中 → 哈希表。⭐ 「上结构」本身有维护成本。
- **树的遍历为什么有四种？各自不可替代在哪？** → 前序用于序列化/复制，中序用于 BST 有序输出，后序用于自底向上汇总，层序用于按层处理。见 [树的遍历.md](树的遍历.md) 第一节。

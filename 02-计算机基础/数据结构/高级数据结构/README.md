## 一、核心思想

**本节要点**：所谓「高级」，本质都是**用额外假设换取更快的操作** —— 用概率换空间、用偏序换 `O(1)` 取极值、
用主动淘汰换线性时间、用平衡换最坏保证。

| 结构 | 拿什么换什么 |
|---|---|
| 位图 / 布隆过滤器 | 用**比特与概率**换空间（`O(1)` 判存在，但会误判） |
| HyperLogLog / Count-Min Sketch | 用**概率**换空间（估基数 / 频次，不存原值） |
| 堆 / 优先队列 | 用**偏序**（只保证堆顶最小）换 `O(1)` 取极值 |
| 单调栈 / 单调队列 | 用「**主动删除永远不会成为答案的元素**」换线性时间 |
| 平衡树 | 用**旋转 / 颜色 / 多路**换「最坏仍是 `O(log n)`」 |
| 跳跃表 | 用**随机层数**换「免旋转的动态有序」（只给期望，不给最坏） |

⭐ 一句话概括本目录与基础结构的差别：**基础结构**（数组 / 链表 / 哈希）只回答「存和取」，而
**高级结构**回答「按某种顺序快速取极值」或「用极小的空间回答近似问题」。

| 需求 | 基础结构的做法 | 高级结构 |
|---|---|---|
| 精确判「在不在」 | 哈希表 | 位图（更省内存，但要求范围有限） |
| 判「**可能**在不在」（超大规模） | 哈希（存不下） | **布隆过滤器**（用约 1% 误判换 10~100 倍空间） |
| 反复取最小 / 最大 | 排序一次后取（但无法动态插入） | **堆**（动态插入下仍是 `O(log n)`） |
| 找「下一个更大的元素」 | 每个元素向后扫 → `O(n²)` | **单调栈**（`O(n)`） |
| 动态维护有序集合 | 有序数组（插入 `O(n)`） | **平衡树**（最坏 `O(log n)`）/ **跳表**（期望 `O(log n)`、免旋转） |

## 二、适用条件

**本节要点**：每个结构都有**一条硬前提**，违反它得到的不是「慢」，而是「**结果不可信**」或「内存直接爆掉」。

| 结构 | 硬前提 | 违反的后果 |
|---|---|---|
| **位图** | 取值范围有限且**较稠密** | ⚠️ 稀疏大范围（如 64 位用户 ID）内存爆炸 → 换 RoaringBitmap |
| **布隆过滤器** | 能接受误判（**只会假阳性，不会假阴性**） | ⚠️ **不支持删除**；把「可能存在」当成「一定存在」就会出业务事故 |
| **HyperLogLog** | 只关心**基数**、不关心具体元素 | 需要精确计数时不可用（误差 ≈ `1.04/√m`） |
| **Count-Min Sketch** | 只关心频次，且能接受**只高不低** | 拿估计值当真实值做容量判断会偏保守（也可能被热点挤占而失真） |
| **堆** | 只需要**极值**，不需要有序遍历 | 想「改中间元素的值」必须自己维护下标，否则结构被破坏 |
| **单调栈 / 单调队列** | 问题能表达成「找左右第一个更大 / 更小」 | ⚠️ 带窗口的问题用单调栈会算错（**过期元素删不掉**），必须用单调队列 |
| **平衡树** | 需要**动态有序 + 最坏保证** | 只需期望复杂度时可换跳表（[跳跃表.md](跳跃表.md)）；只读场景用排序数组更省 |
| **跳跃表** | 能接受**期望**（无最坏保证）、且数据在内存 | ⚠️ 磁盘按页读必须换 B+ 树（逐层降 = 逐层随机 I/O）；硬时限场景该用红黑树（判据见 [跳跃表.md](跳跃表.md) 第六节） |

### 一条更实用的判据

```text
这个结构的保证是「确定性」还是「概率性」的？
├─ 确定性（堆 / 单调栈 / 平衡树）
│   └─ 结果一定对，代价是常数更大、实现更复杂
└─ 概率性（布隆 / HLL / CMS）
    └─ 结果可能错（但有方向），换来的空间收益是数量级的
```

⭐ **工程上要问的第一个问题就是这一条** —— 把概率结构的输出当成精确值用于计费、库存、对账，
是本目录所有坑里后果最严重的一个。

## 三、解题模板

**本节要点**：只需一步 —— **先问「我要回答的是哪个问题」**，然后按下面的决策树选结构。

```text
你要回答什么？
├─ 某个元素在不在？
│   ├─ 精确 + 范围有限      → 位图（BitSet）                    [位图与布隆过滤器.md]
│   └─ 近似 + 亿级元素      → 布隆过滤器（约 1% 误判换空间）
├─ 有多少个不同的？（去重计数）
│   └─ 不要求精确           → HyperLogLog                       [基数与频率估计.md]
├─ 某元素出现了几次？（频次）
│   └─ 允许「只高不低」     → Count-Min Sketch                   [基数与频率估计.md]
├─ 反复取最大 / 最小（含 Top-K）？
│   └─ 大小 K 的小顶堆                                          [堆与优先队列.md]
├─ 每个元素的「左右第一个更大 / 更小」？
│   ├─ 没有窗口             → 单调栈                            [单调栈与单调队列.md]
│   └─ 有滑动窗口           → 单调队列（存下标才判得了过期）
├─ 动态维护一个有序集合（插 / 删 / 查 / 前驱后继）？
│   ├─ 要最坏保证           → 平衡树（红黑树 / AVL / B+ 树）     [平衡树.md]
│   └─ 可接受期望 / 并发写   → 跳表                              [跳跃表.md]
├─ 两个元素是不是同一组？（连通 / 等价类）
│   └─ 并查集（按秩 + 路径压缩）                                [并查集、Trie与一致性哈希.md]
├─ 有哪些键以某前缀开头？（前缀 / 最长前缀匹配）
│   └─ 字典树 Trie（散列表做不到）                              [并查集、Trie与一致性哈希.md]
└─ 增减节点时只让一小段 key 换归属？
    └─ 一致性哈希环 + 虚拟节点                                  [并查集、Trie与一致性哈希.md]
```

### ⭐ 三个自检

```text
□ 这个结果是「精确」还是「近似」的？（概率结构不能当精确值用）
□ 需要「动态插入」吗？（不需要 → 排序数组 + 二分即可，静态场景跳表不划算）
□ 数据规模与取值范围多大？（决定位图会不会爆内存）
```

## 五、正确性证明与复杂度保证

**本节要点**：本目录的「证明」比基础结构**软** —— 要么是**摊还**（前面多花的、后面省回来），
要么是**概率**（可接受的小概率出错），要么是**不变量**（平衡条件）。

| 结构 | 保证类型 | 关键不变量 |
|---|---|---|
| [堆与优先队列.md](../树/堆与优先队列.md) | **结构性 + 偏序** | 每个节点 ≤ 其孩子（小顶堆）⇒ 堆顶即最小；⚠️ **建堆 `O(n)` 不是 `O(n log n)`**，靠「越靠下的节点越多、但下沉高度越小」的求和收敛 |
| [单调栈与单调队列.md](单调栈与单调队列.md) | **摊还** | 每个元素最多进栈 / 出队**各一次** ⇒ 总操作数 ≤ `2n`（实测入栈 1000 + 出栈 1000 = 2000） |
| [平衡树.md](../树/平衡树.md) | **不变量** | AVL：左右子树高度差 ≤ 1；红黑树：**最长路径 ≤ 2 × 最短路径**（实测 1.45）⇒ 树高 `O(log n)` |
| [跳跃表.md](跳跃表.md) | **概率（期望）** | 层数服从几何分布 ⇒ 查找期望 ≈ `2·log₂n` 次比较（理论 33、实测 30.1）；⚠️ **不给最坏保证**，理论上可退化成一条链表 |
| [位图与布隆过滤器.md](位图与布隆过滤器.md) | **概率** | **无一假阴性**；假阳性率随位数组大小与哈希个数变化 |
| [基数与频率估计.md](基数与频率估计.md) | **概率 + 单侧界限** | HLL 误差 ≈ `1.04/√m`；CMS **只高不低**（不会低估） |

### ⭐ 两类最值得记住的推导

**① 建堆为什么是 `O(n)`**：每个节点下沉的代价是它的**高度**，而高度为 `h` 的节点约有 `n / 2^(h+1)` 个 ——
两者相乘求和收敛到 `O(n)`。⚠️ 这也解释了本项目的实测：递减输入下 `push` 建堆是 `build` 的 **4.39 倍**，
但随机输入只有 **1.22 倍**（`O(n log n)` 只是上界，逐个 `push` 的期望代价本就接近 `O(n)`）。

**② 红黑树的「最长 ≤ 2 × 最短」**：由「黑高相同」+「红节点不能相邻」两条性质推出 ——
最短路径全黑、最长路径红黑相间，于是最长最多是最短的两倍 ——
⭐ 这就是红黑树**不需要 AVL 那样严格的高度差、却仍能保证 `O(log n)`** 的原因。

## 六、常见陷阱

**本节要点**：本目录的坑**集中在「把近似当精确」与「前提被违反」两类** —— 前者是业务事故，后者是静默算错。

| 陷阱 | 症状 | 怎么避免 |
|---|---|---|
| **位图用在稀疏大范围** | 内存爆炸 | 先看取值范围；超稀疏用 RoaringBitmap（[位图与布隆过滤器.md](位图与布隆过滤器.md)） |
| **想删除布隆过滤器里的元素** | 做不到，或误判率飙升 | 布隆**不支持删除**；需要删除用 Counting Bloom / Cuckoo Filter |
| **把 HLL 当精确计数** | 得到的数字有偏差 | 接受误差（`1.04/√m`）；要精确就用位图或 HashSet |
| **忽略 CMS 的「只高不低」** | 把估计值当真实值用 | 记住它**只会高估**，做容量判断要留余量 |
| **改了堆中间元素却不修复** | 结构被破坏，后续 `pop` 出错 | 用 `heap.Fix`（Go）或手动调整；⚠️ 要自己维护「元素 → 下标」的映射 |
| **堆的方向搞反** | 求 Top-K 大却用了大顶堆 | ⚠️ **Java `PriorityQueue` 默认是小顶堆**（不是大的）；大顶堆靠反转比较器或存负数 |
| **滑窗最值用单调栈** | 结果偏大（用到了已出窗口的元素） | 带窗口必须用**单调队列**（存下标才判得了过期） |
| **AVL 与红黑树选错** | 写多场景旋转过多、性能不升反降 | AVL 查询更快、红黑树插删旋转更少（[平衡树.md](../树/平衡树.md) 第四节） |
| **把跳表的「期望」当「最坏」** | 硬时限场景不达标；只读数据还白付 2 倍于二分的比较常数 | 跳表只给期望（实测 ≈ 30 次比较，二分 ≈ 16 次）；要最坏保证用红黑树，静态数据排序 + 二分（[跳跃表.md](跳跃表.md) 第五、六节） |
| **只背旋转、不会分析** | 画不出旋转前后的树形 | 记两条：**中序不变** + **高度降低**（实测旋转后中序不变、高度 3→2） |

## 七、与其他思想对比

**本节要点**：高级结构**很少单独出场** —— 它总是「某个算法能更快一点」的原因。见到 `O(n log n)` 的算法，
背后大概率藏着一个堆或一棵平衡树。

### 高级结构 vs 基础数据结构

⚠️ **「树有哪些形态」「堆是什么」这类概述在 [README.md](../README.md)**，
本目录只讲实现与性质。两边的分工是：

| | [README.md](../README.md) | 本目录 |
|---|---|---|
| 回答 | **它是什么、适合解决什么问题** | **它怎么实现、性质怎么维持、边界在哪** |
| 形态 | 对照表与复杂度总表 | 上浮下沉的完整实现、旋转的四种形态、`O(n)` 建堆的推导 |

### 高级结构 vs 动态规划

结构常是 DP 的**优化手段**：

| 场景 | 优化 |
|---|---|
| DP 每次要取「当前最优候选」 | 用**堆**把线性的「扫一遍找最小」降成 `O(log n)` |
| LIS 的 `O(n²)` DP | 用 [二分查找.md](../../算法/基础算法/二分查找.md) 的 `tails` 数组降成 `O(n log n)` |
| 状压 DP 的状态集 | 用 [位运算.md](../../算法/基础算法/位运算.md) 的位掩码表示 |

### 高级结构 vs 贪心

⭐ **堆与单调栈常常就是贪心的实现载体**：

| 贪心算法 | 靠什么结构实现 |
|---|---|
| Dijkstra | 小顶堆（[Dijkstra.md](../../算法/图论算法/最短路/Dijkstra.md)） |
| Prim | 优先队列（[Prim.md](../../算法/图论算法/最小生成树/Prim.md)） |
| 霍夫曼编码 | 最小堆（[霍夫曼编码.md](../../算法/贪心/霍夫曼编码.md)） |
| 活动选择 / 区间调度 | 排序（[区间调度.md](../../算法/贪心/区间调度.md)） |

⚠️ 反过来说：**这些算法里的「堆」如果写错，算法不会报错，只会给出次优解** ——
这也解释了为什么本目录的篇目要和那些算法篇互引。

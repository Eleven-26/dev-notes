## 一、核心思想

**本节要点**：所谓「高级」，本质都是**用额外假设换取更快的操作** —— 用主动淘汰换线性时间、
用随机层数换免旋转、用一次倒排换直接命中、用环形槽换取模常数。

| 结构 | 拿什么换什么 |
|---|---|
| 单调栈 / 单调队列 | 用「**主动删除永远不会成为答案的元素**」换线性时间 |
| 跳跃表 | 用**随机层数**换「免旋转的动态有序」（只给期望，不给最坏） |
| 倒排索引 | 用**写入时的一次倒排**换「值 → 主键集合」的直接命中（不再全表扫） |
| 时间轮 | 用**定长环形槽 + 取模**换定时器插入与推进的 `O(1)` |
| 并查集 | 用**按秩合并 + 路径压缩**换「连通判断接近常数」 |

⭐ 一句话概括本目录与基础结构的差别：**基础结构**（数组 / 链表 / 哈希）只回答「存和取」，
而**高级结构**回答「按某种顺序快速取极值」或「合并 / 检索 / 定时」。

| 需求 | 基础结构的做法 | 高级结构 |
|---|---|---|
| 反复取最小 / 最大 | 排序一次后取（但无法动态插入） | **堆**（动态插入下仍是 `O(log n)`） |
| 找「下一个更大的元素」 | 每个元素向后扫 → `O(n²)` | **单调栈**（`O(n)`） |
| 动态维护有序集合 | 有序数组（插入 `O(n)`） | **平衡树**（最坏 `O(log n)`）/ **跳表**（期望 `O(log n)`、免旋转） |
| 「值 → 主键集合」的命中 | 全表扫 `O(n)` | **倒排索引**（词典 + 有序倒排表） |
| 判两个元素是否同组 | 每次重新遍历 | **并查集**（近似 `O(1)`） |
| 海量定时器 | 每 tick 扫全表 | **时间轮**（插入 / 推进 `O(1)`） |

### 与概率结构的分界

| | 本目录 | [概率与统计/](../概率与统计/README.md) |
|---|---|---|
| 结果 | **一定对**（跳跃表只弱化最坏界） | 可能错，误差方向固定 |
| 空间 | 随元素数增长 | 固定预算 |
| 判据 | 需要精确答案 | 能接受近似（前置过滤 / 容量估算） |

⚠️ **先问这一条，再谈结构选型** —— 把概率结构的输出当精确值用于计费、库存、对账，
是这两个目录里后果最严重的一类事故。

## 二、适用条件

**本节要点**：每个结构都有**一条硬前提**，违反它得到的不是「慢」，而是「**结果不可信**」或「结构被破坏」。

| 结构 | 硬前提 | 违反的后果 |
|---|---|---|
| **单调栈 / 单调队列** | 问题能表达成「找左右第一个更大 / 更小」 | ⚠️ 带窗口的问题用单调栈会算错（**过期元素删不掉**），必须用单调队列 |
| **跳跃表** | 能接受**期望**（无最坏保证）、且数据在内存 | ⚠️ 磁盘按页读必须换 B+ 树（逐层降 = 逐层随机 I/O）；硬时限场景该用红黑树（判据见 [跳跃表.md](跳跃表.md) 第六节） |
| **倒排索引** | 倒排表必须**有序** | 差分压缩、求交、跳点**三件事全部失效** —— 有序是它的硬前提，不是优化 |
| **时间轮** | 延迟必须**小于一圈**（否则要分层 / 记圈数） | ⚠️ 任务**提前整整一圈**触发，且**不报错**（实测：期望第 261 个 tick，第 6 个就跑） |
| **并查集** | 只做**合并与查询**，不需要拆开 | ⚠️ **不支持回滚**；带删除的连通性要换更重的结构 |

> 概率结构的硬前提（位图范围、布隆不能删、布谷鸟桶数是 2 的幂等）见
> [README.md](../概率与统计/README.md) 第二节。

### 一条更实用的判据

```text
这个结构的保证是「确定性」还是「概率性」的？
├─ 确定性（本目录：单调栈 / 跳表期望 / 倒排 / 时间轮 / 并查集）
│   └─ 结果一定对，代价是常数更大、实现更复杂
└─ 概率性（概率与统计/：布隆 / 布谷鸟 / HLL / CMS）
    └─ 结果可能错（但有方向），换来的空间收益是数量级的
```

⭐ **工程上要问的第一个问题就是这一条**。答案决定你该进哪个目录，而不是先背结构名。

## 三、解题模板

**本节要点**：只需一步 —— **先问「我要回答的是哪个问题」**，然后按下面的决策树选结构。

```text
你要回答什么？
├─ 反复取最大 / 最小（含 Top-K）？
│   └─ 大小 K 的小顶堆                                          [堆与优先队列.md](../堆/堆与优先队列.md)
├─ 每个元素的「左右第一个更大 / 更小」？
│   ├─ 没有窗口             → 单调栈                            [单调栈与单调队列.md]
│   └─ 有滑动窗口           → 单调队列（存下标才判得了过期）
├─ 动态维护一个有序集合（插 / 删 / 查 / 前驱后继）？
│   ├─ 要最坏保证           → 平衡树（红黑树 / AVL / B+ 树）     [平衡树.md](../树/内存平衡树/平衡树.md)
│   └─ 可接受期望 / 并发写   → 跳表                              [跳跃表.md]
├─ 要「值 → 主键集合」的命中、还要多条件求交？
│   └─ 倒排索引（求交时**按 df 升序**、小表先行）                [倒排索引.md]
├─ 海量定时器，插入与推进都要 `O(1)`？
│   └─ 时间轮（⚠️ 延迟必须 < 一圈）                              [时间轮.md]
├─ 两个元素是不是同一组？（连通 / 等价类）
│   └─ 并查集（按秩 + 路径压缩）                                [并查集.md]
├─ 有哪些键以某前缀开头？（前缀 / 最长前缀匹配）
│   └─ 字典树 Trie（散列表做不到）                              [Trie.md](../树/空间与字符串树/Trie.md)
├─ 增减节点时只让一小段 key 换归属？
│   └─ 一致性哈希环 + 虚拟节点                                  [一致性哈希.md](../../../04-架构与系统/分布式/服务治理/一致性哈希.md)
└─ 判「可能存在」/ 估基数 / 估频次？
    └─ 概率结构（⚠️ 结果不精确）                               [README.md](../概率与统计/README.md)
```

### ⭐ 三个自检

```text
□ 这个结果是「精确」还是「近似」的？（近似 → 概率与统计/）
□ 需要「动态插入」吗？（不需要 → 排序数组 + 二分即可，静态场景跳表不划算）
□ 结构在内存还是磁盘上？（磁盘有序索引 → B+ 树，见 树/磁盘存储树/）
```

## 五、正确性证明与复杂度保证

**本节要点**：本目录的「证明」比基础结构**软** —— 要么是**摊还**（前面多花的、后面省回来），
要么是**期望**（随机层数），要么是**不变量**（有序 / 等价类）。

| 结构 | 保证类型 | 关键不变量 |
|---|---|---|
| [单调栈与单调队列.md](单调栈与单调队列.md) | **摊还** | 每个元素最多进栈 / 出队**各一次** ⇒ 总操作数 ≤ `2n`（实测入栈 1000 + 出栈 1000 = 2000） |
| [跳跃表.md](跳跃表.md) | **概率（期望）** | 层数服从几何分布 ⇒ 查找期望 ≈ `2·log₂n` 次比较（理论 33、实测 30.1）；⚠️ **不给最坏保证**，理论上可退化成一条链表 |
| [倒排索引.md](倒排索引.md) | **确定性** | 倒排表**有序** ⇒ 求交结果精确、压缩无损；⚠️ 前提就是那条有序性 |
| [时间轮.md](时间轮.md) | **确定性**（前提成立时） | 每个任务**只被处理一次**（到期那一次）；⚠️ 前提是「延迟在一圈内」 |
| [并查集.md](并查集.md) | **摊还** | 按秩合并保证树高 `O(log n)`，路径压缩再摊还到反阿克曼函数 `α(n)` |

### ⭐ 两条最值得记住的推导

**① 单调栈为什么是 `O(n)`**：虽然内层有 `while`，但每个元素**最多入栈一次、出栈一次** ——
把「内层循环」的总次数摊到每个元素上只有常数次，所以是**摊还** `O(n)`，不是最坏 `O(n²)`。

**② 并查集为什么「接近 `O(1)`」**：单用路径压缩是摊还 `O(log n)`，单用按秩合并是最坏 `O(log n)`；
两者合用才得到摊还 `O(α(n))`，而 `α(n) ≤ 4`（在可想象的输入规模内）。⚠️ 关键是不可拆 —— **不支持回滚**。

> 堆 / AVL / 红黑树的保证在各自篇目里推导：[堆与优先队列.md](../堆/堆与优先队列.md)（**建堆 `O(n)` 不是 `O(n log n)`**）、
> [AVL树.md](../树/内存平衡树/AVL树.md)（`1.44 log₂(n+2)`）、[红黑树.md](../树/内存平衡树/红黑树.md)（最长 ≤ 2 × 最短，实测 1.45）。

## 六、常见陷阱

**本节要点**：本目录的坑**集中在「前提被违反」** —— 结构被破坏或结果静默出错，通常不报错。
概率结构的「把近似当精确」见 [README.md](../概率与统计/README.md) 第六节。

| 陷阱 | 症状 | 怎么避免 |
|---|---|---|
| **时间轮的延迟超过一圈** | 任务**提前整整一圈**触发，且不报错 | 分层时间轮，或每槽记「还要转几圈」（[时间轮.md](时间轮.md) 第三节） |
| **倒排表在压缩时丢了有序性** | 求交与跳转全错，且难定位 | 差分 / RoaringBitmap 都**要求输入有序** —— 压缩前先确认排序（[倒排索引.md](倒排索引.md)） |
| **滑窗最值用单调栈** | 结果偏大（用到了已出窗口的元素） | 带窗口必须用**单调队列**（存下标才判得了过期） |
| **改了堆中间元素却不修复** | 结构被破坏，后续 `pop` 出错 | 用 `heap.Fix`（Go）或手动调整；⚠️ 要自己维护「元素 → 下标」的映射 |
| **堆的方向搞反** | 求 Top-K 大却用了大顶堆 | ⚠️ **Java `PriorityQueue` 默认是小顶堆**（不是大的）；大顶堆靠反转比较器或存负数 |
| **AVL 与红黑树选错** | 写多场景旋转过多、性能不升反降 | AVL 查询更快、红黑树插删旋转更少（[平衡树.md](../树/内存平衡树/平衡树.md) 第二节） |
| **把跳表的「期望」当「最坏」** | 硬时限场景不达标；只读数据还白付 2 倍于二分的比较常数 | 跳表只给期望（实测 ≈ 30 次比较，二分 ≈ 16 次）；要最坏保证用红黑树，静态数据排序 + 二分（[跳跃表.md](跳跃表.md) 第五、六节） |
| **以为并查集能删边** | 拆开后连通性无法回滚 | 并查集只支持合并；需要删除时换带删除的连通性结构 |
| **只背旋转、不会分析** | 画不出旋转前后的树形 | 记两条：**中序不变** + **高度降低**（实测旋转后中序不变、高度 3→2） |

## 七、与其他思想对比

**本节要点**：高级结构**很少单独出场** —— 它总是「某个算法能更快一点」的原因。见到 `O(n log n)` 的算法，
背后大概率藏着一个堆或一棵平衡树。

### 高级结构 vs 基础数据结构

⚠️ **「树有哪些形态」「堆是什么」这类概述在 [README.md](../README.md)**，
本目录只讲实现与性质。两边的分工是：

| | [README.md](../README.md) | 本目录 |
|---|---|---|
| 回答 | **它是什么、适合解决什么问题** | **它怎么实现、性质怎么维持、边界在哪** |
| 形态 | 对照表与复杂度总表 | 上浮下沉的完整实现、旋转的四种形态、`O(n)` 建堆的推导 |

### 高级结构 vs 动态规划

结构常是 DP 的**优化手段**：

| 场景 | 优化 |
|---|---|
| DP 每次要取「当前最优候选」 | 用**堆**把线性的「扫一遍找最小」降成 `O(log n)` |
| LIS 的 `O(n²)` DP | 用 [二分查找.md](../../算法/基础算法/查找/二分查找.md) 的 `tails` 数组降成 `O(n log n)` |
| 状压 DP 的状态集 | 用 [位运算.md](../../算法/基础算法/数组与序列技巧/位运算.md) 的位掩码表示 |

### 高级结构 vs 贪心

⭐ **堆与单调栈常常就是贪心的实现载体**：

| 贪心算法 | 靠什么结构实现 |
|---|---|
| Dijkstra | 小顶堆（[Dijkstra.md](../../算法/图论算法/最短路/Dijkstra.md)） |
| Prim | 优先队列（[Prim.md](../../算法/图论算法/最小生成树/Prim.md)） |
| 霍夫曼编码 | 最小堆（[霍夫曼编码.md](../../算法/贪心/霍夫曼编码.md)） |
| 活动选择 / 区间调度 | 排序（[区间调度.md](../../算法/贪心/区间调度.md)） |

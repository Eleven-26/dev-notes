# 编译原理

> 本目录准备收「**后端开发用得上的那部分编译原理**」：源码到可执行文件的四段流水线
> （词法 / 语法 / 语义 / 代码生成）、Go 与 Java 两条截然不同的落地路线、以及**性能与可读性**被编译器决定的那些点。
>
> ⚠️ **本目录目前是空壳** —— 只有这一份导读，还没有任何零件篇；相关内容当前在
> [go/运行时/](../../01-编程语言/go/运行时/) 与 [java/运行时/](../../01-编程语言/java/运行时/)，链接见「三、这些内容现在在哪」。
>
> 内容整理自个人学习笔记。

---

## 一、本目录收什么？与相邻目录的边界在哪？

**本节要点**：判据是「**这条结论是编译/翻译过程本身的原理，还是某语言运行时的行为**」。

| 归本目录 | 不归本目录，归 | 原因 |
|---|---|---|
| 词法 / 语法分析、AST、语义检查 | [../../01-编程语言/](../../01-编程语言/)（某语言的语法本身） | 一边是"怎么把源文本变成结构"，一边是"这门语言规定写成什么样" |
| 中间表示、优化（内联、逃逸、SSA、循环变换） | [../../01-编程语言/go/运行时/](../../01-编程语言/go/运行时/)（运行时怎么执行） | 优化发生在编译期，行为体现在运行期 |
| 链接与装载：静态 / 动态链接、符号、PIC | [../../06-工程实践/部署/](../../06-工程实践/部署/)（镜像里怎么跑起来） | 机制归本目录，交付归部署 |
| JIT、分层编译、逃逸分析**为什么算编译** | [../../01-编程语言/java/运行时/](../../01-编程语言/java/运行时/)（JVM 的参数与实测） | 原理在此，参数与实测在语言目录 |
| 垃圾回收算法的理论底座 | [../垃圾回收/](../垃圾回收/) | 已自成体系，不搬散（同 [算法/README.md](../算法/README.md) 第二节的口径） |

## 二、规划篇目（缺口登记）

**本节要点**：以下篇目**尚未写出**，按仓库约定**不留链接**（避免断链），只登记题目与判定依据。

| 规划篇名 | 要回答的问题 | 门槛判定（能否 ≥1 屏原理） |
|---|---|---|
| 编译四段流水线 | 词法 → 语法 → 语义 → 代码生成，每段的输入输出与出错表现 | ✅ 能 |
| AST 与语义检查 | 语法正确但类型 / 作用域错误的例子；语法树到符号表的过渡 | ✅ 能 |
| 编译优化：内联、逃逸、死代码 | ⭐ 为什么"编译器优化"救不了写得很差的代码；哪些优化会被 `//go:noinline` 之类屏障关掉 | ✅ 能 |
| AOT 与 JIT 两条路线 | Go（直接编译到机器码）与 Java（字节码 + 分层 JIT）在启动时间、峰值性能、可观测性上的取舍 | ✅ 能 |
| 链接与装载 | 静态 / 动态链接、符号解析、为什么同一个 `.so` 换机器就跑不起来 | ⚠️ 待评估，可能与部署合并 |

## 三、这些内容现在在哪？

**本节要点**：先不搬，**建立边界即可**；写新篇时再从这些位置回收共性结论。

- **Go 侧**：编译期行为与运行时结构在 [../../01-编程语言/go/运行时/](../../01-编程语言/go/运行时/)（GMP 调度、内存分配等），
  `go build` / `go vet` / `gofmt` 的校验口径见 [../../README.md](../../README.md)。
- **Java 侧**：字节码、JIT 分层编译与 GC 在 [../../01-编程语言/java/运行时/](../../01-编程语言/java/运行时/) 与 [../垃圾回收/](../垃圾回收/)。
- **算法层**（词法匹配的实现：KMP / BM / AC 自动机）→ [../算法/字符串匹配/](../算法/字符串匹配/)。
- **正则与语法**（各语言 `regexp` 的差异，含 RE2 无回溯）→ 语言目录，编译原理侧不重复。

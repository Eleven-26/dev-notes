# 编译原理

> 本目录收「**后端开发用得上的那部分编译原理**」：源码到可执行文件的四段流水线
> （词法 / 语法 / 语义 / 代码生成）、三条落地路线（AOT / 分层 JIT / 每请求编译）、以及**性能与可读性**被编译器决定的那些点。
>
> ✅ **本目录已落地四篇**：[从可执行文件到第一条指令.md](从可执行文件到第一条指令.md)（语言无关，可执行文件 → 第一条指令）、
> [AOT、JIT与解释执行.md](AOT、JIT与解释执行.md)（三条路线的取舍与实测）、
> [机器码、字节码与opcode.md](机器码、字节码与opcode.md)（三种产物形态的编码与消费者）。另两篇按职责落在语言目录：
> [从源码到main.md](../../01-编程语言/go/运行时/从源码到main.md)（Go 侧构建期编译）、
> [执行链路.md](../../01-编程语言/php/执行链路.md)（PHP 侧每请求编译）。
> 尚未落地的篇目见第二节的缺口登记。

## 一、本目录收什么？与相邻目录的边界在哪？

**本节要点**：判据是「**这条结论是编译/翻译过程本身的原理，还是某语言运行时的行为**」。

| 归本目录 | 不归本目录，归 | 原因 |
|---|---|---|
| 词法 / 语法分析、AST、语义检查 | [01-编程语言/](../../01-编程语言/)（某语言的语法本身） | 一边是"怎么把源文本变成结构"，一边是"这门语言规定写成什么样" |
| 中间表示、优化（内联、逃逸、SSA、循环变换） | [运行时/](../../01-编程语言/go/运行时/)（运行时怎么执行） | 优化发生在编译期，行为体现在运行期 |
| 产物形态：机器码 / 字节码 / opcode 的编码与「谁消费它」 | [计算机组成原理/](../计算机组成原理/)（机器码进 CPU 之后发生什么） | 一边是「字节怎么拼、被谁读」，一边是「读进来之后怎么执行」 |
| 链接与装载：静态 / 动态链接、符号、PIC | [部署/](../../06-工程实践/部署/)（镜像里怎么跑起来） | 机制归本目录，交付归部署 |
| JIT、分层编译、逃逸分析**为什么算编译** | [运行时/](../../01-编程语言/java/运行时/)（JVM 的参数与实测） | 原理在此，参数与实测在语言目录 |
| 垃圾回收算法的理论底座 | [垃圾回收/](../垃圾回收/) | 已自成体系，不搬散（同 [README.md](../算法/README.md) 第二节的口径） |

## 三、这些内容现在在哪？

**本节要点**：先不搬，**建立边界即可**；写新篇时再从这些位置回收共性结论。

- **Go 侧**：编译期行为与运行时结构在 [运行时/](../../01-编程语言/go/运行时/)（GMP 调度、内存分配等），
  `go build` / `go vet` / `gofmt` 的校验口径见 [README.md](../../README.md)。
- **本目录已落地的边界**：[从可执行文件到第一条指令.md](从可执行文件到第一条指令.md) 只负责「可执行文件 → 第一条指令」这一段（ELF、`execve`、装载器、VMA、缺页）。
  `_rt0_amd64` 之后的所有运行时初始化**不在本篇**，见 [程序启动流程.md](../../01-编程语言/go/运行时/程序启动流程.md)。
  判据：出现 `schedinit` / `mallocinit` / `main.main` 这类符号 → 归语言目录；出现 `PT_LOAD` / `AT_BASE` / `VMA` → 归本目录。
- **三条路线怎么分**：[AOT、JIT与解释执行.md](AOT、JIT与解释执行.md) 只做**跨语言的判据与对照**（编译发生在哪一刻、启动与峰值两条曲线、分层编译的 retirement）；
  某一条路线**怎么落地**归语言目录——Go 侧 [从源码到main.md](../../01-编程语言/go/运行时/从源码到main.md)、PHP 侧 [执行链路.md](../../01-编程语言/php/执行链路.md)。
  判据：出现 `go build` 工具调用数、`.a`、`gopclntab` 或 `php-fpm`、`opcache`、`validate_timestamps` 这类键名 → 语言目录；出现「AOT / JIT / 解释执行」三者比较 → 本目录。
- **产物形态怎么分**：[机器码、字节码与opcode.md](机器码、字节码与opcode.md) 只讲**编码格式与消费者**（49 / 23 字节怎么来、`ModRM`/`SIB` 怎么拆、class 版本号为什么是边界）。
  机器码**进去之后 CPU 里发生什么**（五段流水线、IPC、分支预测、写缓冲）归 [计算机组成原理/](../计算机组成原理/)。
  判据：出现 `ModRM` / `class` 版本号 / `opcode` 助记符 → 本目录；出现 `IPC` / `branch-misses` / `µop` / `LOCK` → 计算机组成原理。
- **Java 侧**：字节码、JIT 分层编译与 GC 在 [运行时/](../../01-编程语言/java/运行时/) 与 [垃圾回收/](../垃圾回收/)。
- **算法层**（词法匹配的实现：KMP / BM / AC 自动机）→ [字符串匹配/](../算法/字符串匹配/)。
- **正则与语法**（各语言 `regexp` 的差异，含 RE2 无回溯）→ 语言目录，编译原理侧不重复。

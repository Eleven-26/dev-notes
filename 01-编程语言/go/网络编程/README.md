# Go 网络编程

> 覆盖：**Go 侧从字节到网关的完整链条**——`net` 包的连接抽象、HTTP 的三种视角（手写协议 / `net/http` 服务端 / `net/http` 客户端）、以及网关四件套（总装、路由、反向代理、客户端 IP）。
> 一句话分工：**协议层看 `net` 包，报文层看手写服务端，接口层看 `net/http` 两侧，工程层看网关四篇。**
>
> 不覆盖：**协议本身**（报文格式、握手、拥塞控制）在 [02 / 网络](../../../02-计算机基础/网络/README.md)；**I/O 多路复用**在 [网络IO与netpoll.md](../运行时/网络IO与netpoll.md) 与 [IO多路复用.md](../../../02-计算机基础/操作系统/IO多路复用.md)；**语言无关的并发组织**在 [02 / 并发](../../../02-计算机基础/并发/README.md)。
>
> 当前 **9 篇**，22 张图。素材来自个人学习笔记与项目实测，各篇引语里注明了自己那份素材的出处。

## 一、本目录在 `go/` 里守哪一段？

**本节要点**：判据是**问题落在哪一层**。同一个 HTTP 请求，「报文怎么切」「接口怎么接」「网关怎么转」分别属于不同目录。

| 目录 | 它回答的问题 | 例子 |
|---|---|---|
| [并发编程](../并发编程/README.md) | 多个执行流怎么**分工与交接** | 谁等谁、池开多大、取消了怎么停 |
| [运行时](../运行时/README.md) | 这份代码**跑起来之后**发生什么 | 网络 IO 谁来轮询、内存怎么分、GC 何时停 |
| **本目录** | 字节怎么**收发与解析**、接口怎么**接** | 粘包在哪、超时打断在哪一步、路由谁先匹配 |
| [工程实践](../工程实践/数据访问与连接池.md) | 某个中间件**怎么接进来** | 数据库连接池、Kafka、etcd、日志与错误规范 |
| [可观测性](../可观测性/手写Prometheus导出器.md) | 线上**怎么看见** | 指标导出、链路追踪接入（该册暂无 README） |

⚠️ 三条最容易越界的线：

1. **报文格式本身不在这里**。`HTTP/1.1` 的三种定界、`HTTP/2` 的帧与 HPACK 在 02 层；本目录只讲「Go 怎么用它们、哪里会踩坑」。
2. **`epoll` 与 netpoller 的机制不在这里**。Go 的 netpoller 在 `运行时/网络IO与netpoll.md`，内核侧的 `epoll` 在操作系统目录；本目录只声明「`net.Conn` 背后是它」。
3. **具体中间件的客户端接入不在这里**。gRPC 只留了一篇「不用 `protoc` 怎么写」——那是协议层的 Trick；`grpc-go` 的常规用法在工程实践与 03 层的 gRPC 目录。

## 二、九篇的分工：一 + 三 + 四 + 一

**本节要点**：这不是九个并列话题，是**一条链上的三段加一个旁支**——先有连接（1 篇），再有 HTTP 的三个视角（3 篇），然后是把它们拼起来的网关（4 篇），最后是换协议（1 篇）。

| 组 | 篇目 | 它回答的那个问法 | 核心内容 |
|---|---|---|---|
| **① 连接** | [net包与TCP-UDP编程.md](net包与TCP-UDP编程.md) | **一条 TCP 连接在 Go 里长什么样** | `net` 的三个核心抽象、TCP 最小骨架与客户端超时、粘包拆包怎么真实发生（一次读走 24 字节 / 8 字节缓冲读 38 次才凑齐一帧）、什么时候必须上 `bufio`（裸读 430~~826 ms vs 2.2~~3.6 ms）、deadline 的三种写法、TCP 选项哪些 Go 替你设了、UDP 与 UDS |
| **② 报文层** | [从零实现HTTP服务端.md](从零实现HTTP服务端.md) | **不 import `net/http`，一个 HTTP 服务端要怎么手写** | 从 `net.Listen` 起手的 478 行服务端 + 192 行探针：请求行三段与 token 校验、首部循环的两道闸门、三种定界的判序（`TE` + `CL` 同给必须先拒）、chunked 与 keep-alive 必须排空 body、⭐ 与 `net/http` 的**八项对照**（裸 LF / 20 KB 头 / `TE`+`CL` 三处选了不同的边）与吞吐区间 |
| **② 报文层** | [HTTP服务端与优雅关停.md](HTTP服务端与优雅关停.md) | **`net/http` 的服务端怎么配、怎么停** | `http.Server` 五个超时各自罩哪一段（`WriteTimeout` 到点客户端收到的是 EOF）、`Handler` / `HandlerFunc` / 中间件洋葱、1.22 起的路由增强、⭐ `Shutdown` 的两段式语义、响应侧三件小事 |
| **② 报文层** | [HTTP客户端与连接池.md](HTTP客户端与连接池.md) | **客户端为什么必须复用，池该开多大** | `Client` / `Transport` / `persistConn` 三层分工、一次 `Get()` 的完整链路、⭐ 每请求 new 一个 `Client` 的事故（`dial=200 / fd=1252`）、`Transport` 参数里会咬人的默认值、三个超时分别打断在哪一步、`Response.Body` 两条铁律、会不会替你重试、错误原文对照 |
| **③ 网关** | [从零实现网关.md](从零实现网关.md) | **把前两组拼成一个网关要几步** | 七模块总装（路由 / JWT / 令牌桶 / 熔断 / 负载均衡 / HTTP→gRPC 转码 / 可观测性）、中间件顺序的三条硬约束、逐模块实测 |
| **③ 网关** | [网关路由匹配.md](网关路由匹配.md) | **一条请求该交给哪个上游** | 三种 path 语义与优先级（精确 > 正则 > 最长前缀，与 nginx `location` 同构）、⚠️ 顺序写反会让兜底 `/` 抢走请求、头值匹配的大小写、正则必须预编译 |
| **③ 网关** | [反向代理接入.md](反向代理接入.md) | **`httputil.ReverseProxy` 怎么接** | 单例边界（`Transport` 进程级 / `Proxy` 按上游各一份）、`Director` 里先存 `req.Host` 再改写、XFF 不要手写、`ErrorHandler` 的 502/504/413 映射 |

## 四、读序

**本节要点**：**不要从头读到尾**。先按手上的任务挑一组，缺哪层再补哪层。

1. 要写一个**普通 HTTP 服务**：[HTTP服务端与优雅关停.md](HTTP服务端与优雅关停.md) → 需要调客户端就接 [HTTP客户端与连接池.md](HTTP客户端与连接池.md)。
2. 要写**非 HTTP 的 TCP 服务**：[net包与TCP-UDP编程.md](net包与TCP-UDP编程.md)，重点看第四节（粘包）与第五节（`bufio`）。
3. **想知道标准库替你做了什么**：[从零实现HTTP服务端.md](从零实现HTTP服务端.md) 第七节的八项对照，比读源码快。
4. 要做**网关 / 反向代理**：先 [反向代理接入.md](反向代理接入.md) 与 [网关路由匹配.md](网关路由匹配.md)（两块最容易出事），再 [从零实现网关.md](从零实现网关.md) 看总装，多一层代理就一定要读 [客户端IP接入.md](客户端IP接入.md)。
5. 要**绕开 `protoc`**：[不使用protoc的gRPC.md](不使用protoc的gRPC.md)。

⚠️ 三处强关联，读的时候别当孤立篇：

- **手写服务端 七、⟷ 客户端篇 一、**：`http.ReadRequest` 与 `http.ReadResponse` 共用同一个 `textproto.Reader`（`request.go:1044` / `response.go:155`）——「写服务端解析」与「解上游响应」是同一段代码的两头。
- **服务端篇 2.1 ⟷ 客户端篇 1.1**：`http.Handler` 与 `http.RoundTripper` 是互为反向的两个单方法接口，整个包的可替换面就这两个。
- **服务端篇 2.3 ⟷ 网关四篇**：那五层调用链是 `net/http` 的实现；网关绕开的正是其中第 ② ③ 层（自己读 `net.Conn`、自己解报文），所以网关里的「一次请求」不能按 `net/http` 的超时语义去理解。

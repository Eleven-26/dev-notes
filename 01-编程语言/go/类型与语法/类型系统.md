## 一、命名类型和未命名类型到底差在哪？

**一句话答案**：用 `type` 定义出来的是**命名类型**，直接用类型字面量写出来的是**未命名类型**——只有前者有名字，而"有没有名字"决定了两件事：**能不能被赋值**、**有没有方法**。

### 1.1 两种类型的区别

| | 命名类型 | 未命名类型 |
|---|---|---|
| 怎么写 | `type MyInt int`、`type A []int` | `int`、`[]int`、`map[string]int`、`struct{...}`、`func()`、`chan int`、`*T` |
| 有名字吗 | `reflect.TypeOf(x).Name()` 返回名字 | 返回 `""` |
| 能挂方法吗 | ✅ 可以 | ❌ 不能（`[]int` 没法写方法，得先定义别名类型） |
| 与同底层的类型关系 | **只有自己和自己相同** | 字面量相同就相同 |

⚠️ 反过来说：**你不能给 `[]int` 直接加方法**，必须先 `type Ints []int`——这正是"要不要定义命名类型"最常见的原因。

### 1.2 别名（alias）与定义（definition）不是一回事

Go 1.9 引入了别名：`type MyIntAlias = int` 里的 `=` 让它**和 `int` 是同一个类型**，不是新类型。

```go
type MyInt int        // 定义：新类型，与 int 不同
type MyIntAlias = int // 别名：就是 int，连方法都共享
```

```text
MyInt 的类型名 = MyInt，Kind = int
MyIntAlias 与 int 是同一类型吗？true
MyInt 与 int 是同一类型吗？    false
但可以显式转换：int(MyInt(7)) = 7
```

**易错点**：别名的 `Name()` 返回的是**被别名指向的类型**的名字（`int`），不是 `MyIntAlias`——因为别名没有自己的类型身份。

### 1.3 为什么 `Kind()` 不够用

`Kind()` 返回的是**底层类型的种类**（`int`、`slice`、`struct`…），`Name()` 才是命名类型的名字。判断"是不是同一类型"要用 `reflect.TypeOf(a) == reflect.TypeOf(b)`，**不要用 Kind 比**——`int` 和 `MyInt` 的 Kind 都是 `int`。

## 二、底层类型（underlying type）是"递归找下去"的

**规则**：`type T U` 中，若 `U` 仍是命名类型，就继续往下找，直到遇到**未命名类型**为止——那个就是 `T` 的底层类型。

```go
type A []int // 底层类型 []int
type B A     // 底层类型仍是 []int —— 不是 A！
```

### 2.1 实测：`B` 的底层类型穿透到了 `[]int`

```go
type A []int
type B A

a := A{1, 2, 3}
b := B{4, 5}
fmt.Printf("A：Name=%q Kind=%s 元素=%s → 底层类型 []int\n",
    reflect.TypeOf(a).Name(), reflect.TypeOf(a).Kind(), reflect.TypeOf(a).Elem().Kind())
fmt.Printf("B：Name=%q Kind=%s 元素=%s → 底层类型仍是 []int（递归穿透，不是 A）\n",
    reflect.TypeOf(b).Name(), reflect.TypeOf(b).Kind(), reflect.TypeOf(b).Elem().Kind())
fmt.Printf("两个命名类型能互相转换吗（底层类型相同）？A(B{4,5}) = %v\n", A(b))
fmt.Printf("也都能转成未命名的 []int：[]int(A{1,2,3}) = %v\n", []int(a))
```

```text
A：Name="A" Kind=slice 元素=int → 底层类型 []int
B：Name="B" Kind=slice 元素=int → 底层类型仍是 []int（递归穿透，不是 A）
两个命名类型能互相转换吗（底层类型相同）？A(B{4,5}) = [4 5]
也都能转成未命名的 []int：[]int(A{1,2,3}) = [1 2 3]
```

**为什么这条很重要**：转换规则（第四节）看的就是**底层类型**，不是原类型。`A` 与 `B` 谁也赋不了谁，但因为底层类型都是 `[]int`，互相转换和转 `[]int` 都合法。

## 三、两个类型什么时候算"同一个"？

### 3.1 规则

- **命名类型**：只有它自己与自己相同（`type MyInt int` 与 `int` **不同**）。
- **未命名类型**：**结构完全相同**就相同。对 struct 而言，"结构"包括五项：**字段名、字段类型、字段标签（tag）、字段顺序、字段是否导出**——任一不同就是不同类型。
- 赋值的前提是"类型相同"或"底层类型相同且至少一方是未命名类型"。

### 3.2 实测：只差一个 json 标签，就是两个类型

```go
type U1 = struct {
    Name string `json:"name"`
    Age  int
}
type U2 = struct {
    Name string `json:"nick"`
    Age  int
}

u1 := U1{Name: "tom", Age: 1}
fmt.Printf("U1 的类型名 = %q（匿名 struct 没有名字）\n", reflect.TypeOf(u1).Name())
fmt.Printf("U1 与 U2 是同一类型吗？%v —— 只差一个 json 标签\n",
    reflect.TypeOf(U1{}).String() == reflect.TypeOf(U2{}).String())
fmt.Printf("U1 的标签：reflect 能看到 -> %s\n", reflect.TypeOf(U1{}).Field(0).Tag.Get("json"))
fmt.Printf("U2 的标签：reflect 能看到 -> %s\n", reflect.TypeOf(U2{}).Field(0).Tag.Get("json"))
```

```text
U1 的类型名 = ""（匿名 struct 没有名字）
U1 与 U2 是同一类型吗？false —— 只差一个 json 标签
U1 的标签：reflect 能看到 -> name
U2 的标签：reflect 能看到 -> nick
```

同一次赋值，`go build` 给出的**真实错误**：

```text
fail\unnamed_tag\main.go:11:7: cannot use u2 (variable of type struct{Name string "json:\"nick\""}) as struct{Name string "json:\"name\""} value in assignment
```

编译器把两个标签原样打进了错误信息里——这就是"标签参与类型同一性"最硬的证据。

### 3.3 ⭐ 但**转换**允许忽略标签

赋值不行，**转换却可以**：spec 里转换规则明确写着"忽略 struct tag"。

```go
type X struct{ A string `json:"a"` }
type Y struct{ A string `json:"b"` }

x := X{A: "v"}
fmt.Printf("Y(x) = %+v ← 底层类型「忽略标签」后相同，也允许转换\n", Y(x))
```

```text
Y(x)       = {A:v} ← 底层类型「忽略标签」后相同，也允许转换
```

同一个 `X → Y`，**赋值报错、转换通过**：

```text
fail\tag_assign\main.go:4:34: cannot use x (variable of struct type X) as Y value in variable declaration
```

⚠️ **工程含义**：这是"把内部 DTO 转成对外 VO"时的合法后门——两个 struct 字段一样、只有 json 标签不同，可以直接 `OutVO(inDTO)`，不必手写逐字段赋值。但**别用它掩盖字段含义已经不同的情况**。

## 四、类型转换什么时候合法？

### 4.1 合法条件（记住三条）

1. **底层类型相同**（忽略 struct tag）——任何类型都能互转；
2. **都是未命名的指针类型**，且基类型的底层类型相同（如 `*A` → `*[]int`）；
3. **数值之间互相转换**（`int` ↔ `float64` ↔ `byte`…），**整数 ↔ string**（转的是码点），**string ↔ `[]byte` / `[]rune`**。

### 4.2 ⚠️ 常量转换要求"值必须能被精确表示"

`int(3.99)` 这种写法**编译不过**——常量转换不允许丢精度：

```text
fail\const_convert\main.go:5:10: cannot convert 3.99 (untyped float constant) to type int
```

想截断就得先变成变量：

```go
fv := 3.99 // 必须是变量：常量转换要求「精确可表示」，写 int(3.99) 直接编译不过
fmt.Printf("int(3.99) = %d（截断，不是四舍五入；且常量要能精确表示才允许转换）\n", int(fv))
```

```text
int(3.99)          = 3   （截断，不是四舍五入；且常量要能精确表示才允许转换）
```

### 4.3 ⚠️ `string(65)` 不是 `"65"`

整数转 string 转的是**码点（rune）**：

```go
fmt.Printf("string(rune(65))   = %q  ⚠️ 转的是码点不是数字；写成 string(65) 会被 go vet 拒\n", string(rune(65)))
fmt.Printf("strconv.Itoa(65)   = %q  ← 想要字符串数字得用它\n", strconv.Itoa(65))
fmt.Printf("string([]byte{0xE4,0xB8,0xAD}) = %q\n", string([]byte{0xE4, 0xB8, 0xAD}))
```

```text
string(rune(65))   = "A"  ⚠️ 转的是码点不是数字；写成 string(65) 会被 go vet 拒
strconv.Itoa(65)   = "65"  ← 想要字符串数字得用它
string([]byte{0xE4,0xB8,0xAD}) = "中"
```

而 `string(65)` 这种**没有显式写出 rune 的写法会被 `go vet` 直接拦下**：

```text
vetwarn\stringint.go:7:14: conversion from untyped int to string yields a string of one rune, not a string of digits
```

### 4.4 `string` ↔ `[]byte` / `[]rune` 转换一定发生拷贝

```text
[]byte("abc") 后改 bs[0] -> "Abc"（string 是只读的，转换产生了副本）
再把 bs[0] 改成 'Z'，已生成的 s 还是 "Abc"（又一次拷贝）
两者共享底层数组吗？false（各占一块内存，转换即拷贝）
```

⭐ **性能相关的结论**：**转换即分配**。这就是 `fmt.Sprintf("%s", s)` 在某些热路径上为什么不如 `io.WriteString(w, s)`——前者要转 `[]byte`。想看零拷贝的写法见 [零拷贝.md](../运行时/零拷贝.md)。

### 4.5 不能转的情况（真实编译错误）

| 写法 | 编译器怎么说 |
|---|---|
| `int("65")` | `cannot convert "65" (untyped string constant) to type int` —— 字符串转数字是**解析**，得用 `strconv.Atoi` |
| `[]int([]MyInt{1,2,3})` | `cannot convert a (variable of type []MyInt) to type []int` —— **元素类型不同的切片不能整体转换**，只能 for 循环逐个转 |

## 五、方法集：值接收者和指针接收者到底影响了什么？⭐

**这是第 3 章最值钱的一节**——「为什么这个方法要用指针接收者」这类问题，答案全在方法集规则里。

### 5.1 规则（spec 原文口径）

| 类型 | 方法集 |
|---|---|
| `T` | **只含**值接收者方法 `func (T) M()` |
| `*T` | 值接收者方法 **+** 指针接收者方法 `func (*T) M()` |

**为什么这么规定**：指针接收者方法可能要修改 `T`，而接口里存的 `T` 是**不可寻址的副本**——编译器不允许你在一份临时副本上调一个"会改自己"的方法。

### 5.2 实测：把方法集"数"出来

```go
type Counter struct{ n int }

func (c Counter) Get() int       { return c.n }  // 值接收者
func (c *Counter) Inc()          { c.n++ }       // 指针接收者
func (c Counter) String() string { return fmt.Sprint(c.n) }

c, pc := Counter{n: 1}, &Counter{n: 1}
fmt.Printf("Counter（值）   的方法集大小 = %d\n", reflect.TypeOf(c).NumMethod())
fmt.Printf("*Counter（指针）的方法集大小 = %d\n", reflect.TypeOf(pc).NumMethod())
```

```text
Counter（值）   的方法集大小 = 2
*Counter（指针）的方法集大小 = 3
值满足 Getter：true；指针满足 Incr：true
```

用自查工具看得更清楚（工具代码见本篇「使用」段）：

```text
main.Counter  值方法集 2：[Get String]
*main.Counter 指针方法集 3：[Get Inc String]
main.Counter 满足 main.Getter：值=true 指针=true
main.Counter 满足 main.Incr：值=false 指针=true
main.Counter 满足 main.Stringer：值=true 指针=true
```

### 5.3 编译错误证据：值类型满足不了"指针接收者接口"

```text
fail\methodset_value\main.go:11:15: cannot use Counter{} (value of struct type Counter) as Incr value in variable declaration: Counter does not implement Incr (method Inc has pointer receiver)
```

Go 的错误信息直接告诉你**差哪个方法、为什么差**（`method Inc has pointer receiver`）——这句话值得背下来，排错时一眼定位。

### 5.4 那到底该用值接收者还是指针接收者？

| 判据 | 选值接收者 | 选指针接收者 |
|---|---|---|
| 要不要改接收者自身 | 不改 | **要改**（计数器、缓存、`sync.Mutex`） |
| 方法集要覆盖到"值" | **要**（`T` 和 `*T` 都能调） | 无所谓 |
| 结构体大小 | 小（几个字，如 `time.Time`） | 大（拷贝成本高） |
| 一致性 | —— | ⭐ **只要有一个方法用了指针接收者，其余方法都该用指针**（否则方法集割裂，很难解释） |

⚠️ 反过来最常踩的坑：**结构体里嵌 `sync.Mutex` 并用值接收者**——`Lock` 是指针接收者，嵌进去后只有 `*Outer` 满足 `sync.Locker`；更严重的是**整体复制这个结构体 = 复制了锁**，`go vet` 会报 `copylocks`。

## 六、方法值和方法表达式有什么区别？

| 写法 | 名字 | 绑定接收者吗 | 类型 |
|---|---|---|---|
| `f := x.M` | **方法值** | ✅ 绑定，且**取出的那一刻接收者已经求值** | `func(...)` |
| `g := T.M` | **方法表达式** | ❌ 不绑定，接收者变成第一个参数 | `func(T, ...)` |
| `h := (*T).M` | 同上（指针版） | ❌ 不绑定 | `func(*T, ...)` |

### 6.1 实测：方法值"复制"了接收者

```go
d := Counter{n: 10}
val := d.Get // 方法值：立刻求值并「复制」接收者
d.n = 99     // 改原对象
fmt.Printf("d.n 改成 99 后，d.Get() = %d，而早先取出的 val() = %d\n", d.Get(), val())

expr := Counter.Get // 方法表达式：没绑定接收者，调用时第一个参数当接收者
fmt.Printf("Counter.Get(d) = %d（表达式调用要自己传接收者）\n", expr(d))

incExpr := (*Counter).Inc
incExpr(&d)
fmt.Printf("(*Counter).Inc(&d) 之后 d.n = %d（指针接收者的表达式调用能改到原对象）\n", d.n)
```

```text
d.n 改成 99 后，d.Get() = 99，而早先取出的 val() = 10
Counter.Get(d) = 99（表达式调用要自己传接收者）
(*Counter).Inc(&d) 之后 d.n = 100（指针接收者的表达式调用能改到原对象）
通过指针取方法值 pc.Get() = 1
```

**结论**：`val` 拿到的是 `d` 在 `n=10` 时的快照——方法值的**接收者已经绑定并复制**，之后改 `d` 不影响 `val`。

### 6.2 什么时候用哪个

- **方法值**：需要"延迟调用但已确定对象"——`http.HandlerFunc(srv.ServeHTTP)`、`time.AfterFunc(d, obj.Clean)`、注册回调；
- **方法表达式**：需要一个"把接收者当参数传"的函数——泛型工具、`sort.Slice` 里的比较、把方法当"无状态函数"传进管道。

## 七、组合与方法集：嵌入值还是嵌入指针？

Go 用**组合（embedding**）代替继承，但嵌入的东西是值还是指针，会**改变外层类型的方法集**。

### 7.1 规则

| 外层 S 嵌入 | `S` 的方法集 | `*S` 的方法集 |
|---|---|---|
| `T`（值） | 只有 `T` 的方法（**不含** `*T` 的） | `T` + `*T` 的方法 |
| `*T`（指针） | `T` + `*T` 的方法 | `T` + `*T` 的方法 |

一句话记：**嵌入指针，两种方法集一样大；嵌入值，值的方法集缺一块**。

### 7.2 实测

```go
type Inner struct{ v int }

func (Inner) V()  {} // 值接收者
func (*Inner) P() {} // 指针接收者

type OuterValue struct{ Inner }    // 嵌入值
type OuterPointer struct{ *Inner } // 嵌入指针

ov, op := OuterValue{Inner{1}}, OuterPointer{&Inner{2}}
ovp, opp := &ov, &op
fmt.Printf("OuterValue （嵌入 Inner  值）：值 %d / 指针 %d\n",
    reflect.TypeOf(ov).NumMethod(), reflect.TypeOf(ovp).NumMethod())
fmt.Printf("OuterPointer（嵌入 *Inner 指针）：值 %d / 指针 %d\n",
    reflect.TypeOf(op).NumMethod(), reflect.TypeOf(opp).NumMethod())
```

```text
OuterValue （嵌入 Inner  值）：值 1 / 指针 2
OuterPointer（嵌入 *Inner 指针）：值 2 / 指针 2
→ 嵌入值：指针接收者的方法只进 *S 的方法集；嵌入指针：两者都能拿到
```

对应的编译错误：

```text
fail\embed_methodset\main.go:13:12: cannot use OuterValue{} (value of struct type OuterValue) as P value in variable declaration: OuterValue does not implement P (method P has pointer receiver)
```

⚠️ **工程含义**：想让外层类型的**值**就能满足接口（例如要把它塞进 `map[string]SomeIface` 直接存值），嵌入的东西要么全用值接收者，要么嵌**指针**。`sync.Mutex` 这类必须指针接收者的组件，嵌入时应写成 `struct{ *sync.Mutex }` 或干脆用命名字段。

## 八、函数类型也是一种类型

```go
type Fn func(int) string
```

- 它是**命名类型**，可以挂方法（`func (f Fn) String() string`），所以能当"可调用的对象"用；
- 零值是 `nil`；
- ⚠️ **只能和 `nil` 比较**，两个函数值之间不能比较：

```text
fail\func_compare\main.go:9:6: invalid operation: f == g (func can only be compared to nil)
```

实测：

```text
函数类型零值与 nil 比较：f == nil -> true
赋值后 f == nil -> false，调用 f(7) = "7"
Fn 的类型名 = "Fn"，Kind = func
底层类型（reflect 侧看不到，用转换验证）：string(Fn(intToStr)(7)) = "7"
```

**标准库里的经典手法**：`http.HandlerFunc` 就是一个函数类型，靠给它挂一个 `ServeHTTP` 方法，把"函数"变成"满足 `http.Handler` 接口的对象"：

```go
type HandlerFunc func(ResponseWriter, *Request)

func (f HandlerFunc) ServeHTTP(w ResponseWriter, r *Request) { f(w, r) }
```

## 九、Go 1.18 之后到底加了什么？怎么判断"这个特性我能不能用"？⭐

**本节要点**：这一节专门补旧书（Go 1.11 前后）没有的内容，**每条都标引入版本**；更关键的是给出一条判据——**版本门槛不用装多个 Go，改 `go.mod` 的语言版本就能实测出来**。

### 9.1 判据：看 `go.mod` 的 `go` 行，不是看 `go version`

Go 1.21 起工具链会按 `go.mod` 里的 `go` 行设置 `-lang`，**超出该语言版本的语法直接编译失败**。
下面每一条读数都出自同一条工具链（容器 `golang:1.26-alpine`，`go version go1.26.8 linux/amd64`；宿主机 1.26.5 行为一致），只改 `go.mod` 那一行：

```text
module lv

go 1.17        # 改这里：1.17 / 1.18 / 1.20 / 1.21 / 1.22 / 1.23
```

⚠️ 这条判据有**一个例外**：个别特性（`range over int`）的门槛只设在 `go/types` 里，编译器放行、`go vet` 才拦 —— 见 9.4。

### 9.2 泛型与 `any`（1.18+）

`go 1.17` 下写一个再普通不过的泛型函数，编译器一次给三行：

```text
./main.go:5:12: type parameter requires go1.18 or later (-lang was set to go1.17; check go.mod)
./main.go:5:14: predeclared any requires go1.18 or later (-lang was set to go1.17; check go.mod)
./main.go:13:27: implicit function instantiation requires go1.18 or later (-lang was set to go1.17; check go.mod)
```

改成 `go 1.18` 后同一份代码直接跑通（实测输出 `9`，即取切片 `[]int{9, 8}` 的首元素）：

```go
func first[T any](s []T) T {
	var z T
	if len(s) == 0 {
		return z
	}
	return s[0]
}
```

- `any` **不是新类型**，它是 `interface{}` 的**别名**（对照第一节 `type A = int` 那条规则）：`var a any = 1; var e interface{} = a; var back any = e` 一路赋值不用任何转换，实测输出 `any/interface{} 互通: 1 1 1`；
- ⚠️ 泛型的**约束本身也是接口类型**，所以第五节、第七节关于方法集与接口满足性的规则对类型参数照样成立；`comparable` 只是预定义约束里唯一带特殊待遇的那个（可比较类型集合见第二节）。

### 9.3 `min` / `max` / `clear`（1.21+）

这三个是**内建函数**（不是新标准库函数），`go 1.20` 下的真实报错：

```text
./main.go:7:14: built-in min requires go1.21 or later (-lang was set to go1.20; check go.mod)
./main.go:7:25: built-in max requires go1.21 or later (-lang was set to go1.20; check go.mod)
./main.go:8:2: clear requires go1.21 or later (-lang was set to go1.20; check go.mod)
```

`go 1.21` 下实测输出：

```text
3 7
[0 0 0]
```

- `min`/`max` 作用在**有序类型**上（整数、浮点、字符串，见第二节的"可比较"口径），实测 `min(3,7)= 3`、`max(3,7)= 7`、`min(2.5,1.5)= 1.5`、`max("a","b")= b`；
- ⚠️ 命名类型只要**底层类型有序**就能用，且**结果类型保持不变**：实测 `min(MyInt(3), MyInt(7)) = 3`，而 `var mi MyInt = MyInt(min(3, 7))` 的 `%T` 读数是 `main.MyInt`（不是 `int`）；
- `clear` 对 map 是"清空但仍非 nil"（实测 `clear(m) len= 0 nil? false`），对 slice 是"全部置零值、**长度不变**"（`[1 2 3]` → `[0 0 0]`）。这两个语义正好对应第一节"零值"那套规则。

### 9.4 `for` 循环变量：1.22 起每轮一个**新变量**

同一份代码、同一工具链，只切 `go.mod`：

```go
fs := []func() int{}
for i := 0; i < 3; i++ {
	fs = append(fs, func() int { return i })
}
fmt.Println(fs[0](), fs[1](), fs[2]())
```

```text
# go.mod: go 1.21  -> 3 3 3
# go.mod: go 1.22  -> 0 1 2
```

- 1.22 **之前**：`i` 是**同一个变量**被反复改，闭包共享它，所以全是最后一轮的 `3` —— 经典坑，当年要靠循环体首写 `i := i` 造副本；
- 1.22 **之后**：每轮**新建一个变量**，副本语义自动成立，`i := i` 变成噪音；
- ⚠️ **这是行为变更而不是新增语法**：靠"循环结束后读循环变量拿到末值"的旧代码会静默改变结果；`go` 行留在 1.21 及以下可整体退回旧语义，这也是 9.1 那条判据最有用的地方。

同一节里还有一个**版本门控的例外**值得记住：`for i := range 5`（**range 一个整数**）属于 **1.22+**，但门槛只设在类型检查器里，**不在编译器里**。同一份代码（`for i := range 5` 累加）在 `go.mod: go 1.21` 下两条命令的实测读数：

```text
# go run main.go  -> range over int sum = 10        （照常跑，不报错）
# go vet  ./...   -> vet: ./main.go:7:17: cannot range over 5 (untyped int constant): requires go1.22 or later
```

把 `go` 行改成 `1.22`，两条都过（`go run` 仍是 `range over int sum = 10`，`go vet` 无输出）。

- 结论：**别只试 `go build` / `go run` 就断定"这特性旧版本也能用"**——`range over func`（1.23+）编译器会拦，`range over int`（1.22+）只有 `go vet`、gopls 这类走 `go/types` 的工具会拦；**判版本要用 `go vet` 复验一遍**。

### 9.5 `range` 可以遍历函数（1.23+，`range over func`）

`go 1.22` 下遍历一个返回 `iter.Seq` 的函数会被拒：

```text
./main.go:20:17: cannot range over nums(3) (value of func type iter.Seq[int]): requires go1.23 or later (-lang was set to go1.22; check go.mod)
```

`go 1.23` 起实测通过：

```go
func countdown(n int) iter.Seq[int] {
	return func(yield func(int) bool) {
		for i := n; i > 0; i-- {
			if !yield(i) {
				return
			}
		}
	}
}

for v := range countdown(4) { /* 4 3 2 1 */ }
for i := range 5           { /* 0..4，累加实测 = 10；这条是 1.22+，见 9.4 */ }
```

- 与第八节的关系：**函数类型第一次有了语言级的遍历语法**。`iter.Seq[V]` 的定义就是 `func(yield func(V) bool)` 的命名类型，`yield` 返回 `false` 表示"消费方要提前退出"（`break` / `return` 都会走到这条路径）；
- ⚠️ 迭代函数里的 `yield` 返回后**不要再假设状态没变**——消费方可以在两次 `yield` 之间做任何事，这是它和"回调"最容易写错的地方。

## 使用：写一个"方法集 + 接口满足性"自查工具

类型系统这一章的知识，落到日常就两个问题：**"这个方法该用值还是指针接收者"** 和 **"为什么这个类型赋不进那个接口"**。下面这个工具直接打印答案，可以直接放进项目 `internal/` 里用。

```go
package main

import (
	"fmt"
	"reflect"
	"strings"
)

type Getter interface{ Get() int }
type Incr interface{ Inc() }
type Stringer interface{ String() string }

type Counter struct{ n int }

func (c Counter) Get() int       { return c.n }
func (c Counter) String() string { return fmt.Sprint(c.n) }
func (c *Counter) Inc()          { c.n++ }

// ShowMethodSet 打印 T 与 *T 的方法集
func ShowMethodSet(v any) {
	t := reflect.TypeOf(v)
	pt := reflect.PtrTo(t)
	fmt.Printf("%s  值方法集 %d：%s\n", t, t.NumMethod(), names(t))
	fmt.Printf("%s 指针方法集 %d：%s\n", pt, pt.NumMethod(), names(pt))
}

func names(t reflect.Type) string {
	var b []string
	for i := 0; i < t.NumMethod(); i++ {
		b = append(b, t.Method(i).Name)
	}
	return "[" + strings.Join(b, " ") + "]"
}

// Implements 判断某个类型（值 / 指针）能否满足接口
// 用法：Implements[Counter]((*Getter)(nil))
func Implements[T any](iface any) {
	t := reflect.TypeOf((*T)(nil)).Elem()
	it := reflect.TypeOf(iface).Elem()
	fmt.Printf("%s 满足 %s：值=%v 指针=%v\n", t, it,
		t.Implements(it), reflect.PtrTo(t).Implements(it))
}

func main() {
	ShowMethodSet(Counter{})
	Implements[Counter]((*Getter)(nil))
	Implements[Counter]((*Incr)(nil))
	Implements[Counter]((*Stringer)(nil))
}
```

```text
main.Counter  值方法集 2：[Get String]
*main.Counter 指针方法集 3：[Get Inc String]
main.Counter 满足 main.Getter：值=true 指针=true
main.Counter 满足 main.Incr：值=false 指针=true
main.Counter 满足 main.Stringer：值=true 指针=true
```

**怎么用它排查问题**：

1. 遇到 `X does not implement Y (method Z has pointer receiver)` → 跑一遍 `ShowMethodSet`，看 `Z` 是不是只在指针方法集里，把赋值改成 `&x`；
2. 设计新类型前先跑一遍 `Implements[T]`（把目标接口的零值指针传进去），确认"值能不能满足"符合预期——**如果需要值也能满足，就别用指针接收者**；
3. 嵌入组合的类型（第七节）同样跑一遍，看方法集是被"砍掉"了还是翻倍了。

## 延伸追问

- **`type A int` 和 `type A = int` 有什么区别？** → 前者是**新类型**（与 `int` 不同类型，可以挂自己的方法）；后者是**别名**，与 `int` 完全同一个类型，共享方法集。
- **什么是"底层类型"？`type B A` 的底层类型是 `A` 吗？** → 不是，是**递归穿透**到非命名类型为止，所以 `type B A`（`type A []int`）的底层类型仍是 `[]int`。
- **两个 struct 字段完全一样，能互相赋值吗？** → 要看是否**同名类型**与**标签**：命名类型之间不能直接赋值；未命名 struct 之间若标签不同也不是同一类型（实测编译错误里标签会被打出来）。但**转换**允许忽略标签。
- **为什么 `string(65)` 得到 `"A"`？** → 整数转 string 转的是**码点（rune）**；要十进制字符串用 `strconv.Itoa`。写 `string(65)` 会被 `go vet` 的 `stringintconv` 拦下。
- **值接收者和指针接收者怎么选？** → 要改自身 / 结构体大 / 一致性 → 指针；要"值也能满足接口" / 本身很小且不可变 → 值。⚠️ 同一类型的接收者风格要统一。
- **`T` 和 `*T` 的方法集差在哪？为什么这么设计？** → `*T` 多出所有指针接收者方法；因为接口里存的 `T` 是不可寻址副本，不允许在上面调"会修改自身"的方法。
- **方法值 `x.M` 和方法表达式 `T.M` 的区别？** → 方法值**绑定并复制**接收者（之后改原对象不影响已取出的函数值）；方法表达式不绑定，接收者成为第一个参数。
- **嵌入值和嵌入指针，外层方法集有什么差别？** → 嵌 `T`：`S` 只有 `T` 的方法，`*S` 才多出 `*T` 的；嵌 `*T`：`S` 与 `*S` 都拿到全部。
- **两个函数值能比较吗？** → 不能，只能与 `nil` 比较（`invalid operation: f == g`）。
- **怎么确认一个新语法要哪个 Go 版本？** → 不用装多个工具链：`go.mod` 的 `go` 行会设 `-lang`，把版本往下改，编译器直接报 `requires goNN.NN or later (-lang was set to ...; check go.mod)`（第九节三条报错都这么来的）。
- **改低 `go` 行没报错，就能确定这特性旧版本能用？** → 不能。`range over int`（1.22+）在 `go 1.21` 下 `go run` 照样输出 `10`，只有 `go vet` 报 `cannot range over 5 (untyped int constant): requires go1.22 or later` —— 门槛设在 `go/types` 而不是编译器（9.4 有实测对比）。
- **`any` 是新的类型吗？和 `interface{}` 有区别吗？** → 没有，它是 `interface{}` 的**别名**（`type A = int` 那种别名），方法集、断言语义完全一致；泛型约束里写 `any` 就是"任意类型"。
- **为什么 `int(3.99)` 编译不过？** → 常量转换不允许丢精度，必须先赋给变量再转。

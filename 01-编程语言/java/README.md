# Java 本目录导读

> 本目录收 **Java 语言的机制与实现**：运行时（JVM 怎么跑类与内存）、并发（锁与内存模型）、
> 基础容器、框架（Spring Boot）以及接入类手册。
>
> ⚠️ **这里不重复 [目录.md](../../目录.md) 的知识点描述** —— 那篇按技术栈列「有什么」，
> 本篇只回答「**从哪读、按什么顺序、谁是谁的前置**」。按「Java 这条线」系统过一遍时从这里进。

## 一、先读哪两篇

| 先读 | 为什么是它 |
|---|---|
| [运行时/JVM与垃圾回收.md](运行时/JVM与垃圾回收.md) | Java 的运行时长什么样全在这一篇：堆怎么分代、对象什么时候进老年代、收集器怎么演进、GC 日志怎么读。**不读它，后面所有「为什么会有这个问题」都缺一个解释框架** |
| [并发/锁与AQS.md](并发/锁与AQS.md) | Java 并发的地基。`synchronized` 的对象头、`ReentrantLock` 的取舍、AQS「一个 `state` 四种语义」—— 后面线程池与并发容器全部建立在这套机制上 |

⭐ 这两篇也是**与 Go 对照反差最大**的两篇：Go 用 goroutine + channel（CSP），Java 用线程 + 锁（共享内存）。
如果你是从 Go 过来看 Java，这两篇的「读它理由」最足。

## 二、两条主线（各按依赖顺序读）

### 主线 A：运行时（自下而上）

```text
类加载机制.md          ① 类怎么被找到、验证、准备、解析、初始化
      ↓                （这篇讲「装上」）
运行时数据区与栈帧.md   ② 装上之后，内存怎么分、栈帧长什么样
      ↓                （这篇讲「住在哪」）
JVM与垃圾回收.md        ③ 这些内存怎么回收、怎么调优
                       （这篇讲「怎么清」）
```

⭐ **顺序不能倒**：GC 要回收的是「运行时数据区」里的东西（局部变量表是 GC Roots 的第一类）；
而运行时数据区的前提是「类已经被加载」。

### 主线 B：并发（自原理到工具）

```text
JMM与内存屏障.md        ① 内存模型与可见性 —— 并发问题的「物理层」
      ↓                 （happens-before 是后面所有结论的判据）
锁与AQS.md              ② 怎么解决它：锁、CAS、AQS 同步器
      ↓
线程池.md               ③ 线程怎么管、任务怎么排队与拒绝
并发容器.md             ④ 共享数据怎么装（ChM / COW / BlockingQueue）
```

⭐ `JMM` 与 `锁与AQS` 是**互相印证的一对**：前者讲「为什么 `volatile` 保不住原子性」，
后者给出「`volatile++` 实测丢 2/3 更新」的直接证据。建议连着读。

## 六、三条反直觉提醒（读完容易忘的）

| 提醒 | 依据 |
|---|---|
| **`volatile` 不保证原子性** | `volatile int i; i++` 是「读-改-写」三步，4 线程各加 50 万次实测**丢约 2/3**（[并发/锁与AQS.md](并发/锁与AQS.md) 第二节） |
| **公平锁的代价约 300 倍** | 非公平 23.9~24.3 ms vs 公平 7369~8926 ms。**默认用非公平**，`synchronized` 本身就是非公平（[并发/锁与AQS.md](并发/锁与AQS.md) 2.3） |
| **`submit` 会静默吞掉异常** | `execute` 的异常打到 stderr 且线程死亡；`submit` 的异常被 `FutureTask` 收走，**只有 `get()` 才抛**（[并发/线程池.md](并发/线程池.md) 第五节） |

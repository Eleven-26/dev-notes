## 目录与命名约定

- 一级目录固定为 `01-` 至 `07-`，用于稳定排序：语言 → 基础 → 数据与中间件 → 架构 → 模式 → 工程 → 面试。
- 分类概念用中文；语言、技术及组件目录用英文小写，如 `go/`、`java/`、`mysql/`、`redis/`、`docker/`、`k8s/`、`tcp/`。
- 同一主题有多篇内容时才建子目录；`07-面试/` 不再细分目录。
- 文件名可保留技术专名的原有大小写。大小写敏感的 Git 路径改名须用 `git mv` 两步操作，避免被 Windows/macOS 静默忽略。
- 每个文件聚焦一个知识点；同一知识点只在一处讲透，其余位置通过链接引用。

## 文档内容约定

篇首引语用于声明内容归属：

1. **面试真题**：注明整理自大厂面试真题，一篇一道题或一组强关联问题。
2. **个人学习笔记**：以知识体系为主，侧重原理、对比、选型和实测。
3. **书籍/博客素材**：注明作者、原文/书名、章节或日期及链接；单节补充来源时在该节单独标明。
4. **组件与中间件手册**：采用“介绍 + 使用方法”结构，Go 与 Java 示例都应提供（适用时）。

统一规则：
- 正文按「一、二、三……」组织；各节用 `**本节要点**` 概括，保留 `## 延伸追问`。
- 学习笔记避免面试答题口吻；“面试真题”类不受此限制。归属看篇首引语，不看文件名。
- 正文末尾添加「关联」小节；目录、素材清单、说明和协作约定等索引类文件除外。可在关联末尾用一行汇总反向引用。
- 有 API 或操作步骤的工具、组件文档应提供 `## 使用：具体主题`；机制/算法类可用正文代码示例替代。
- 中间件实例保持单例，不在请求路径中重复创建连接池。

## 配图、代码与验证

- 配图数量按内容需要决定；涉及**数据结构形态、操作流程、数据流转、调用时序、状态机**时必须配图，存放在对应目录的 `images/` 下。图片允许暂不被正文引用。
- 图片格式统一为.svg格式。
- 图片引用使用相对路径，alt 写中文说明；图片前后留空行。新图片采用可读主题名。
- 代码围栏的语言标记后直接写代码，围栏内部不要多余空行。
- Go 示例按适用情况运行 `go build`、`go vet`、`gofmt`，并标明版本与验证口径；Java 或其他内容若未运行/编译，必须明确说明，不得编造 API 或输出。
- 实测环境、依赖版本、数据集和结果要可追溯；书籍旧版本与当前版本不一致时，明确区分来源口径与实测口径。

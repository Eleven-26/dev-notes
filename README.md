# dev-notes

开发知识笔记。**中文一级目录 + 二级知识点目录，每个文件聚焦一个知识点。**

> 知识点索引 **[目录.md](目录.md)**；全仓素材来源（书籍 / 自有博客）见 [素材清单.md](素材清单.md)。

---

## 说明

- **目录约定**：一级目录分两类——**分类性质用中文**（`数据存储`、`中间件`、`网络`、`容器`、`分布式`、`安全`、`版本控制`、`垃圾回收`、`面试`、`算法`、`可观测性`）；
  涉及语言与技术的**用英文，且目录名一律小写**（`go`、`java`、`php`、`linux`；二级目录 `mysql`、`redis`、`docker`、`k8s`、`tcp`）。
  一级目录下**同一知识点有多个文件时建二级目录收纳**（如 `数据存储/mysql/`、`go/并发/`、`容器/docker/`）。
  文件名保持原有大小写（专名如 `Docker网络与镜像源.md`、`K8s部署与生命周期.md`、`TCP滑动窗口.md`）。

  > ⚠️ **目录名必须全小写**：在 Windows / macOS 这类大小写不敏感的文件系统上，`core.ignorecase=true`
  > 会让 git **静默忽略**大小写改名——工作区是 `Go/`，git 里仍是 `go/`，`git status` 干净无任何提示，
  > 提交后 GitHub 上是小写，而链接写 `Go/…` 就会 404（本项目 2026-09-25 实际踩过）。
  > **修改已提交路径的大小写必须走 `git mv` 两跳**（`git add` 对纯大小写改动同样无效），否则索引里的拼写不会变。

- **每个文件聚焦一个知识点**；根目录只保留 [目录.md](目录.md)（知识点索引）、[素材清单.md](素材清单.md)（素材出处）与本说明。
- 内容来源分三类，**编号体系统一为 `一、二、三、…` + 疑问句式标题**（2026-09-25 统一），三者的区别在"**篇首引语声明的是哪一类**"与组织方式：
  1. **面试真题整理**（Go / 数据库 / 网络 / 系统 / 分布式方向）：**一个文件一道题**（或一组强关联的题），引语写「内容整理自大厂 Go 后端面试真题」，**每题都带 `**考察意图**`** 与面试官追问方向；素材来源见 [素材清单.md](素材清单.md)。
  2. **个人学习笔记**（算法 / Java / GC / 安全 / Git / PHP / Linux 等，以及 2026-09-28 按此口径改写的一批 Go / 分布式 / MySQL / Redis 篇目）：引语写「内容整理自个人学习笔记」，以知识体系为主线组织，同为 `一、二、三` 编号 + 疑问句式标题，**用 `**本节要点**`**（而不是考察意图）点出"这一节要看什么"，侧重对比表、选型结论与实测。
  3. **中间件与组件手册**（数据存储 / 中间件 / 可观测性）：采用「介绍 + 使用方法」结构，同为 `一、二、三` 体系，**使用示例同时给出 Go 与 Java 两个版本**。

  > ⚠️ **`**考察意图**` 与 `**本节要点**` 不要混用**：前者是真题类专用（`audit_full.py` 用它做"每题都带标注"的配对校验），
  > 后者是笔记类专用。改写归属时**引语与标注必须一起改**，否则体检脚本会报不匹配。

- **每个文件结尾都有「关联」小节**（索引 / 清单 / 说明类文件除外：`目录.md`、`素材清单.md`、本说明），用于保持知识点之间的双向可达；相同考点只在一处讲透（单一来源），其余位置改为交叉引用。
- **`## 使用` 实操段**：讲「有对外 API / 可操作步骤」的文档（组件、中间件、工具、命令手册）在正文之后给一段 `## 使用：<具体主题>`
  —— 它是**上手路径**，与「实测输出」（校验证据）**不能互相替代**；示例里的类名 / 方法名 / 参数必须来自本篇正文，**不臆造 API、不伪造输出**。
  机制与算法类文档（`go/运行时/` 的底层结构、`垃圾回收/`、`算法/` 等）以正文代码块演示代替，不强制加该节。
- **「关联」小节末尾可有一行反向引用汇总**（`> 反向引用（本篇被下列文档引到）：…`）—— 补上「谁引到了我」，
  与正向条目「我为什么推荐它」互补；只加一行，避免关联节膨胀成链接清单。
- 中间件实例一律**单例**（Go 用 `sync.OnceValue`，Java 用 Spring 单例 Bean），不在请求路径里新建连接池。
- 文中配图已**全部本地化**到各自目录的 `images/` 下（用相对路径引用，不依赖外部图床）。
- 代码块格式约定：**开栏围栏（```bash / ```go 等）后不再空一行**，语言标记行的下一行直接就是代码；
  围栏内侧（开栏后、闭栏前）不留多余空行。
- Go 示例均经 `go build` / `go vet` / `gofmt` 校验并在文中标注依赖版本；Java 示例的校验口径见 [数据存储/mysql/索引与优化.md](数据存储/mysql/索引与优化.md)「使用二」；无对应运行环境时会显式标注「未做运行时验证」或「未编译校验」。

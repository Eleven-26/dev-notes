# 设计模式笔记索引

> 本目录整理自个人博客「PHP 设计模式」系列 15 篇（2019-10 ~ 2019-11），
> 内容出自《深入PHP：面向对象、模式与实践（第三版）》的学习笔记。
>
> **每篇以博客原文为骨架**——保留原文的章节结构、讲解文字与代码示例；在此之上加三件事：
> 1. **实测纠错**：原文代码在本机 PHP 8.0.2 下跑一遍，把告警、致命错误、语义陷阱单独成节；
> 2. **补 Java / Go 实现**：每个模式都给出三语言可编译可跑的示例 + 差异对照表；
> 3. **补「面试官会追问什么」**：模式之间的边界、什么时候不该用。
>
> 文中所有 `text` 块都是原始 stdout，代码在本机 PHP 8.0.2 / go1.26.5 / jdk1.8 上真跑过（见第五节校验口径）。

## 三、建议阅读顺序

1. 先读 [六大原则.md](原则/六大原则.md)——它给了所有模式的"为什么"，也给了"什么时候不该用"的判据。
2. 再按分类读模式。每篇结构一致：**原文讲解（博客骨架）→ PHP 实现 → 原文写法的实测纠错 → 优化写法 → Java → Go → 三语言对照 → 面试官会追问什么 → 关联**。
3. 想快速建立"PHP 特殊性"这张图，按顺序读这四节就够：
   [单例模式.md 第四节](创建型/单例模式.md) → [注册模式.md 第四节](创建型/注册模式.md) → [观察者模式.md 第三节](行为型/观察者模式.md) → [代理模式.md 的缓存代理小节](结构型/代理模式.md)。

**PHP 特殊性的一条主线**：php-fpm 每个请求结束就回收用户态内存，这一条同时决定了单例、注册表、观察者表、缓存代理"能不能跨请求"，
也是 PHP 与 Java/Go 在同一模式下写法差异的根因。各篇相关小节都回链到这条主线。

## 四、模式之间的边界

面试最爱问"这几个不都是包一层/都是 new 对象吗"，答法按**它回答的问题**区分，而不是按类图：

| 问题 | 归属 |
| --- | --- |
| 该 new 哪个类？ | 工厂 / 抽象工厂 |
| 怎么在不改老类的前提下加行为？ | 装饰器（接口不变）/ 策略（换算法） |
| 谁控制这次访问（延迟、缓存、权限、远程）？ | 代理 |
| 调用方要的接口形状不对，谁来翻译？ | 适配器 |
| 一串子系统调用能不能收敛成一个入口？ | 外观 |
| 一对多通知，谁要被告知？ | 观察者 |
| 这一步用哪种算法，能不能替换？ | 策略 |
| 怎么遍历一个聚合而不暴露内部结构？ | 迭代器 |
| 整体-部分要不要统一对待？ | 组合 |
| 集合按条件筛选，条件能不能组合？ | 过滤器 |
| 全局怎么拿到同一个实例 / 一张对象表？ | 单例 / 注册 |
| 横切关注点要不要单独成层？ | 面向切面（+ 装饰器、代理是它的手工件） |

## 五、校验口径

- **PHP**：`D:\phpstudy_pro\Extensions\php\php8.0.2nts\php.exe`（PHP 8.0.2 / Zend 4.0.2，CLI）。每个代码块先 `php -l` 再执行，正文 `text` 块为原始 stdout。语法定位 **PHP 8.0**：属性类型声明需 7.4+、构造器属性提升需 8.0+，全目录未使用 `readonly` / `enum` 等 8.1+ 特性（本机最高只有 8.0.2，用了就无法验证）。
- **Go**：`go1.26.5`，`go run` 实跑；可用 Go 1.23+ 的 `iter.Seq` / `iter.Seq2`（见 [迭代器模式.md](行为型/迭代器模式.md)）。
- **Java**：`D:\java\jdk1.8`（`javac -encoding UTF-8` + `java`）实跑，语法限制在 **JDK 8**。
- **关于原文代码**：博客原文的输出写法面向浏览器（`<br/>`、`<hr>`、`<span style="color:red">`）。复核时统一替换为 `PHP_EOL` / 纯文本，**只改输出方式，不改逻辑**，各篇在对应小节里都注明了这处替换。
- **未验证项**：全目录没有任何真实中间件实例（MySQL / Redis / MQ 均未连），涉及框架内部实现（Laravel / Symfony / Swoole）的描述属于"公开用法或定性推断"级；文中不含任何性能基准数字。

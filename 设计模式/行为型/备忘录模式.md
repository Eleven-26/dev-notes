## 一、备忘录解决什么问题

备忘录（Memento）属于行为型模式：**在不破坏封装的前提下，捕获一个对象的内部状态并在外部保存，之后可以把对象恢复到这个状态**。

它要解决的是"**撤销/回滚需要旧状态，但旧状态不该暴露给外部**"：

| 需求 | 没有备忘录时 |
| --- | --- |
| 撤销编辑 | 要么把所有字段开成 `public` 让外面随便读（封装被破坏） |
| 回滚配置 | 要么自己写"反向操作"（有些操作不可逆，见 [命令模式.md](命令模式.md)） |
| 事务式批处理 | 出错时无法"回到开始前" |
| 对比两次状态 | 拿不到"某一时刻的完整快照" |

**核心矛盾**：撤销需要旧状态 → 但状态的读取权限不能放开。备忘录的解法是把"旧状态"打包成一个**只能由原发器解读、外部只能存取**的对象。

三个角色：

| 角色 | 职责 | 本篇对应 |
| --- | --- | --- |
| Originator（原发器） | 持有当前状态；**产出**快照、**从**快照**恢复** | `TextEditor` |
| Memento（备忘录） | 承载某一时刻的状态；**对外不可变、不可解读** | `EditorSnapshot` |
| Caretaker（负责人） | 保管快照（栈/队列/磁盘），**不看内容** | `SnapshotHistory` |

**关键点**：Caretaker 手里握着一堆快照，但它**读不出里面是什么**；只有 Originator 能解读。这条"宽接口给原发器、窄接口给负责人"是备忘录的灵魂。

## 二、PHP 标准实现

场景：**带快照的文本编辑器**（表单草稿、配置编辑、批量操作前的存档都长这样）。

```php
<?php

declare(strict_types=1);

/** 元信息：一个可变对象，用来演示「快照里存引用」的坑 */
final class Meta
{
    public function __construct(
        public string $title = '初稿',
        public array $tags = ['draft']
    ) {}
}

/**
 * 备忘录：不可变。
 * 字段私有 + 只在构造时赋值 + 只提供读方法 —— 谁都无法在拿到之后改它。
 */
final class EditorSnapshot
{
    public function __construct(
        private string $content,
        private int $cursor,
        private Meta $meta
    ) {}

    /** @internal 只应由原发器调用（PHP 没有 friend class，只能靠约定 + 文档） */
    public function content(): string
    {
        return $this->content;
    }

    /** @internal */
    public function cursor(): int
    {
        return $this->cursor;
    }

    /** @internal 返回副本，避免调用方改到快照里的对象 */
    public function meta(): Meta
    {
        return clone $this->meta;
    }

    public function summary(): string
    {
        return sprintf('内容=%s 游标=%d 标题=%s', $this->content ?: '(空)', $this->cursor, $this->meta->title);
    }
}

/** 原发器：真正持有状态，负责产出快照与从快照恢复 */
final class TextEditor
{
    private string $content = '';
    private int $cursor = 0;
    private Meta $meta;

    public function __construct()
    {
        $this->meta = new Meta();
    }

    public function type(string $text): void
    {
        $head = substr($this->content, 0, $this->cursor);
        $tail = substr($this->content, $this->cursor);
        $this->content = $head . $text . $tail;
        $this->cursor += strlen($text);
    }

    public function setTitle(string $title): void
    {
        $this->meta->title = $title;
    }

    public function content(): string
    {
        return $this->content;
    }

    /** 产出快照。注意 meta 必须 clone —— 否则快照与原件共享同一个对象 */
    public function save(): EditorSnapshot
    {
        return new EditorSnapshot($this->content, $this->cursor, clone $this->meta);
    }

    /** 从快照恢复 */
    public function restore(EditorSnapshot $snapshot): void
    {
        $this->content = $snapshot->content();
        $this->cursor = $snapshot->cursor();
        $this->meta = $snapshot->meta();
    }
}

/** 负责人：只管存取，不关心快照里是什么（有容量上限，超了丢最早的） */
final class SnapshotHistory
{
    /** @var list<EditorSnapshot> */
    private array $stack = [];

    public function __construct(private int $limit = 10) {}

    public function push(EditorSnapshot $snapshot): void
    {
        $this->stack[] = $snapshot;
        while (count($this->stack) > $this->limit) {
            array_shift($this->stack);   // 超限丢弃最早的快照
        }
    }

    public function pop(): ?EditorSnapshot
    {
        return array_pop($this->stack);
    }

    public function size(): int
    {
        return count($this->stack);
    }
}
```

**使用示例**：

```php
// 原发器：改状态 → 存快照
$editor = new TextEditor();
$history = new SnapshotHistory(2);       // 容量上限 2，超了丢最早
$editor->type('Hello');
$history->push($editor->save());         // 存下第 1 个快照

$editor->type(' World');
$editor->save()->summary();              // 内容=Hello World 游标=11 标题=初稿

// 负责人只管存取；pop() 取出快照交回原发器恢复
$editor->restore($history->pop());
$editor->content();                      // Hello（回到保存那一刻）
```

实测（PHP 8.0.2 CLI）：

```text
1_第一次保存      : 栈内 1 个快照，内容=Hello 
2_内容推进后      : Hello World
3_继续输入        : Hello World again
4_恢复上一个快照  : Hello World
5_快照摘要        : 内容=Hello World 游标=11 标题=初稿

6_容量上限 2 存 3 个 : 栈内剩 2 个
   栈顶恢复出来的是   : abc（丢的是最早那个 a，不是最新的）

7_快照摘要（深拷贝）: 内容=(空) 游标=0 标题=初稿（原件已改成「被改过了」，快照不受影响）
8_快照里的标题（不克隆） : 被改过了（快照被原件改动了 → 这就是坑）

9_快照字段可见性         : private（只能构造时赋值）
10_快照类是否 final      : true（不可被继承改写）
```

要看的点：

- **第 1~4 行是主流程**：`save()` 产出快照、`restore()` 回到过去。**恢复的是"整份状态"**（内容 + 游标 + 元信息），不是某一个字段；
- **第 6 行是容量治理**：快照栈必须有上限。实测 limit=2 时存 3 个，**丢的是最早那个**（`abc` 还在），这个顺序不能反；
- **第 7、8 行是同一个坑的两面**：第 7 行 `clone` 了（快照安全），第 8 行没 `clone`（快照被原件改掉）。这是备忘录模式最容易出错的地方 —— 见第四节；
- **第 9、10 行**是快照不可变的两个必要条件：字段 `private`、类 `final`。

### 让它算「标准写法」的 5 个细节

| # | 做法 | 为什么 |
| --- | --- | --- |
| 1 | 快照类**只读**：字段 `private` + 只在构造时赋值 + 类 `final` | "不可变"是这个模式的前提，不是风格偏好 |
| 2 | 快照**必须深拷贝**所有可变成员（对象、数组、切片） | 否则"快照"与原件共享同一块内存，等于没存 |
| 3 | 原发器提供 `save()` / `restore()` 成对方法 | 状态的读写都收在原发器里，外部只传递快照对象 |
| 4 | 负责人**只做存取**，且带**容量上限** | 无限增长的快照栈是内存泄漏；上限也决定了"能回退几步" |
| 5 | 恢复时**整体替换**，不要逐字段打补丁 | 逐字段恢复迟早漏掉一个（新增字段时最明显） |

## 三、宽接口与窄接口

备忘录的核心设计是**同一个对象、两套可见性**：

| | 谁能用 | 能做什么 |
| --- | --- | --- |
| **宽接口** | 原发器 | 读取快照内的全部状态（`content()` / `cursor()` / `meta()`） |
| **窄接口** | 负责人 / 外部 | 只能持有和传递，**读不出内容** |

三语言的实现手段不同，理解这个差异比记住写法更重要：

| | PHP | Java | Go |
| --- | --- | --- | --- |
| 手段 | 快照字段 `private` + 读方法标 `@internal` | **空标记接口** `interface Memento {}` + 私有实现类 | **含未导出方法的接口** + 未导出结构体 |
| 强度 | 最弱（同进程内任何代码都能调读方法，只是约定） | 强（外部拿不到实现类型） | 强（包外无法实现、也无法调用未导出方法） |
| 实测 | `9_快照字段可见性 : private` | `9_窄接口方法数 : 声明的方法 0 个，真实类型 Snapshot 是私有的` | `9_窄接口的唯一方法 : *main.snapshot 只暴露 summary()` |

Java 的空标记接口是最经典的表达：

```java
/** 窄接口（空标记接口）：负责人只能持有它，**读不到任何内容** */
interface Memento {
}

// 原发器内部：
private static final class Snapshot implements Memento { /* ... */ }
```

负责人拿到的静态类型是 `Memento`，它**一个方法都没有**；只有 `TextEditor.restore()` 内部做 `(Snapshot) memento` 强转才拿得到数据。

Go 用"接口里放一个未导出方法"达到同样效果 —— 包外类型根本无法满足这个接口：

```go
// Memento 窄接口：只有一个**未导出**方法 —— 包外类型无法实现它，也无法调用它。
type Memento interface {
	summary() string
}

// snapshot 备忘录：字段全部未导出 → 包外既造不出来、也读不到内容
type snapshot struct {
	content string
	cursor  int
	meta    Meta
}
```

⚠️ **PHP 是最弱的**：`private` 只挡住"直接改"，挡不住"调用读方法"。所以 PHP 里更依赖**约定**（`@internal` 注释 + code review）。真需要更强约束，可以把快照的读方法做成 `Closure::bind` 才能拿到的私有闭包，但那纯属过度设计 —— **PHP 的工程实践是接受这一点，用文档和命名说清楚**。

## 四、这个模式最容易翻车的地方：浅拷贝

**快照里只要有一个可变成员没深拷贝，"快照"就是假的。** 实测第 7、8 行：

```text
7_快照摘要（深拷贝）: 内容=(空) 游标=0 标题=初稿（原件已改成「被改过了」，快照不受影响）
8_快照里的标题（不克隆） : 被改过了（快照被原件改动了 → 这就是坑）
```

第 8 行的场景是"直接把对象引用塞进快照"：

```php
public function badSnapshot(): Meta
{
    return $this->meta;      // ⚠️ 返回的是同一个对象
}
```

之后原件一改（`$shared->meta->title = '被改过了'`），"快照"跟着变 —— **因为它俩本来就是同一个东西**。

三种语言里"哪些成员需要深拷贝"完全不同，这是最容易漏的地方：

| | 值语义（自动安全） | 引用语义（必须手动拷贝） |
| --- | --- | --- |
| PHP | 标量、**数组**（写时复制） | **对象**（句柄语义） |
| Java | 基本类型、不可变对象（`String` / 包装类 / `BigDecimal`） | **对象、数组、集合** |
| Go | 标量、结构体值、数组（`[N]T`） | **指针、切片、map、channel** |

三个具体陷阱：

1. **PHP 的数组是"值"、对象是"引用"** —— 同一个对象里两类属性的行为相反。这与 [原型模式.md](../创建型/原型模式.md) 里讲的是同一条规则；
2. **Go 的结构体赋值是值拷贝，但切片/map 字段仍指向同一块底层数据** —— 实测第 8 行就是这个：
   ```text
   8_切片共享底层数组   : 原对象 Tags = [被改过了] ← bad 的改动穿透到了 shared
   ```
   `bad := shared` 看似拷贝了整个结构体，但 `Tags` 字段共享底层数组，改 `bad.Tags[0]` 就连累 `shared`。**必须 `copy()`**；
3. **Java 的"不可变对象"是安全的** —— `String` / `Integer` 等不用拷贝。但 `List` / `Map` / `Date`（可变！）必须拷。

一个实用判据：**能把快照做成"全是标量 + 不可变对象"就做成这样**。如果快照里只放一个 `string`（比如把对象序列化成 JSON 字符串），深拷贝问题自动消失，代价是反序列化成本。

## 五、边界：备忘录 vs 命令（撤销的两种做法）

| | 备忘录（快照） | 命令（逆操作） |
| --- | --- | --- |
| 撤销依据 | 执行**前**的状态副本 | 执行**时**采集的反向信息 |
| 内存 | 每步一份完整状态，**费内存** | 只存增量，**省内存** |
| 通用性 | **通用**（任何对象都能快照） | 每个命令都要仔细写反向逻辑 |
| 不可逆操作 | 也能"撤销"（回滚状态） | 无解（发短信没法撤回） |
| 典型场景 | 表单草稿、配置回滚、游戏存档、事务回滚 | 文本编辑、绘图撤销、数据库 undo log |

**现实中两者常混用**：文本编辑器用逆操作（增量小），表单提交用快照（一次一份草稿）。命令模式第三节列过这张对照表，本篇是它的另一半。

另外两个容易混的近亲：

- **与原型模式**：快照常用 `clone` 实现（"复制一份留底"），但原型模式的目的是"**造新对象**"，备忘录的目的是"**留住旧状态**"。手段相同、意图不同；
- **与事务/持久化**：把快照写到磁盘/数据库，就变成"版本历史"（如 Git 的 commit、配置中心的版本回滚）。**模式不变，只是负责人换成了存储层** —— 这也是它在后端最常见的形态。

## 六、Java / Go 实现

### Java 实现

```java
/** 窄接口（空标记接口）：负责人只能持有它，读不到任何内容 */
interface Memento {
}

/** 原发器：真正持有状态，负责产出快照与从快照恢复 */
static final class TextEditor {
    private String content = "";
    private int cursor = 0;
    private Meta meta = new Meta("初稿");

    /** 产出快照。meta 必须拷贝 —— 否则快照与原件共享同一个对象 */
    Memento save() {
        return new Snapshot(content, cursor, meta.copy());
    }

    /** 从快照恢复 */
    void restore(Memento memento) {
        Snapshot s = (Snapshot) memento;   // 只有本类能拿到真实类型
        content = s.content;
        cursor = s.cursor;
        meta = s.meta;
    }

    /** 私有内部类：外部拿不到类型，只能当成 Memento 持有 */
    private static final class Snapshot implements Memento {
        private final String content;
        private final int cursor;
        private final Meta meta;

        Snapshot(String content, int cursor, Meta meta) {
            this.content = content;
            this.cursor = cursor;
            this.meta = meta;
        }
    }
}
```

**使用示例**：

```java
// 原发器改状态 → 负责人存快照
TextEditor editor = new TextEditor();
SnapshotHistory history = new SnapshotHistory(2);   // 容量上限 2，超了丢最早
editor.type("Hello");
history.push(editor.save());                        // 存下第 1 个快照

editor.type(" World");
System.out.println(editor.content());               // Hello World

// pop() 拿到的静态类型是 Memento，只能交回原发器恢复
Memento top = history.pop();
editor.restore(top);
System.out.println(editor.content());               // Hello
```

JDK 1.8 实测输出与 PHP 版逐行一致。Java 侧三点差异：

- **`final` 字段 + 无 setter = 不可变**，这是 Java 里最标准的做法。《Effective Java》条目 17 讲的就是这条；
- **窄接口用空标记接口**，是本篇唯一一个 Java 比 PHP 更"严"的地方；
- **JDK 14+ 的 `record`** 能把快照写成一行（本机 JDK 8 无法验证）：
  ```java
  record Snapshot(String content, int cursor, Meta meta) implements Memento { }
  ```
  records 天然不可变（字段 `final` + 只有访问器），正是为这种"纯数据载体"设计的。

### Go 实现

```go
// Memento 窄接口：只有一个**未导出**方法 —— 包外类型无法实现它，也无法调用它。
// 这是 Go 里表达「黑盒」的标准手法。
type Memento interface {
	summary() string
}

// snapshot 备忘录：字段全部未导出 → 包外既造不出来、也读不到内容
type snapshot struct {
	content string
	cursor  int
	meta    Meta
}

// Save 产出快照。注意 meta 必须深拷贝 —— 否则快照与原件共享同一个 Tags 底层数组
func (e *Editor) Save() Memento {
	return &snapshot{content: e.content, cursor: e.cursor, meta: e.meta.clone()}
}

// Restore 从快照恢复（类型断言：只有本包能拿到真实类型）
func (e *Editor) Restore(m Memento) {
	s, ok := m.(*snapshot)
	if !ok {
		return
	}
	e.content = s.content
	e.cursor = s.cursor
	e.meta = s.meta
}
```

**使用示例**：

```go
// 原发器改状态 → 负责人存快照
editor := NewEditor()
history := NewHistory(2)      // 容量上限 2，超了丢最早
editor.Type("Hello")
history.Push(editor.Save())   // 存下第 1 个快照

editor.Type(" World")
editor.Content()              // Hello World

// Pop() 返回的是窄接口 Memento，只能交回原发器恢复
editor.Restore(history.Pop())
editor.Content()              // Hello（回到保存那一刻）
```

go1.26.5 实测输出（与 PHP/Java 一致）：

```text
1_第一次保存      : 栈内 1 个快照，内容=Hello 
...
7_快照摘要（深拷贝）: 内容=(空) 游标=0 标题=初稿 ← 原件已改，快照不受影响
8_切片共享底层数组   : 原对象 Tags = [被改过了] ← bad 的改动穿透到了 shared

9_窄接口的唯一方法   : *main.snapshot 只暴露 summary()（未导出，包外调用不了）
```

Go 的三点差异：

- **封装是"包级"而不是"类级"**。`snapshot` 的字段在**同一个包内**谁都能读 —— 所以 Go 里"窄接口"只在跨包时成立。工程上的对策是把备忘录放在独立包（`internal/memento`），用包边界当封装边界；
- **深拷贝要手写**（没有 clone 机制）：
  ```go
  func (m Meta) clone() Meta {
      tags := make([]string, len(m.Tags))
      copy(tags, m.Tags)

      return Meta{Title: m.Title, Tags: tags}
  }
  ```
  这也意味着**新增一个引用类型字段时，必须同步改 `clone()`**，否则快照静默失效；
- **`Restore` 用类型断言**拿到真实类型，断言失败时本实现选择静默返回。生产代码里更该返回 `error` 或 panic —— **静默失败会让"恢复"看起来成功了**。

## 七、三语言对照

| | PHP | Java | Go |
| --- | --- | --- | --- |
| 不可变手段 | `private` 字段 + `final` 类 | `final` 字段 + 无 setter（或 `record`） | 未导出字段 |
| 窄接口 | 约定（`@internal`） | **空标记接口 + 私有实现类** | **未导出方法 + 未导出类型** |
| 深拷贝 | `clone`（对象）/ 数组自动写时复制 | 逐字段拷贝或拷贝构造器 | **手写 `clone` + `copy()`** |
| 负责人 | `array` 当栈 | `List` / `Deque` 当栈 | `slice` 当栈 |
| 容量上限 | `array_shift` 丢最早 | `remove(0)` 丢最早 | `s = s[1:]` 丢最早 |
| 生态代表 | Laravel 的"草稿/版本"、配置回滚 | `java.util.Memento`（社区实现）、各编辑器的 UndoManager | `internal` 包里的审计/回滚快照 |

**三语言共通的一条**：快照越"简单"（越接近纯值），越不容易出错。**能在快照里只放不可变数据，就别放可变对象** —— 这是这个模式唯一需要长期维护的约定。

## 八、面试官会追问什么

- **备忘录和命令模式的区别？** → 撤销的两条路：备忘录存**执行前的完整状态**（通用但费内存），命令存**反向操作所需的信息**（省内存但要逐个写反向逻辑，且不可逆操作无解）。现实中常混用。
- **为什么快照必须不可变？** → 它是"过去某一刻"的凭证，一旦能被改，"能不能恢复"就不由它自己决定了。手段：字段 `private`/`final`、只在构造时赋值、类 `final`/不导出。
- **"宽接口/窄接口"是什么意思？** → 同一个快照对象，**原发器能读全部内容**（宽），**负责人只能持有不能读**（窄）。Java 用空标记接口、Go 用未导出方法；PHP 没有这个机制，只能靠 `@internal` 约定 —— **这是 PHP 在本模式上的固有弱点**。
- **浅拷贝会怎样？** → 快照与原件共享同一块内存，"存了等于没存"。PHP 的数组是值语义所以安全、对象不安全；Go 的结构体是值语义但**切片/map 字段仍共享底层数组**；Java 的可变对象（`List`/`Map`/`Date`）都必须手动拷。
- **快照要存多少步？** → 必须有上限（本篇实测 limit=2 时丢最早那个）。上限的取值是"能用多久"与"内存能扛多久"的权衡；真要长期保留就得落盘/入库，负责人换成存储层。
- **PHP 里哪里有这个模式？** → 表单草稿与自动保存、配置中心的版本回滚、CMS 的内容修订历史。**注意 php-fpm 每个请求结束就回收内存**，跨请求的快照必须落到 session / 数据库 / Redis，不能只放在静态属性里（同 [观察者模式.md](观察者模式.md) 里那条主线）。
- **能不能不做快照，直接用数据库事务？** → 数据库事务解决的是"同一事务内的回滚"，**跨请求、跨用户操作的撤销它管不了**。而"撤销一次业务动作"（如审批撤回）需要的正是备忘录式的状态快照。
- **什么时候不该用？** → 状态很大（整张大表、大文件）时快照成本高得离谱。这时改用**事件溯源**（只存变化，回放重建）或逆操作。

## 一、命令解决什么问题

命令（Command）属于行为型模式：**把一个请求（一次操作）封装成对象**，从而让请求可以被**参数化、排队、记录日志、以及撤销**。

它要解决的核心问题是"**操作本身需要被当成数据来对待**"：

| 需求 | 没有命令时 |
| --- | --- |
| 撤销 | 每处调用都要自己记住"怎么反着做" |
| 排队 / 延迟执行 | 只能把"要做什么"写成参数，参数类型很快就会变成一堆 `if` |
| 审计 / 重放 | 得在每个方法里手写日志 |
| 组合操作（宏） | 没有统一的东西可以放进容器 |

**命令就是那个"统一的东西"** —— 一旦操作变成了对象，它就能像数据一样被存进数组、写进队列、送去序列化。

四个角色：

| 角色 | 职责 | 本篇对应 |
| --- | --- | --- |
| Command | 声明执行（与撤销）的接口 | `Command` |
| ConcreteCommand | 绑定"接收者 + 参数"，知道怎么执行与撤销自己 | `InsertTextCommand` / `DeleteTailCommand` |
| Receiver | 真正干活的领域对象，**不知道命令存在** | `TextEditor` |
| Invoker | 触发命令、记录历史，**不认识任何具体命令** | `CommandInvoker` |

**"Receiver 不知道 Command，Invoker 不知道具体命令"** 是这个模式的解耦要点 —— 中间的 `Command` 把两边隔开。

## 二、PHP 标准实现

场景：**可撤销的文本编辑**（编辑器、表单草稿、批量操作都长这样）。

```php
<?php

declare(strict_types=1);

/** 命令接口：把「一次操作」封装成对象，因此可以被排队、记录、撤销 */
interface Command
{
    public function execute(): void;

    public function undo(): void;
}

/** 接收者（Receiver）：真正干活的领域对象，它不知道命令的存在 */
final class TextEditor
{
    private string $content = '';

    public function insert(string $text): void
    {
        $this->content .= $text;
    }

    public function deleteTail(int $length): void
    {
        $this->content = substr($this->content, 0, max(0, strlen($this->content) - $length));
    }

    public function content(): string
    {
        return $this->content;
    }
}

/** 具体命令：持有接收者 + 执行所需参数，并知道怎么撤销自己 */
final class InsertTextCommand implements Command
{
    public function __construct(
        private TextEditor $editor,
        private string $text
    ) {}

    public function execute(): void
    {
        $this->editor->insert($this->text);
    }

    public function undo(): void
    {
        $this->editor->deleteTail(strlen($this->text));
    }
}

/** 具体命令：删除末尾若干字符（与插入是可逆的一对） */
final class DeleteTailCommand implements Command
{
    private string $removed = '';

    public function __construct(
        private TextEditor $editor,
        private int $length
    ) {}

    public function execute(): void
    {
        $this->removed = substr($this->editor->content(), -$this->length);
        $this->editor->deleteTail($this->length);
    }

    public function undo(): void
    {
        $this->editor->insert($this->removed);   // 撤销时要恢复「当时删掉的」内容
    }
}

/** 调用者（Invoker）：只管执行与记录历史，不认识任何具体命令 */
final class CommandInvoker
{
    /** @var list<Command> */
    private array $history = [];

    public function run(Command $command): void
    {
        $command->execute();
        $this->history[] = $command;
    }

    public function undoLast(): bool
    {
        $command = array_pop($this->history);
        if ($command === null) {
            return false;
        }
        $command->undo();
        return true;
    }

    public function historySize(): int
    {
        return count($this->history);
    }
}
```

**使用示例**：

```php
// Invoker 只认 Command：执行一步、记一步历史
$editor  = new TextEditor();
$invoker = new CommandInvoker();
$invoker->run(new InsertTextCommand($editor, 'Hello'));   // content: Hello

// 撤销信息由命令自己在执行时采集
$invoker->run(new DeleteTailCommand($editor, 2));         // content: Hel
$invoker->undoLast();                                     // true → content: Hello
$invoker->historySize();                                  // 1（只剩 Insert）
```

实测（PHP 8.0.2 CLI）：

```text
1_连续两步之后   : Hello, World
2_撤销一步       : Hello
3_再撤销一步     : (空)
4_删除末尾 3 个  : abc
5_撤销删除       : abcdef（恢复的是当时删掉的内容）
6_历史条数       : 1
```

第 4、5 行是命令模式最值得看的部分：**删除命令在 `execute()` 时把被删的内容记下来**（`$this->removed`），`undo()` 时把它插回去。也就是说，**撤销所需要的信息由命令自己在执行时采集**，Invoker 完全不管。

### 4 个让它算「标准写法」的细节

| # | 做法 | 为什么 |
| --- | --- | --- |
| 1 | `Command` 接口只有 `execute` / `undo` | 接口越小，越容易实现"宏命令"（一个命令内部持有多个命令） |
| 2 | 具体命令**持有接收者**，而不是自己实现业务 | 业务逻辑仍留在领域对象里，命令只做"装配 + 记账" |
| 3 | **撤销信息在执行时采集**（`$removed`） | 不能靠"再算一遍"来撤销 —— 状态可能已经变了（本实测正是如此：删掉的内容必须原样记住） |
| 4 | Invoker 只认 `Command` | 换成队列、换成日志、换成宏命令都不用改 Invoker |

## 三、撤销的两种实现方式

实测里用的是"逆操作"，这是两种主流做法之一：

| 方式 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **逆操作**（本篇） | 每个命令实现一个与 `execute` 相反的动作 | 内存占用小 | 每个命令都要仔细写反向逻辑；某些操作**不可逆**（如"发短信"） |
| **快照**（备忘录模式） | 执行前把接收者的状态存一份 | 实现简单、通用 | 占内存；状态大时不可行 |

现实项目里常**混用**：文本编辑用逆操作（增量小、可逆），表单提交用快照（一次提交一份草稿）。快照那种做法就是**备忘录模式**（Memento），与本篇是配套关系。

还有两个实践要点：

- **并非所有操作都能撤销**：`SendEmailCommand::undo()` 没有意义。这类命令要么不实现 `undo`（拆成两个接口），要么在 `undo()` 里抛 `NotSupportedException`。**别写一个什么都不做的空 `undo()`**，那会让调用方以为撤销成功了。
- **撤销栈通常有上限**：编辑器里的 `history` 一般只保留最近 N 步，否则长时间编辑会吃掉大量内存。

## 四、边界：命令 vs 策略 vs 责任链

| | 命令 | 策略 | 责任链 |
| --- | --- | --- | --- |
| 封装的是 | **一次请求**（含参数与撤销） | 一种**算法** | 一串**处理者** |
| 有没有状态 | 有（撤销所需的信息） | 通常无状态 | 通常无状态 |
| 谁触发 | Invoker（可以延迟、排队、记录） | 调用方直接选 | 请求沿链传递 |
| 典型问题 | "这次操作怎么记录/撤销" | "用哪种算法" | "谁来处理这次请求" |

最容易混的是**命令 vs 策略**：两者都是"把行为包成对象"。区别在于 —— **策略回答"用哪种算法"，命令回答"把这次操作记下来"**。策略对象通常无状态且可复用；命令对象携带参数与撤销信息，天然是一次性的。

## 五、Java / Go 实现

### Java 实现

```java
/** 命令接口：把「一次操作」封装成对象 */
interface Command {
    void execute();

    void undo();
}

/** 具体命令：持有接收者 + 参数，并知道怎么撤销自己 */
static final class InsertTextCommand implements Command {
    private final TextEditor editor;
    private final String text;

    InsertTextCommand(TextEditor editor, String text) {
        this.editor = editor;
        this.text = text;
    }

    public void execute() { editor.insert(text); }

    public void undo() { editor.deleteTail(text.length()); }
}

/** 另一个具体命令：删除末尾若干字符 */
static final class DeleteTailCommand implements Command {
    private final TextEditor editor;
    private final int length;
    private String removed = "";

    public void execute() {
        String content = editor.content();
        removed = content.substring(Math.max(0, content.length() - length));
        editor.deleteTail(length);
    }

    /** 撤销时要恢复「当时删掉的」内容，而不是重新算一遍 */
    public void undo() { editor.insert(removed); }
}
```

**使用示例**：

```java
// 接收者与 Invoker 分离：Invoker 只调 execute / undo
TextEditor editor = new TextEditor();
CommandInvoker invoker = new CommandInvoker();
invoker.run(new InsertTextCommand(editor, "Hello"));     // content: Hello

// 撤销信息由命令自己记住
invoker.run(new DeleteTailCommand(editor, 2));           // content: Hel
invoker.undoLast();                                      // true → content: Hello
invoker.historySize();                                   // 1（只剩 Insert）
```

JDK 1.8 实测输出与 PHP 版逐行一致：

```text
1_连续两步之后   : Hello, World
2_撤销一步       : Hello
3_再撤销一步     : (空)
4_删除末尾 3 个  : abc
5_撤销删除       : abcdef（恢复的是当时删掉的内容）
6_历史条数       : 1
```

Java 里最常见的命令模式落地是 **`Runnable` / `Callable`**：一个"可执行的任务"把操作与参数封装起来，可以丢给线程池（排队执行）、可以放进队列（延迟执行）—— 这与命令模式的 Invoker 完全对应。Spring 的 `TransactionTemplate`、各类任务调度框架也是这个形状。

### Go 实现

```go
// Command 命令接口：把「一次操作」封装成对象，因此可以被排队、记录、撤销
type Command interface {
	Execute() error
	Undo() error
}

// DeleteTailCommand 另一个具体命令
type DeleteTailCommand struct {
	editor  *TextEditor
	length  int
	removed string
}

func (c *DeleteTailCommand) Execute() error {
	content := c.editor.Content()
	if c.length > len(content) {
		return errors.New("要删除的长度超过内容长度")
	}
	c.removed = content[len(content)-c.length:]
	c.editor.DeleteTail(c.length)
	return nil
}

func (c *DeleteTailCommand) Undo() error {
	c.editor.Insert(c.removed) // 恢复「当时删掉的」内容
	return nil
}
```

**使用示例**：

```go
// 接收者 + Invoker：Invoker 只认 Command 接口
editor := &TextEditor{}
invoker := &CommandInvoker{}
_ = invoker.Run(NewInsertTextCommand(editor, "Hello"))   // content: Hello

// 撤销信息由命令自己记住
_ = invoker.Run(NewDeleteTailCommand(editor, 2))         // content: Hel
invoker.UndoLast()                                       // true → content: Hello
invoker.HistorySize()                                    // 1（只剩 Insert）
```

go1.26.5 实测输出（与 PHP/Java 一致）：

```text
1_连续两步之后   : Hello, World
2_撤销一步       : Hello
3_再撤销一步     : (空)
4_删除末尾 3 个  : abc
5_撤销删除       : abcdef （恢复的是当时删掉的内容）
6_历史条数       : 1
```

Go 的两点差异：

- **命令通常定义成"带方法的函数类型"**：如果命令无参数、不需要撤销，`type Command func() error` 就够了，不必建接口。本例因为要 `Undo` 且有状态，才用结构体；
- **`Execute` 返回 `error`**：Go 里失败是值，所以命令可以"执行失败且不进历史"（本实现的 `Run` 正是这么做的）—— 而 PHP/Java 版需要靠异常来达到同样效果。

## 六、三语言对照

| | PHP | Java | Go |
| --- | --- | --- | --- |
| 命令接口 | `interface` | `interface` | 接口或**函数类型** |
| 执行失败 | 抛异常 | 抛异常 | **返回 `error`，可决定是否入历史** |
| 命令对象存哪儿 | `array`（天然值拷贝） | `List`（引用） | `slice` |
| 撤销信息 | 属性（`$removed`） | 字段（`removed`） | 字段（`removed`） |
| 生态代表 | Laravel Queue 的 Job、Symfony Messenger | `Runnable` / `Callable` 提交线程池 | 函数值 + 队列（`chan`） |

三语言共通的一条：**命令对象一旦带上状态（撤销信息、参数），就不能被复用**。这与 [../行为型/策略模式.md](../行为型/策略模式.md) 里"策略应尽量无状态"正好相反 —— 判断依据是"这个对象代表的是算法，还是某一次具体操作"。

## 七、面试官会追问什么

- **命令模式的核心价值是什么？** → 把"一次操作"变成对象，于是它可以被排队、记录、重放、撤销。**关键动作是"封装成对象"**，其余能力都是它的副产品。
- **命令和策略的区别？** → 策略封装"算法"（通常无状态、可复用），命令封装"一次请求"（带参数与撤销信息，一次性的）。
- **撤销怎么实现？** → 两种：**逆操作**（每个命令写反向逻辑，省内存但要小心不可逆操作）与**快照**（存状态，通用但费内存，即备忘录模式）。实践中常混用。
- **必须实现 `undo()` 吗？** → 不必。不可逆的命令（发短信、扣款）不该假装能撤销。拆成 `Executable` 与 `Undoable` 两个接口，或者在 `undo()` 里明确抛"不支持"。
- **命令能用来做审计吗？** → 能，而且这是它的强项：Invoker 手里有完整的历史序列，序列化后就是可重放的日志（配合幂等设计）。但注意**命令里可能含敏感参数**，入库前要脱敏。
- **PHP 里哪里有命令模式？** → Laravel 的 Job（`ShouldQueue` 的命令）、Symfony Messenger 的 Message/Handler、各类批量操作的"任务对象"。
- **和队列的关系？** → 命令是"可排队的对象"这一抽象；队列是它的典型 Invoker。把命令序列化丢进 Redis/MQ，就是分布式版的 Invoker。

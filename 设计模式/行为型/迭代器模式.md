## 一、什么是迭代器模式

原文的定义：

> 迭代器模式（Iterator），又叫做游标（Cursor）模式。提供一种方法访问一个容器（Container）对象中各个元素，
> 而又不需暴露该对象的内部细节。迭代器模式为遍历不同的聚集结构提供如开始、下一个、是否结束、当前哪一项等统一的接口。

原文紧接一句关键提示：**PHP 标准库（SPL）中提供了迭代器接口 `Iterator`，要实现迭代器模式，实现该接口即可。**

也就是说，在 PHP 里这是**语言与标准库已经替你实现好的模式** —— 这一点后面第五节会展开，它是 PHP 与 Java/Go 最大的差异所在。

原文提到的"四个问题"，其实就是迭代器协议的全部内容：

| 协议方法 | 回答的问题 | SPL 里的名字 |
| --- | --- | --- |
| 开始 | 回到第一个元素 | `rewind()` |
| 当前哪一项 | 现在指到哪个元素 | `current()` |
| 下一个 | 往后移一位 | `next()` |
| 是否结束 | 还能不能继续 | `valid()` |

配合 `key()`，`foreach ($it as $k => $v)` 就能像遍历数组一样遍历任意容器。

## 二、应用场景

原文给的判据：

> 当你需要访问一个聚合对象，而且不管这些对象是什么都需要遍历的时候，就应该考虑使用迭代器模式。
> 另外，当需要对聚集有多种方式遍历时，可以考虑去使用迭代器模式。

翻成实践语言：

| 场景 | 说明 |
| --- | --- |
| 容器内部结构要隐藏 | 外部不必知道是数组、链表还是树 |
| 同一集合要多种遍历 | 先序/后序、正序/倒序、按层级 |
| 数据量大或算不出来 | 惰性产出，边算边给（生成器） |
| 数据源不是内存 | 逐行读文件、分页拉接口、游标查库 |

**最后一行是现代 PHP 里迭代器最常出现的地方**：一次查出 100 万行会 OOM，用生成器逐行 yield 则内存恒定。原文写于 2019 年，没有展开这一层。

## 三、原文写法参考（博客 2019 版）

> ⚠️ **本节代码是博客原文，仅作对照，不是推荐写法。**
> 它的两个问题在第四节实测，**推荐实现见第五节「PHP 标准实现」**——
> 原文示范的是"手写 Java 五件套"，而 PHP 里有 `IteratorAggregate` 与生成器，40 行样板能压到 12 行。

### 3.1 原文代码

```php
<?php

/**
 * 迭代器模式
 * Class MyIterator
 */
class MyIterator implements Iterator
{
    private $var = array();

    public function __construct($array)
    {
        if (is_array($array)) {
            $this->var = $array;
        }
    }

    public function rewind() {
        echo "倒回第一个元素";
        echo "<br>";
        reset($this->var);
    }

    public function current() {
        $var = current($this->var);
        echo "当前元素: $var";
        echo "<br>";
        return $var;
    }

    public function key() {
        $var = key($this->var);
        echo "当前元素的键: $var";
        echo "<br>";
        return $var;
    }

    public function next() {
        $var = next($this->var);
        echo "移向下一个元素: $var";
        echo "<br>";
        return $var;
    }


    public function valid() {
        $var = $this->current() !== false;
        echo "检查有效性: {$var}";
        echo "<br>";
        return $var;
    }
}
```

调用段：

```php
//=======================迭代器模式测试===============================

$values = array(1,2,3);
$it = new MyIterator($values);
foreach ($it as $k => $v) {
    print "此时键值对 -- key $k: value $v";
    echo "<hr>";
}
```

原文刻意在每个协议方法里 `echo` 一句，为的是**把 `foreach` 的调用顺序打印出来** —— 这是本篇最有教学价值的设计，也是后面第四节的入口。

### 3.2 原文运行结果

原文输出（浏览器里用 `<br>` 换行）。本机 CLI 复核时把 `echo "<br>"` 换成 `PHP_EOL`、`echo "<hr>"` 删去，**调用顺序与原文完全一致**：

```text

当前元素: 1
检查有效性: 1
当前元素: 1
当前元素的键: 0
此时键值对 -- key 0: value 1
移向下一个元素: 2
当前元素: 2
检查有效性: 1
当前元素: 2
当前元素的键: 1
此时键值对 -- key 1: value 2
移向下一个元素: 3
当前元素: 3
检查有效性: 1
当前元素: 3
当前元素的键: 2
此时键值对 -- key 2: value 3
移向下一个元素: 
当前元素: 
检查有效性: 
```

（PHP 8.0.2 CLI 实测。原文在 2019 年的运行结果与此逐行一致 —— 这段样例确实没写错。）

从这段输出能读出两件事：

1. **`foreach` 每轮要调三次方法**：`valid()` → `current()` → `key()`，循环体执行完再 `next()`；
2. **`current()` 被调用了两次**（一次在 `valid()` 内部，一次被 `foreach` 自己调），所以"当前元素: 1"打印了两遍。

第 2 点就是下一节要处理的问题。

## 四、原文写法的两处问题（实测）

### 4.1 `valid()` 内部调 `current()` 是重复调用

原文 `valid()` 的实现是 `$this->current() !== false`。这行代码有两个副作用：

- **性能**：每轮多调一次 `current()`。如果 `current()` 里有 IO（读文件、查库），代价直接翻倍。
- **正确性**：`current()` 在此处被当成"纯查询"，但它可能带副作用（原文的 `echo` 就是最轻的副作用）。更严重的是，如果容器里的元素**本身可能是 `false`**，`current() !== false` 这套判据会**提前终止遍历**。

正确的判据是不依赖元素值的方式：

```php
public function valid(): bool
{
    return key($this->var) !== null;   // 与元素内容无关
}
```

这一点在 PHP 里尤其重要：`current()` 在数组指针越界时返回 `false`，所以**用 `false` 当"结束"的哨兵值，必然与"元素值恰好是 false"冲突**：

```text
$it = new MyIterator([1, false, 3]);
```

按原文的 `valid()`，遍历到 `false` 就会停 —— **第三个数永远拿不到，且不报错**。这类 bug 在生产里极难定位。

### 4.2 补一句原系列没写的：`foreach` 对数组和对对象，语义不同

| 被遍历对象 | 语义 | 循环体内改动的影响 |
| --- | --- | --- |
| 数组 `foreach ($arr as $v)` | 遍历的是**副本** | 改 `$v` 不影响原数组 |
| 数组 `foreach ($arr as &$v)` | 引用遍历 | 改 `$v` 改原数组（循环后须 `unset($v)`） |
| 实现 `Iterator` 的对象 | 遍历的是**迭代器自身状态** | 多个 `foreach` 共享同一个指针，**不能嵌套遍历同一个迭代器实例** |

最后一行是实践里最常踩的：同一个迭代器对象被嵌套遍历（或先 `foreach` 再 `foreach`），第二次往往从"上一次结束的位置"开始。

## 五、PHP 标准实现（推荐）

> 这一节就是本篇的推荐写法。第三节的原文代码只用于对照，**新代码不要照着原文写**。

### 5.1 别照抄"Java 五件套"：`IteratorAggregate` + `yield`

原文实现 `Iterator` 接口时要手写 `rewind/current/key/next/valid` 五个方法 —— 这是 Java 风格的写法。PHP 里如果**底层数据本身就是数组**，这五个方法全是样板代码。

更 PHP 的写法是实现 `IteratorAggregate`（只要求一个 `getIterator()`），把遍历交给生成器：

```php
<?php

declare(strict_types=1);

final class NumberBucket implements IteratorAggregate
{
    public function __construct(private array $values) {}

    public function getIterator(): Generator
    {
        foreach ($this->values as $k => $v) {
            yield $k => $v;
        }
    }
}

foreach (new NumberBucket([1, 2, 3]) as $k => $v) {
    echo "key {$k}: value {$v}", PHP_EOL;
}
```

实测输出：

```text
key 0: value 1
key 1: value 2
key 2: value 3
```

代码量从 40 行降到 12 行，"当前哪一项/下一个/是否结束"三件事由生成器托管，且**不会出现 4.1 的哨兵值 bug**。

### 5.2 贴近生产的例子：把"翻页"藏进生成器

上面那个例子只说明语法。**真实项目里迭代器模式最值钱的用法是"把分批拉取伪装成一条平铺序列"**：

```php
/** 分批拉取：把「翻页」藏进生成器，调用方只看到一条平铺的序列 */
final class OrderCursor implements IteratorAggregate
{
    public int $pagesFetched = 0;

    /**
     * @param Closure(int $page, int $size): list<array{id:string,amount:int}> $fetchPage
     */
    public function __construct(
        private Closure $fetchPage,
        private int $pageSize = 2
    ) {}

    public function getIterator(): Generator
    {
        $page = 1;
        while (true) {
            $rows = ($this->fetchPage)($page, $this->pageSize);
            if ($rows === []) {
                return;                       // 数据源返回空 → 结束了
            }
            $this->pagesFetched++;
            yield from $rows;                 // 把这一页「倒」进序列
            if (count($rows) < $this->pageSize) {
                return;                       // 不满页 → 已是最后一页，少发一次空请求
            }
            $page++;
        }
    }
}
```

调用方完全看不到"页"这个概念：

```php
foreach (new OrderCursor($fetch) as $row) {   // $fetch = 按页查库/调接口
    // 处理一条订单
}
```

**使用示例**：

```php
// 数据源按页给：闭包签名是 (page, size) -> list<row>
$all    = [/* 5 条订单 ... */];
$fetch  = static fn (int $page, int $size): array => array_slice($all, ($page - 1) * $size, $size);
$cursor = new OrderCursor($fetch, 2);

// 调用方只看到一条平铺序列，看不到「页」
foreach ($cursor as $row) {
    // 处理一条订单
}
$cursor->pagesFetched;                          // 实际请求的页数

// 每次 foreach 都重新进 getIterator()，因此可反复遍历
foreach ($cursor as $row) {
    break;                                      // break 后剩下的页不再请求
}
```

实测（数据源共 5 条、每页 2 条）：

```text
--- 1) 全部遍历 ---
拿到           : SO-1,SO-2,SO-3,SO-4,SO-5
实际请求页数   : 3（5 条 / 每页 2 条 = 3 页，没有多余的空请求）

--- 2) 只要前 3 条就 break ---
实际请求页数   : 2（只拉到第 2 页 → 后续页根本没发请求）

--- 3) IteratorAggregate 可以重复遍历 ---
第一遍         : SO-1,SO-2,SO-3,SO-4,SO-5
第二遍         : SO-1,SO-2,SO-3,SO-4,SO-5
（每次 foreach 都会重新进 getIterator()，所以能反复遍历）

--- 4) 裸生成器：只能遍历一次 ---
第一遍         : SO-1,SO-2,SO-3,SO-4,SO-5
第二遍         : 抛 Exception：Cannot traverse an already closed generator
```

四行结论：

| 实测 | 含义 |
| --- | --- |
| 第 1 组 | **不满页就收尾**（`count($rows) < $pageSize`）省掉一次"明知是空"的请求 —— 这是分批拉取的常规优化 |
| 第 2 组 | **惰性是真金白银**：消费前 3 条，就只付出 2 页的代价。换成"先把全部查出来再遍历"，无论用几条都要全量 IO |
| 第 3 组 | `IteratorAggregate` 每次 `foreach` 都重新进 `getIterator()`，因此**天然可重复遍历** |
| 第 4 组 | 裸生成器**不能重复遍历** —— 这正是"返回 `IteratorAggregate` 而不是返回生成器"的理由 |

原文用 `MyIterator` 手写五方法也可以遍历，但**做不到第 2 组的效果**（`valid()`/`current()` 会先把数据备好），也做不到第 3 组的"每次遍历都是新的一次拉取"。

### 5.3 生成器真正的价值：惰性，以及能表示"算不完"的集合

生成器不是语法糖，它带来了数组给不了的能力 —— **惰性求值**：

```php
function naturals(): Generator
{
    for ($i = 1; ; $i++) {   // 无限循环，但不会爆内存
        yield $i;
    }
}

echo "取前 5 个自然数: ";
foreach (naturals() as $v) {
    if ($v > 5) {
        break;
    }
    echo $v, ' ';
}
```

实测输出：

```text
取前 5 个自然数: 1 2 3 4 5 
```

`naturals()` 是一个**无限序列**。用数组实现等价功能必然 OOM；用生成器，内存占用与"消费了几个"成正比，与"总共有几个"无关。这就是流式读取大文件、分页拉接口的底层机制。

### 5.4 生成器的两条限制，必须知道

**限制一：生成器只能遍历一次。**

```php
$nums = naturals();
foreach ($nums as $v) {
    if ($v >= 2) {
        break;
    }
}
foreach ($nums as $v) {   // 第二次
    echo $v;
}
```

实测输出：

```text
Exception: Cannot rewind a generator that was already run
```

生成器内部维护着执行位置，`rewind()` 在已经开始运行的生成器上会直接抛异常。**需要反复遍历的场合，返回数组，或者每次调用都新建生成器**（`getIterator()` 里 `yield` 恰好满足后者 —— 每次 `foreach` 都会重新进 `getIterator()`）。

⚠️ **报错消息取决于生成器的状态**，别只记住一句：

| 生成器状态 | 第二次遍历时的报错 |
| --- | --- |
| **已跑完**（正常结束） | `Cannot traverse an already closed generator` |
| **中途 `break`**（跑过但没结束） | `Cannot rewind a generator that was already run` |

上面这段是"中途 `break`"的情形；本节 5.2 实测第 4 组是"已跑完"的情形。两者都是同一个原因（位置已定，不能回退），但**用消息去搜索时会搜到不同答案**。

**限制二：`yield` 所在的函数一旦变成生成器，`return` 的语义就变了。** `return $x` 不再返回值，而是通过 `getReturn()` 读取，且必须在遍历结束之后才能取。

### 5.5 选型表

| 写法 | 何时用 |
| --- | --- |
| 直接 `foreach` 数组 | 90% 的场景，不需要任何模式 |
| `IteratorAggregate` + `yield` | 要隐藏内部结构、要惰性、要能复用遍历 |
| 手写 `Iterator` | 需要精细控制指针（如双向、可回退、树形遍历） |
| `Generator` 函数 | 数据源是流（文件、接口分页、游标） |
| `RecursiveIterator` | 树形结构，见 [../结构型/组合模式.md](../结构型/组合模式.md) |

一句话：**PHP 里"迭代器模式"的成本几乎为零，所以它的问题不是"要不要用"，而是"用哪种形态"。**

## 六、Java 实现

Java 把迭代器**内置在设计里**：`Iterable` 负责"能被遍历"，`Iterator` 负责"遍历状态"，`for-each` 只是语法糖。

```java
import java.util.Iterator;
import java.util.NoSuchElementException;

public class IteratorDemo {
    static final class NumberBucket implements Iterable<Integer> {
        private final int[] values;

        NumberBucket(int... values) { this.values = values; }

        public Iterator<Integer> iterator() {
            return new Iterator<Integer>() {
                private int cursor = 0;

                public boolean hasNext() { return cursor < values.length; }

                public Integer next() {
                    if (!hasNext()) {
                        throw new NoSuchElementException();
                    }
                    return values[cursor++];
                }
            };
        }
    }

    public static void main(String[] args) {
        for (int v : new NumberBucket(1, 2, 3)) {
            System.out.println("value: " + v);
        }

        Iterator<Integer> it = new NumberBucket(4, 5).iterator();
        while (it.hasNext()) {
            System.out.println("explicit: " + it.next());
        }
    }
}
```

**使用示例**：

```java
// for-each 走 Iterable 协议，骨架内部调 iterator()
for (int v : new NumberBucket(1, 2, 3)) {
    System.out.println("value: " + v);              // value: 1 / 2 / 3
}

// 也可显式拿游标：hasNext() + next()
Iterator<Integer> it = new NumberBucket(4, 5).iterator();
while (it.hasNext()) {
    System.out.println("explicit: " + it.next());   // explicit: 4 / 5
}
```

JDK 1.8 实测输出：

```text
value: 1
value: 2
value: 3
explicit: 4
explicit: 5
```

Java 与 PHP 的三个关键差异：

1. **协议是"两方法"，不是"五方法"**：`hasNext()` + `next()` 就够，`remove()` 是可选操作。**Java 没有 `rewind()`** —— 要重新遍历必须重新拿一个 `iterator()`。
2. **`next()` 越界抛 `NoSuchElementException`**。本机实测：第二次调用抛异常，而不是返回值。
3. **`Iterable` 与 `Iterator` 是分开的两个接口**，这正是 PHP `IteratorAggregate` / `Iterator` 的同一个思路 —— 一个容器可以反复 `iterator()` 出新游标。

## 七、Go 实现

Go 在 1.23 之前**没有迭代器接口这回事**，`for range` 只支持数组、切片、map、channel 四种内置类型。要遍历自定义容器，只能暴露 `Next()` 方法手写循环：

```go
for it := c.Iterator(); it.HasNext(); {
    v := it.Next()
}
```

Go 1.23 起引入了 **range-over-func**：`iter.Seq[V]` 与 `iter.Seq2[K, V]`，`for range` 可以直接遍历一个函数。

```go
package main

import (
	"fmt"
	"iter"
)

// Numbers 返回 iter.Seq（Go 1.23+ 的迭代器形态）：range-over-func
func Numbers(n int) iter.Seq[int] {
	return func(yield func(int) bool) {
		for i := 1; i <= n; i++ {
			if !yield(i) {
				return // 调用方 break 时 yield 返回 false
			}
		}
	}
}

// Pairs 返回 iter.Seq2，一次产出键与值
func Pairs(values []string) iter.Seq2[int, string] {
	return func(yield func(int, string) bool) {
		for i, v := range values {
			if !yield(i, v) {
				return
			}
		}
	}
}

func main() {
	for v := range Numbers(3) {
		fmt.Println("value:", v)
	}

	for k, v := range Pairs([]string{"a", "b", "c"}) {
		fmt.Printf("key %d: value %s\n", k, v)
	}

	for v := range Numbers(100) {
		if v > 2 {
			break
		}
		fmt.Println("taken:", v)
	}
}
```

**使用示例**：

```go
// 只取值：iter.Seq 可直接 for range
for v := range Numbers(3) {                   // value: 1 / 2 / 3
    fmt.Println("value:", v)
}

// 一次拿键与值：iter.Seq2
for k, v := range Pairs([]string{"a", "b", "c"}) {
    fmt.Printf("key %d: value %s\n", k, v)    // key 0: value a ...
}

// 惰性：break 后不再继续算（Numbers(100) 只算了 3 个）
for v := range Numbers(100) {
    if v > 2 { break }                        // taken: 1 / 2
    fmt.Println("taken:", v)
}
```

go1.26.5 实测输出：

```text
value: 1
value: 2
value: 3
key 0: value a
key 1: value b
key 2: value c
taken: 1
taken: 2
```

这是 Go 里与 PHP 生成器**最接近的形态**：同样是"用语言特性把迭代状态藏起来"，同样惰性（`Numbers(100)` 因为 `break` 只算了 3 个），同样不能回溯。区别在于 Go 用**回调**（`yield` 是一个函数，返回 `false` 表示停止），PHP 用**协程**（`yield` 是关键字，由引擎挂起/恢复）。

## 八、PHP / Java / Go 对照

| 维度 | PHP | Java | Go |
| --- | --- | --- | --- |
| 语言内置的迭代形态 | `foreach` + SPL `Iterator` | `Iterable` / `Iterator` + `for-each` | `for range`（1.23+ 支持函数） |
| 容器与游标是否分离 | `IteratorAggregate`（容器）vs `Iterator`（游标） | `Iterable` vs `Iterator` | `iter.Seq` 返回值本身即游标 |
| 手写迭代器的最少方法数 | 5（`rewind/current/key/next/valid`） | 2（`hasNext/next`） | 0（写一个返回 `iter.Seq` 的函数） |
| 惰性迭代的首选 | 生成器 `yield` | `Stream` / 自定义 `Iterator` | `iter.Seq` + 闭包 |
| 重新遍历 | 新建迭代器 / 每次 `getIterator()` 重新 yield | 重新 `iterator()` | 重新调用构造函数 |
| 越界行为 | `valid()` 返回 `false` | 抛 `NoSuchElementException` | `yield` 返回 `false`，循环自然结束 |

三者共通的一点：**迭代器是"一次性游标"，不是"可反复查询的视图"**。这条在三种语言里都成立，也都能通过"返回新的迭代器"来规避。

## 九、面试官会追问什么

- **PHP 里还要手写迭代器吗？** → 多数情况不用，`foreach` + 数组就够；要隐藏结构或惰性产出，用 `IteratorAggregate` + `yield`，别照抄 Java 五件套。
- **`Iterator` 和 `IteratorAggregate` 的区别？** → `Iterator` 自己就是游标，实例被遍历时状态唯一，**不能嵌套遍历**；`IteratorAggregate` 是容器，每次 `foreach` 都调 `getIterator()` 拿一个新游标，可嵌套、可重复。
- **生成器为什么只能遍历一次？** → 它是个协程，内部保存着执行位置；已经跑过的生成器 `rewind()` 会抛 `Cannot rewind a generator that was already run`（实测）。要复用就每次新建。
- **`current() !== false` 当结束判据有什么问题？** → 元素值本身是 `false` 时会**提前终止且不报错**。应该用 `key() !== null` 或 `valid()` 的独立状态判断。原文样例恰好踩了这个点。
- **为什么 `foreach` 每轮调用顺序是 valid → current → key → … → next？** → 从原文样例的输出可以直接读出来（这正是原文加 `echo` 的价值）。
- **迭代器和"一次查出 10 万行"的关系？** → 用生成器逐行/逐批产出，内存与"消费量"成正比而非"总量"；这也是 `yield` 在实际项目里最常见的用法。
- **Go 里怎么实现迭代器？** → 1.23 前靠 `HasNext/Next` 手写循环，1.23 起用 `iter.Seq` / `iter.Seq2` 配合 `for range`；`break` 通过 `yield` 返回 `false` 通知上游停止。

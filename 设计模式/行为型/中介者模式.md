## 一、中介者解决什么问题

中介者（Mediator）属于行为型模式：**用一个中介对象封装一组对象之间的交互**，让这些对象不必显式地互相引用。

它要解决的是"**交互关系爆炸**"：

| 组件数 | 两两通信需要的连线 | 用中介者后 |
| --- | --- | --- |
| 4 | 6 条（4×3÷2） | **4 条**（每个连中介者） |
| 10 | 45 条 | **10 条** |
| 20 | 190 条 | **20 条** |

连线数从 **O(N²) 降到 O(N)** —— 这就是它的全部价值。连线在代码里的表现就是"字段/依赖"：不用中介者，每个组件都要持有它需要通知的那几个组件。

| 需求 | 没有中介者时 |
| --- | --- |
| 表单里 A 变了要联动 B、C、D | 每个组件都持有另外几个，构造顺序成了难题 |
| 要调整联动关系 | 得改组件本身 |
| 要复用某个组件到另一张表单 | 它绑死了原来那几个"同伴"，挪不走 |
| 想看清"有哪些联动规则" | 规则散在 N 个组件里，得全读一遍 |

**核心手法**：把"组件之间互相通信"改成"组件都跟中介者通信"，规则集中到中介者一处。

四个角色：

| 角色 | 职责 | 本篇对应 |
| --- | --- | --- |
| Mediator | 声明"上报变化"的接口 | `Mediator::notify()` |
| ConcreteMediator | 持有所有同事，**规则的唯一实现处** | `RegistrationForm` |
| Colleague | 只持有中介者，**不认识任何其它同事** | `CountrySelect` / `ProvinceSelect` / … |
| 通知 | 同事变化时上报，中介者决定谁受影响 | `$this->mediator->notify($this, 'changed')` |

**"同事之间互不认识"是判据**：实测第 8、9 行拿反射列出组件属性，只有"自己的值 + mediator"，**没有任何别的组件**。

## 二、PHP 标准实现

场景：**注册表单的字段联动**（国家 → 省份 → 校验 → 按钮可用性）。

```php
<?php

declare(strict_types=1);

/** 中介者接口：所有同事都通过它上报变化 */
interface Mediator
{
    public function notify(Component $sender, string $event): void;
}

/** 同事基类：只持有中介者，不持有任何其它同事 */
abstract class Component
{
    protected ?Mediator $mediator = null;

    public function setMediator(Mediator $mediator): void
    {
        $this->mediator = $mediator;
    }

    /** 自己发生了变化 → 通知中介者，由它去协调别人 */
    protected function changed(): void
    {
        $this->mediator?->notify($this, 'changed');
    }
}

/** 国家下拉框 */
final class CountrySelect extends Component
{
    private string $value = '';

    /** @return list<string> */
    public function options(): array
    {
        return ['中国', '美国', '日本'];
    }

    public function select(string $value): void
    {
        if ($value === $this->value) {
            return;              // 值没变就不通知，避免无谓的联动
        }
        $this->value = $value;
        $this->changed();
    }

    public function value(): string
    {
        return $this->value;
    }
}

/** 省份下拉框：它的选项依赖国家，但自己不「认识」国家下拉框 */
final class ProvinceSelect extends Component
{
    /** @var array<string,list<string>> */
    private const MAP = [
        '中国' => ['广东', '浙江', '江苏'],
        '美国' => ['加州', '德州'],
        '日本' => ['东京都', '大阪府'],
    ];

    private string $value = '';

    /** @var list<string> */
    private array $options = [];

    /** 由中介者调用（而不是自己去问 CountrySelect） */
    public function load(string $country): void
    {
        $this->options = self::MAP[$country] ?? [];
        $this->value = '';      // 国家变了 → 之前选的省份作废
    }

    /** @return list<string> */
    public function options(): array
    {
        return $this->options;
    }

    public function select(string $value): void
    {
        if (!in_array($value, $this->options, true) || $value === $this->value) {
            return;
        }
        $this->value = $value;
        $this->changed();
    }

    public function value(): string
    {
        return $this->value;
    }
}

/** 提交按钮：能不能点，由中介者统一裁决 */
final class SubmitButton extends Component
{
    private bool $enabled = false;

    public function setEnabled(bool $enabled): void
    {
        $this->enabled = $enabled;
    }

    public function enabled(): bool
    {
        return $this->enabled;
    }
}

/** 提示文案 */
final class MessageLabel extends Component
{
    private string $text = '';

    public function show(string $text): void
    {
        $this->text = $text;
    }

    public function text(): string
    {
        return $this->text;
    }
}
```

具体中介者 —— **整个表单的联动规则只在这里出现一次**：

```php
final class RegistrationForm implements Mediator
{
    private CountrySelect $country;
    private ProvinceSelect $province;
    private SubmitButton $submit;
    private MessageLabel $message;

    /** @var list<string> */
    public array $log = [];

    public function __construct()
    {
        $this->country = new CountrySelect();
        $this->province = new ProvinceSelect();
        $this->submit = new SubmitButton();
        $this->message = new MessageLabel();

        foreach ([$this->country, $this->province] as $component) {
            $component->setMediator($this);
        }
        $this->sync();     // 初始状态也走一遍规则
    }

    public function notify(Component $sender, string $event): void
    {
        $this->log[] = sprintf('%s.%s', (new ReflectionClass($sender))->getShortName(), $event);

        if ($sender === $this->country) {
            $this->province->load($this->country->value());
        }
        $this->sync();
    }

    /** 规则汇总处 */
    private function sync(): void
    {
        if ($this->country->value() === '') {
            $this->message->show('请选择国家');
            $this->submit->setEnabled(false);

            return;
        }
        if ($this->province->value() === '') {
            $this->message->show('请选择省份（省份列表随国家变化）');
            $this->submit->setEnabled(false);

            return;
        }
        $this->message->show('(无)');
        $this->submit->setEnabled(true);
    }
}
```

**使用示例**：

```php
// 具体中介者：全部联动规则只写在它里面
$form = new RegistrationForm();

// 同事只通过 setMediator() 接入，彼此之间没有任何引用
$country = new CountrySelect();
$country->setMediator($form);
$country->select('中国');            // changed() → 上报给中介者

// 省份下拉框由中介者调 load() 填充，它自己不认识国家下拉框
$province = new ProvinceSelect();
$province->setMediator($form);
$province->load($country->value());
$province->options();                // ['广东', '浙江', '江苏']
$province->select('浙江');
$form->log;                          // ['CountrySelect.changed', 'ProvinceSelect.changed']
```

实测（PHP 8.0.2 CLI）：

```text
1_初始状态        : 省份选项=0 个 已选省份=(空) 提示=请选择国家 按钮=禁用
2_选国家「中国」  : 省份选项=广东,浙江,江苏 已选省份=(空) 提示=请选择省份（省份列表随国家变化） 按钮=禁用
3_选省份「浙江」  : 省份选项=广东,浙江,江苏 已选省份=浙江 提示=(无) 按钮=启用
4_换国家「美国」  : 省份选项=加州,德州 已选省份=(空) 提示=请选择省份（省份列表随国家变化） 按钮=禁用   ← 已选省份被作废
5_选省份「加州」  : 省份选项=加州,德州 已选省份=加州 提示=(无) 按钮=启用

6_通知日志        : CountrySelect.changed > ProvinceSelect.changed > CountrySelect.changed > ProvinceSelect.changed
7_再选一次「美国」: 通知数 4 → 4（值没变 → 组件不通知，避免联动抖动）

8_CountrySelect 的属性 : value, mediator
   → 只有自己的值 + 中介者，没有任何别的组件
9_ProvinceSelect 的属性: value, options, mediator

10_没有中介者时       : 先看它的省份选项 —— 空，它不知道该去问谁
```

四个值得看的点：

- **第 2 行**：选国家后，省份选项被换成中国的、已选省份被清空、按钮仍禁用 —— **这一串动作发生在中介者的 `notify()` 里**，`CountrySelect` 完全不知道发生了什么；
- **第 4 行是最能体现中介者价值的一行**：换国家时"作废已选省份"这条规则，如果不用中介者，就得让 `CountrySelect` 去操作 `ProvinceSelect`（`$this->province->reset()`），两个组件从此绑死；
- **第 6 行是通知链**：`CountrySelect.changed` → 中介者做联动 → `ProvinceSelect.changed` → ……**顺序就是联动顺序**；
- **第 7 行防抖动**：重复选同一个值不产生通知。没有这条，组件间会互相触发成环。

### 让它算「标准写法」的 5 个细节

| # | 做法 | 为什么 |
| --- | --- | --- |
| 1 | 同事**只持有中介者**，不持有任何其它同事 | 这就是模式本身。实测第 8、9 行的属性列表是判据 |
| 2 | 规则集中在中介者的一个方法里（`sync()`） | "有哪些联动"变成一个可以一次读完的地方 |
| 3 | **值没变不通知**（`if ($value === $this->value) return;`） | 组件互相通知极易成环；入口去重是最便宜的防环手段 |
| 4 | 构造时**注入中介者 + 走一遍初始规则** | 否则"初始状态"是各组件默认值的巧合，不是规则的结果 |
| 5 | 中介者提供**只读访问器**给外部驱动（`country()` / `province()`） | 页面/测试需要驱动组件，但不该直接操作它们的状态 |

⚠️ **第 3 条不足以防环**：真正成环时（A 变 → 触发 B 变 → 又触发 A 变）入口去重挡不住。生产代码里还需要**重入保护**（一个 `$syncing` 布尔量）或"只允许单向传播"。这也是中介者模式最容易踩的运行时问题。

## 三、边界：中介者 vs 外观

这两者最常混，因为都"把一堆对象收拢到一个入口"。区别在**方向**：

| | 中介者 | 外观（Facade） |
| --- | --- | --- |
| 交互方向 | **双向** —— 子系统（同事）**回调**中介者 | **单向** —— 外观调子系统，子系统**不知道**外观存在 |
| 子系统之间 | 通过中介者**互相影响** | 彼此可以互不认识 |
| API 形状 | 事件式（`notify(sender, event)`） | 用例式（`placeOrder()`） |
| 谁在"驱动" | 同事的变化驱动 | 调用方驱动 |
| 目的 | 收敛**组件间的交互** | 收敛**调用方的调用序列** |
| 典型 | 表单联动、聊天室、UI 控件协调 | 下单用例、支付网关、一键启动 |

**一句话判据**：**信息是"往外流"就对了** —— 同事主动上报变化 → 中介者；**只有调用方往里调** → 外观。

另一个近亲是**观察者**：

| | 中介者 | 观察者 |
| --- | --- | --- |
| 谁认识谁 | 同事只认识中介者 | 主体只认识"订阅者列表"（接口） |
| 有没有规则 | **有**：中介者知道"A 变了该影响谁" | **没有**：一律广播给所有订阅者 |
| 通知范围 | 精确（只通知受影响的） | 全部 |
| 典型 | 表单联动（只重载省份） | 事件总线 / 埋点 / 消息通知 |

**判据**：**"要不要做判断"** —— 要做判断（谁受影响、按什么顺序）就是中介者；只是"都告诉他们"就是观察者。

## 四、上帝对象：这个模式的固有风险

把所有规则收到一处，好处是"能一次读完"，坏处是**它会长成一个什么都管的类** —— 这是中介者模式被批评最多的点，也是与"上帝服务"（见 [../结构型/外观模式.md](../结构型/外观模式.md)）的同一个病。

控制手段：

| 手段 | 说明 |
| --- | --- |
| **一个中介者管一个局部** | 一张表单一个、一个页面区域一个。**不要建"全局中介者"** |
| 规则拆成小方法 | `sync()` / `validate()` / `reset()` 分开，而不是一个 300 行的 `notify()` |
| 复杂规则下沉 | 校验逻辑做成独立的 `Validator`，中介者只负责"什么时候调它" |
| 量化判据 | 外观模式那篇给了"上帝服务"的反射判据（方法体行数 × 分支数），同样适用于中介者 |

**判据**：如果中介者的 `notify()` 里出现了"SMS 网关怎么调"这类细节，说明它越界了 —— 那是 [../结构型/外观模式.md](../结构型/外观模式.md) 里说的"子系统知识泄漏"。

## 五、Java / Go 实现

### Java 实现

```java
/** 中介者接口：所有同事都通过它上报变化 */
interface Mediator {
    void notify(Component sender, String event);
}

/** 同事基类：只持有中介者，不持有任何其它同事 */
abstract static class Component {
    protected Mediator mediator;

    void setMediator(Mediator mediator) {
        this.mediator = mediator;
    }

    protected void changed() {
        if (mediator != null) {
            mediator.notify(this, "changed");
        }
    }
}

/** 具体中介者：整个表单的联动规则只在这里出现一次 */
static final class RegistrationForm implements Mediator {
    private final CountrySelect country = new CountrySelect();
    private final ProvinceSelect province = new ProvinceSelect();
    private final SubmitButton submit = new SubmitButton();
    private final MessageLabel message = new MessageLabel();

    RegistrationForm() {
        country.setMediator(this);
        province.setMediator(this);
        sync();
    }

    @Override
    public void notify(Component sender, String event) {
        log.add(sender.getClass().getSimpleName() + "." + event);
        if (sender instanceof CountrySelect) {
            province.load(((CountrySelect) sender).value());
        }
        sync();
    }
}
```

**使用示例**：

```java
// 具体中介者：全部联动规则只写在它里面
RegistrationForm form = new RegistrationForm();

// 同事只通过 setMediator() 接入，彼此之间没有任何引用
CountrySelect country = new CountrySelect();
country.setMediator(form);
country.select("中国");                      // changed() → 上报给中介者

// 省份下拉框由中介者调 load() 填充，它自己不认识国家下拉框
ProvinceSelect province = new ProvinceSelect();
province.setMediator(form);
province.load(country.value());
System.out.println(province.options());       // [广东, 浙江, 江苏]
province.select("浙江");
System.out.println(form.log);                 // [CountrySelect.changed, ProvinceSelect.changed]
```

JDK 1.8 实测输出与 PHP 版逐行一致。Java 侧的差异：

- **`sender instanceof X` 判断发送者类型**。在同事种类多时，这串 `instanceof` 会变成新的分支堆积 —— 此时可以给 `Component` 加一个 `kind()` 枚举，或让中介者按"事件名"分派；
- **JDK 9+ 可用 `Optional` / `switch` 表达更干净**，但本机 JDK 8 只能这样写；
- **GUI 框架里的 `Listener` / `EventBus` 都是中介者的变体**：`ActionListener` 把"按钮被点了"上报给中介者，中介者决定谁受影响。**Swing 的 `EventQueue` 本质上是全局中介者**，也正因此很难拆。

### Go 实现

```go
// Mediator 中介者接口：所有同事都通过它上报变化
type Mediator interface {
	Notify(sender Component, event string)
}

// Component 同事接口
type Component interface {
	SetMediator(Mediator)
}

// base 给出同事的默认实现：只持有中介者，不持有任何其它同事
type base struct {
	mediator Mediator
}

func (b *base) SetMediator(m Mediator) { b.mediator = m }

// notify 把自己变化这件事告诉中介者，由它去协调别人
func (b *base) notify(sender Component, event string) {
	if b.mediator != nil {
		b.mediator.Notify(sender, event)
	}
}

// CountrySelect 国家下拉框
type CountrySelect struct {
	base
	value string
}
```

**使用示例**：

```go
// 具体中介者：全部联动规则只写在它里面
form := NewRegistrationForm()

// 同事只通过 SetMediator() 接入，彼此之间没有任何引用
country := NewCountrySelect()
country.SetMediator(form)
country.Select("中国")     // notify() → 上报给中介者

// 省份下拉框由中介者调 Load() 填充，它自己不认识国家下拉框
province := NewProvinceSelect()
province.SetMediator(form)
province.Load(country.Value())
province.Options()         // [广东 浙江 江苏]
province.Select("浙江")
len(form.Log)              // 2
```

go1.26.5 实测输出（与 PHP/Java 一致）：

```text
1_初始状态        : 省份选项=0 个 已选省份=(空) 提示=请选择国家 按钮=禁用
...
7_再选一次「美国」: 通知数 4 → 4（值没变 → 组件不通知，避免联动抖动）

8_CountrySelect 的字段 : base（嵌入）, value
9_ProvinceSelect 的字段: base（嵌入）, value, options
```

Go 的三点差异：

- **用"内嵌 `base`"代替继承**。同事的默认实现（持有 mediator + `notify`）放在 `base` 里，各组件嵌入即可 —— 这是 Go 里复用"基类行为"的标准手法；
- **`notify` 必须把 `sender` 显式传进去**。Go 没有 `this` 的多态（内嵌的 `base` 不知道外层是谁），所以调用点是 `c.notify(c, "changed")` —— **这个"多传一个自己"的写法是 Go 里做中介者/观察者的固定套路**；
- **中介者用类型 switch 分派**：`switch sender.(type)` 或 `if c, ok := sender.(*CountrySelect); ok`。比 Java 的 `instanceof` 更啰嗦一点，但同样是显式的。

## 六、三语言对照

| | PHP | Java | Go |
| --- | --- | --- | --- |
| 同事的"基类" | `abstract class` | `abstract class` | **内嵌 `base` 结构体** |
| 找发送者 | `$sender === $this->country` | `sender instanceof X` | **类型 switch / 类型断言** |
| 传"自己" | `$this->` 自带 | `this` 自带 | **必须显式传 `sender`** |
| 同事集合 | `array` | `List` | `[]Component` |
| 通知入口去重 | 值比较 | 值比较（`equals`） | 值比较 |
| 生态代表 | Symfony Form 的事件订阅、Laravel Livewire 的联动 | Swing/AWT 的 Listener、EventBus | 前端框架式的手写协调层 |

**三语言共通**：中介者的可维护性**不取决于写法，取决于它管多大范围**。一个表单一个中介者是良性的，一个应用一个中介者必然腐化成上帝对象。

## 七、面试官会追问什么

- **中介者和外观的区别？** → 方向相反：外观是**单向**收敛调用（外观调子系统，子系统不知道外观），中介者是**双向**协调（同事会回调中介者，且同事之间通过它互相影响）。判据：**有回调**就是中介者。
- **中介者和观察者的区别？** → 观察者是**无差别广播**（所有订阅者都收到），中介者**做判断**（谁受影响、什么顺序）。前者是"都告诉他们"，后者是"我决定谁受影响"。
- **为什么说它是"多对多转一对多"？** → 不用它时有 N 个组件、最多 N(N-1)/2 条依赖边；用了它，每条边都换成"组件 → 中介者"，总数降到 N。**依赖数量从 O(N²) 到 O(N)**，这是它唯一的量化收益。
- **最大的风险是什么？** → **上帝对象**。规则集中在一处是优点也是缺点，控制手段是"一个中介者管一个局部" + 规则下沉到独立的 Validator/Service。
- **怎么防通知成环？** → 三招：入口去重（值没变不通知，本篇实测第 7 行）、重入保护（`$syncing` 标志量）、单向传播（只允许 A→B 不允许 B→A）。**只靠第一招挡不住真正的环**。
- **PHP 里哪里有？** → 表单联动（Symfony Form 的 `FormEvents`）、Livewire 的 `updated()` 钩子、各类后台管理系统的"省市联动 / 级联下拉"。它们本质都是"字段 A 变化触发一组规则"。
- **和发布订阅（消息队列）什么关系？** → 中介者是**进程内**的协调，发布订阅是**跨进程**的广播。中介者管的是"谁受我影响"，MQ 管的是"谁想听" —— 后者没有判断，更接近观察者。
- **什么时候不该用？** → 组件之间**只有单向、固定的调用关系**时（这种情况用外观或直接调用更简单）；或者联动规则很少（两三个 `if` 就能写完）时，引入中介者只是多了一层。

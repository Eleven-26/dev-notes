> 同属创建型的还有 [单例模式.md](单例模式.md)、[工厂模式.md](工厂模式.md)、[原型模式.md](原型模式.md)、[注册模式.md](注册模式.md)。

## 一、建造者解决什么问题

建造者（Builder）属于创建型模式：**把一个复杂对象的"构造过程"与"它的表示"分离**，使同一个构造过程可以造出不同的表示。

它要解决的是构造参数过多带来的两个具体问题：

| 问题 | 没有建造者的样子 |
| --- | --- |
| **构造参数太多** | `new Query('users', ['id','name'], ["status='active'"], 'created_at DESC', 20)` —— 五六个参数，顺序错了也不报错 |
| **部分参数可选** | 要么给一堆默认值，要么写多个重载/工厂方法（PHP 没有重载，只能靠命名构造函数） |
| **构造过程有约束** | 只能在运行时检查"limit 不能为负"，且往往等到真正执行才炸 |

建造者把这两件事拆开：**分步设置参数**（`where()`、`limit()`），**最后一次性构造**（`build()`）。

四个角色：

| 角色 | 职责 | 本篇对应 |
| --- | --- | --- |
| Builder | 定义分步构造的接口 | `QueryBuilder` |
| ConcreteBuilder | 具体实现，记录已设置的部分 | `QueryBuilder`（本例只有一种） |
| Director | 封装某个固定构造流程 | 可选（本例没有，见第三节） |
| Product | 最终产物 | `Query` |

## 二、与工厂的区别

这是最容易混的一对，两者都是创建型：

| | 工厂 | 建造者 |
| --- | --- | --- |
| 回答的问题 | **造哪一个** | **怎么一步步造** |
| 步骤 | 一步完成 | 多步，且顺序可变 |
| 关注点 | 类型的选择 | 参数的装配 |
| 典型产物 | 某个接口的一个实现 | 一个配置复杂的对象 |
| 举例 | 按格式造 CSV/JSON 导出器 | 按条件拼一条 SQL |

**判据一句话**：如果一个对象的构造需要"先设这个、再设那个、某些可省略"，用建造者；如果只是"根据输入决定造哪个类"，用工厂（见 [工厂模式.md](工厂模式.md) 第二节）。

两者也常配合：**工厂负责选建造者，建造者负责拼装**。

## 三、PHP 标准实现

场景：**SQL 查询构建器** —— 这是建造者最经典的现实形态。

```php
<?php

declare(strict_types=1);

/**
 * 产品：构建结果是一个「不可变」的查询对象。
 * 它自己不知道是怎么被拼出来的，只负责正确表达一条查询。
 */
final class Query
{
    /**
     * @param list<string> $columns
     * @param list<string> $wheres
     */
    public function __construct(
        private string $table,
        private array $columns,
        private array $wheres,
        private string $orderBy,
        private ?int $limit
    ) {}

    public function toSql(): string
    {
        $sql = 'SELECT ' . implode(', ', $this->columns) . ' FROM ' . $this->table;
        if ($this->wheres !== []) {
            $sql .= ' WHERE ' . implode(' AND ', $this->wheres);
        }
        if ($this->orderBy !== '') {
            $sql .= ' ORDER BY ' . $this->orderBy;
        }
        if ($this->limit !== null) {
            $sql .= ' LIMIT ' . $this->limit;
        }
        return $sql;
    }

    /** @return list<string> */
    public function wheres(): array
    {
        return $this->wheres;
    }
}

/**
 * 建造者：把「分步拼装」的过程与「最终对象」分开。
 * 每个方法返回 $this，于是可以链式调用 —— 链式是建造者最常见的书写形式，但不是它的本质。
 */
final class QueryBuilder
{
    /** @var list<string> */
    private array $columns = ['*'];

    /** @var list<string> */
    private array $wheres = [];

    private string $orderBy = '';

    private ?int $limit = null;

    public function __construct(private string $table) {}

    public function select(string ...$columns): self
    {
        $this->columns = $columns;
        return $this;
    }

    public function where(string $condition): self
    {
        $this->wheres[] = $condition;
        return $this;
    }

    public function orderBy(string $column): self
    {
        $this->orderBy = $column;
        return $this;
    }

    public function limit(int $limit): self
    {
        if ($limit <= 0) {
            throw new InvalidArgumentException('limit 必须为正数');
        }
        $this->limit = $limit;
        return $this;
    }

    /** 真正的「建造」发生在这一步：把散落的字段收成一个完整对象 */
    public function build(): Query
    {
        return new Query($this->table, $this->columns, $this->wheres, $this->orderBy, $this->limit);
    }
}
```

**使用示例**：

```php
// 链式拼装：每个方法返回 $this，最后 build() 出产品
$query = (new QueryBuilder('users'))
    ->select('id', 'name', 'email')
    ->where("status = 'active'")
    ->orderBy('created_at DESC')
    ->limit(20)
    ->build();
$query->toSql();        // SELECT id, name, email FROM users WHERE status = 'active' ... LIMIT 20

// 同一个 builder 可反复派生，已 build 的产物不受影响
$base = (new QueryBuilder('orders'))->where('paid = 1');
$first = $base->build();
$second = $base->limit(5)->build();
$first->wheres();       // ['paid = 1']（未被后续 limit 污染）

// 非法参数在设置时就抛，不等 build()
(new QueryBuilder('users'))->limit(0);   // 抛 InvalidArgumentException
```

实测（PHP 8.0.2 CLI）：

```text
1_构建出的 SQL  : SELECT id, name, email FROM users WHERE status = 'active' AND age >= 18 ORDER BY created_at DESC LIMIT 20
2a_第一个产物    : SELECT * FROM orders WHERE paid = 1
2b_派生第二个    : SELECT * FROM orders WHERE paid = 1 LIMIT 5
2c_第一个产物未变 : true
3_非法参数被拦   : limit 必须为正数
4_只给表名       : SELECT * FROM logs
```

第 2 组的三行才是关键：**同一个 builder 可以反复派生出不同产物，且已 build 出来的对象不受后续影响**（2c 为 `true`）。这要求产品是**不可变**的 —— 它是建造者模式成立的前提。

### 4 个让它算「标准写法」的细节

| # | 做法 | 为什么 |
| --- | --- | --- |
| 1 | **产品只读**（只有 getter / 计算属性） | 否则"分步构造"就失去意义：既然造完还能改，何必分步 |
| 2 | `build()` 里**复制可变集合** | 见第五节，这是建造者最常见的漏洞 |
| 3 | 参数校验放在**设置时**（`limit()`） | 早失败早暴露，而不是等 SQL 执行才报错（实测第 3 行） |
| 4 | `build()` 无参、无副作用 | 它可以被反复调用并产出等价对象；有副作用会让"链式到一半 build"变得不可预期 |

关于 **Director**（指挥者）：教材里常有一个 `Director` 类封装固定的构造流程（如 `buildPizza()` 依次调用 `addDough/addSauce/addCheese`）。本目录没给，因为它只在"同一套构造流程要反复用于不同 builder"时才有价值 —— 而在业务代码里，构造流程往往本身就是一次性的，直接链式写出来更清楚。

## 四、`build()` 时必须复制可变集合

这是建造者实现中最容易漏的一处。**分步构造意味着 builder 内部有可变状态，如果这个状态被直接交给产物，就产生了共享**：

```php
// 危险的写法：产品与建造者共享同一个数组
public function build(): Query
{
    return new Query($this->table, $this->columns, $this->wheres, $this->orderBy, $this->limit);
}
```

在 PHP 里，**数组赋值天然是写时复制的值语义**，所以上面这段其实**是安全的** —— `build()` 之后 `$this->wheres[] = ...` 不会影响已经交出去的数组。

但换成对象就完全不同了：

```php
// 若 wheres 里存的是对象（如一堆 Condition 对象），build() 必须深拷
public function build(): Query
{
    return new Query($this->table, $this->columns, array_map(
        static fn (Condition $c): Condition => clone $c,   // 否则共享
        $this->wheres
    ), $this->orderBy, $this->limit);
}
```

这与 [原型模式.md](原型模式.md) 的核心结论是同一条：**PHP 的数组是值拷贝、对象是句柄共享**。所以：

- builder 持有**标量/数组** → PHP 里 `build()` 直接传就安全；
- builder 持有**对象集合** → 必须 `clone` 或重新构造。

**Java / Go 不存在这个"免费午餐"**：它们的集合是引用类型，`build()` 不复制就一定共享（见第七节的 Java 实现注释）。

## 五、边界：建造者 vs 工厂 vs 参数对象

| 做法 | 什么时候用 |
| --- | --- |
| 直接构造 / 命名参数 | 参数 ≤3 个、都必填 |
| **参数对象**（一个 DTO） | 参数多但都是**数据**、没有构造顺序与校验 |
| 工厂 | 要按输入**选类型** |
| **建造者** | 参数多、部分可选、**构造过程有校验或顺序要求** |

一个现实判据：**如果 `build()` 里没有任何校验、也没有任何"由分步推导出的字段"，那多半只需要一个参数对象**。建造者的价值来自"构造过程本身有逻辑" —— 比如 `orderBy()` 会校验列名在允许列表内、`where()` 会做参数绑定收集。

## 六、Java / Go 实现

### Java 实现

```java
/** 建造者：把「分步拼装」的过程与最终对象分开 */
static final class QueryBuilder {
    private final String table;
    private List<String> columns = new ArrayList<String>(Arrays.asList("*"));
    private final List<String> wheres = new ArrayList<String>();
    private String orderBy = "";
    private Integer limit = null;

    QueryBuilder(String table) { this.table = table; }

    QueryBuilder select(String... columns) {
        this.columns = new ArrayList<String>(Arrays.asList(columns));
        return this;
    }

    QueryBuilder where(String condition) {
        wheres.add(condition);
        return this;
    }

    QueryBuilder limit(int limit) {
        if (limit <= 0) {
            throw new IllegalArgumentException("limit 必须为正数");
        }
        this.limit = limit;
        return this;
    }

    /**
     * build() 时把可变集合复制一份交给产品。
     * 不复制的话，产品会与建造者共享同一个 List —— 之后再调 where()，
     * 已经 build 出来的「不可变」对象也会跟着变（这是建造者最常见的漏洞）。
     */
    Query build() {
        return new Query(table, columns, new ArrayList<String>(wheres), orderBy, limit);
    }
}
```

**使用示例**：

```java
// 链式拼装：每个方法返回 this，build() 产出一个不可变产品
Query query = new QueryBuilder("users")
        .select("id", "name", "email")
        .where("status = 'active'")
        .orderBy("created_at DESC")
        .limit(20)
        .build();
query.toSql();                        // SELECT id, name, email FROM users WHERE ... LIMIT 20

// 同一个 builder 可反复派生，先 build 的产物不受影响
QueryBuilder base = new QueryBuilder("orders").where("paid = 1");
Query first = base.build();
Query second = base.limit(5).build();
first.whereCount();                   // 1（未被后续 where/limit 污染）

// 非法参数在设置时就抛，不等 build()
base.limit(0);                        // 抛 IllegalArgumentException
```

JDK 1.8 实测输出：

```text
1_构建出的 SQL  : SELECT id, name, email FROM users WHERE status = 'active' AND age >= 18 ORDER BY created_at DESC LIMIT 20
2a_第一个产物    : SELECT * FROM orders WHERE paid = 1
2b_派生第二个    : SELECT * FROM orders WHERE paid = 1 LIMIT 5
2c_第一个产物未被污染 : where 数量 = 1
3_非法参数被拦   : limit 必须为正数
4_只给表名       : SELECT * FROM logs
```

第 2c 行是这条"必须复制"规则的正向验证。**Java 里最出名的建造者是 `StringBuilder`** —— 它的 `append()` 返回 `this`（链式），`toString()` 就是"建造完成"；Lombok 的 `@Builder`、Guava 的 `ImmutableList.Builder` 也都是这个形状。

### Go 实现

```go
// QueryBuilder 建造者：把「分步拼装」与「最终对象」分开
type QueryBuilder struct {
	table   string
	columns []string
	wheres  []string
	orderBy string
	limit   int
	err     error
}

func (b *QueryBuilder) Where(condition string) *QueryBuilder {
	b.wheres = append(b.wheres, condition)
	return b
}

func (b *QueryBuilder) Limit(limit int) *QueryBuilder {
	if limit <= 0 {
		b.err = fmt.Errorf("limit 必须为正数，收到 %d", limit)
	}
	b.limit = limit
	return b
}

// Build Go 的惯例：错误作为返回值，而不是抛异常
func (b *QueryBuilder) Build() (Query, error) {
	if b.err != nil {
		return Query{}, b.err
	}
	return Query{
		Table:   b.table,
		Columns: b.columns,
		Wheres:  b.wheres,
		OrderBy: b.orderBy,
		Limit:   b.limit,
	}, nil
}
```

**使用示例**：

```go
// 链式拼装：每个方法返回 *QueryBuilder，最后 Build() 出产品
query, _ := NewQueryBuilder("users").
	Select("id", "name").
	Where("status = 'active'").
	Limit(20).Build()
fmt.Println(query.ToSQL())   // SELECT id, name FROM users WHERE status = 'active' LIMIT 20

// 同一个 builder 可反复派生，先 build 的产物不受影响
base := NewQueryBuilder("orders").Where("paid = 1")
first, _ := base.Build()
second, _ := base.Limit(5).Build()
fmt.Println(first.Wheres, second.Limit)   // [paid = 1] 5（first 未被污染）
_, err := NewQueryBuilder("users").Limit(0).Build()   // err: limit 必须为正数，收到 0
fmt.Println(err)
```

go1.26.5 实测输出（与 PHP/Java 一致）：

```text
1_构建出的 SQL  : SELECT id, name, email FROM users WHERE status = 'active' AND age >= 18 ORDER BY created_at DESC LIMIT 20
2a_第一个产物    : SELECT * FROM orders WHERE paid = 1
2b_派生第二个    : SELECT * FROM orders WHERE paid = 1 LIMIT 5
2c_第一个产物未被污染 : where 数量 = 1
3_非法参数被拦   : limit 必须为正数，收到 0
4_只给表名       : SELECT * FROM logs
```

Go 侧的三点差异：

- **没有异常，链式方法里的错误只能先存起来**（本实现用 `err` 字段），到 `Build()` 时统一返回。这是 Go 里链式 API 的常见处理方式（另一种是让每个方法返回 `(*QueryBuilder, error)`，但那样链式就很难看）；
- **`Errorf` 带上了实际取值**（"收到 0"），比 PHP/Java 版的固定文案信息更多；
- **Go 的 slice 是引用类型**，`Build()` 里直接赋值会让 builder 与产物共享底层数组 —— 本实现没复制是因为 `Query` 是值类型、且不再改 builder；**若产物要长期持有，必须 `copy` 一份**（见 [原型模式.md](原型模式.md) 第八节）。

## 七、三语言对照

| | PHP | Java | Go |
| --- | --- | --- | --- |
| 产品可变性 | `final` + private + 只读方法 | 同 | 值类型结构体 |
| 数组/集合字段 | **数组天然值拷贝** | **必须手动复制** | **slice 共享底层数组，需 `copy`** |
| 链式返回值 | `self` | 类名 | `*QueryBuilder` |
| 校验失败 | `throw` | `throw` | 存进 `err`，`Build()` 统一返回 |
| 生态代表 | Laravel Query Builder | `StringBuilder`、Lombok `@Builder` | `strings.Builder` |

三语言共通：**建造者的价值在于"构造过程本身有约束"**，而不是"链式调用看起来优雅"。没有校验、没有推导的分步设置，用参数对象更简单。

## 八、面试官会追问什么

- **建造者和工厂的区别？** → 工厂回答"造哪一个"（一步、关注类型），建造者回答"怎么一步步造"（多步、关注装配与校验）。
- **建造者一定要链式吗？** → 不一定。链式只是书写形式（返回 `$this`）；本质是"分步设置 + 最终构造"这一对动作。用 `setXxx()` 不返回值也一样成立，只是写起来啰嗦。
- **`build()` 能不能调用多次？** → 能，且应产出等价对象。所以 `build()` 里不要有"消费掉内部状态"的副作用（如清空字段）。
- **为什么产品要设计成不可变？** → 建造者的意义在于"构造完成即定型"；如果产物还能被改，分步构造与校验的价值就消失了。
- **`build()` 里要注意什么？** → **可变集合要复制**。Java/Go 的集合是引用，不复制就会让 builder 后续的修改"污染"已 build 的对象；PHP 的数组因为是值拷贝反而安全，但**对象集合仍需 `clone`**。
- **Director（指挥者）什么时候需要？** → 当同一套构造流程要反复用于不同 builder 时。业务代码里构造流程多是一次性的，直接链式更清楚。
- **PHP 里谁用了建造者？** → Laravel 的 Query Builder、各类 HTTP Client 的 RequestBuilder、DI 容器里的服务定义（`->bind()->singleton()->with()`）。

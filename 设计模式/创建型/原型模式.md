# 原型模式：PHP 的 `clone` 默认只拷一半，另一半给你埋雷

> 素材来源：博客系列 [PHP 设计模式(十)：原型模式](https://blog.csdn.net/weixin_43837229/article/details/102713189)。
> 本篇把它重写成能直接落地的版本，核心是补一条原系列一笔带过、却最容易出 bug 的事实：
> **PHP 的 `clone` 默认是"浅拷贝"，而且它对"对象属性"和"数组属性"的处理不对称——对象属性复制引用（共享），数组属性复制值（独立）。** 这个差异本篇用实跑证据摊开，并给出三种深拷贝做法及各自代价。
>
> 单例故意堵 `clone`（见 [单例模式.md](单例模式.md)），原型专门用 `clone`，两者动机相反。

## 一、原型模式在 PHP 里就是 `clone`：什么时候真值得用

原型（Prototype）属于创建型模式：不从零 `new`，而是**复制一个现成实例**得到新对象。PHP 里它对应语言内置的 `clone` 关键字 + `__clone()` 魔术方法，不需要额外框架。

值得用的典型场景：

- **对象构造昂贵**（填充了大量默认配置、建立好内部缓存/树结构），想"以某个模板为起点"快速派生。
- **要避免重复初始化**：一个配好的"基准配置对象"复制 N 份再各改各的。
- **快照 / 撤销**：改之前先 `clone` 留一份。

不该用的场景：对象几乎无状态、或构造本来就很便宜——那 `new` 更直观，`clone` 反而增加"到底共不共享"的心智负担（就是第二节的雷）。

## 二、`clone` 默认浅拷贝：对象共享引用、数组复制值（实测）

先看最反直觉的一条：`clone` 之后，**改副本里的内层对象，原对象也会变；但改副本里的数组，原数组不受影响**。因为两者拷贝语义不同。

```php
<?php

declare(strict_types=1);

final class Conn
{
    public function __construct(public string $host = '127.0.0.1') {}
}

final class Proto
{
    public Conn $conn;      // 对象属性
    public array $tags = []; // 数组属性
    public int $count = 0;   // 标量属性

    public function __construct()
    {
        $this->conn = new Conn('orig');
        $this->tags = ['a', 'b'];
    }
}

$a = new Proto();
$b = clone $a;

// 1) 对象属性：clone 后仍指向同一个 Conn
$b->conn->host = 'CHANGED';
echo 'obj_prop_shared: ', var_export($a->conn === $b->conn, true), PHP_EOL;
echo 'obj_prop_orig_host: ', $a->conn->host, PHP_EOL;

// 2) 数组属性：clone 后是各自独立的一份
$b->tags[] = 'c';
echo 'arr_count_a: ', count($a->tags), ' arr_count_b: ', count($b->tags), PHP_EOL;

// 3) 标量属性
$b->count = 99;
echo 'scalar_a: ', $a->count, ' scalar_b: ', $b->count, PHP_EOL;
```

```text
obj_prop_shared: true
obj_prop_orig_host: CHANGED
arr_count_a: 2 arr_count_b: 3
scalar_a: 0 scalar_b: 99
```

逐条读懂：

- **对象属性 `$conn`**：`clone` 只复制"指向同一个 `Conn` 的引用"，`$a->conn === $b->conn` 为 `true`。于是 `$b->conn->host = 'CHANGED'` 把 `$a` 的内层也改了——这就是浅拷贝最典型的串改事故。
- **数组属性 `$tags`**：PHP 数组是**值类型**（底层写时复制），`clone` 给它一份独立副本，`$b->tags[] = 'c'` 不影响 `$a`（`a` 仍是 2 个）。
- **标量属性**同理，独立。

一句话记忆：**`clone` 复制的是"这一层属性槽的值"。属性值若是对象，那只是复制了引用；属性值若是数组/标量，那是复制了值。** 所以浅拷贝下"嵌套对象"是共享的、"数组"是独立的——正好和很多人的直觉相反。

> 注意数组的独立性有限：如果数组里装的是**对象**（`['k' => new Foo()]`），数组本身是复制了，但里面的对象元素**仍是引用共享**，效果等同第一行的对象属性。第三节递归 `__clone` 就是来处理这种"数组里套对象"的。

## 三、深拷贝的三种做法与代价

要让副本和原对象彻底断开，得自己做深拷贝。PHP 里三种主流做法：

```php
<?php

declare(strict_types=1);

final class Wheel
{
    public function __construct(public string $model = 'A') {}
}

final class Car
{
    public Wheel $wheel;
    public function __construct() { $this->wheel = new Wheel('A'); }

    // 做法3：显式工厂 / 复制方法 —— 深拷贝最可控，性能也最好
    public function duplicate(): self
    {
        $c = new self();
        $c->wheel = new Wheel($this->wheel->model);
        return $c;
    }
}

// 基准：clone 是浅拷贝，内层对象仍共享
$a = new Car();
$shallow = clone $a;
$shallow->wheel->model = 'SHARED';
echo 'shallow_shared: ', var_export($a->wheel === $shallow->wheel, true), ' a=', $a->wheel->model, PHP_EOL;

// 做法2：序列化绕一圈 —— 一行搞定，但要求对象树可序列化
$b = new Car();
$deepS = unserialize(serialize($b));
$deepS->wheel->model = 'SER';
echo 'serialize_deep: same=', var_export($b->wheel === $deepS->wheel, true), ' b=', $b->wheel->model, PHP_EOL;

// 做法3：显式工厂 duplicate()
$c = new Car();
$deepF = $c->duplicate();
$deepF->wheel->model = 'FACT';
echo 'factory_deep: same=', var_export($c->wheel === $deepF->wheel, true), ' c=', $c->wheel->model, PHP_EOL;
```

```text
shallow_shared: true a=SHARED
serialize_deep: same=false b=A
factory_deep: same=false c=A
```

递归 `__clone()` 是"做法1"——把深拷贝逻辑挂进魔术方法，让普通 `clone` 就变深：

```php
<?php

declare(strict_types=1);

final class Item
{
    public function __construct(public int $n = 0) {}
}

final class Box
{
    public Item $item;
    /** @var Item[] */
    public array $list = [];
    public function __construct()
    {
        $this->item = new Item(1);
        $this->list[] = new Item(10);
    }
    public function __clone()
    {
        // 对象属性：手动再 clone 一层
        $this->item = clone $this->item;
        // 数组里装的对象：循环逐个 clone
        foreach ($this->list as $k => $v) {
            $this->list[$k] = clone $v;
        }
    }
}

$a = new Box();
$b = clone $a;
$b->item->n = 999;
$b->list[0]->n = 888;
echo 'clone_rec_deep: item_same=', var_export($a->item === $b->item, true),
     ' list_same=', var_export($a->list[0] === $b->list[0], true), PHP_EOL;
echo 'original_untouched: a.item.n=', $a->item->n, ' a.list[0].n=', $a->list[0]->n, PHP_EOL;
```

```text
clone_rec_deep: item_same=false list_same=false
original_untouched: a.item.n=1 a.list[0].n=10
```

三种做法选型：

| 做法 | 怎么写 | 优点 | 代价 / 不适用 |
| --- | --- | --- | --- |
| 递归 `__clone()` | 魔术方法里对每个内层对象 `clone` | 语义清晰、无序列化开销、可控 | 对象树深时要逐层处理，易漏；有循环引用会栈溢出 |
| `unserialize(serialize($o))` | 一行 | 全自动深拷贝，最省心 | **要求整棵树可序列化**：含闭包、资源句柄（`$pdo`、文件指针）会失败或丢状态；有 CPU/内存开销 |
| 显式工厂 `duplicate()` | 手写复制方法重建 | 最可控、性能最好、能顺便重置派生字段 | 每加字段要记得同步；不通用 |

实践建议：**配置/DTO 这类"纯数据"对象用序列化最省事；带句柄/闭包的核心对象用显式 `duplicate()`；既想 `clone` 语法又需部分深拷贝时用递归 `__clone()`。**

## 四、`__clone()` 里两个坑：静态属性和资源句柄

```php
<?php

declare(strict_types=1);

final class WithStatic
{
    public static int $instances = 0;
    public int $id;
    public function __construct() { $this->id = ++self::$instances; }
    public function __clone()
    {
        // 误解：想在 __clone 里给副本"发新身份"——但改的是全类共享的静态计数器
        $this->id = ++self::$instances;
    }
}

$a = new WithStatic();
$b = clone $a;
echo 'a.id=', $a->id, ' b.id=', $b->id, PHP_EOL;
// 静态属性不属于任何实例，clone 根本不复制它；++ 改的是全类那一份
echo 'static_is_shared: ', var_export(WithStatic::$instances === 2, true),
     ' (a/b 都改的是同一个计数器)', PHP_EOL;

// 资源句柄：clone 复制的是同一个 resource（底层同一个流）
$h = fopen('php://memory', 'r+');
$holder = new class($h) {
    public function __construct(public $fh) {}
};
$copy = clone $holder;
fwrite($copy->fh, "XY");
rewind($holder->fh);
echo 'resource_shared: ', var_export($holder->fh === $copy->fh, true),
     ' read=', fread($holder->fh, 10), PHP_EOL;
fclose($h);
```

```text
a.id=1 b.id=2
static_is_shared: true (a/b 都改的是同一个计数器)
resource_shared: true read=XY
```

两个坑：

1. **静态属性不会被 `clone` 复制**。静态属性属于类、不属于实例，`clone` 只复制实例属性。所以想"给副本发一个全局唯一 ID"，靠 `clone` + `__clone` 里 `++self::$instances` 能生效，恰恰是因为这个计数器是**全类共享**的——它不是"复制"出来的，而是"共享的那一个被 +1"。别指望 `clone` 帮你隔离静态状态（这一点和 [单例模式.md](单例模式.md) 第四节"静态属性跨不了请求、但在同进程内是共享的"是同一套语义）。
2. **资源句柄（`fopen` 指针、`$pdo`、socket）在 `clone` 后是同一个底层资源**。上面 `$holder->fh === $copy->fh` 为 `true`：往副本的流里 `fwrite`，从原对象的流位置能读到同一批数据。也就是说 `clone` 一个持有连接/文件句柄的对象**得到的是共享同一连接的两个壳**，几乎不是你想要的"独立副本"。深拷贝这类对象必须走**显式工厂**（重新 `fopen`/重连），或在 `__clone()` 里显式重建句柄——序列化也带不走资源（`serialize` 资源会得到 `null`/告警）。

## 五、Go / Java 对照（都已本机编译 + 运行）

Go（`go1.26.5`，`go vet` + `go run` 通过）——**Go 没有 `clone`/原型内置**，结构体赋值是"逐字段值拷贝"，但指针字段仍是别名，深拷贝必须手写：

```go
package main

import "fmt"

type Conn struct{ Host string }

type Doc struct {
	conn *Conn   // 指针：拷贝结构体只复制指针 -> 内层共享
	tags []string // 切片：共享底层数组
	n    int
}

// Go 没有内置 clone：深拷贝要手写
func (d Doc) deepCopy() Doc {
	c := Doc{n: d.n}
	if d.conn != nil {
		cc := *d.conn
		c.conn = &cc
	}
	c.tags = append([]string(nil), d.tags...)
	return c
}

func main() {
	a := Doc{conn: &Conn{Host: "orig"}, tags: []string{"x"}}
	b := a.deepCopy()
	b.conn.Host = "CHANGED"
	b.tags[0] = "y"
	fmt.Println("shallow_via_assign shares pointer; deepCopy isolates:")
	fmt.Println("a.conn.Host:", a.conn.Host, " b.conn.Host:", b.conn.Host)
	fmt.Println("a.tags[0]:", a.tags[0], " b.tags[0]:", b.tags[0])
}
```

```text
shallow_via_assign shares pointer; deepCopy isolates:
a.conn.Host: orig  b.conn.Host: CHANGED
a.tags[0]: x  b.tags[0]: y
```

> 和 PHP 的关键差异：Go 的 `[]string` 切片赋值后**共享底层数组**（改 `b.tags[0]` 会影响 `a`），所以 `deepCopy` 里必须 `append` 复制；而 PHP 的数组属性 `clone` 后**是独立的**（第二节实测）。同一件"数组/切片"，两种语言的深浅正好相反，别把经验直接搬过去。

Java（`javac 1.8.0_321` 编译 + `java` 运行）——Java 的 `Object.clone()` 同样是浅拷贝，深拷贝要么内层再 `clone` 要么手写：

```java
public class Prototype {
    static final class Conn {
        String host;
        Conn(String h) { host = h; }
    }

    static final class Doc implements Cloneable {
        Conn conn;
        int n;
        Doc(Conn c, int n) { this.conn = c; this.n = n; }

        // 浅拷贝：Object.clone 只复制字段（conn 仍是同一个引用）
        @Override
        protected Doc clone() throws CloneNotSupportedException {
            return (Doc) super.clone();
        }

        // 深拷贝：内层对象再手动 new 一份
        Doc deepClone() throws CloneNotSupportedException {
            Doc d = (Doc) super.clone();
            d.conn = new Conn(conn.host);
            return d;
        }
    }

    static void run() throws Exception {
        Doc a = new Doc(new Conn("orig"), 1);
        Doc b = a.clone();          // 浅
        b.conn.host = "CHANGED";
        System.out.println("shallow_conn_shared=" + (a.conn == b.conn) + " a.host=" + a.conn.host);

        Doc c = a.deepClone();      // 深
        c.conn.host = "DEEP";
        System.out.println("deep_conn_shared=" + (a.conn == c.conn) + " a.host=" + a.conn.host + " c.host=" + c.conn.host);
    }
}

class PrototypeDemo {
    public static void main(String[] args) throws Exception {
        Prototype.run();
    }
}
```

```text
shallow_conn_shared=true a.host=CHANGED
deep_conn_shared=false a.host=CHANGED c.host=DEEP
```

三者对照：

| | PHP | Go | Java |
| --- | --- | --- | --- |
| 内置复制 | `clone` 关键字 | 无（结构体值拷贝 + 手写） | `Object.clone()`（需实现 `Cloneable`） |
| 默认深浅 | 浅（但数组属性按值复制） | 逐字段值拷贝，引用/切片别名 | 浅（字段直接复制） |
| 深拷贝做法 | 递归 `__clone` / 序列化 / 显式工厂 | 手写 `deepCopy` / JSON 往返 | `clone` 链 / 序列化 / 拷贝构造 |
| 社区评价 | 视场景 | 无内置反而清晰 | `Cloneable` 被公认设计糟糕（《Effective Java》建议别用） |

## 面试官会追问什么

- **PHP `clone` 是深拷贝还是浅拷贝？** → 浅拷贝，且对对象属性复制引用、对数组属性复制值，两者语义不对称（第二节实测）。
- **怎么实现深拷贝？各有什么问题？** → 递归 `__clone`（要逐层处理、循环引用会栈溢出）、`unserialize(serialize())`（要求可序列化、带不走资源/闭包、有开销）、显式工厂 `duplicate()`（最可控但要手动同步字段）。
- **`__clone()` 里能改静态属性来给副本发号吗？** → 能，但那不是"复制"，静态属性全类共享，`++` 改的是同一个计数器（第四节实测）。
- **持有数据库连接的对象能 `clone` 复用吗？** → 不能得到独立副本，`clone` 后句柄是同一个底层资源；要独立连接必须重连（显式工厂）。
- **为什么 Go 切片 `deepCopy` 要 `append`，PHP 数组 `clone` 却不用？** → Go 切片赋值共享底层数组，PHP 数组是值类型（写时复制），拷贝语义相反。

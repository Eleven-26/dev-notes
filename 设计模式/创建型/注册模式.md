## 一、什么是注册模式

原文的定义：

> 注册模式（Registry）也叫做注册树模式、注册器模式。
> 注册模式**为应用中经常使用的对象创建一个中央存储器来存放这些对象** ——
> **通常通过一个只包含静态方法的抽象类来实现**（或者通过单例模式）。

应用场景原文只有一句，但很准确：

> 可以把一些常用的对象注册到注册树上，**可重复利用**。

三个角色：

| 角色 | 职责 |
| --- | --- |
| 注册表（Registry） | 中央存储器，按名字存/取对象 |
| 键（id） | 字符串标识，通常用类名或常量 |
| 值（item） | **已经构造好的对象实例** |

**最后一行是与工厂的分界线**：工厂注册的是"怎么造"，注册表注册的是"造好的东西"。这也是它最容易被误用的地方 —— 存实例意味着**对象在注册那一刻就已经被创建了**。

## 二、PHP 标准实现

原文用 `extends ArrayObject` + 全静态方法 + 内部单例。标准写法是**一个可实例化的普通类**：

```php
<?php

declare(strict_types=1);

/** 服务 ID 集中成常量，避免字符串散落各处拼错 */
final class Service
{
    public const MAILER = 'mailer';
    public const LOGGER = 'logger';
}

/** 注册表：一张按名字存取「对象」的表，取回来的是现成实例 */
final class Registry
{
    /** @var array<string, object> */
    private array $items = [];

    public function set(string $id, object $item): void
    {
        if (isset($this->items[$id])) {
            throw new LogicException("已注册，重复注册通常是 bug：{$id}");
        }
        $this->items[$id] = $item;
    }

    public function get(string $id): object
    {
        if (!isset($this->items[$id])) {
            throw new OutOfBoundsException("未注册：{$id}");
        }
        return $this->items[$id];
    }

    public function has(string $id): bool
    {
        return isset($this->items[$id]);
    }

    public function remove(string $id): void
    {
        unset($this->items[$id]);
    }
}
```

**使用示例**：

```php
// 注册表：注册的是「现成实例」，取回来就是那一个
$registry = new Registry();
$registry->set(Service::LOGGER, new Logger('app'));

$registry->get(Service::LOGGER);        // 拿回刚注册的那个实例
$registry->has(Service::LOGGER);        // true
$registry->remove(Service::LOGGER);     // 摘掉（再 get 会抛 OutOfBoundsException）

// 容器：注册的是「工厂」，第一次 get 才真正构造
$container = new Container();
$container->set(Service::LOGGER, static fn (): Logger => new Logger('from-container'));

$first = $container->get(Service::LOGGER);      // 第一次：调用工厂构造
$second = $container->get(Service::LOGGER);     // 第二次：直接返回缓存
var_dump($first === $second);                   // bool(true)
```

实测（PHP 8.0.2 CLI）：

```text
1a_取回的是同一对象   : true
1b_has 判断           : true
1c_remove 之后 has    : false
1d_取未注册项         : 未注册：logger
1e_重复注册           : 已注册，重复注册通常是 bug：mailer
```

三条设计决定值得说明：

| # | 做法 | 为什么 |
| --- | --- | --- |
| 1 | **不用 `extends ArrayObject`** | 继承一个 SPL 类只是省了几个方法名，却把整个 `ArrayObject` 的公共 API（`append`、`asort`、`exchangeArray`…）都暴露给了调用方 |
| 2 | **不用全静态方法** | 静态注册表等于全局状态，**测试之间会互相污染**，且无法在同一个进程里跑两个隔离的注册表 |
| 3 | **重复注册抛异常、取不到也抛异常** | 原文的 `get()` 取不到返回 `null`，把"键名拼错"这种错误推到了调用方，且类型上不再可空 |

## 三、注册表 vs 单例 vs 容器

这三者最容易混，判据是**管的是一个还是一组**：

| | 单例 | 注册表 | 容器 |
| --- | --- | --- | --- |
| 管什么 | **一个**类的一个实例 | **一组**对象的映射表 | 一组对象的**创建与生命周期** |
| 存的是什么 | 实例（藏在类内部） | 实例（按 key 存） | **构造方案**（闭包/类名） |
| 何时创建 | 第一次 `instance()` | 注册那一刻（**已经造好**） | 第一次 `get()`（懒） |
| 能否替换 | 不能（写死在类里） | 能（重新 set） | 能（重新绑定） |
| 典型实现 | `Config::instance()` | `Registry::set/get` | PSR-11 `ContainerInterface` |

一句话：**注册表是"已经造好的对象的储物柜"，容器是"按需生产的工厂 + 储物柜"**。

## 四、原文写法的三个问题

1. **全静态 + 内部单例＝双重全局状态**。原文的 `Registry::getInstance()` 本身就是单例，所有 `set/get` 又是静态方法 —— 结果是"一个进程内只有一张表，且谁都能改"。这在单元测试里最难受：A 测试注册的东西会漏到 B 测试。
2. **取不到返回 `null`**。调用方必须自己判空（`if ($test === null)`），而"忘记判空"正是 `null` 型 bug 的经典来源。标准做法是**抛异常**，让错误在源头暴露。
3. **`get()` 里 `!$instance->offsetExists($name)` 与 `offsetGet` 分两次查**。中间若有并发写入，可能取到不一致的结果（PHP 单请求单线程下不致命，但常驻模型下是隐患）。

## 五、容器为什么取代了注册表

现代 PHP 项目（Laravel / Symfony）几乎不再出现 `Registry`，原因是容器把注册表没解决的三件事一起解决了：

| 问题 | 注册表 | 容器 |
| --- | --- | --- |
| 对象何时创建 | 注册时就创建（**哪怕这次请求用不到**） | 第一次 `get()` 才创建 |
| 依赖怎么来 | 人工在外面造好再塞进来 | 工厂闭包里声明，甚至自动解析 |
| 可测试性 | 全局静态，测试互相污染 | 每个测试 new 一个容器 |

实测里 `2a`/`2b` 两行就是这个差别：

```text
2a_get 之前构造次数   : 0
2b_两次 get 之后次数  : 1（容器保证只造一次）
```

容器在 `get()` 之前**一次都没构造**（懒），两次 `get()` 之后也只构造了 **1 次**（缓存）。这正是原文想要的"可重复利用"，但代价更低、生命周期更清晰。

```php
final class Container
{
    /** @var array<string, object> */
    private array $resolved = [];

    /** @var array<string, Closure(self): object> */
    private array $factories = [];

    public function set(string $id, Closure $factory): void
    {
        $this->factories[$id] = $factory;
    }

    public function get(string $id): object
    {
        if (isset($this->resolved[$id])) {
            return $this->resolved[$id];
        }
        if (!isset($this->factories[$id])) {
            throw new OutOfBoundsException("未注册：{$id}");
        }
        return $this->resolved[$id] = ($this->factories[$id])($this);
    }

    public function has(string $id): bool
    {
        return isset($this->factories[$id]);
    }
}
```

**注意 `has()` 的语义差异**：注册表的 `has()` 问"表里有这个对象吗"，容器的 `has()` 问"**知道怎么造**这个东西吗"。后者在懒加载下才是正确的问法。

## 六、Java / Go 实现

### Java 实现

```java
/** 注册表：按名字存取「对象」，取回来的是现成实例 */
static final class Registry {
    private final Map<String, Object> items = new HashMap<String, Object>();

    void set(String id, Object item) {
        if (items.containsKey(id)) {
            throw new IllegalStateException("已注册，重复注册通常是 bug：" + id);
        }
        items.put(id, item);
    }

    Object get(String id) {
        if (!items.containsKey(id)) {
            throw new NoSuchElementException("未注册：" + id);
        }
        return items.get(id);
    }

    boolean has(String id) { return items.containsKey(id); }

    void remove(String id) { items.remove(id); }
}

/** 容器：注册的是工厂，用到才造，且只造一次 */
static final class Container {
    private final Map<String, Object> resolved = new HashMap<String, Object>();
    private final Map<String, Supplier<Object>> factories = new HashMap<String, Supplier<Object>>();

    void set(String id, Supplier<Object> factory) { factories.put(id, factory); }

    Object get(String id) {
        if (resolved.containsKey(id)) {
            return resolved.get(id);
        }
        Supplier<Object> factory = factories.get(id);
        if (factory == null) {
            throw new NoSuchElementException("未注册：" + id);
        }
        Object item = factory.get();
        resolved.put(id, item);
        return item;
    }
}
```

**使用示例**：

```java
// 注册表：注册的是「现成实例」
Registry registry = new Registry();
Logger logger = new Logger("app");
registry.set(Service.LOGGER, logger);

Logger got = (Logger) registry.get(Service.LOGGER);   // API 返回 Object，需强转
registry.has(Service.LOGGER);                          // true
registry.remove(Service.LOGGER);

// 容器：注册的是「工厂」
Container container = new Container();
container.set(Service.LOGGER, () -> new Logger("from-container"));

Logger first = (Logger) container.get(Service.LOGGER);    // 第一次：调用工厂
Logger second = (Logger) container.get(Service.LOGGER);   // 第二次：缓存
System.out.println(first == second);                      // true
```

JDK 1.8 实测输出与 PHP 版逐行一致：

```text
1a_取回的是同一对象   : true
1b_has 判断           : true
1c_remove 之后 has    : false
1d_取未注册项         : 未注册：logger
1e_重复注册           : 已注册，重复注册通常是 bug：mailer
2a_get 之前构造次数   : 0
2b_两次 get 之后次数  : 1（容器保证只造一次）
```

Java 侧的对应物更成熟：**Spring 的 `ApplicationContext` 就是容器**（`getBean` ≈ `get`，`@Component` ≈ 注册），而**注册表模式在 Java 社区基本被判为反模式**（与 `ServiceLocator` 同罪）—— 它让依赖变得不可见：看一个类的构造函数，你完全不知道它还需要从注册表里拿什么。

### Go 实现

```go
// Registry 注册表：按名字存取「对象」
type Registry struct {
	items map[string]any
}

func (r *Registry) Set(id string, item any) error {
	if _, ok := r.items[id]; ok {
		return errors.New("已注册，重复注册通常是 bug：" + id)
	}
	r.items[id] = item
	return nil
}

func (r *Registry) Get(id string) (any, error) {
	item, ok := r.items[id]
	if !ok {
		return nil, errors.New("未注册：" + id)
	}
	return item, nil
}

// Container 容器：注册的是「怎么造」，用到才造，且只造一次
type Container struct {
	resolved  map[string]any
	factories map[string]func() any
}

func (c *Container) Get(id string) (any, error) {
	if item, ok := c.resolved[id]; ok {
		return item, nil
	}
	factory, ok := c.factories[id]
	if !ok {
		return nil, errors.New("未注册：" + id)
	}
	item := factory()
	c.resolved[id] = item
	return item, nil
}
```

**使用示例**：

```go
// 注册表：注册的是「现成实例」
registry := NewRegistry()
_ = registry.Set(ServiceLogger, Logger{Channel: "app"})   // 重复注册返回 error

got, _ := registry.Get(ServiceLogger)                     // 返回 (any, error)
registry.Has(ServiceLogger)                               // true
registry.Remove(ServiceLogger)

// 容器：注册的是「工厂」，第一次 Get 才构造
container := NewContainer()
container.Set(ServiceLogger, func() any { return Logger{Channel: "from-container"} })

first, _ := container.Get(ServiceLogger)
second, _ := container.Get(ServiceLogger)
fmt.Println(first == second)                              // true
```

go1.26.5 实测输出（与 PHP/Java 一致）：

```text
1a_取回的是同一对象   : logger(app)
1b_has 判断           : true
1c_remove 之后 has    : false
1d_取未注册项         : 未注册：logger
1e_重复注册           : 已注册，重复注册通常是 bug：mailer
2a_get 之前构造次数   : 0
2b_两次 get 之后次数  : 1 （容器保证只造一次）
```

Go 侧的两点差异：**错误是返回值**（`(any, error)`），所以调用方天然要处理"取不到"；而且 Go 社区**强烈反对注册表/全局容器**，标准做法是**在 `main()` 里显式构造依赖并层层传递**（`wire`、`fx` 这类工具也是把依赖图写成代码），理由与 Java 一致：依赖要看得见。

## 七、三语言对照

| | PHP | Java | Go |
| --- | --- | --- | --- |
| 注册表落点 | 静态类（原文）→ 可实例化类（标准） | `ServiceLocator`（已判反模式） | 基本不用 |
| 容器的官方代表 | PSR-11 `ContainerInterface` | Spring `ApplicationContext` | 手写装配 / `wire` |
| 取不到时 | `throw` | `throw` | 返回 `error` |
| 社区态度 | 容器取代注册表 | 容器取代 `ServiceLocator` | **显式传参**取代全局表 |

三语言共同的结论：**注册表模式的现代形态是"容器"，而容器的现代用法是"依赖注入"而不是"到处 `get`"**。区别就在一句话 —— **依赖应该出现在构造函数里，而不是藏在某个全局表里**。

## 八、面试官会追问什么

- **注册模式、单例、容器的区别？** → 单例管一个实例，注册表管一组"已造好的对象"，容器管一组对象的"创建 + 生命周期"（懒加载）。
- **为什么现在很少见 `Registry`？** → 容器能懒加载、能声明依赖、每个测试可以 new 一个；注册表是全局静态状态，测试互相污染，且依赖不可见。
- **`has()` 在注册表和容器里语义一样吗？** → 不一样。注册表问"有对象吗"，容器问"知道怎么造吗"。
- **注册表存实例和存工厂有什么区别？** → 存实例意味着**注册那一刻对象就被造出来了**，哪怕这次请求用不到；存工厂才能懒加载（实测 `get()` 前构造次数为 0）。
- **Service Locator 为什么被认为是反模式？** → 它把依赖从"构造函数签名"挪到了"运行时查找"，看代码看不出依赖关系，替换与测试都变难。与 [工厂模式.md](工厂模式.md) 第五节"什么时候不需要工厂"是同一个判断。
- **常驻模型（Swoole）下用注册表要注意什么？** → 表会跨请求存活，存的又是实例，极易把请求级数据（当前用户、租户）带进下一个请求，与 [单例模式.md](单例模式.md) 第五节的串号风险同源。

## 一、什么是单例模式

原文的定义：

> 作为对象的创建模式，单例模式确保某一个类**只有一个实例**，并且对外提供这个全局实例的**访问入口**。
> 它不会创建实例副本，而是会向单例类内部存储的实例返回一个引用。

原文总结的三个特点，也就是常说的**「四私一公」**：

> 1. 需要一个**保存类的唯一实例的静态成员变量**；
> 2. **构造函数、重建函数和克隆函数必须声明为私有的**，防止外部程序创建或复制实例副本；
> 3. 必须提供一个**访问这个实例的公共静态方法**，从而返回唯一实例的一个引用。
>
> 简称四私一公（三个私有方法、一个私有属性和一个公共方法）。

拆成表格：

| # | 约束 | 实现手段 | 不做的后果 |
| --- | --- | --- | --- |
| 1 | 不许外部 `new` | `private function __construct()` | 谁都能 `new`，实例数不受控 |
| 2 | 不许复制 | `private function __clone()` | `clone` 绕过静态属性，造出第二个 |
| 3 | 不许反序列化 | `__wakeup()` 里抛异常 | 反序列化不走构造函数，只写私有构造挡不住 |
| 4 | 有全局访问点 | `public static function instance()` | 实例无法在模块间共享 |
| 5 | 唯一实例存放在类内部 | `private static ?self $instance` | 没有"唯一性"的载体 |

第 2、3 条最容易被忽略，第四节的实测就是针对它们。**注意第 3 条的写法**：原文写的是 `private function __wakeup(){}`，这在 PHP 8 下既会告警、又挡不住反序列化 —— 详见 3.3 与第四节。

## 二、应用场景

原文用数据库操作说明"为什么需要单例"，这段话值得原样留着：

> 使用单例模式的好处很大，以数据库操作为例。若不采用单例模式，当程序中出现大量数据库操作时，
> 每次都要执行 new 操作，每次都会消耗大量的内存资源和系统资源，
> 而且**每次打开和关闭数据库连接都是对数据库的一种极大考验和浪费**。
> 使用了单例模式，只需要实例化一次，不需要每次都执行 new 操作，极大降低了资源的耗费。

这段话在**常驻进程**（Java / Go / Swoole）里完全成立。但在 php-fpm 下有个前提变了：**每个请求结束后用户态内存都会被回收**，"只实例化一次"指的是**一次请求内**（第五节展开）。

按现代工程视角，真正该用"全局唯一"的只有这几类：

| 适合 | 说明 |
| --- | --- |
| 连接 / 客户端对象 | 数据库连接池、Redis 客户端、HTTP 客户端 —— 建一次很贵 |
| 配置 | 全进程一份只读配置 |
| 无状态工具类 | 日志、事件派发器 |

**不适合**：任何带请求级状态的对象（用户上下文、当前租户）—— 那会变成串数据的根源。

## 三、PHP 标准实现

### 3.1 形态一：类自己管单例

这是博客原文的路线，规范化之后是这样：

```php
<?php

declare(strict_types=1);

final class Config
{
    private static ?self $instance = null;

    /** @var array<string,string> */
    private array $values = [];

    private function __construct() {}

    public static function instance(): self
    {
        return self::$instance ??= new self();
    }

    public function get(string $key, ?string $default = null): ?string
    {
        return $this->values[$key] ?? $default;
    }

    public function set(string $key, string $value): void
    {
        $this->values[$key] = $value;
    }

    /** 堵住 clone：可见性必须是 private */
    private function __clone() {}

    /** 堵住反序列化：注意必须是 public，否则 PHP 8 会报可见性告警且挡不住 */
    public function __wakeup(): void
    {
        throw new LogicException('单例不允许反序列化');
    }
}
```

### 3.2 形态二：交给容器（推荐）

同样是"全局唯一"，但**唯一性由容器保证，类保持普通**：

```php
final class Logger
{
    public function __construct(private string $channel) {}

    public function log(string $message): string
    {
        return "[{$this->channel}] {$message}";
    }
}

final class Container
{
    /** @var array<string, object> */
    private array $instances = [];

    /** @var array<string, Closure(self): object> */
    private array $factories = [];

    public function singleton(string $id, Closure $factory): void
    {
        $this->factories[$id] = $factory;
    }

    public function get(string $id): object
    {
        if (isset($this->instances[$id])) {
            return $this->instances[$id];
        }
        if (!isset($this->factories[$id])) {
            throw new RuntimeException("未注册的服务：{$id}");
        }
        return $this->instances[$id] = ($this->factories[$id])($this);
    }
}
```

**使用示例**：

```php
// 形态一：类自己管单例 —— 两次拿到同一对象，状态共享
$config = Config::instance();
$config->set('env', 'prod');
Config::instance()->get('env');        // 'prod'（是同一个实例）

// 两条后门都已被堵住
clone $config;                         // Error: Call to private Config::__clone()
unserialize(serialize($config));       // 抛 LogicException（__wakeup 里抛）

// 形态二：交给容器 —— 同一 id 只造一次，Logger 自己仍是普通类
$container = new Container();
$container->singleton('logger', static fn (): Logger => new Logger('app'));
$container->get('logger') === $container->get('logger');   // true
new Logger('test')->log('hello');                          // [test] hello（可自由实例化，便于测试）
```

两段代码的实测输出：

```text
1_两次 instance 是同一对象 : true
2_状态共享                 : prod
3_clone 被拦住            : Error - Call to private Config::__clone() from global scope
4_反序列化被拦住          : LogicException - 单例不允许反序列化
5_容器两次 get 同一实例   : true
6_普通类可自由实例化(可测) : [test] hello
```

**第 5 行与第 6 行合起来才是重点**：容器保证了"同一 id 只创建一次"，但 `Logger` 自己**没有被写死成单例** —— 测试时可以直接 `new Logger('test')` 造一个替身。而形态一的 `Config` 做不到这一点：测什么都得先 `Config::instance()`，且它带着全局状态。

### 4 个让它算「标准写法」的细节

| # | 做法 | 为什么 |
| --- | --- | --- |
| 1 | `final class` + `private __construct` 一起用 | 少了 `final`，子类 `extends` 后静态属性会被共享，语义错乱 |
| 2 | `self::$instance ??= new self()` | PHP 7.4+ 可用，天然幂等；但**没有并发保护**（PHP 单请求单线程，够用；Swoole 协程下要加锁） |
| 3 | `__clone()` 私有、`__wakeup()` **必须是 public** | PHP 8 会对非 public 的魔术方法报 `Warning: The magic method ... must have public visibility` |
| 4 | 静态属性用 `?self` 而非 `self` | 可空类型让"尚未创建"这个状态在类型系统里显式存在 |

## 四、三条约束必须都堵住（实测）

`private __construct` 只挡得住 `new`。另外两条路要单独堵：

**clone** 被私有 `__clone` 挡住，但抛的是 `Error`（致命错误）而不是异常：

```text
3_clone 被拦住 : Error - Call to private Config::__clone() from global scope
```

业务代码写 `catch (Exception $e)` **抓不到它**，必须用 `Throwable`。

**反序列化**则绕得更彻底 —— 它**不经过构造函数**，只触发 `__wakeup()`（PHP 7.4+ 还可用 `__unserialize()`）。所以"只写私有构造"是挡不住的：

```text
4_反序列化被拦住 : LogicException - 单例不允许反序列化
```

这一条在真实项目里的意义远不止"挡单例"：PHP 的反序列化 POP 链（`unserialize` → `__wakeup` / `__destruct` 魔术方法串联）就是靠这些入口打进去的，能把任意类实例化出来。**在 `__wakeup` 里抛异常是最直接的堵法。**

> 顺带说清原文的两个坑，都在本机实测过：
> 1. `private function __wakeup(){}` 在 PHP 8.0.2 下报 `Warning: The magic method Config::__wakeup() must have public visibility`；
> 2. 更严重的是，**它挡不住反序列化** —— 空实现的 `__wakeup` 什么都不做，`unserialize(serialize($obj))` 实测造出了第二个实例（`is_same_object: false`）。**可见性写错 + 空实现 = 完全没防**。

## 五、PHP 的单例只「单」一次请求

这是 PHP 与 Java/Go 差别最大的一点，也是原文写于 2019 年时没有展开的部分。

PHP 是 **shared-nothing** 模型：php-fpm 每个请求结束后，Zend 会回收用户态内存，静态属性随之消失。

| 运行模型 | `instance()` 的作用域 | 想跨请求复用怎么办 |
| --- | --- | --- |
| php-fpm（传统 PHP） | **单个请求内**唯一 | 静态属性无效；只能靠连接持久化或换模型 |
| Swoole / RoadRunner / FrankenPHP 常驻 | **整个进程生命周期**内唯一 | 天然复用，但**必须考虑协程隔离与多进程不共享** |
| CLI 脚本 | 单次进程运行 | 同常驻 |

这条直接改变了"单例有什么用"的答案：

- **在 php-fpm 下**，单例省的不是"每次请求的连接开销"（连接本来就随请求销毁），而是"同一请求内重复 new 同一个东西"；
- **在常驻模型下**，单例才真的省连接，代价是**它变成跨请求共享状态** —— 里面存了用户态数据就会串号。这与 [../行为型/观察者模式.md](../行为型/观察者模式.md) 第三节的"注册表跨请求"是同一件事，与 [../结构型/代理模式.md](../结构型/代理模式.md) 的缓存代理也是同一件事。

## 六、Java 实现

Java 里最标准的单例写法不是双检锁，而是**枚举**（《Effective Java》的结论）：JVM 保证唯一，且天然防反射、防反序列化。

```java
public class SingletonStandard {

    /** 枚举单例：JVM 保证唯一，且天然防反射、防反序列化 */
    enum Config {
        INSTANCE;

        private final java.util.Map<String, String> values = new java.util.HashMap<String, String>();

        void set(String key, String value) { values.put(key, value); }

        String get(String key) { return values.get(key); }
    }

    /** 类自己管单例：双检锁写法，需要 volatile 防指令重排 */
    static final class Registry {
        private static volatile Registry instance;

        private Registry() {}

        static Registry instance() {
            if (instance == null) {
                synchronized (Registry.class) {
                    if (instance == null) {
                        instance = new Registry();
                    }
                }
            }
            return instance;
        }
    }
}
```

**使用示例**：

```java
// 枚举单例：两次拿到同一实例，状态共享
Config.INSTANCE.set("env", "prod");
Config.INSTANCE.get("env");            // "prod"

// 反射也造不出第二个 —— 枚举的天然保护
java.lang.reflect.Constructor<Config> c =
        Config.class.getDeclaredConstructor(String.class, int.class);
c.setAccessible(true);
c.newInstance("X", 1);                 // 抛 IllegalArgumentException

// 类自己管单例：双检锁 + volatile，延迟初始化
Registry.instance() == Registry.instance();   // true
```

JDK 1.8 实测输出：

```text
1_枚举两次拿到同一实例 : true
2_状态共享             : env=prod
3_反射创建枚举被拒     : IllegalArgumentException - Cannot reflectively create enum objects
4_双检锁两次同实例     : true
```

**第 3 行是 Java 独有的收获**：枚举单例连反射都造不出第二个（`Cannot reflectively create enum objects`），而普通类的私有构造在 Java 里是可以被 `setAccessible(true)` 绕过的。这是枚举写法被推荐的根本原因。

三种 Java 写法的取舍：

| 写法 | 并发安全 | 防反射 | 适用 |
| --- | --- | --- | --- |
| 饿汉（`static final` 字段） | ✅ | ❌ | 初始化成本低 |
| 双检锁 | ✅（需 `volatile`） | ❌ | 需要延迟初始化 |
| **枚举** | ✅ | ✅ | **首选**（除非要继承别的类） |

## 七、Go 实现

Go 的标准写法是 `sync.Once`：

```go
var (
	configOnce     sync.Once
	configInstance *Config
)

// GetConfig 标准单例：sync.Once 保证并发下也只执行一次初始化
func GetConfig() *Config {
	configOnce.Do(func() {
		configInstance = &Config{values: map[string]string{}}
	})
	return configInstance
}
```

**使用示例**：

```go
// 两次调用拿回同一个指针 —— sync.Once 保证只初始化一次
cfg := GetConfig()
fmt.Println(cfg == GetConfig())        // true

// 状态共享：一处写入，处处可见
cfg.Set("env", "prod")
fmt.Println(GetConfig().Get("env"))    // prod

// 并发下也只初始化一次：100 个协程拿到的是同一个实例
var wg sync.WaitGroup
for i := 0; i < 100; i++ {
	wg.Add(1)
	go func() { defer wg.Done(); _ = GetConfig() }()
}
wg.Wait()
```

go1.26.5 实测输出：

```text
1_两次拿到同一实例 : true
2_状态共享         : env = prod
3_100 个协程拿到 1 个不同实例
```

**第 3 行是 `sync.Once` 相对"手写 `if instance == nil`"的全部价值**：100 个协程并发调用，拿到的永远是同一个实例（手写判断在并发下会创建多个，且 `go vet` 会警告）。

不过要说明：**Go 社区其实不太用单例**。更地道的做法是在 `main()` 里显式创建依赖并层层传递（依赖注入），只在真正全局的东西（如默认 logger）上才用 `sync.Once` 或包级变量。这与 3.2 节"交给容器"是同一个思路。

## 八、PHP / Java / Go 对照

| | PHP | Java | Go |
| --- | --- | --- | --- |
| 推荐写法 | **交给容器 `singleton()`** | **枚举单例** | **`sync.Once`**，或干脆显式传递依赖 |
| 类自管时的唯一性载体 | `private static ?self` | `static volatile` 字段 | 包级变量 |
| 防 `clone` | `private __clone()` | 无此语法（`final` + 私有构造） | 无此语法（值类型/指针语义） |
| 防反序列化 | `__wakeup` 抛异常 | 枚举天然防；普通类需 `readResolve()` | 无序列化机制 |
| 防反射 | 无（`ReflectionClass` 可绕过） | 枚举天然防 | 无 |
| 生命周期 | **一次请求**（php-fpm） | JVM 全程 | 进程全程 |
| 并发安全 | 单请求单线程，天然安全 | 需 `volatile` + 双检锁 | 需 `sync.Once` |

最后两行是核心差异：**PHP 靠"进程用完即弃"免掉了并发问题，代价是状态活不过一次请求；Java/Go 状态活得久，代价是必须自己处理并发与内存。**

## 九、面试官会追问什么

- **单例模式有什么缺点？** → 隐式全局状态、单元测试难（没法替换替身）、隐藏依赖（看构造函数看不出来它依赖什么）。现代 PHP 的做法是把"唯一性"交给容器，类保持普通。
- **`private __construct` 就够了吗？** → 不够。`clone` 和反序列化是两条后门：前者抛 `Error`（`catch (Exception)` 抓不到），后者**不经过构造函数**、只触发 `__wakeup`。
- **`__wakeup` 写成 private 会怎样？** → PHP 8 下报可见性告警，且**空实现挡不住反序列化**（实测 `is_same_object: false`）。必须 public，且里面要真抛异常。
- **PHP 的单例能省数据库连接吗？** → 在 php-fpm 下**不能**：连接与实例都随请求销毁，省的是"同请求内重复 new"。要真省连接得靠常驻模型（Swoole）或连接池。
- **常驻模型下用单例要注意什么？** → 它变成跨请求共享状态：注册、初始化只做一次，且**绝不能存用户态数据**（会串号）。
- **Java 为什么推荐枚举单例？** → JVM 保证唯一，且防反射（`Cannot reflectively create enum objects`）与防反序列化，普通类做不到。
- **Go 里怎么写单例？** → `sync.Once` + 包级变量；但更地道的做法是依赖注入，单例只留给真正全局的对象。
- **怎么让单例可测试？** → 不要用 `Class::instance()` 直接拿实例，而是把实例**注入**进来；如果一定要单例，把"唯一性"挪到容器层（3.2）。

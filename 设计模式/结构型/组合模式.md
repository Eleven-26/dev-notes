# 组合模式：Part-Whole 树，PHP 里的递归正解是实现 RecursiveIterator

> 素材来源：博客系列 [PHP 设计模式(十三)：组合模式](https://blog.csdn.net/weixin_43837229/article/details/102985306)。
> 本篇重写版补齐原文没讲透的四件事：**用 `RecursiveIterator` 让树"可迭代"的正规姿势（附先序/后序打印顺序实测）、叶子与组件要不要拆两个类（透明性 vs 安全性）、成环的真实后果（实测内存耗尽）与修复、目录式缓存失效的版本链算法**。

## 一、什么时候才真的需要组合模式

组合（Composite，结构型模式）：把对象组成**树**来表达 Part-Whole 层级，让客户端**统一对待"单个对象"和"对象组合"**——叶子和容器实现同一接口，调用方不写 `instanceof`。三个真实场景，判据都是"行为要沿树传播"：

| 场景 | 统一对待的是什么 | 传播的行为 |
| --- | --- | --- |
| 权限菜单 | 目录节点和动作节点都是 `Node` | 渲染/遍历整棵树（第二节实测） |
| 目录式缓存失效 | 任意层级的路径节点 | 版本链沿祖先/后代传播（第五节实测） |
| 评论树 | 顶层评论和回复 | 折叠、计数、删除级联 |

只需要平铺列表 + `parent_id`、没有"对整棵树干活"的需求时，别建组合树。实测均用 `D:\phpstudy_pro\Extensions\php\php8.0.2nts\php.exe`，下同。

## 二、最小实现：组合类实现 RecursiveIterator，遍历顺序实测

手写 `walk()` 递归是新手做法；PHP 让树"可迭代"的正道是组合类实现 `RecursiveIterator`，递归遍历交给标准库 `RecursiveIteratorIterator`——先序/后序变成构造参数，树本身零改动：

```php
<?php
declare(strict_types=1);

interface Node { public function label(): string; }

final class Item implements Node
{
    public function __construct(private string $name) {}
    public function label(): string { return $this->name; }
}

// 组合：本身是 Node，同时实现 RecursiveIterator 来迭代自己的孩子
final class Group implements Node, RecursiveIterator
{
    /** @var Node[] */ private array $children = [];
    private int $pos = 0;
    public function __construct(private string $name) {}
    public function add(Node $n): void { $this->children[] = $n; }
    public function label(): string { return $this->name; }
    public function current(): Node { return $this->children[$this->pos]; }
    public function key(): int { return $this->pos; }
    public function next(): void { $this->pos++; }
    public function rewind(): void { $this->pos = 0; }
    public function valid(): bool { return $this->pos < count($this->children); }
    public function hasChildren(): bool { return $this->current() instanceof self; }
    public function getChildren(): ?RecursiveIterator { $c = $this->current(); return $c instanceof self ? $c : null; }
}

// 森林入口：让"根节点自己"也进入遍历（普通 ArrayIterator 不下钻，必须包成 Recursive）
final class Forest extends ArrayIterator implements RecursiveIterator
{
    public function hasChildren(): bool { return $this->current() instanceof Group; }
    public function getChildren(): ?RecursiveIterator { $c = $this->current(); return $c instanceof Group ? $c : null; }
}

// 权限菜单：系统设置 > (仪表盘, 用户管理[列表/导出], 角色管理[列表])
$root = new Group('系统设置'); $root->add(new Item('仪表盘'));
$user = new Group('用户管理'); $user->add(new Item('列表')); $user->add(new Item('导出'));
$root->add($user);
$role = new Group('角色管理'); $role->add(new Item('列表'));
$root->add($role);

foreach ([RecursiveIteratorIterator::SELF_FIRST => '先序(进子树前)', RecursiveIteratorIterator::CHILD_FIRST => '后序(出子树后)'] as $mode => $name) {
    $seq = [];
    foreach (new RecursiveIteratorIterator(new Forest([$root]), $mode) as $node) { $seq[] = $node->label(); }
    echo $name, ': ', implode(' -> ', $seq), PHP_EOL;
}
```

```text
先序(进子树前): 系统设置 -> 仪表盘 -> 用户管理 -> 列表 -> 导出 -> 角色管理 -> 列表
后序(出子树后): 仪表盘 -> 列表 -> 导出 -> 用户管理 -> 列表 -> 角色管理 -> 系统设置
```

读两条：**先序 SELF_FIRST**（进子树前先碰父）用于渲染面包屑、授权向下传播；**后序 CHILD_FIRST**（出子树后才碰父）用于自底向上聚合——删除级联、目录大小汇总必须后序，否则父节点聚合时孩子还没算完（默认模式 LEAVES_ONLY 只吐叶子，对应"只要动作不要目录"的权限点列表）。`Forest` 那层包装不能省：`RecursiveIteratorIterator` 只下钻 `RecursiveIterator`，普通迭代器里的组合节点会被当成叶子。

## 三、叶子和组件要不要分成两个类：透明性 vs 安全性

```php
<?php
declare(strict_types=1);

// —— 透明性：add() 提升到组件接口，叶子也有 add()，实现为抛异常 ——
interface Component { public function add(self $child): void; }
final class LeafC implements Component { public function add(Component $child): void { throw new LogicException('叶子节点不支持 add()'); } }
final class GroupC implements Component { /** @var Component[] */ private array $children = []; public function add(Component $child): void { $this->children[] = $child; } }

$g = new GroupC(); $g->add(new LeafC());
echo "transparent group.add: ok\n";
try { (new LeafC())->add(new LeafC()); } catch (Throwable $e) { echo 'transparent leaf.add: ', get_class($e), ': ', $e->getMessage(), "\n"; }

// —— 安全性：接口不含 add()，add() 只存在于组合类 ——
interface SafeNode {}
final class LeafS implements SafeNode {}
final class GroupS implements SafeNode { /** @var SafeNode[] */ private array $children = []; public function add(SafeNode $child): void { $this->children[] = $child; } }

$nodes = [new LeafS(), new GroupS()];
try { foreach ($nodes as $n) { $n->add(new LeafS()); } } catch (Throwable $e) { echo 'safe uniform call: ', get_class($e), ': ', $e->getMessage(), "\n"; }

$accepted = 0;
foreach ($nodes as $n) { if ($n instanceof GroupS) { $n->add(new LeafS()); $accepted++; } }
echo 'safe instanceof-guarded: add accepted on ', $accepted, '/', count($nodes), " nodes\n";
```

```text
transparent group.add: ok
transparent leaf.add: LogicException: 叶子节点不支持 add()
safe uniform call: Error: Call to undefined method LeafS::add()
safe instanceof-guarded: add accepted on 1/2 nodes
```

透明性让客户端保持多态（对 `Node[]` 统一调 `add()`——"统一对待叶子和容器"这个卖点才成立），代价是叶子背着永远抛异常的方法；安全性接口干净，但第三、四行实测就是代价现场：**统一调用直接 `Error`，退而求其次到处 `instanceof`，多态失效，组合模式被自己拆掉**。PHP 没有编译期检查，`instanceof` 分支的腐蚀成本比 Java/C# 更高，所以 **PHP 推荐透明性 + 叶子抛 `LogicException`**（对照 [六大原则.md](../原则/六大原则.md) 第三节，这也是一种 LSP 违约，两害相权取其轻）。

## 四、防环：同一节点被挂两次，实测内存耗尽

树允许共享节点引用，一旦某祖先被挂成自己后代的 child，朴素递归就停不下来。先复现（下面是标注"接上文"的片段，脚本会跳过；输出来自同一代码在本机临时文件的手工运行）：

```php
<?php
// 接上文：Node/Item/Group 与第二节相同，仅给 Group 另加一个 children() 只读访问器
declare(strict_types=1);

$root = new Group('根'); $a = new Group('目录A'); $a->add(new Item('文件1'));
$root->add($a);
$a->add($root); // 环：祖先被挂成自己的孩子

function naive(Node $n): array
{
    $out = [$n->label()];
    if ($n instanceof Group) { foreach ($n->children() as $c) { $out = array_merge($out, naive($c)); } }
    return $out;
}

echo count(naive($root)), PHP_EOL;
```

```text
Fatal error: Allowed memory size of 268435456 bytes exhausted (tried to allocate 20480 bytes) in C:\Users\Administrator\AppData\Local\Temp\dpw\c3a.php on line 33
```

退出码 255；手工运行用的是含全部类定义的完整版脚本（上面截的是主干），`line 33` 即完整版里 `naive($c)` 那一行，换机器路径行号会变、消息主体逐字一致。注意不是"卡住的死循环"而是**递归栈 + 不断 array_merge 的数组把 256M 内存吃光直接 Fatal**。修复：`spl_object_id` 记录**当前路径上已访问的节点**（"路径集"而非"全局 visited"，否则无环树里合法的共享节点会误报）：

```php
<?php
declare(strict_types=1);

interface Node { public function label(): string; }
final class Item implements Node { public function __construct(private string $name) {} public function label(): string { return $this->name; } }
final class Group implements Node
{
    /** @var Node[] */ private array $children = [];
    public function __construct(private string $name) {}
    public function add(Node $n): void { $this->children[] = $n; }
    public function label(): string { return $this->name; }
    public function children(): array { return $this->children; }
}

function safeWalk(Node $n, array $path = []): array
{
    $id = spl_object_id($n);
    if (isset($path[$id])) { throw new RuntimeException('检测到环: ' . implode(' -> ', $path) . ' -> ' . $n->label()); }
    $path[$id] = $n->label();
    $out = [$n->label()];
    if ($n instanceof Group) { foreach ($n->children() as $c) { $out = array_merge($out, safeWalk($c, $path)); } }
    return $out;
}

$root = new Group('根'); $a = new Group('目录A'); $a->add(new Item('文件1'));
$root->add($a); $root->add(new Item('文件2'));
$badRoot = new Group('根'); $badA = new Group('目录A'); $badA->add(new Item('文件1'));
$badRoot->add($badA); $badA->add($badRoot); // 同一对象既是祖先又是后代

echo 'good tree: ', implode(' / ', safeWalk($root)), "\n";
try { safeWalk($badRoot); } catch (Throwable $e) { echo 'cyclic tree: ', get_class($e), ': ', $e->getMessage(), "\n"; }
```

```text
good tree: 根 / 目录A / 文件1 / 文件2
cyclic tree: RuntimeException: 检测到环: 根 -> 目录A -> 根
```

更根本的一招在**挂载入口**防：`add()` 里发现 `$child === $this` 或 `$this` 在 `$child` 子树里就抛异常，别让坏树进遍历。

## 五、真实场景两则：目录式缓存失效与评论树

**缓存失效**：朴素做法是失效一个目录就扫全部子 key；正解是**节点的缓存键 = 自己 + 全部祖先的版本号拼接**，失效任意节点只 bump 它自己那一个版本号，O(深度) 完成，整棵子树的键自动变化，兄弟不受波及：

```php
<?php
declare(strict_types=1);

final class VersionTree
{
    /** @var array<string,int> */ private array $v = [];
    public function invalidate(string $p): void { $this->v[$p] = ($this->v[$p] ?? 1) + 1; }
    public function cacheKey(string $p): string
    {
        $parts = explode('/', trim($p, '/')); $vs = [];
        for ($i = count($parts); $i > 0; $i--) { $vs[] = $this->v['/' . implode('/', array_slice($parts, 0, $i))] ?? 1; } // 版本链：子在前、父在后
        return 'page:' . $p . ':v' . implode('.', $vs);
    }
}

$c = new VersionTree();
echo 'menu1  ', $c->cacheKey('/site/nav/menu1'), PHP_EOL;
echo 'footer ', $c->cacheKey('/site/footer'), PHP_EOL;
$c->invalidate('/site/nav');
echo 'menu1  ', $c->cacheKey('/site/nav/menu1'), PHP_EOL;
echo 'footer ', $c->cacheKey('/site/footer'), PHP_EOL;
```

```text
menu1  page:/site/nav/menu1:v1.1.1
footer page:/site/footer:v1.1
menu1  page:/site/nav/menu1:v1.2.1
footer page:/site/footer:v1.1
```

`menu1` 自己从没被 invalidate 过，但版本链第二位（祖先 `nav`）1→2，键随之变化；`footer` 与 `nav` 是兄弟，链上没有 `nav`，纹丝不动——这就是"行为沿树传播"。**评论树**：存储永远是平铺 `parent_id` 表，组合树只是"按 parent_id 把评论装配成内存对象图"后的视图，装配一次、遍历多次才回本；只要一层回复的场景两列查询就够，别为模式硬建树。

## 六、校验口径

- PHP 块：本机 `php8.0.2nts`（PHP 8.0.2，CLI）逐块执行，`php -l` 通过后整块运行，`text` 块是原始 stdout。第四节崩溃块是标注"接上文"的片段，其输出来自同一代码在本机临时文件的手工运行（stdout；stderr 另有一份带 `PHP ` 前缀的相同消息，退出码 255），未经脚本自动对账。
- 语法用到构造器提升、协变返回类型（`current(): Node`），**最低 PHP 8.0**；`spl_object_id()` 需 7.2+；未用 8.1 特性。`268435456 bytes` 是本机 `memory_limit=256M` 的如实反映。
- 本篇未附 Go/Java 对照块（篇幅取舍）；JDK 现成的组合是 `java.io.File` 与 Swing `JComponent`，可自查对照。全篇无 Redis/DB 实例，第五节为纯内存演示。

## 面试官会追问什么

- **组合和装饰器都是"对象套对象"，区别？** → 装饰器一对一套一个且增强行为；组合一对多且聚合行为（size/sum/遍历），同一个 `add()` 语义完全不同。
- **叶子调用 `add()` 是空实现还是抛异常？** → 实测见第三节：PHP 推荐抛 `LogicException`，空实现把装配 bug 藏到更深处。
- **树里有环会怎样？** → 不是卡住的死循环，是朴素递归把内存吃光直接 Fatal（第四节实测）；修复是路径集 `spl_object_id` + 挂载入口校验。
- **为什么用 `RecursiveIteratorIterator` 不手写递归？** → 遍历策略与树结构解耦（换参数不换代码），还能叠 `RecursiveCallbackFilterIterator` 剪枝。
- **组合树怎么落库？** → 平铺 `parent_id` 存、内存装配；失效用版本链（第五节）而不是级联 UPDATE 全子树。

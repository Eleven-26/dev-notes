# 适配器模式：换的是供应商，不是调用方

> 素材来源：博客系列 [PHP 设计模式(五)：适配器模式](https://blog.csdn.net/weixin_43837229/article/details/102660296)。
> 重写版补上原文没讲的三块：**类适配器为什么在 PHP 里基本不成立**（单继承 + `trait` 假继承，实测）、
> **`__call` 万能适配器到底赔掉什么**（静态分析 / typo 时机 / 接口合法性，对照实跑）、**`psr/log` 桥接的正解是 `AbstractLogger`**。
> 邻居模式见 [装饰器模式.md](装饰器模式.md)、[代理模式.md](代理模式.md)、[外观模式.md](外观模式.md)，一句话区分在第五节。

## 一、适配器只回答一个问题：调用方要的形状由谁来翻译

适配器（Adapter，结构型）：**不改任何一方，加一个中间类把 A 的形状翻译成 B 的形状**。
被适配者（Adaptee）= 第三方已有的实现，目标接口（Target）= 我的调用方认识的那个形状。

判据很硬：**只有"这一方不能改"（vendor 目录 / 别的团队 / 上线多年的老 SDK）时，适配器才是唯一解**。
调用方能改就直接改调用方；只有一两个调用点且都能改时，适配器是多余的一层。

## 二、对象适配器：PHP 里唯一顺手的那一种

对象适配器 = **组合**：持有被适配者实例，构造时注入。

```php
<?php

declare(strict_types=1);

interface PaymentGateway
{
    /** 本项目统一用"分"，返回第三方流水号 */
    public function charge(int $fen, string $orderNo): string;
}

final class AlipaySdk
{
    public function createTrade(array $p): array { return ['trade_no' => 'ALI' . strtoupper(substr(md5($p['out_trade_no']), 0, 8)), 'yuan' => $p['total_amount']]; }
}

final class WechatSdk
{
    public function unifiedOrder(float $yuan, string $bizId): string { return 'WX' . strtoupper(substr(md5($bizId), 0, 8)) . '/yuan=' . $yuan; }
}

final class AlipayGateway implements PaymentGateway
{
    public function __construct(private AlipaySdk $sdk) {}
    public function charge(int $fen, string $orderNo): string
    {
        $r = $this->sdk->createTrade(['out_trade_no' => $orderNo, 'total_amount' => $fen / 100]);
        return $r['trade_no'] . '/yuan=' . $r['yuan'];
    }
}

final class WechatGateway implements PaymentGateway
{
    public function __construct(private WechatSdk $sdk) {}
    public function charge(int $fen, string $orderNo): string { return $this->sdk->unifiedOrder($fen / 100, $orderNo); }
}

// 业务层只认接口：换供应商只改装配处这一行
function checkout(PaymentGateway $gw, string $no): string { return $gw->charge(9900, $no); }

echo 'alipay : ', checkout(new AlipayGateway(new AlipaySdk()), 'ORDER-01'), PHP_EOL;
echo 'wechat : ', checkout(new WechatGateway(new WechatSdk()), 'ORDER-01'), PHP_EOL;
echo '业务函数签名未动: ', (new ReflectionFunction('checkout'))->getParameters()[0]->getType(), PHP_EOL;
```

```text
alipay : ALIAAE30104/yuan=99
wechat : WXAAE30104/yuan=99
业务函数签名未动: PaymentGateway
```

两个供应商的方法名、参数容器（数组 vs 标量）、单位（元）、返回类型全不一样，业务层看到的是同一个签名。
`yuan=99` 是故意打的：**分↔元这类单位换算必须写在适配器里并被断言**，散在业务层的 `/100` 迟早漏一处。
同理，供应商抛的 `VendorTimeoutException` 也要在适配器里换成你自己的异常类型，否则业务层 `catch` 里仍然写着供应商类名，等于换了个漏口的适配器。

## 三、类适配器在 PHP 里排不上号：`trait` 是假继承

教科书的类适配器是 `extends Adaptee implements Target`——**用继承权换签名翻译**。Java 行（单继承 + 多实现），
PHP 只有一个父类名额、通常已被框架基类占用；更糟的是 `trait` 冒充不出继承：

```php
<?php

declare(strict_types=1);

interface PaymentGateway
{
    public function charge(int $fen, string $orderNo): string;
}

class FrameworkRepo
{
    public function table(): string { return 'pay_order'; }
}

final class AlipaySdk
{
    public function createTrade(array $p): array { return ['trade_no' => 'ALI' . strtoupper(substr(md5($p['out_trade_no']), 0, 8))]; }
}

// 类适配器 = extends 被适配者 + implements 目标接口，但 PHP 只有一个父类名额
try {
    eval('class BrokenAdapter extends FrameworkRepo, AlipaySdk implements PaymentGateway {}');
    echo "双继承: 居然编译通过了\n";
} catch (ParseError $e) {
    echo '双继承: ', $e->getMessage(), PHP_EOL;
}

// 用 trait 绕开单继承：trait 只搬方法体，不提供继承，$this->createTrade() 是"假设父类存在"
trait AlipayAdapterTrait
{
    public function charge(int $fen, string $orderNo): string { return $this->createTrade(['out_trade_no' => $orderNo])['trade_no']; }
}

final class RepoPaid extends FrameworkRepo implements PaymentGateway
{
    use AlipayAdapterTrait;
}

$host = new RepoPaid();
echo 'trait 宿主 instanceof 目标接口: ', var_export($host instanceof PaymentGateway, true), PHP_EOL;
echo 'trait 宿主的父类方法照常可用: ', $host->table(), PHP_EOL;
try {
    $host->charge(9900, 'ORDER-01');
    echo "trait 宿主->charge: 成功\n";
} catch (Throwable $e) {
    echo 'trait 宿主->charge: ', get_class($e), ' -> ', $e->getMessage(), PHP_EOL;
}
echo 'charge() 声明在: ', (new ReflectionMethod(RepoPaid::class, 'charge'))->getDeclaringClass()->getName(), PHP_EOL;
echo '宿主内持有的委托对象数（换供应商的抓手）: ', count(array_filter(get_object_vars($host), 'is_object')), PHP_EOL;
```

```text
双继承: syntax error, unexpected token ",", expecting "{"
trait 宿主 instanceof 目标接口: true
trait 宿主的父类方法照常可用: pay_order
trait 宿主->charge: Error -> Call to undefined method RepoPaid::createTrade()
charge() 声明在: RepoPaid
宿主内持有的委托对象数（换供应商的抓手）: 0
```

三条结论就是"PHP 没有类适配器位置"的完整证据链：

1. **`extends A, B` 直接 ParseError**——继承被适配者的名额往往已经给了框架基类。
2. **`trait` 骗过类型系统**：宿主 `instanceof` 为真，但 trait 只搬方法体不搬继承关系，`$this->createTrade()` 运行时才炸
   `Call to undefined method`。要让 trait 版能跑就得把被适配者实现**一起复制**进宿主——那已经是 fork 供应商代码；
   两个 trait 带同名适配方法时还要 `insteadof` 手工裁决。**trait 的复用发生在编译期扁平化，适配器的换目标发生在运行期装配，两件事对不上。**
3. **委托对象数 = 0**：没有可注入的缝，换供应商要改宿主类，单测要换实现只能上 `runkit` 或真连沙箱
   （类适配器另一处静默风险是 `parent::` 直连被适配者，`parent::createTrade()` 在这根本编译不过）。

**结论：PHP 里写对象适配器——`interface` 负责形状，`private` 字段负责那个可替换的被适配者。**

## 四、`__call` 万能适配器：省 3 行样板，赔掉 5 件事

诱惑长这样："接口 20 个方法，我用 `__call` 全转发，一行搞定。"

```php
<?php

declare(strict_types=1);

interface PaymentGateway
{
    public function charge(int $fen, string $orderNo): string;
}

final class AlipaySdk
{
    public function createTrade(array $p): array { return ['trade_no' => 'ALI' . strtoupper(substr(md5($p['out_trade_no']), 0, 8))]; }
}

final class ExplicitGateway implements PaymentGateway
{
    public function __construct(private AlipaySdk $sdk) {}
    public function charge(int $fen, string $orderNo): string { return $this->sdk->createTrade(['out_trade_no' => $orderNo])['trade_no']; }
}

// "万能适配器"：__call 全量转发，宣称不用为每个方法写翻译
final class MagicGateway
{
    public function __construct(private AlipaySdk $sdk) {}
    public function __call(string $name, array $args): mixed { return $this->sdk->{$name}(...$args); }
}

function checkout(PaymentGateway $gw): string { return $gw->charge(9900, 'ORDER-01'); }

echo 'explicit 版: ', checkout(new ExplicitGateway(new AlipaySdk())), PHP_EOL;
$m = new MagicGateway(new AlipaySdk());
echo 'method_exists(magic, "charge"): ', var_export(method_exists($m, 'charge'), true),
    ' / 反射可见: ', implode(',', array_map(static fn (ReflectionMethod $x): string => $x->getName(),
        (new ReflectionClass($m))->getMethods(ReflectionMethod::IS_PUBLIC))), PHP_EOL;
try {
    checkout($m);
} catch (Throwable $e) {
    echo '注入给业务函数: ', get_class($e), ' -> ', explode(', called in', $e->getMessage())[0], PHP_EOL;
}
try {
    $m->creatTrade(['out_trade_no' => 'ORDER-01']);
} catch (Throwable $e) {
    echo '方法名少打一个 e: ', get_class($e), ' -> ', $e->getMessage(), PHP_EOL;
}
echo '返回值真实类型: ', get_debug_type($m->createTrade(['out_trade_no' => 'ORDER-01'])), '（接口承诺 string）', PHP_EOL;
// 让 magic 直接 implements 接口？编译期 Fatal、catch 不住，用子进程复现
$probe = __DIR__ . '/a3_probe.php';
file_put_contents($probe, "<?php\ninterface G { public function charge(int \$f): string; }\nfinal class Magic implements G { public function __call(\$n, \$a): mixed { return 'x'; } }\n");
$out = [];
$rc = 0;
exec(escapeshellarg(PHP_BINARY) . ' -d display_errors=1 ' . escapeshellarg($probe) . ' 2>&1', $out, $rc);
echo 'magic 敢 implements 接口吗: rc=', $rc, ' -> ', trim(explode(' in ', $out[0] ?? '')[0]), PHP_EOL;
unlink($probe);
```

```text
explicit 版: ALIAAE30104
method_exists(magic, "charge"): false / 反射可见: __construct,__call
注入给业务函数: TypeError -> checkout(): Argument #1 ($gw) must be of type PaymentGateway, MagicGateway given
方法名少打一个 e: Error -> Call to undefined method AlipaySdk::creatTrade()
返回值真实类型: array（接口承诺 string）
magic 敢 implements 接口吗: rc=255 -> PHP Fatal error:  Class Magic contains 1 abstract method and must therefore be declared abstract or implement the remaining methods (G::charge)
```

| 代价 | 实测证据 |
| --- | --- |
| 静态分析失效 | 反射只看得到 `__construct,__call`，PHPStan/Psalm 同样看不到适配方法 |
| IDE 补全失效 | 同一个原因；`method_exists` 直接 `false` |
| typo 从编译期退到运行期 | `creatTrade` 要等跑到那行才 `Error`，报的还是**供应商**的方法名 |
| 返回类型漏了 | 接口承诺 `string`，实得 `array` |
| **压根 implements 不了** | `__call` 不算实现抽象方法，`implements G` 是编译期 Fatal（rc=255） |

最后一条最狠：**适配器的目标就是"变成某个接口"，而 `__call` 恰好给不了接口**，"万能适配器"是自相矛盾的东西。
何况它只做签名翻译、不做语义翻译——`yuan=99` 那种单位换算 `__call` 永远转发不出来。
`__call` 剩下的合理用法只有一种：方法集**开放**的转发（`ArrayAccess` 代理、事件总线、装饰器兜底），且**接口里的方法必须仍然真实声明**。

## 五、三个真会踩到的场景，以及和外观/代理的边界

| 场景 | Adaptee | Target | 适配器额外承担 |
| --- | --- | --- | --- |
| 老 SDK 换供应商 | `AlipaySdk` / `WechatSdk` | `PaymentGateway` | **单位与精度换算**（分↔元）、异常归一 |
| 第三方包接口不合本项目 | vendor 里的 `final class` | 项目内部的窄接口 | 把宽接口收窄（接口隔离）、屏蔽包内 DTO |
| `psr/log` 与框架日志桥接 | 框架 logger（`write(int $pri, ...)`） | `Psr\Log\LoggerInterface` | 级别映射表 |

共同点：调用方**很多**、被适配者**不能改**。反面提醒：只有一两个调用点时别上适配器（改了等于没适配，纯增维护面）；
也别给 vendor 的每个方法都配适配器，只适配用到的那几个；这条缝上不会出现第二个实现时，
适配器 + 工厂 + 容器绑定三件套就是纯负债。第三行的坑最具体：`LoggerInterface` 是 1 个 `log()` + 8 个快捷方法，
**裸 `implements` 要写 9 个方法，而 `__call` 在这里非法**（第四节实测）——正解是 psr/log 自带的 `AbstractLogger`：

```php
<?php

declare(strict_types=1);

namespace Psr\Log {
    // 真 PSR-3 = log() + 8 个快捷方法；这里留 2 个演示形状，样板按比例放大（本机也没装 psr/log 包）
    interface LoggerInterface
    {
        public function log($level, string|\Stringable $message, array $context = []): void;
        public function error(string|\Stringable $message, array $context = []): void;
        public function info(string|\Stringable $message, array $context = []): void;
    }
    // psr/log 自带的 AbstractLogger 就是这笔"翻译样板税"的出口：只把 log() 留给子类
    abstract class AbstractLogger implements LoggerInterface
    {
        public function error(string|\Stringable $m, array $c = []): void { $this->log('error', $m, $c); }
        public function info(string|\Stringable $m, array $c = []): void { $this->log('info', $m, $c); }
    }
}

namespace App {
    use Psr\Log\AbstractLogger;
    use Psr\Log\LoggerInterface;

    // 框架自带日志器：方法名、参数顺序、级别表示法（数字优先级）全对不上
    final class ThinkPhoneLogger
    {
        public array $lines = [];
        public function write(int $pri, string $text, array $meta): bool
        {
            $this->lines[] = sprintf('[%s] %s %s', [2 => 'ERR', 4 => 'INFO'][$pri] ?? '?', $text, json_encode($meta, JSON_UNESCAPED_UNICODE));
            return true;
        }
    }

    final class ThinkPhoneBridge extends AbstractLogger
    {
        private const PRI = ['info' => 4, 'error' => 2];
        public function __construct(private ThinkPhoneLogger $inner) {}
        public function log($level, string|\Stringable $message, array $context = []): void
        {
            $this->inner->write(self::PRI[$level] ?? 4, (string) $message, $context);
        }
    }

    function billing(LoggerInterface $log): void
    {
        $log->info('扣款成功', ['order' => 'ORD-1']);
        $log->error('回调超时', ['retry' => 3]);
    }

    $raw = new ThinkPhoneLogger();
    billing(new ThinkPhoneBridge($raw));   // 业务/第三方包只认 LoggerInterface
    $iface = count((new \ReflectionClass(LoggerInterface::class))->getMethods());
    $own = array_filter((new \ReflectionClass(ThinkPhoneBridge::class))->getMethods(\ReflectionMethod::IS_PUBLIC),
        static fn (\ReflectionMethod $m): bool => $m->getDeclaringClass()->getName() === ThinkPhoneBridge::class && $m->getName() !== '__construct');
    echo '接口方法数=' . $iface . '：裸 implements 得写 ' . ($iface - 1) . ' 个翻译方法，继承 AbstractLogger 后只写 ' . count($own)
        . ' 个: ' . implode(',', array_map(static fn (\ReflectionMethod $m): string => $m->getName(), $own)), PHP_EOL;
    foreach ($raw->lines as $l) { echo $l, PHP_EOL; }
}
```

```text
接口方法数=3：裸 implements 得写 2 个翻译方法，继承 AbstractLogger 后只写 1 个: log
[INFO] 扣款成功 {"order":"ORD-1"}
[ERR] 回调超时 {"retry":3}
```

**样板多不是 `__call` 的理由，而是"上游已经替你写好 `AbstractLogger`"的信号。**
级别映射写成常量表 `PRI` 而不是 `switch`：它只是一张表、没有逻辑；`warning` 该映到框架的 `ERR` 还是 `INFO` 是产品决定，
写成表就是这个决定唯一存在的地方。

边界一句话表：

| 模式 | 判据 | 接口变了吗 |
| --- | --- | --- |
| 适配器 | 两个**本来不兼容**的接口之间加一次**翻译** | 变了：实现 Target，转发 Adaptee |
| 外观 | 一组子系统收敛成**一个更简单的入口**，不翻译谁 | 变了：新建更高层的窄接口 |
| 代理 | 和被代理对象**同一个接口**，只改**访问时机/权限** | 没变：Target 就是被代理者的接口 |

再压缩：**适配器改形状，外观降复杂度，代理改访问。**
判别只有一条——你的类和老接口签名一模一样，那它就是代理或装饰器，不是适配器。
想给 `charge()` 加缓存/重试？那是装饰器的活，塞进适配器就是把三种模式糊成一个上帝类。

## 六、Go / Java 对照（结论，未附代码块）

Go 的接口是**隐式**满足的，很多场景不需要适配器；嵌入（embedding）则补上了 PHP 缺的那条类适配器路线，
且不受单继承限制。Java 两种都能写（`extends Adaptee implements Target` 可编译），这是第三节 PHP 走不通的反证，
但 Java 社区仍主推对象适配器——类适配器没有可注入的缝，Mockito 能 mock 类却替换不了 `parent::` 那条直连。

| | PHP | Go | Java |
| --- | --- | --- | --- |
| 对象适配器 | 首选：`private` 字段 + `implements` | 同（`struct` 字段） | 同 |
| 类适配器 | **基本不用**（单继承 + `trait` 假继承，第三节实测） | 可用（嵌入提升方法） | 可用（`extends` + `implements`） |
| 接口匹配 | 必须显式 `implements` | **隐式**：签名对上就满足 | 必须显式 `implements` |
| 运行时换实现 | 换注入对象即可 | 换被嵌入的值（方法集编译期固定） | 换注入对象 |

## 校验口径

- 第二~五节四段 PHP 本机实跑：`D:\phpstudy_pro\Extensions\php\php8.0.2nts\php.exe`（PHP 8.0.2 / Zend 4.0.2，CLI），逐段 `php -l` 通过后执行，`text` 块是原始 stdout。
  第四节末尾 rc=255 的 `PHP Fatal error` **不可 catch**，故脚本内写了个探针文件、用 `PHP_BINARY` 起子进程取回原文（探针建在脚本同目录并即时 `unlink`）。
- **PHP 门槛 8.0+**：构造器属性提升需 7.4+，`__call(...): mixed` 与 `string|\Stringable` 需 **8.0+**（7.4 在第四节直接 Parse error）。未用 `readonly`/`enum`（8.1+）。
- **无 composer 依赖、无中间件**：第五节的 `LoggerInterface`/`AbstractLogger` 是手抄形状（留 2 个快捷方法，真实 PSR-3 是 8 个），
  验证的是"9 个方法 → 1 个方法"这条结论；`AlipaySdk`/`WechatSdk`/`ThinkPhoneLogger` 均为本地替身，`md5` 流水号只为断言翻译发生。
- 第六节的 Go/Java 是结论性对照，**本篇未附其代码块**（"隐式接口""嵌入提升方法"属语言规范事实）；要跑通的跨语言版本见 [装饰器模式.md](装饰器模式.md) 第六节、[代理模式.md](代理模式.md) 第七节。
- 全文无性能数字：只测"有没有发生 / 类型对不对 / 方法能不能被静态看到"。

## 面试官会追问什么

- **适配器和装饰器结构一样，怎么区分？** → 看接口：适配器实现**新接口**，装饰器和被装饰者**同一个接口**（[装饰器模式.md](装饰器模式.md)）。
- **PHP 为什么不推荐类适配器？** → 单继承名额常被框架基类占用；`extends 被适配者` 还把"不可注入、不可 mock、`parent::` 不可替换"焊死（第三节 `trait` 方案委托对象数 = 0）。
- **`__call` 万能适配器错在哪？** → 静态分析失效、IDE 补不出、typo 退到运行期、单位换算不会被翻译，而且**根本 implements 不了接口**（`__call` 不算实现抽象方法，实测 rc=255）。
- **什么时候不该写适配器？** → 调用方能改时直接改调用方；这条缝上不会出现第二个实现时，适配器+工厂+容器三件套是过度设计。
- **`psr/log` 桥接为什么继承 `AbstractLogger`？** → `__call` 在接口适配上非法，而快捷方法全是同一句转发的样板；`AbstractLogger` 收走样板、只留 `log()`（第五节实测）。
- **适配器里能加缓存/重试吗？** → 一写就变成装饰器，应拆成 `RetryDecorator implements PaymentGateway` 套在适配器**外面**。

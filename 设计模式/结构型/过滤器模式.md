## 一、什么是过滤器模式

原文的定义：

> 过滤器模式（Filter Pattern）或标准模式（Criteria Pattern）是一种设计模式，
> 这种模式允许开发人员**使用不同的标准来过滤一组对象，通过逻辑运算以解耦的方式把它们连接起来**。
> 这种类型的设计模式属于结构型模式，它**结合多个标准来获得单一标准**。

最后一句是全部要点：**"标准"可以再组合成"新标准"，而组合过程本身也是解耦的**。

三个角色：

| 角色 | 职责 | 原文对应 |
| --- | --- | --- |
| 标准 / 谓词（Criteria） | 判断单个元素是否保留 | 抽象类 `Criteria` |
| 组合标准（And / Or / Not） | 把多个标准拼成一个新标准 | `AndCriteria` / `OrCriteria` |
| 被筛选集合 | 原始数据 | `Person[]` |

## 二、应用场景

原文写得很简洁：**数据过滤、筛选、验证等**。

展开一下"等"里还有什么 —— 这些都是同一形状：

| 场景 | 谓词在判断什么 |
| --- | --- |
| 列表页多条件筛选 | 部门、状态、关键字 |
| 权限过滤 | 当前用户是否可见该资源 |
| 数据校验 | 字段是否满足一组规则 |
| 数据导出/清洗 | 脏数据判定 |

## 三、PHP 标准实现

原文用抽象类 `Criteria` + 继承实现每个标准，`AndCriteria` / `OrCriteria` 再各写一个类。标准写法里，**一个标准就是一个 `callable(object): bool`**，组合靠三个函数：

```php
<?php

declare(strict_types=1);

/**
 * 谓词组合器：过滤器模式在 PHP 里的标准形态。
 * 每个「标准（Criteria）」就是一个 callable(object): bool，组合靠这三个函数。
 */
final class Predicates
{
    /** 全部满足（AND），短路 */
    public static function all(callable ...$predicates): callable
    {
        return static function (object $candidate) use ($predicates): bool {
            foreach ($predicates as $predicate) {
                if (!$predicate($candidate)) {
                    return false;              // 短路：后面的谓词不再求值
                }
            }
            return true;
        };
    }

    /** 任一满足（OR），短路 */
    public static function any(callable ...$predicates): callable
    {
        return static function (object $candidate) use ($predicates): bool {
            foreach ($predicates as $predicate) {
                if ($predicate($candidate)) {
                    return true;
                }
            }
            return false;
        };
    }

    /** 取反（NOT） */
    public static function not(callable $predicate): callable
    {
        return static fn (object $candidate): bool => !$predicate($candidate);
    }
}

/** 筛选器：用生成器做到惰性，调用方决定是立刻取回还是边算边用 */
final class Filter
{
    public static function apply(iterable $items, callable $predicate): Generator
    {
        foreach ($items as $item) {
            if ($predicate($item)) {
                yield $item;
            }
        }
    }

    public static function toList(iterable $items, callable $predicate): array
    {
        // 第二个参数 false：重新索引，不保留原键（对比实测第 7、8 行）
        return iterator_to_array(self::apply($items, $predicate), false);
    }
}
```

用法就是「定义几个标准，然后拼」：

```php
$employees = [
    new Employee('Ann', 'eng', true),
    new Employee('Bob', 'eng', false),
    new Employee('Cara', 'sales', true),
    new Employee('Dan', 'sales', false),
];

$inEng    = static fn (Employee $e): bool => $e->department() === 'eng';
$inSales  = static fn (Employee $e): bool => $e->department() === 'sales';
$isRemote = static fn (Employee $e): bool => $e->isRemote();

echo '1_远程工程师       : ', names(Filter::apply($employees, Predicates::all($inEng, $isRemote))), PHP_EOL;
echo '2_工程师或远程     : ', names(Filter::apply($employees, Predicates::any($inEng, $isRemote))), PHP_EOL;
echo '3_非工程师         : ', names(Filter::apply($employees, Predicates::not($inEng))), PHP_EOL;

// 嵌套组合：远程 且 (工程师 或 销售)
$remoteEngOrSales = Predicates::all($isRemote, Predicates::any($inEng, $inSales));
echo '4_远程且(工程师|销售): ', names(Filter::apply($employees, $remoteEngOrSales)), PHP_EOL;
```

**使用示例**：

```php
// 一个「标准」就是闭包：输入对象、返回 bool
$isRemote = static fn (Employee $e): bool => $e->isRemote();
$employees = [new Employee('Ann', 'eng', true), new Employee('Bob', 'eng', false)];

// apply 返回生成器，惰性求值：不取就不算
$gen = Filter::apply($employees, $isRemote);
$gen->current();                                        // Ann（此处才求值）

// toList 立即取回并重新索引（区别于 array_filter 保留原键）
Filter::toList($employees, $isRemote);                  // [Employee(Ann)]

// 组合器可嵌套，取反即 not
Filter::toList($employees, Predicates::not($isRemote)); // [Employee(Bob)]
```

实测（PHP 8.0.2 CLI）：

```text
1_远程工程师       : Ann
2_工程师或远程     : Ann, Bob, Cara
3_非工程师         : Cara, Dan
4_远程且(工程师|销售): Ann, Cara
5_AND 短路：后续谓词被调用 0 次（应为 0）
6_惰性取首个       : Ann
7_array_filter 保留原键 : 2,3
8_toList 连续下标       : 0,1
```

### 7 个让它算「标准写法」的细节

| # | 做法 | 为什么 |
| --- | --- | --- |
| 1 | 标准用 `callable` 而不是抽象类 | 一个标准通常只有一行判断，为它建类是杀鸡用牛刀 |
| 2 | 组合器返回**新谓词**，而不是"结果数组" | 组合物还能再组合（第 4 行即嵌套）；若像原文那样返回结果集，表达式层级就被拍平了 |
| 3 | **`AND`/`OR` 都短路** | 第 5 行实测：第一个谓词返回 `false` 后，后续谓词调用次数为 0；大集合 + 有 IO 的谓词差距明显 |
| 4 | 筛选返回 `Generator`，需要数组时显式 `toList()` | 让"要不要物化"暴露给调用方，而不是替它决定 |
| 5 | **物化时重新索引** | 第 7、8 行对照：`array_filter` 保留原键（`2,3`），生成器物化后是 `0,1`。给前端或做 JSON 序列化时，保留原键会变成对象而不是数组 |
| 6 | 谓词只读，不改元素 | 谓词带副作用会让"短路"变成坑：第 3 条保证的是**没命中的谓词不会被调用** |
| 7 | 组合器放静态方法里，不散落在全局 | `Predicates::all()` 可被 IDE 跳转、可被命名空间隔离，也便于单测 |

## 四、原文写法的两个问题

原文的抽象类写法能跑，实测结果也与它注释一致。但放进工程有两个代价：

**问题一：每个标准一个类，且必须 `new` 才能组合。**

原文的组合要求传 `Criteria` 实例。标准只有一行判断却要建类、建实例，而闭包版本天然可嵌套：

```php
$complex = Predicates::all($isRemote, Predicates::any($inEng, $inSales), Predicates::not($isOnLeave));
```

**问题二：`OrCriteria` 里用 `in_array` 去重，是个隐藏的 O(n²)。**

原文的 OR 实现是"两边各筛一遍，再把结果合并去重"：

```php
foreach ($otherCriteriaItems as $person) {
    if (!in_array($person, $firstCriteriaItems)) {   // 每个元素扫一遍已收集的列表
        $firstCriteriaItems[] = $person;
    }
}
```

- **复杂度**：n 个元素时最坏 O(n²)。标准写法在**谓词层面**做 OR，同一个元素只被判断一次，天然不会重复，不需要去重这一步；
- **比较语义**：`in_array` 默认松散比较，对象之间按属性逐个比较（`==`）而不是按身份（`===`）。两个属性完全相同、但业务上是不同记录的对象会被判成"重复"，在有值对象的数据里会静默丢数据。

正确的做法是 §三 的 `Predicates::any()`：**先算"这个元素要不要"，再决定收不收**，而不是"先各筛一遍再合并结果"。

## 五、边界：和策略、责任链、迭代器各管什么

| | 过滤器 | 策略 | 责任链 |
| --- | --- | --- | --- |
| 返回值 | bool（只回答"要不要"） | 业务结果 | 处理结果或"传给下一个" |
| 对数据做什么 | 只选不改，纯函数 | 可任意加工 | 可加工、拦截、短路 |
| 顺序敏感吗 | 不敏感（与或非可交换） | 单选一个 | 顺序即语义 |
| 组合代数 | and/or/not **封闭**：组合后还是谓词 | 一般不提供组合子 | 链式传递 |

判别口诀：**能画出"谓词进、bool 出、组合后仍是谓词"这个闭环的，才是过滤器**；会改数据、会中断流程的已经滑向责任链。

与**迭代器**的关系是上下游：过滤器负责"筛出哪些"，迭代器负责"怎么被消费"（见 [../行为型/迭代器模式.md](../行为型/迭代器模式.md)）。两者交汇处正是 Go 1.23 的 `iter.Seq`。

## 六、为什么真实项目里它常被 SQL 条件下推取代

原文的例子是把 6 个 `Person` 全查出来再在内存里筛。真实项目里集合通常来自数据库 —— 这时**过滤应该下推到 SQL**：数据库筛是 O(命中行数) 的传输，内存筛是 O(全表行数) 的 PHP 进程内存。百万行的表 `->get()` 出来再 `array_filter`，先 OOM 的是 PHP。

下推的关键是**让谓词可序列化**：闭包不透明、翻不成 SQL，换成「SQL 片段 + 绑定参数」的数组即可，而**组合代数一行不用改**：

| 做法 | 什么时候合适 |
| --- | --- |
| SQL `WHERE` / Laravel Scope / 查询构造器 | 数据在库里、条件能翻译成 SQL（绝大多数列表页） |
| 内存过滤器（本篇写法） | 数据已在内存、条件表达不进 SQL、或需要复用同一套规则做纯计算 |

反过来，下面这些情况内存过滤器**仍是最优解**：

| 场景 | 为什么下推不了 |
| --- | --- |
| 已加载集合的二次筛选（页内搜索、二次权限过滤） | 数据已在手里，再查库反而慢 |
| 外部接口返回的整包 JSON | 对方 API 不接受自定义条件 |
| 单元测试 fixture | 谓词是纯函数，喂几行数据断言 bool 即可，不用起数据库 |
| 依赖进程内状态的判定（会话、Feature flag） | 硬翻成 SQL 会漏业务口径 |

判据一句话：**数据源能接条件就下推，接不了或已加载完才用内存谓词。**

## 七、Java 实现

Java 标准库里**已经内置了这套组合器**：`java.util.function.Predicate` 自带 `and` / `or` / `negate`，`Stream` 自带惰性。

```java
import java.util.Arrays;
import java.util.List;
import java.util.function.Predicate;
import java.util.stream.Collectors;

public class FilterStandard {
    static final class Employee {
        private final String name;
        private final String department;
        private final boolean remote;

        Employee(String name, String department, boolean remote) {
            this.name = name;
            this.department = department;
            this.remote = remote;
        }

        String name() { return name; }
        String department() { return department; }
        boolean isRemote() { return remote; }
    }

    public static void main(String[] args) {
        List<Employee> employees = Arrays.asList(
                new Employee("Ann", "eng", true),
                new Employee("Bob", "eng", false),
                new Employee("Cara", "sales", true),
                new Employee("Dan", "sales", false)
        );

        Predicate<Employee> inEng = e -> "eng".equals(e.department());
        Predicate<Employee> inSales = e -> "sales".equals(e.department());
        Predicate<Employee> isRemote = Employee::isRemote;

        // Predicate 自带 and / or / negate —— 标准库直接就是组合器
        employees.stream().filter(inEng.and(isRemote)).collect(Collectors.toList());
        employees.stream().filter(inEng.or(isRemote)).collect(Collectors.toList());
        employees.stream().filter(inEng.negate()).collect(Collectors.toList());
        employees.stream().filter(isRemote.and(inEng.or(inSales))).collect(Collectors.toList());
    }
}
```

**使用示例**：

```java
// 「标准」就是 Predicate，自带 and / or / negate
List<Employee> employees = Arrays.asList(
        new Employee("Ann", "eng", true),
        new Employee("Bob", "eng", false),
        new Employee("Cara", "sales", true),
        new Employee("Dan", "sales", false));
Predicate<Employee> inEng = e -> "eng".equals(e.department());
Predicate<Employee> isRemote = Employee::isRemote;

employees.stream().filter(inEng.and(isRemote)).collect(Collectors.toList()); // Ann
employees.stream().filter(inEng.negate()).collect(Collectors.toList());      // Cara, Dan

// 惰性：findFirst 命中就停，不再评估后续元素
employees.stream().filter(isRemote).findFirst();   // Optional[Ann]
```

JDK 1.8 实测输出与 PHP 版逐行一致：

```text
1_远程工程师       : Ann
2_工程师或远程     : Ann, Bob, Cara
3_非工程师         : Cara, Dan
4_远程且(工程师|销售): Ann, Cara
5_stream.findFirst 只评估了 1 个元素（应为 1）
```

两点值得记：**`Predicate::and` 默认短路**（与 PHP 版一致）；**`Stream` 是惰性的** —— `findFirst()` 之后不再评估后续元素（实测只评估了 1 个）。若换成对 `List` 手写 `for` 循环，这两条都要自己保证。

## 八、Go 实现

Go 标准库没有谓词组合器，但函数类型让这件事变得很直接：

```go
// Predicate 一个「标准」：输入元素，返回是否保留
type Predicate func(Employee) bool

// All 全部满足（AND），短路
func All(predicates ...Predicate) Predicate {
	return func(e Employee) bool {
		for _, p := range predicates {
			if !p(e) {
				return false
			}
		}
		return true
	}
}

// Any 任一满足（OR），短路
func Any(predicates ...Predicate) Predicate {
	return func(e Employee) bool {
		for _, p := range predicates {
			if p(e) {
				return true
			}
		}
		return false
	}
}

// Not 取反（NOT）
func Not(p Predicate) Predicate {
	return func(e Employee) bool { return !p(e) }
}
```

**使用示例**：

```go
// 「标准」就是一个 func(Employee) bool
inEng := func(e Employee) bool { return e.Department == "eng" }
isRemote := func(e Employee) bool { return e.Remote }

employees := []Employee{{"Ann", "eng", true}, {"Cara", "sales", true}}

// 组合器返回新的 Predicate，可继续嵌套
p := All(isRemote, inEng)      // 远程 且 工程师

// Filter 一次遍历、无中间切片；惰性要靠 First 手动表达
Filter(employees, p)           // [Ann]
First(employees, isRemote)     // (Ann, true)
```

go1.26.5 实测输出（与 PHP、Java 一致）：

```text
1_远程工程师       : Ann
2_工程师或远程     : Ann, Bob, Cara
3_非工程师         : Cara, Dan
4_远程且(工程师|销售): Ann, Cara
5_AND 短路：后续谓词被调用 0 次（应为 0）
6_惰性取首个       : Ann
```

Go 的差异在**惰性要手动表达**：Go 没有生成器，`Filter` 要么返回新切片（本实现在此），要么接收回调逐项消费；要"取第一个就停"得自己写 `First()`（本实现），或改用 **Go 1.23+ 的 `iter.Seq`** 把筛选表达成 `range` 可遍历的函数（写法见 [../行为型/迭代器模式.md](../行为型/迭代器模式.md)）。

## 九、PHP / Java / Go 对照

| | PHP | Java | Go |
| --- | --- | --- | --- |
| 谓词类型 | `callable` + PHPDoc | `Predicate<T>` | `func(T) bool` |
| 组合器来源 | **自己写三个函数** | **标准库自带** `.and/.or/.negate` | 自己写三个函数 |
| 惰性 | 生成器 `yield` | `Stream` | 手动 `First()` 或 `iter.Seq` |
| 物化时是否重新索引 | `array_filter` 保留原键，需 `array_values` / `iterator_to_array(..., false)` | `collect()` 天然连续 | `append` 到新切片天然连续 |
| 常见落地位置 | `Collection::filter()` / Laravel Scope | `stream().filter()` | 循环内联 / `iter.Seq` |

三语言共通的一点：**谓词必须是纯函数**。一旦谓词带副作用，"短路"就变成了不可见的行为差异 —— 同一份数据换个组合顺序，副作用执行次数就变了。

## 十、面试官会追问什么

- **过滤器和策略代码长得一样，怎么区分？** → 看返回值契约：策略返回处理结果；过滤器返回 `bool`，且必须提供 and/or/not 组合子才成其为过滤器。**没有组合代数的 "Criteria 类" 只是带 `if` 的策略。**
- **为什么生产代码里很少见到 Criteria 类？** → 闭包形态无法下推数据库；换成 SQL 片段数组或 Laravel Scope 后，组合代数原封不动活下来（第六节）。
- **`array_filter` 有什么坑？** → 保留原键（实测 `2,3`），序列化或给前端前要 `array_values()` / `iterator_to_array(..., false)`；回调逐行求值、顺序稳定，但**没有跨行短路**。
- **谓词组合要注意什么？** → 短路与纯函数。带副作用的谓词会把短路变成隐性行为。
- **原文 `OrCriteria` 的 `in_array` 去重有什么问题？** → O(n²)，且 `in_array` 默认松散比较（对象按属性比较），属性相同但身份不同的记录会被误判成重复而丢掉。
- **and/or/not 构成什么代数结构？** → 布尔代数（与/或/非，吸收律成立），所以过滤器链能像表达式一样做常量折叠、去重、下推 —— **查询优化器干的就是这件事**。
- **多条件组合怎么测？** → 谓词是纯函数、组合器是纯代数：单测对 `Predicates::all($a, $b)` 喂几行 fixture 断言 `bool`，不需要数据库、不需要 mock。

## 一、常见数据结构有哪些？该重点掌握哪些？

**来源**：`p=50` 小鹏后台开发二面（日常实习）· 时长 4分36秒

**考察意图**：**这题本质是考察"备考策略"，而不是考察你能不能背出一堆数据结构**。

### 一、先分类：线性 vs 非线性

```text
常见数据结构
├── 线性结构
│     ├── 数组
│     ├── 链表
│     ├── 栈
│     └── 队列
└── 非线性结构
      ├── 树：红黑树、B 树 / B+ 树、字典树
      ├── 图
      ├── 跳表
      ├── 并查集
      └── 布隆过滤器
```

### 二、线性结构：必须全部掌握

> **数组、链表、栈、队列——这四个是基础中的基础，必须掌握。**
>
> 它们**理解上没有难度**，而且**只要真正理解了每种结构"是什么"，
> 它们之间的区别自然而然就能讲出来**。

**所以对这四类不需要背对比表，重点是把"是什么"搞懂。**

### 三、非线性结构：至少熟练 2~3 种经典结构

**要求**：不管面大厂还是小厂，**手上要有 2~3 种能熟练表达的非线性结构**。

**推荐的 2~3 种（性价比最高）**：

| 结构 | 为什么值得选 |
|---|---|
| **红黑树** | 经典平衡树，面试高频（`map` 的替代实现、`epoll` 的底层、Java TreeMap） |
| **B 树 / B+ 树** | **数据库索引**的底层结构，与后端岗位强相关 |
| **跳表** | Redis **有序集合（zset）** 的底层实现，Go/Redis 方向必问 |

### 四、面试技巧：不会的时候如何"引导"（这段很实用）

> **面试中一定会遇到你不擅长的领域，这很正常——没有任何人要求你所有内容都能答出来。**

**正确做法：主动引导到你会的地方**：

```text
面试官：你熟悉"平衡二叉树"吗？
你：这个我不太熟悉，但我熟悉红黑树 / B+ 树……
    （然后自然过渡到你能展开讲的结构上）
```

**为什么有效**：
- 面试官问数据结构，往往**不是要一个标准答案**，而是想找一个**能聊下去的点**；
- 你**主动提供一个能深入的点**，对话就转到你的主场，**面试官也会觉得你"有料"**；
- 切忌**硬编**——编不出来反而暴露基本功不扎实。

### 五、按目标公司业务做针对性准备

**这是原视频最实用的一条建议**：

| 目标公司业务 | 重点准备 |
|---|---|
| **地图导航、推荐系统** | **图**及其衍生结构 |
| **文件系统、数据库索引** | **B 树 / B+ 树** |
| **缓存、去重** | **布隆过滤器** |
| **Redis 相关** | **跳表** |

**原则**：
> **提前了解目标公司的业务方向，就能有针对性地准备数据结构。**
>
> 另外，**如果你在实际项目中用过某个数据结构，一定要重点体现**——
> 例如项目里做过缓存过滤、用了布隆过滤器，那就把这段经历讲清楚，
> 这比"我知道这个结构"有说服力得多。

### 面试答题建议

- 先讲**线性四件套**（说明基础扎实），再讲**你熟练的 2~3 种非线性结构**（说明有深度）；
- 谈到具体结构时，**顺带说出它在真实系统中的落地**
  （B+ 树 → MySQL 索引；跳表 → Redis zset；红黑树 → epoll/Java TreeMap）——
  **把"数据结构"和"工程实践"关联起来，是这个回答最大的加分项**。

## 面试官会追问什么

- **面试官为什么会问「该掌握哪些」？** → 这是**备考策略题**，考的是你有没有形成取舍。罗列一堆结构反而暴露没有重点。
- **答不上来某个结构的实现怎么办？** → 先给分类框架（线性/非线性、内存/磁盘、有序/无序），再挑 2~3 个**能说透**的展开；铺开十个不如讲透三个。
- **怎么把结构和工程实践关联起来？** → 每个结构挂一个真实用法：B+ 树 → MySQL 索引、跳表 → Redis ZSet、红黑树 → epoll / TreeMap、布隆过滤器 → 缓存穿透防护。
- **要不要背复杂度？** → 要，但更要能讲 Big-O 之外的**常数、缓存局部性、额外内存与并发维护成本**（见 [../算法/复杂度分析.md](../算法/复杂度分析.md)）。
- **准备到什么程度算够？** → 能对每个结构回答三问：什么场景用它、它的代价在哪、替代方案是什么。
